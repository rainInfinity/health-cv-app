# 产品需求与功能范围

本文维护已确认的产品目标、开放条件与待补充契约，不表示目标能力均已实现。采集、文件或界面成功不能替代健康指标有效性。

## 产品定位与决策

面向普通用户的日常健康管理，按健康指标而不是相机、传感器和文件组织功能。目标指标为血压、心率、呼吸率、血氧饱和度；新增指标需单独确认。不提供临床诊断或个性化健康建议。

| 决策 | 要求 |
| --- | --- |
| 独立测量 | 每项指标分别发起任务、维护可用性、状态、结果和历史；不因共同信号就推定其他指标已有结果。 |
| 逐项开放 | 各项完成算法契约、适用范围、质量、评估规则与实际路径验证后再开放，不默认四项同时可用。 |
| 结果展示 | 保留原始读数、单位、测量时间、质量和固定算法版本，展示经确认的参考范围与评估状态。 |
| 客户端评估 | 使用关联指标及算法版本的版本化规则，不在页面散布阈值判断；规则声明人群、必要资料、单位、边界和缺值处理。 |
| 不适用与缺资料 | 可展示合格原始读数，但不生成无依据的评估状态或参考范围；不默认要求填写全部资料。 |
| 历史评估 | 按当前规则重新评估，原始读数和测量时间不改；显示规则版本与评估时间，避免将状态变化误解为读数变化。 |

## 功能要求

### 账号与资料

支持注册、登录、退出及本人资料查看／更新。未知、未填写和明确“否”有不同语义，不能相互替代。资料字段及 PATCH 规则以[云端接口](../development/cloud-client-api.md)为准；凭据与会话边界见[认证会话](../development/native-auth-session.md)。

### 准备、结果与历史

- 测量前说明该方法必需的动作与权限；准备提示、预计时长和重测规则按具体方法确认，不能从调试参数直接推导。
- 低质量、无有效信号、算法失败、请求失败、无记录分别表达；缺失结果不补零、默认健康值或样例。
- 记录按指标和单次任务区分，趋势只使用真实、有效且语义一致的读数。
- 当前普通用户接口没有任务删除或取消能力，不承诺尚无接口支持的操作。

### 隐私与生命周期

健康资料、结果、采集文件和上传行为须明确用途、授权、访问控制、本地／服务端保留期限及用户可执行的删除方式；这些细则是正式开放的前提。目前不假定默认期限、自动上传或上传成功即删除。

## 当前实现边界

- 原生应用已有开屏、两步引导和健康／功能／历史／我的／开发五个 Tab；历史入口及未开放的资料、健康记录等功能使用统一说明，不等于目标历史能力已交付。
- 功能页按部位或指标进入准备。面部产品页接入真实本地 RPPG，指尖页为隔离的模拟流程，血压流程尚未接入；界面存在不表示相应指标已经达到正式开放条件。
- 面部页面只展示当前会话有效频谱窗口的平均；无有效窗口显示 `--`，不回写首页、最近检测时间或健康历史。逐搏初步值与频谱平均是不同结果，见[RPPG 协议](../acquisition/android-rppg.md)。
- 相机 PPG、独立传感器和被动 RPPG 是本地工程能力；新被动会话不录像，旧视频仅保留查询。它们不自动构成普通用户测量方法、跨源同步或医学结果。
- 云端 SDK 与认证可独立使用，但 Native 尚未完成真实采集产物的创建任务、上传、提交和结果回显闭环；示例模型的统计字段不能当作健康指标合同。
- Demo 样例、登录态界面样例、指标图形及主题颜色不属于真实测量记录，也不证明算法、评估或风险筛查可用。旧项目字段、阈值和流程仅供参考。

实现模块职责见[代码组织](../architecture/code-organization.md)，页面与模拟边界见[Demo 说明](../design-demo/README.md)。

## 指标开放前的合同

四项指标分别补齐以下内容，不共享未经确认的结果假设：

1. **结果**：字段、单位、精度、时间语义、算法版本及读数组合。血压是否使用收缩压／舒张压须由新合同确认，旧项目 `sbp`／`dbp` 不构成本项目合同。
2. **质量**：成功条件、质量信息、拒绝／无信号／算法失败的区分与用户含义。文件存在不能证明质量合格。
3. **适用性**：人群、必要资料、测量前提与操作方法。
4. **评估**：阈值、边界、单位换算、缺资料、不适用、规则版本及更新流程。
5. **验证**：真实测量路径与算法合同相符；技术采集、模拟器或合成输入不替代指标有效性。
6. **产品与隐私**：预计时长、重测、未开放指标的隐藏／不可用／规划展示方式，以及授权、保留和删除规则。

无扰被动采集是否进入普通用户功能，需另行明确使用场景、用户价值和授权；相机参数、原始文件、诊断状态与传感器调试不作为产品指标。
