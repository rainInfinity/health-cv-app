# 产品需求与功能范围

本文维护已确认的产品目标、开放条件与待补充契约，不表示目标能力均已实现。采集、文件或界面成功不能替代健康指标有效性。

## 产品定位与决策

面向普通用户的日常健康管理，按健康指标和检测方式组织功能。指尖统一场景提供心率、呼吸率、血氧及糖尿病风险成员，指尖＋胸口统一场景提供血压；成员分别判定有效性。不提供临床诊断或个性化健康建议。

| 决策 | 要求 |
| --- | --- |
| 统一场景 | 指尖各入口共用一个 PPG 场景，血压各入口共用一个 PPG＋ACC 场景；入口目标不创建独立指标任务。 |
| 独立有效性 | 任务完成不等于所有成员成功；部分成功保留有效成员，全部失败不显示默认读数。 |
| 结果数据 | 保留原始读数、单位、服务端 submittedAt、实际质量、风险编码及固定算法版本；数据字段不自动成为新增 UI 内容。 |
| 评估边界 | 血压按确认的90／60与140／90边界展示偏低／正常／偏高三级，原始值判断且低高交叉偏高优先；其他无依据评估占位，不生成临床诊断。保留原静态参考信息、配色及通用说明／建议。 |
| 历史范围 | 当前指标和日期范围全部有效记录统一进入原趋势与统计，不按来源、算法或版本分组；风险不生成均值和趋势。 |

## 功能要求

### 账号与资料

支持注册、登录、退出及本人资料查看／更新。未知、未填写和明确“否”有不同语义，不能相互替代。资料字段及 PATCH 规则以[云端接口](../development/cloud-client-api.md)为准；凭据与会话边界见[认证会话](../development/native-auth-session.md)。

### 准备、结果与历史

- 测量前说明该方法必需的动作与权限；准备提示、预计时长和重测规则按具体方法确认，不能从调试参数直接推导。
- 数据层区分低质量、无有效信号、算法失败、请求失败和无记录，不补零、默认健康值或样例。页面迁移已确认的加载、空态及失败设计，保留成功态布局和静态参考信息，不展示内部技术阶段。指尖部分成功保持“检测完成”，失败项说明未生成或质量过低；检测失败只重测，结果获取失败只重查原任务，任务创建失败只重测，不提供失败详细报告。
- 记录按指标和单次任务区分，趋势只使用真实、有效且语义一致的读数。
- 当前普通用户接口没有任务删除或取消能力，不承诺尚无接口支持的操作。

### 隐私与生命周期

产品接触式检测须先登录并检查当前渠道统一模型，不增加独立 PPG／ACC 上传用途确认弹窗或专属确认偏好；系统权限与既有准备、操作指导保持。正常采集及资源／文件收尾后自动上传提交，没有额外提交步骤。面部和无扰本地路径不因此入云。

保留期限和删除政策尚无统一约定，不承诺自动删除、用户取消服务端任务或后台／跨进程上传恢复。退出、换号、重测和离页撤销本地后续动作，不删除完成文件，也不等同取消已提交任务。

## 当前实现边界

- 原生保留开屏、两步引导和五个 Tab。资料、个人资料及帮助反馈尚未开放，不提供假编辑或假提交。
- 产品指尖与血压开始前检查认证和当前渠道统一模型；未配置相应场景时明确反馈不可用，不回退其他算法。准备和采集中保留系统权限、原有指导、原生覆盖、联合准入、正式时钟及关闭屏障，不能由动画、文件或工程候选推断健康有效。
- 正常完整收尾后自动创建任务、按引用顺序上传必需文件并提交实际采集方式及正式时长。查询真实任务、成员结果、质量与授权输出；无固定样例或三秒成功等待。报告读取失败不抹去有效数值。
- 首页读取各指标最新有效记录，各自显示 submittedAt；首次无缓存时加载骨架，返回或聚焦不自动重取，支持下拉刷新，新有效记录通过对应查询键更新。后续加载圈随被替换内容的实际尺寸变化，获取或刷新失败后显示空数据。指标卡及血压详情直接进入对应指标的北京时间当日日区间，检测主按钮仍进入真实测量。历史首次读取、切换筛选和同区间刷新共用页面加载，读取失败共用失败文案及重新获取，不使用 Toast，加载及失败不展示旧内容或声明；其他历史入口保留筛选，不增加任务报告按钮。
- 糖尿病风险在首页、指尖简要结果和详情、历史列表与记录详情中统一映射已有0／1／2编码为较低风险／中风险／较高风险，不展示概率或风险分数；字号20、行高26，使用与其他读数一致的主文字色。详细结果的看板与解读单行显示等级，其余入口仍为等级和“风险”分两行居中，历史行高自然适应。风险排版不改变加载圈占位尺寸；独立加载圈采用主题渐变和浅色底轨，渐变底按钮内保留白色前景。缺失或失败不默认低风险，原始概率及编码保持不变，产品档位不构成医学风险分层或诊断。
- 面部只展示当前会话有效频谱窗口均值，不混入云端首页或历史；无扰服务与独立开发采集保持本地边界。模拟器、录像、模型推理和真实文件均不证明人体信号质量、医学准确性或临床许可。

实现模块职责见[代码组织](../architecture/code-organization.md)，页面与模拟边界见[Demo 说明](../design-demo/README.md)。

## 指标开放前的合同

已支持字段和算法以[云端接口](../development/cloud-client-api.md)及后端合同为准。新增或扩展指标时，分别明确以下内容：

1. **结果**：字段、单位、精度、时间语义、算法版本及读数组合；血压 sbp/dbp 必须来自同任务的同一成功成员。
2. **质量**：成功条件、质量信息、拒绝／无信号／算法失败的区分与用户含义。文件存在不能证明质量合格。
3. **适用性**：人群、必要资料、测量前提与操作方法。
4. **评估**：阈值、边界、单位换算、缺资料、不适用、规则版本及更新流程。
5. **验证**：真实测量路径与算法合同相符；技术采集、模拟器或合成输入不替代指标有效性。
6. **产品与隐私**：预计时长、重测、未开放指标的隐藏／不可用／规划展示方式，以及授权、保留和删除规则。

功能页无扰开关控制既有本地服务，启用前沿用知情说明与系统权限。无扰结果不进入云端健康记录；相机参数、原始文件和传感器诊断不作为产品指标。
