# 心沐交互设计 Demo

独立、零依赖的移动端设计演示，不连接真实业务。品牌资源直接读取 `apps/native/assets/` 中的 SVG、应用图标与 favicon，不额外维护一套副本；不修改认证 SDK 或根依赖配置。

## 启动

在项目根目录执行：

```sh
node docs/design-demo/server.mjs
```

浏览器访问 <http://127.0.0.1:4173/>。无需安装依赖；停止时按 `Ctrl+C`。

端口占用时可指定其他端口：

```sh
node docs/design-demo/server.mjs 4174
```

服务只监听本机 `127.0.0.1`，不能从同一 Wi-Fi 的其他设备直接访问。需要通过 HTTP 访问，不要双击 `index.html` 使用 `file://`。其他静态托管需将 `/brand-assets/xinmu-logo.svg`、`/brand-assets/icon.png`、`/brand-assets/favicon.png` 映射到 `apps/native/assets/` 中的同名文件；本地服务仅通过精确白名单暴露这三项资源，不开放整个 assets 目录。

## 页面与操作

桌面左侧采用思维导图式导航：“页面”为根节点，通过连接线分出“主界面”“账户”“启动展示”“首次体验”四个分类，包含十个基础页面。“健康”“我的”右侧各分出“未登录／已登录”两个上下排列的状态节点，父节点垂直居中，连接线从右侧分叉。当前状态高亮，无需填写登录表单即可切换；切换会更新两个页面共用的本地演示登录状态，不修改资料。侧栏宽度为 344px，桌面间距随窗口收缩，手机预览仍保持 390px 宽。“启动展示”包含桌面和开屏，“首次体验”包含功能引导、授权引导。点击入口切页；不提供拖拽画布。较矮窗口中侧栏可独立滚动。移动端仍为全屏显示，底部导航不变。

桌面侧栏提供与“页面”同级对齐的“组件”根节点，右侧通过连接线分出同宽、同列且文字居中的“弹窗”和“Toast”；Toast 右侧继续分出成功、错误、加载中、信息四种预览按钮，始终展示，不提供展开／收起控件或加减号。Toast 父节点仅作分组标签，不作为按钮。状态按钮的读屏名称和悬停提示保留 `success`、`error`、`loading`、`information` 技术标识。预览不切页、不修改演示数据，仍在手机区域内展示。侧栏底部不再显示固定样例等说明；“重置演示”移至右侧手机预览下方并右对齐，矮桌面窗口预留底部空间，避免遮挡预览。移动端隐藏桌面侧栏与该重置按钮，业务页面入口不变。

Toast 固定在手机顶部状态栏下方（距手机顶端 60px），左右留白 16px；四种状态统一白底、中性边框、深色正文与灰色关闭按钮，保留 22px 圆角和轻阴影。状态主要通过面性图标区分：成功为青绿实心圆与白色勾、错误为玫红实心圆与白色叉、加载为青绿粗环、信息为蓝色实心圆与白色 `i`，并保留中文状态名称。错误提示使用 `alert` 语义，其余使用 `status`；所有提示均可关闭。成功、错误和信息在 3.5 秒后自动消失，重复触发重新计时；加载提示持续到被下一条提示替换或手动关闭，不模拟真实异步结果。加载图标缓慢旋转，开启“减少动态效果”时静止。现有保存、演示登录注册、退出及重置完成提示使用 `success`。

登录、注册通过校验后，以及点击退出登录时，按钮和 Toast 同步进入加载态约 1 秒：按钮显示旋转图标及“登录中…”／“注册中…”／“退出中…”，Toast 显示“正在登录…”／“正在注册…”／“正在退出登录…”。加载期间按钮禁用，重复提交不再触发操作；按钮尺寸、渐变和正常透明度不变。完成后执行原有本地状态切换并替换为成功提示；校验失败仍显示表单错误，不进入加载态。等待期间切页会取消尚未完成的操作，避免旧计时跳回账户页。“减少动态效果”模式下两个加载图标均静止，等待和结果不变。这只是离线演示，不请求真实认证服务。

| 页面 | 地址 | 可体验内容 |
| --- | --- | --- |

四个状态可通过 `#home-guest`、`#home-logged-in`、`#account-guest`、`#account-logged-in` 直接预览，刷新对应地址会恢复该演示状态。普通 `#home`／`#account` 和底部导航沿用当前共享登录状态；登录后两页同时切换为已登录，退出后同时恢复未登录。预览已登录状态只设置本地演示身份，不进行真实认证，也不增加手机业务界面中的状态切换按钮。

底部导航为“健康、功能、历史、我的”。指标 Tab 支持左右方向键及 `Home`、`End`；弹层可用 `Esc`、关闭按钮或点击遮罩关闭。浏览器前进、后退可切换页面。

弹窗、遮罩与 Toast 均限制在手机区域内，不以浏览器视口定位；遮罩不覆盖桌面侧栏。弹窗相对手机区域居中，长内容在弹窗内滚动；打开时禁用手机背景页面交互，`Tab`／`Shift+Tab` 在弹窗控件间循环。弹窗与遮罩统一以透明度进行 200ms 淡入、150ms 淡出，不位移、不缩放；淡出完成后隐藏遮罩、恢复手机交互，并将焦点返回仍存在的触发入口。关闭过程中重新打开会取消旧动画，避免旧回调隐藏新弹窗。“减少动态效果”模式下立即开关。桌面侧栏仍可切页，切页时关闭弹窗并在淡出后恢复手机页面交互。

手机上查看启动页、重看功能引导或重置演示：我的 → 右上角设置；三个入口独立，不再从开屏进入首次引导。

## 数据与认证边界

- 所有健康数据是固定样例，日期范围为 2026-10-25 至 2026-10-31；筛选其他日期会出现空状态。
- 血氧仪表为 85–100%、15 格、圆角灰底，当前 98% 显示 13 格主题浅薄荷绿。区间只按已确认的视觉方案展示，不表示医学阈值已经验证。
- 糖尿病风险没有样例结果，不生成假分数、等级或趋势。
- 已登录主页及功能页的测量入口只打开功能说明，不请求相机、传感器或健康权限，不生成测量成功状态；未登录主页入口先进入登录。
- 指尖心率与呼吸率共用一次采集说明，已登录首页两项指标的功能入口也指向该说明；面部心率单独说明前置相机采集方式，不展示冒充面部测量结果的历史样例。
- 功能页进入或重新渲染时，按浏览器当前时间与最近样例时间的实际间隔显示分钟、小时或整天；记录日期本身不漂移。指尖联合、血压、血氧沿用 2026-10-31 08:30（北京时间）样例，面部无独立记录显示“尚未测量”，风险无样例显示“尚未评估”。时钟早于记录时显示“测量时间待核对”，不伪造刚刚测量。
- 登录不是认证：任意非空用户名和密码只用于体验页面流转，不与注册密码比对、不签发令牌。不要输入真实密码。
- 注册不创建真实账号；完成后返回登录并预填用户名。未模拟 Django 服务端的完整密码规则。
- 用户名、资料、偏好、反馈、注册用户名和筛选条件仅在当前标签页内存中保留，刷新后清除。密码不写入演示状态、日志、URL、LocalStorage 或 SessionStorage。
- 没有后端请求、文件上传、真实通知或被动采集；服务端 CSP 禁止页面发起连接请求。
- 所有公开输入进入 HTML 模板前均转义；服务仅提供精确白名单中的静态资源。

### 个人资料契约与草稿

“我的 → 个人资料”统一编辑基本信息与健康病史，不再提供独立健康资料卡片或健康资料引导。字段按 `Req.Users.ProfilePatchRequest` 命名，不表示已接入服务端：

| 字段 | 页面及提交语义 |
| --- | --- |
| `name` | 姓名／称呼，选填，最多 50 字符；示例初值为“小安”，主动清空为 null |
| `gender` | 0 未知／未填写、1 男、2 女；不能提交 null |
| `birthDate` | 日期选择，保存 `YYYY-MM-DD`，不换算成年龄；主动清空为 null |
| `heightCm` / `weightKg` | cm／kg，正数、最多两位小数；按后端总位数限制为不超过 999.99／9999.99，主动清空为 null |
| `historyJson.isHypertensive` | 高血压病史：有／无／不清楚，默认不选中 |
| `historyJson.isDiabetic` | 糖尿病病史：有／无／不清楚，默认不选中；不能把高血糖直接当作糖尿病 |
| `medicalHistory` | 其他病史选填文本，可补充尚未确诊的高血糖；主动清空为 null |

仅将相对已保存状态发生变化的字段组成局部更新，缺席字段不覆盖已有值。病史“有”为 true、“无”为 false；从明确回答改为“不清楚”时生成键值 null，并从本地病史对象中删除对应键，再次打开按未填写展示，不自动选择“无”。另一病史及已有扩展内容保留。关闭弹窗或离开页面不保存草稿，部分填写及全部留空均可保存。所有资料仅在当前标签页保留，刷新或重置演示恢复初值，不上传，不生成诊断或风险结论。

## 视觉约定

以当前健康与功能页反向整理 `apps/native/src/shared/theme/theme.ts`，Demo 在 `styles.css` 中做对应映射，不导入 React Native 平台模块。健康、功能页渐变收拢为 `--background-home`／`--background-functions`；按钮、健康主卡和功能卡分别使用 `--gradient-button`／`--gradient-health-card`／`--gradient-function-card`。卡片保留 22px 圆角和轻微右下阴影；白色浮层使用独立阴影，输入框使用 8px 圆角、按钮为胶囊形。标题、说明、数字与首页布局间距通过文字和布局变量复用，保留窄屏差异，不将所有页面边距强行统一。

颜色分为品牌、装饰、操作反馈和健康评估，不按生理领域强制绑定装饰色。Toast 使用正式反馈 token：`success #16836B`、`error #C54868`、`loading #087D83`、`information #2E6F91`。前两项为从当前薄荷与亮玫红衍生的新颜色，不再维护 Toast 私有色板。白底和面性图标不变，成功、错误图标与白色的计算对比度均为 4.67；这不代表整页或渐变白字满足 AA。完整主题规范与由原生主题导出的总览图见 `../development/frontend-development.md`。

首页心率、呼吸率分别复用旧项目主页的 `IconXinlv`、`IconFei` 矢量路径，糖尿病风险复用其血压图标 `IconXueya`（圆形血滴）。来源为旧项目 `src/assets/iconfont/`，仅将 SVG 路径内联到 Demo，不依赖旧项目组件或字体。三个图标统一为 48×48px；心率与风险使用柔和玫红 `#DD5D7D`，呼吸率使用按钮渐变起始色 `#0AB6C0`（复用 `--primary`）与白色肺部，不改变指标名称或结果含义。

心率与呼吸率的图形区域仍为 64×64px。心率背景保留双圈缓慢扩散波纹，周期 4.8 秒，仅改变透明度与缩放、不影响布局；开启系统“减少动态效果”时保持静止。该动效仅为视觉装饰，不代表实时心率或采集状态。

功能页卡片采用半透明浅白到淡青绿的微弱渐变，不透明度约 76%–84%，保留原有 22px 圆角、阴影与布局；其他页面卡片背景不变，文字和插画本身不降低透明度。五幅本地 SVG 使用更鲜明的玫红、青绿和浅蓝渐变，保留白色贴纸描边和轻阴影，不依赖网络图片。

五幅功能插画统一使用 96×84px 展示框，按实际图形包围盒等比缩放、居中对齐，而非只统一外框。血压测量、血氧饱和度、糖尿病风险在归一基准上再整体缩小约 10%。缩放值固化在 SVG 图层中，不在页面运行时计算；保留原始比例、内部手势与图标覆盖关系，不拉伸图形。

五张功能卡片的插画与文字间距统一为 8px（原为 12px），插画尺寸、卡片内边距和卡片之间的间距不变。已检查 375px、320px 显示及五项入口，无横向溢出。

指尖插画以用户实拍的相对位置为基础，采用简化卡通轮廓：食指沿机背向上贴住左上镜头，拇指在左侧偏下，另一侧用平滑曲线概括其余手指的握持。移除关节皱褶、筋线和多余指甲细节，改用浅色渐变与白色描边，不强调关节弯曲；保留后摄模组与黄色闪光灯。心率与呼吸率图标保持相近尺度，分别旋转形成扇形；肺部位于右上方并后绘制，覆盖心形右侧约一半的横向轮廓范围。面部心率心形与指尖心形保持相同实际缩放比例，移除圆形底框，保留贴合心形的白色描边与玫红渐变，顺时针旋转 30°。不将插画当作经过验证的操作指南。

指尖插画中的心率、呼吸率图标组当前 SVG 位移为 `translate(-24 -6)`；最近一次相对调整为再下移 4 个单位。图标覆盖右侧握持手指，大小、组内扇形排列和呼吸率前景层次不变。已在 375px 宽度实际检查，显示正常、无横向溢出。

糖尿病风险插画不含心形，使用血滴、GLU 字样与葡萄糖六边形 G 标志表达血糖相关风险；仅为功能插画，不展示血糖检测结果。

登录、注册页共用居中品牌组合：左侧 64px LOGO，右侧上下排列 26px“心沐”和 12px Slogan“关心每一次心动。”。右侧两行左对齐、行间距 4px，与 LOGO 间距 12px，图标与文字块垂直居中；Slogan 仅位于名称下方，不在整组下方。原标题及说明已移除，返回、页面切换、表单和底部居中隐私说明保留，认证交互不变。已实际检查 390px、375px、320px：品牌组居中、无横向溢出，超长页面可滚动。

首页移除右上角通知按钮，在该位置展示“仅供健康管理参考，非医学诊断依据。”；历史页仍在标题旁分两行展示。功能页标题右侧单行展示“测量结果仅供参考，非医学诊断依据”，已检查 320px、375px、390px 宽度下不换行、不与标题重叠且无横向溢出。说明不在指标区或页面底部重复。Demo 外框、读屏标签及详情弹层仍明确标注样例数据属性。

渐变按钮的白色文字沿用已确认视觉，不能据此宣称满足 WCAG AA 文字对比度。这里只提供浅色、简体中文界面。

## 文件职责

- `index.html`：桌面预览外壳与弹层容器。

- `app.js`：路由、导航、弹层和标签页内的演示状态。
- `server.mjs`：仅支持 GET/HEAD 的本地静态服务，品牌资源使用精确文件白名单。
