# 测量业务与接入说明

## 1. 范围与维护边界

本文维护原生测量的业务流程、交互和结果含义。当前业务归 `apps/native/src/app/measurement`，不创建独立业务包；原生采集及设备生命周期以对应协议为准，UI 和查询约定见[前端开发约定](frontend-development.md)。面部保持本地 RPPG，指尖及血压使用真实采集后的统一云端场景。

第 10 节维护已接入的指尖与血压检测语音提示，按检测方式组织；面部心率与被动检测没有接入检测语音。

指尖使用后摄、可选补光、空间覆盖门控及本轮真实脉搏。补光不支持或未知不单独阻断检测，不改变原生覆盖准入；采集客户端只产生原始文件和展示脉搏，不计算健康指标。

产品指尖与血压开始前须登录并取得当前渠道统一模型，不增加独立云端用途确认弹窗。正常目标结束、文件定稿和资源释放后自动创建、顺序上传并提交，报告使用真实成员结果、实际质量与授权处理后文件。首页和历史只查询服务端有效记录，不用本地完成事实或样例追加。面部、无扰及独立开发入口不因本流程入云；无云端配置时产品接触式不可启动。

本文维护业务含义和已确认的中文提示，运行时文本位于 [zh-CN.json](../../apps/native/src/app/i18n/locales/zh-CN.json)。调整流程或文案时同步维护资源、实际消费逻辑与本文；不把未使用的资源键当成已有交互。底层参数、算法、文件字段和时钟协议分别以 [PPG](../acquisition/android-ppg.md)、[RPPG](../acquisition/android-rppg.md) 为准，UI 和图表实现遵守[前端开发约定](frontend-development.md)，不在此复制底层协议或验收记录。

## 2. 核心概念

| 概念 | 业务含义 |
| --- | --- |
| 检测方式 `method` | 面部、指尖或指尖＋胸口，决定准备引导与实际采集路径。 |
| 指标入口 `target` | 报告重点与返回上下文；指尖各目标共用统一 PPG 场景，血压共用统一 PPG＋ACC 场景，不切换独立算法。 |
| 一轮测量 | 从明确开始到采集、收尾及云端结果；业务关联开始时认证代次、captureId、taskId、固定版本和上传回执，重复完成通知不重复推进。 |
| 原生采集身份 | 面部 `sessionId`，指尖 `captureId` 及其原始采集 `sessionId`；状态、波形和产物必须属于当前轮，标识不能混用。 |
| 本轮展示结果 | 面部已观察到的有效频谱窗口摘要，或指尖真实覆盖、进度与波形；展示缓存不等于完整文件记录。 |
| 采集产物 | 原生定稿的本轮文件引用；有文件不表示采满目标时长、信号有效或已得到健康指标。 |

## 3. 共用入口与检测准备

### 3.1 入口与返回

功能页三个部位和首页检测主按钮共用 [entry.ts](../../apps/native/src/app/measurement/entry.ts) 的有限映射；首页指标只负责历史浏览，功能页不再有分类或指标列表：

- 面部部位和面部心率进入同一面部流程；心率、呼吸率、血氧及风险指标走同一指尖方式，指尖部位不预选指标，不因入口执行额外算法。
- 血压主按钮进入胸口方式及对应准备偏好；首页各指标和血压详情入口直接进入对应指标的北京时间当日日区间，移除旧指标详情浮层。
- 未跳过准备时先进入 `MeasurementGuide`。面部确认后替换准备页；指尖、血压保留准备页，检测返回先回准备，再返回原首页或功能入口。
- 已保存或当次勾选跳过时直接进入对应检测，不挂载隐藏准备页或补声音提醒；完整关闭后返回原来源。
- 本轮正常收尾后自动进入云端阶段，再从简要结果进入 `FingertipResults`／`BloodPressureResults`；报告以 `taskId` 查询，同轮往返额外携带 `captureId`。历史报告仅需 taskId，不要求原生轮次存活。详情返回不重采或重传，Android 返回先收起结果再按原来源退出。
- 贴胸操作指导的跳过偏好独立，不影响上述导航；“我的健康记录”和普通历史 Tab 保留当前筛选，首页指标入口显式覆盖指标与日期。
- 所有接触式入口、准备开始及设备启动前检查身份与当前渠道统一模型；跳过准备不能绕过。未登录进入既有登录流程，返回原来源后等待再次明确开始，不从登录回调自动打开设备。
- 不增加独立上传用途确认弹窗，不读写其专属确认偏好；系统权限、既有声音提醒与操作指导保持原有流程。
- 指尖显式匹配目录 `ppg.active.offline.all`，血压匹配 `ppg_acc.active.offline.all`；必要时继续分页核对实际 modelId、非示例和必需输入。缺失明确反馈不可用，不按名称猜测或回退独立算法。

| 指尖要点 | `coverTitle/coverHint`：覆盖后摄／后置镜头；`gentleTitle/gentleHint`：轻放指尖／不要用力；`stableTitle/stableHint`：保持稳定／手臂支撑。 |

“以后不再提示”按检测方式保存为设备偏好，指尖各指标共用指尖偏好；重启保留，退出账号不清除。勾选后当次点击开始也跳过声音提醒，后续同时跳过准备页与声音提醒。偏好不代表已授权、预览就绪或已经采集。

未勾选跳过时，准备页点击开始先显示独立的页内声音提醒弹层：

| 项目 | 资源键与现行文案 | 行为 |
| --- | --- | --- |
| 标题 | `soundReminderTitle`：提示 | 只说明声音准备，不改变系统设置。 |
| 正文 | `soundReminder`：为便于听取检测过程中的操作引导，请打开手机声音，并将媒体音量调至清晰可闻。 | 不检查或自动调整音量。 |
| 确认 | `confirm`：立即检测 | 弹层淡出完成后进入检测页；面部进入后仍须点击本页开始按钮。 |
| 取消 | `returnPreparation`：返回准备 | 仅关闭弹层，留在准备页。关闭入口、遮罩和 Android 返回键同样不启动检测。 |

准备页和声音提醒本身不申请相机权限、不打开设备，也不播放检测语音或控制音量；两种方式进入检测页后的启动时机不同，见下文。跳过偏好只跳过准备页与声音提醒，不关闭指尖或血压检测中的语音。

## 4. 面部心率检测

### 4.1 主流程

资源命名空间为 `pages/face-measurement`。产品状态是展示映射，不是一份独立的原生状态机。

| 阶段与进入条件 | 页面表现与文案 | 业务动作与推进条件 |
| --- | --- | --- |
| 进入检测页，尚未开始 | `ready`：待开始；`tapStart`：点击开始；`readyHint`：点击开始检测，保持面部完整入镜。平均为 `--`，计时 `00:00`，波形为空。 | `start`：开始检测。进入页面不创建 runtime、不授权、不挂载真实预览。 |
| 用户明确开始，授权、预览准备及找脸 | `measuring`：检测中；无有效摘要时 `accumulating`：获取信号中；镜头提示 `keepStill`：面部完整入镜，保持自然静止。 | 串行完成权限、真实预览宿主就绪、打开前摄与原生启动。准备期间按钮加载且不可重复触发；授权、打开和找脸不计入正式计时。 |
| 原生进入 `measuring` | 计时开始递增；已有有效频谱窗口后状态提示为 `stable`：保持稳定。 | 原生决定正式采集及截止，目标三十秒；观察或正式采集中可用 `stop`：结束检测提前结束本轮。 |
| 停止或到时，原生 `stopping` | 仍映射为检测中，操作加载／禁用，不因计时到点立即显示已结束。 | 等待原生相机、算法和文件收尾。 |
| 原生 `completed` 或 `failed` | `ended`：已结束；`endedHint`：检测已结束；主按钮 `restart`：重新检测。技术错误另走统一反馈。 | 冻结本轮计时、摘要和已收到的波形；结束不表示心率有效。 |
| 明确重新检测 | 清空旧摘要、计时和曲线，重新走启动流程。 | 先关闭需要关闭的旧 runtime；已关闭客户端不复用，旧轮回调不得更新新轮。模型启动失败留下的预览可按当前实现重新启动。 |

原生找脸与连续就绪规则见 RPPG 协议。页面不根据动画、预览可见或“检测中”文案判断正式采集已经开始；没有有效结果时也不延长原生目标时长。

### 4.2 平均心率与计时规则

- 平均只累计本轮实际收到的唯一有效频谱窗口，按原生会话、片段和窗口时间去重；重复、迟到、无效及非有限值不参与累计。
- 显示值为有效窗口算术平均的整数展示，单位 `次/分`；无有效窗口保持 `--`。逐搏瞬时心率不填入平均槽位，有波形也不保证平均有值。
- 摘要代表当前页观察到的窗口，不是读取全部文件后重建的权威最终平均；关闭后的空快照不擦除已经冻结的摘要。
- 页面计时从原生 `measuring` 通知建立单调经过时间，仅供展示；不能直接用 JS 时钟减原生绝对纳秒推导截止。
- 到时、提前停止、观察超时或后台中断与信号有效性分别记录。完整面部RPPG产物可以没有有效心率，技术失败不能伪装成正常无信号结果。

### 4.3 必要错误反馈

错误按稳定代码选择中文，不回显原生异常、堆栈或历史诊断。当前使用统一弹窗，确认只关闭反馈；开始／重测仍通过页面主操作，关闭失败后再次返回仍须经过关闭屏障。

| 条件 | 资源键与现行文案 |
| --- | --- |
| 权限不足 | `errorPermission`：未获相机权限，请重试并允许使用前置相机。 |
| 相机占用 | `errorBusy`：相机正由其他会话使用，请先结束原会话后重试。 |
| 预览或宿主未就绪 | `errorPreview`：前摄预览尚未就绪，请重试。 |
| 非支持平台 | `errorPlatform`：面部检测当前仅支持 Android。 |
| 文件、产物或记录链失败 | `errorFile`：结果文件收尾失败，请重试。未确认保存成功。 |
| 模型启动失败 | `errorModel`：面部处理模型启动失败，请重试。 |
| 相机启动或运行失败 | `errorCamera`：前置相机无法启动或已中断，请重试。 |
| 关闭失败，优先于一般错误 | `errorClose`：未能确认已安全关闭，请重试返回。 |
| 其他操作失败 | `errorGeneric`：检测操作未完成，请重试。 |

## 5. 指尖检测

### 5.1 主流程

资源命名空间为 `pages/fingertip-measurement`。本轮明确导航入口自动准备；没有额外的“打开相机”或“手动开始”面板。

| 阶段与进入条件 | 页面状态／状态辅助文案 | 镜头内提示及推进规则 |
| --- | --- | --- |
| 进入、授权及预览准备 | `ready`：准备检测；`statusReady`：指腹轻放，不要按压。 | `hintReady` 与 `hintPartial` 统一为：手指未完全覆盖镜头，请调整位置。申请权限、查询真实后摄与可选补光、等待有效宿主和布局，再打开预览及建立本轮覆盖观测。补光不支持或未知时不请求开启，继续检测准备。 |
| 覆盖未知或未覆盖 | 同准备检测，剩余时间保持 `00:30`。 | 继续等待真实空间覆盖输入；未知不补成 0 或 100。 |
| 原生部分覆盖 | `partial`：调整手指；`statusPartial`：让指腹完整覆盖后置镜头。 | `hintPartial`：手指未完全覆盖镜头，请调整位置。不能靠等待、取整或动画显示满环。 |
| 完整覆盖、稳定确认或 `starting` | `covered`：准备开始；`statusCovered`：保持轻覆，正在确认覆盖。 | `hintCovered`：已完整覆盖，请保持轻覆稳定。完整覆盖连续三秒且输入新鲜后才允许原生启动准备，仍须完成必要锁定和文件准备；此时不扣正式倒计时。 |
| 原生 `capturing` | `running`：检测中；`statusRunning`：自然呼吸，保持手指稳定。 | `hintRunning`：正在检测，请勿移动手指。正式三十秒窗口开启，消费原生剩余时间，并自动切到脉搏波页。 |
| 原生 `stopping`，或正常完成但资源尚未释放 | `stopping`：正在结束；`statusStopping`：正在完成本轮检测。 | `hintStopping`：正在结束，请稍候。等待本轮文件与相机屏障，不提前显示整体成功。 |
| 正常完成且资源释放，进入真实云端流程 | 上传、提交、排队、运行等真实阶段；不显示推理百分比或固定最短等待。 | `hintCompleted`：检测完成，可以移开手指。保持00:00、覆盖末值和本轮曲线；只上传同轮 PPG。 |
| 云端取得可解释终态 | 查看本次结果，区分有效结果、部分成功、全部失败和任务失败。 | 每轮自动展开一次简要结果；收起可重开，重复完成通知不创建第二个任务或重复展开。 |
| 原生 `interrupted` | `interrupted`：检测已中断；`statusInterrupted`：请重新放置手指后重试。 | `hintInterrupted`：本轮已结束，请重新检测。保留实际剩余时间，通过统一反馈提供返回／重新检测。 |
| 原生 `failed` 或本地准备失败 | `failed`：检测未完成；状态辅助文案沿用 `statusInterrupted`。 | 通过统一错误反馈说明可处理原因；不伪装为正常采满。 |

### 5.2 覆盖、计时与展示规则

- 指尖与血压第一阶段的等待覆盖、部分覆盖共用镜头内提示“手指未完全覆盖镜头，请调整位置”；仅统一提示文案，底层覆盖分类、百分比、状态及准入规则保持独立，不改变语音提示。
- 覆盖百分比是原生空间估计，不是等待进度、精确物理面积或医学质量。`coverageReady` 与百分比是不同事实；100% 不等于已经正式采集，也不保证显示满环后恰好三秒开始。
- 三秒完整覆盖准入由原生负责。准备期间失去完整覆盖会退回观测并重新累计；提示防抖和弹窗不控制开窗。
- 正式期间允许原生协议规定的轻微缺角；不能把“不是完整覆盖”直接解释为立即结束。持续覆盖失效或无新帧达到原生丢失条件才中断，当前维持门槛与确认时长见 PPG 协议“产品指尖的覆盖与正式窗口”。短暂失效不暂停、不补足绝对三十秒窗口，已结束轮次不能恢复。
- 倒计时直接使用原生 `remainingMillis` 向上取整的秒值。授权、等待布局、覆盖观测及启动准备不消耗正式三十秒；提前结束保留真实进度，不强制归零。
- 覆盖数字和环按最新真实值最多每 250 ms 消费一次，普通覆盖提示稳定 300 ms 后切换；正式阶段、终态、错误和取消即时处理。重试、后台及离页撤销旧提示回调。
- “流程说明”和“脉搏波”可横向切换或点击分页按钮；流程图使用 `backTitle/backHint`“轻覆后置镜头／指腹轻放，不要按压”和 `frontTitle/frontHint`“正面稳住手机／自然呼吸，保持稳定”。切页不重置采集、历史或原生时钟；回看波形时不误触外层分页。

### 5.3 十秒放置指导

从本轮第一次真实进入 `observing` 起计时，十秒仍未进入正式采集时，每轮最多显示一次；覆盖未知、部分覆盖、完整但未就绪以及后续 `starting` 等待均适用。授权、布局等待和打开预览不计入；覆盖变化或观测／启动准备往返不重新计时。

| 项目 | 资源键与现行文案 |
| --- | --- |
| 标题 | `placementGuideTitle`：未检测到手指；在弹窗内容区水平居中。 |
| 正文 | `placementGuideMessage`：请按示例放置；若已放好仍无反应，试着换一颗后置镜头。 |
| 放置图提示 | `placementGuidePlaceHint`：指腹贴合，不要按压 |
| 移动图标题与提示 | `placementGuideSwitchTitle`：换一颗后置镜头；`placementGuideSwitchHint`：移到另一颗镜头上轻覆 |
| 唯一主动关闭操作 | `placementGuideConfirm`：我已知晓 |

标题不表示此刻原生分类必然是“未覆盖”，触发依据是尚未正式开始。指导显示与确认不暂停采集、不重置覆盖稳定累计；进入 `capturing` 自动收起。失败、后台、离页和重试撤销旧计时及弹窗，新轮重新计时。

弹窗无关闭图标，遮罩和 Android 返回键不关闭；“我已知晓”只收起指导。“换一颗后置镜头”是手指移动图解，不调用镜头切换接口、不更改本轮相机配置。

### 5.4 必要错误与恢复

| 条件 | 资源键与现行文案 |
| --- | --- |
| 权限不足 | `errorPermission`：未获得相机权限。请允许相机访问后重新检测。 |
| 已请求的补光设置应用失败 | `errorTorch`：相机补光设置未能完成，请重新检测。无补光能力不触发此错误。 |
| 无可用后摄 | `errorBackCamera`：当前设备没有可用的后置相机，无法开始指尖检测。 |
| 相机占用 | `errorBusy`：相机正被其他会话占用。请等待该会话结束后重试。 |
| 原生确认覆盖丢失 | `errorCoverage`：手指覆盖已丢失，本轮检测已结束。请重新放置后重新检测。 |
| 后台中断 | `errorBackground`：应用进入后台，本轮检测已结束。返回前台不会自动继续，请重新检测。 |
| 资源关闭失败，优先显示 | `errorClose`：本轮资源尚未安全关闭，暂不能离开。请再次关闭后返回。 |
| 其他失败 | `errorGeneric`：指尖检测未能完成。请检查相机与设备状态后重试。 |

统一反馈提供 `back`“返回”和 `retry`“重新检测”；关闭失败时后一项改为 `retryClose`“再次关闭”。返回仍经过离页守卫，不绕过资源屏障；存在未完成离开请求时，再次关闭重试原导航。其他重试先成功关闭旧轮，再创建新客户端、空覆盖状态及空波形历史。不因缺少后摄切前摄；补光不支持或未知时在构建配置时明确关闭，不添加开启失败后的自动重试。

### 5.5 真实云端结果与详情

只有当前轮正常达到正式目标、`completed/duration_reached`、必需文件定稿、资源释放且无错误或离开请求，才自动创建任务、顺序上传并提交。指尖一份 `ppg`，血压同轮 `ppg＋acc`；不上传 frame、gyro 或其他历史文件。提交实际原生正式经过毫秒、对应方式及 active，不发送 capturedAt、不以三十秒常量代替实际时长。创建响应的固定版本才是本轮权威版本。

创建、上传和提交不通用自动重试。创建／上传失败或回执未知、提交未知后查得草稿，产品均展示任务创建失败并只提供重新检测，数据层保留不确定事实。已知 taskId 的提交超时先查原任务；已接受或终态按真实状态继续，不重放写入。查询失败或不支持载荷为结果获取失败，只重新获取原任务；任务 FAILED 或合法 ALL_FAILED 为检测失败，只重测，不提供详细报告。当前代次前台可见的 SUBMITTED／RUNNING 约两秒非重叠查询，失败停止循环，不把等待过久改判失败；后台暂停查询与后续写，恢复先查已知任务。

简要面板保留约420 ms上移、独立箭头、遮罩隔离及安全区内部滚动。箭头、遮罩或 Android 返回先收起；详情、重测和返回按真实结果开放。云端等待沿用原文案及196 dp白色 Toast、64 dp图标与灰色蒙版，隔离背景触摸但保留 Android 系统返回安全离页，不显示上传、提交或排队等内部阶段。加载不可点蒙版取消，提示按 ID 清理；后台、失焦、重测及退出清理旧提示，本地清理不取消服务端任务。终态或可处理失败每轮只自动展开一次，不等待固定三秒，重复通知不重开已收起面板。

结果按任务状态、场景 outcome、成员 status 三层解释；部分成功保留有效成员，ALL_FAILED无读数和输出。HR／BR共享hr_br成员质量，血压sbp/dbp必须同成员成对；未知载荷反馈不可用，不推测字段。质量使用实际score／threshold或合法质量拒绝，无信号不造评分，不代表医学准确率。读数与质量仅展示时直接舍弃小数，不修改原始结果。风险保留原prob和risk_level编码，只把0／1／2映射为较低风险／中风险／较高风险；界面使用20／26及读数主文字色，详细结果的看板与解读单行显示，简要结果仍为等级与“风险”两行居中，不展示概率。详细结果解读区的数值和单位同行、基线对齐，不在组合内部折行；顶部总览卡的数值与单位保留原有上下布局。缺失或失败仍为 `--`，不能转换血糖、重算档位或解释成临床患病概率或医学等级。

成功／指尖部分成功保留绿色完成标题、原提示、看板和静态参考信息；失败项读数为 `--`，底部为“未能生成结果”，公开质量拒绝为“信号质量过低”，仅真实分数显示角标，血氧保留空仪表。失败解读不附成功建议。指尖合法全部失败保留失败看板，血压失败不保留双读数或有效主卡。失败图标40 dp与标题同行居中，说明独立居中，失败不显示健康声明。成功／部分成功弹层短声明一次、与按钮间距12 dp；详情完整声明及质量说明各一次。详细报告首次只有顶栏、返回和内容区居中加载，获取失败可重新获取原任务，不显示旧报告或声明。产品时间统一使用北京时间 submittedAt，不使用采集起点或 finishedAt 归档。

血压弹窗、详情主卡和整体解读共用 `classifyBloodPressure`，只按同一成功成员的原始 mmHg 双读数判断：收缩压≥140或舒张压≥90为“血压偏高”；否则收缩压<90或舒张压<60为“血压偏低”；其余为“血压正常”。低高交叉偏高优先，判断不使用展示截断值。分级大字和“本次结果”标记沿用蓝／薄荷绿／粉色体系并指向对应段；三段参考条带高16 dp、仅底部圆角，间距按原设计，不以整段椭圆代替。

波形按顶层逻辑名鉴权下载：指尖取成功 hr_br 的处理后 PPG，血压取 bp 的处理后 PPG／SCG Z；旧独立任务按自身无前缀逻辑名。每文件最多5 MiB、20,000行样本，以真实毫秒轴建立相对时间、保持幅值和实际跨度，短段不补点。报告 PPG 已由后端完成方向翻转，前端曲线及纵轴直接使用后端幅值，不再次取负；SCG 保留处理后 Z 方向，采集阶段实时波形的方向规则不变。各图独立六秒横向回看。加载在原164 dp画布显示旋转图形与“正在获取波形”；缺文件、无可用样本、超限或读取失败统一为“波形暂时无法获取”，范围和时长使用 `--`。不增加重试按钮，不隐藏有效读数或重跑推理；再次进入或恢复前台可重新读取。

本轮关联与实时回看只在受控详情往返保留；退出、换号、重测和真正离页撤销本地请求与迟到结果，不删除完成文件或宣称服务端已取消。有效成员终态使最新及健康区间失效后读取权威记录，不手工追加本地读数。

## 6. 共用生命周期与结果规则

### 6.1 授权、离页和后台

- 系统权限弹窗造成的短暂失活，不等于用户放弃本次明确操作；授权成功、页面仍有效且应用已回前台时，可以继续原启动。若已请求离开，授权稍后返回也不能再打开或启动设备。
- 等待预览引用或布局时关闭，必须先取消可取消等待、阻断后续启动，不能等即将卸载的页面继续提供布局。已经发出的原生命令仍须完成收尾。
- 返回、系统返回及受保护导航等待当前所有者的在途命令、相机关闭和文件收尾；关闭失败留页处理，不提前允许新会话接管资源。
- 真正后台中断由原生保留真实原因，不能用 JS 用户停止改写原因。回到前台读取真实状态，不自动续采或创建新轮；再次采集需要明确操作。
- 关闭只作用于当前页所属采集，不停止独立传感器或被动服务。解除单个订阅只移除观察者，不代替关闭命令。

### 6.2 波形、文件与指标

两种检测均保留本轮实际收到的展示历史，每屏六秒，允许平移回看和回到最新；回看时采集继续，结束后仍可回看本轮。漏批、断段或真实时间缺口断线，不补零、不插入样例、不读文件补造遗漏展示批次。指尖切回流程说明只隐藏绘图，不停止历史接收。

完整信号和文件写入归原生，完整波形不进入业务 Store 或查询缓存。重测清空旧轮展示，真正退出或卸载释放本轮展示内存；仅明确进入已释放资源的同轮指尖或血压详情时保留检测页完成状态、覆盖和分页，指尖还保留真实波形回看位置。仍停止语音和不可见绘图、注销采集订阅，不持有相机或 IMU；详情往返不重复结果等待。上述操作不删除已定稿文件。面部RPPG产物、指尖双 CSV 和血压联合文件的发布条件见各采集协议，不按历史列表末项猜测本轮产物。

必须分清以下事实：

| 事实 | 不能据此推导的结论 |
| --- | --- |
| 页面已显示检测中 | 原生已经正式开窗、已经收到有效信号。 |
| 倒计时归零或原生停止接收 | 文件已经定稿、相机已经释放、整轮已经成功。 |
| 文件已经定稿 | 目标时长已采满、关闭成功、信号或指标有效。文件已完成但关闭失败时，两项事实均须保留。 |
| 已有真实脉搏曲线 | 已有有效心率、血氧或其他健康指标。 |
| 面部平均已有值 | 已覆盖全部文件窗口，或已生成正式健康记录。 |
| 本地流程结束 | 已上传、云端成功或可以删除本地文件。 |

面部、无扰和独立开发本地检测不更新云端健康记录。接触式有效任务通过健康查询刷新首页和历史；模拟器输入、录像、波形或文件存在不能证明人体信号有效性和医学准确性。

## 9. 血压检测与贴胸指导

第9.1–9.3节说明 [design-demo 血压检测界面与流程](../design-demo/README.md#血压演示)的展示语义和外部模拟操作，不作为原生阶段、准入或结束规则。原生双源采集按真实状态及[前端开发约定](frontend-development.md#28-检测准备与检测页面)运行；贴胸指导见9.4，真实报告见9.5，不把 Demo 模拟按钮和结果迁入产品。

### 9.1 状态与提示文案

主流程先确认指尖覆盖稳定，再等待手机贴靠胸口；两项条件满足后才开始独立的三十秒检测。状态标签、状态辅助文案和镜头内提示分别对应底部状态、其下方说明及圆形预览中央提示框。

| 阶段／状态 | 状态标签 | 状态辅助文案 | 镜头内提示 |
| --- | --- | --- | --- |
| 等待放置指尖，`ready` | 准备检测 | 指腹轻放，不要按压 | 手指未完全覆盖镜头，请调整位置 |
| 未完全覆盖，`covering` | 调整手指 | 让指腹完整覆盖后置镜头 | 手指未完全覆盖镜头，请调整位置 |
| 完整覆盖、等待稳定，`covering` | 准备贴靠 | 指尖覆盖稳定后，请贴靠胸口 | 已完全覆盖，请保持稳定 |
| 指尖稳定、等待贴胸，`awaiting-chest` | 贴靠胸口 | 靠近心脏，轻贴并保持稳定 | 保持手指覆盖，将手机轻贴胸口 |
| 正式检测，`running` | 检测中 | 保持贴胸，自然呼吸 | 正在检测，保持手指覆盖和贴胸稳定 |
| 检测完成，`completed` | 检测完成 | 本次检测已结束 | 检测完成，可以移开手机和手指 |
| 覆盖丢失，退回 `ready` | 调整手指 | 完整覆盖后，再将手机贴靠胸口 | 手指覆盖不足，请重新轻覆镜头 |

完整覆盖、等待稳定属于 `covering` 内的展示分支，不新增独立状态。完成提示中的“移开手机和手指”是已确认的血压文案目标，不沿用仅提示移开手指的指尖完成文案。

### 9.2 推进、计时与外部模拟操作

| 阶段／触发条件 | 倒计时 | 指引与操作 |
| --- | --- | --- |
| 等待指尖及覆盖稳定确认 | 保持 `00:30` | 默认显示指尖放置页；「模拟贴靠胸口」禁用。 |

### 9.3 展示与规划边界

- 覆盖环和百分比只表示指尖覆盖，不表示贴胸程度或检测进度；满环不直接启动血压检测。
- 切换指尖放置／贴胸指引页不代表已经贴胸，也不启动或暂停检测；进入等待贴胸阶段时才自动切到贴胸指引。
- “未检测到手指”沿用设计稿现有的独立放置指导弹窗，不新增主流程状态，也不为血压增加自动超时规则。
- 当前不增加“贴胸丢失”分支；现有 UI 没有该模拟入口，不据此推定真实贴胸识别能力。
- 准备与采集中不挂载血压数值或波形；正常联合收尾后才自动上传统一场景。健康内容来自服务端有效成员，Demo 模拟数值不构成原生报告合同。

### 9.4 原生贴胸操作指导

本轮首次真实进入 `awaiting_chest` 或 `starting` 时立即展示“贴靠胸口指导”，不另计等待时间。正文为“保持手指覆盖后置镜头，将手机轻贴左侧胸口，靠近心脏位置。”，复用现有两幅原生贴胸逐帧图解，标题居中；只有“我已知晓”可主动收起，无关闭图标，遮罩和 Android 返回键不关闭。

“下次不再提示”默认未勾选，仅确认时保存到设备偏好 `app.measurement-guide.chest-placement.skipped`。重启、重新进入或退出账号后仍保留，独立于准备页跳过偏好；偏好保存失败留在弹窗反馈，允许重新确认。勾选但尚未确认时自动收起，不保存该选择。Demo 对应选择仍只在当前标签页保留。

指导不是贴胸成功确认，不阻断真实准入、开窗或语音。覆盖失效退回指尖、正式开始、终态、后台、失焦、离页或重测时立即收起；同轮再次贴胸、`starting → awaiting_chest` 或重复通知不重弹。未选择跳过的新轮重新获得一次提示资格；仍可使用底部贴胸指引。

### 9.5 原生正常完成后的真实报告

联合正式窗口正常到时、同轮 PPG 双 CSV 和 ACC 定稿、资源全部释放、无错误或离开请求后，自动推进统一 PPG＋ACC 任务。单源完成、倒计时归零或语音结束不足以触发；正常完成保留覆盖末值、00:00及当前分页，再显示真实云端阶段。

报告与弹层使用同任务成功 bp 成员的成对原值、实际质量及 submittedAt；任务失败或 ALL_FAILED 不显示部分血压、固定正常结论或样例参考带。保留完整／短声明及信号质量说明，不称医学准确率。一般说明保留血压计确认及不得依据本次结果自行调整用药的提示。

PPG／SCG 从授权输出读取，遵守5.5的大小、行数、时间轴和方向约定，两图各自独立六秒回看；不生成样例、不以真实原始 ACC 冒充处理后 SCG。下载失败与成员读数独立反馈。

同轮详情受控返回保留覆盖、分页及任务关联，不重开设备、重复上传或等待固定时间。历史报告只凭关联 taskId 鉴权读取；重测先安全关闭并清空旧资格，新轮重新通过身份／用途及原生联合准入。

## 10. 检测语音提示

指尖与血压通过 `expo-audio` 单路播放随包 MP3，可离线使用，仅在前台播放，不请求录音权限、不改变系统音量。六条共用录音位于 `apps/native/assets/audio/common/`，独有录音分别位于 `fingertip/` 和 `blood-pressure/`；资源映射见第 10.3 节。两种方式共用播放底座，各自持有资源表、调度器和页面独占播放器。语音文案与前文现行界面文案分开维护，不因播报修改现有页面提示。准备页声音提醒仍是独立弹层，跳过偏好不变；面部心率与被动检测未接入检测语音。

### 10.1 指尖检测

#### 10.1.1 文案与触发时机

播报统一使用“检测”，不使用“采集”。检测仍由原生状态、剩余时间和资源收尾事实推进，语音不延迟开始、不暂停或延长检测，也不在正式开始前额外等待三秒。

指尖与血压的放置指导统一使用“准备检测，请将食指覆盖后置摄像头，不要用力按压。”，覆盖纠正统一使用“请将食指完整盖住摄像头。”。指尖正式开始提示使用“开始检测，请保持稳定”。

指尖已替换初始指导、正式开始和覆盖纠正三条录音，其他四条迁入共用目录，原有播报时机不变。

| 提示节点 | 播报文案 | 触发时机与次数 |
| --- | --- | --- |
| 放置指导 | 准备检测，请将食指覆盖后置摄像头，不要用力按压。 | 真实预览进入本轮覆盖观测，每轮一次；授权、等待布局与打开预览期间不提前播报。 |
| 正式开始 | 开始检测，请保持稳定 | 原生首次进入本轮 `capturing`；完整覆盖、稳定就绪或 `starting` 均不触发。 |
| 剩余 20 秒 | 时间还剩20秒。 | 本轮正式采集中，原生剩余时间首次跨过 20 秒阈值且提示仍适用时，每轮一次。 |
| 剩余 10 秒 | 时间还剩10秒。 | 本轮正式采集中，原生剩余时间首次跨过 10 秒阈值且提示仍适用时，每轮一次。 |
| 最后三秒及完成 | 三、二、一，检测完成。 | 本轮仍处于 `capturing`，原生剩余时间首次跨入三秒区间时，从头连续播放现有完整合并 MP3，每轮一次；“检测完成”仅指正式检测窗口结束。 |
| 覆盖纠正 | 请将食指完整盖住摄像头。 | 持续观察覆盖，满足第 10.1.2 节的空闲与去重条件时播报。 |
| 长时间未开始 | 请按屏幕示意，调整手指位置。 | 第 5.3 节的十秒放置指导实际显示后，满足低优先级播放条件时播报；每轮最多一次。 |

20 秒、10 秒和 3 秒节点消费原生剩余时间的区间变化，不要求快照恰好等于阈值，不建立独立语音倒计时。重复快照不重播；多个较早节点已过时时，只消费当前适用节点，不排队追播。

十秒指导表示尚未正式开始，不保证此刻没有手指，因此不照读弹窗标题“未检测到手指”。弹窗新显示是独立的帮助时机：此前的覆盖纠正已经结束、声道空闲时，即使覆盖仍然不足，也可播放一次帮助，不要求先恢复完整覆盖。进入正式检测或指导已收起后，不补播旧帮助。

#### 10.1.2 覆盖纠正

覆盖判断持续进行，不能由每次覆盖变化直接触发语音；不采用“初始指导结束后持续一秒、整轮只提示一次”的固定规则。

同时满足以下条件才播“请将食指完整盖住摄像头。”：

- 当前真实覆盖仍需要用户纠正：准备阶段按完整覆盖要求判断；正式检测期间，原生允许的轻微缺角不触发纠正。
- 播报通道空闲，不插入正在播放的其他语音。
- 距离下一条定时关键提示的时间足以播完整句，按实际音频时长判断；时间不足则不启动。
- 本次连续覆盖不足尚未提示。

其他语音播放期间不积压纠正事件；通道空闲后重新核对最新覆盖和阶段，已恢复或不再适用就丢弃。同一次连续覆盖不足只播一次；恢复覆盖后再次不足，才重新获得提示资格，不限制整轮只能一次。被关键提示打断后，不立即重复同一次纠正。

#### 10.1.3 播放时长、优先级与重叠处理

- 始终单路播放。抢占时先停止旧播放，再启动新播放，不允许两条语音同时发声。
- 正式开始可打断尚未结束的放置指导。开始、20 秒、10 秒、最后倒计时及完成属于关键提示，可打断覆盖纠正或放置帮助，不能被低优先级语音延迟。
- 覆盖纠正和十秒放置帮助均为低优先级，不插播、不积压过时内容；通道空闲后按本轮最新事实重新判断，而不是按先来先播的队列补播。
- 两种低优先级提示在同一时机适用时优先覆盖纠正，不在结束回调中自动串播帮助；后来新显示的十秒弹窗不受早期纠正的持续不足去重限制。通用帮助仍须符合可见性、阶段与每轮一次条件。
- 每条提示只消费当前轮次。重复状态通知不重新播放同一关键提示，过时的开始、倒计时或指导不补播。
- 空档判断使用现有音频的实际时长，包含首尾静音，不用未经测量的固定估计安排插播；音频加载或播放失败不阻塞检测，也不自动重复播报。

#### 10.1.4 最后三秒与完成衔接

原生剩余时间首次跨入三秒区间且本轮仍在正式检测时，从头连续播放现有 `countdown-3s.mp3`。“三、二、一，检测完成”是同一段完整音频，并非总长三秒；保留原有自然节奏，不裁剪、不迟到跳播、不调整语速、不要求数字与界面逐秒对齐。已经终止后不补播结束音频，原生截止也不等待音频结束。

“检测完成”仅表示正式检测窗口结束，不表示文件保存、资源释放或健康结果成功。结束音频启动后连续播放，不在“一”后暂停等待收尾；本轮达到正式终点后进入 `stopping`、正常完成或发生文件／资源收尾失败，均不截断、回撤或重播结束语。页面仍等待真实文件与资源屏障，并按实际错误反馈；声音及其完成回调不推进页面成功状态。

#### 10.1.5 不播报范围与生命周期

- 暂不加入光照提示，也不为本方案新增光照判定。
- 权限问题与检测中断只保留必要界面反馈，不播语音。
- 完整覆盖、准备开始、正在结束不单独播报；不播“可以移开手指”。
- 正式窗口尚未结束时发生覆盖丢失、技术失败或其他提前中断，立即停止本轮声音；不能把所有 `failed` 都当作窗口结束后的收尾失败。正式终点后的收尾或收尾失败按第 10.1.4 节保留已启动的结束音频。
- 进入后台、失焦、请求离页、卸载或重新检测时，无论是否已到正式终点，都立即停止旧轮语音并撤销待播资格，不等待相机关闭成功；异步加载或播放回调不得恢复旧声音。回前台不补播旧提示，新轮重新消费自己的触发节点。


### 10.2 血压检测

血压使用本轮未经展示防抖的真实快照，语音不读取 React 的稳定提示、不参与覆盖／IMU 准入或文件完成屏障。共用提示使用第 10.3 节的同一份录音，正式开始使用血压独有内容。

| 提示节点 | 播报文案 | 触发与次数 |
| --- | --- | --- |
| 初始放置 | 准备检测，请将食指覆盖后置摄像头，不要用力按压。 | 首次真实 `observing_finger`，每轮一次；准备阶段不提前播报，退回不重播。 |
| 贴胸指导 | 保持手指覆盖，将手机轻贴左胸，靠近心脏位置。 | 每次从指尖阶段稳定进入贴胸准备时播放；恢复覆盖后再次进入须重播。 |
| 正式开始 | 开始检测，请保持贴胸稳定，自然呼吸。 | 真实 `capturing` 且开始节点仍适用，每轮一次。 |
| 剩余 20 秒 | 时间还剩20秒。 | 原生剩余时间跨阈值，每轮一次。 |
| 剩余 10 秒 | 时间还剩10秒。 | 原生剩余时间跨阈值，每轮一次。 |
| 最后三秒及结束 | 三、二、一，检测完成。 | 仍在正式检测时进入三秒区间，从头连续播放完整录音，每轮一次。 |
| 普通覆盖纠正 | 请将食指完整盖住摄像头。 | 已知不足且声道空闲，同一次连续不足只播一次。 |
| 重新覆盖 | 请重新盖住摄像头，保持手指稳定。 | 开窗前从贴胸准备退回指尖且明确不足，替代本次普通纠正，不连播两句。 |
| 十秒放置帮助 | 请按屏幕示意，调整手指位置。 | 既有指导实际可见且仍在 `observing_finger`，每轮最多一次。 |

`awaiting_chest / starting` 是同一贴胸准备段，重复通知、手动分页及 `starting → awaiting_chest` 不重播；覆盖失效退回 `observing_finger` 才结束旧段。重新稳定后再次进入贴胸准备，再次播报指导。首条通知已越过早期阶段时只判断当前提示，不追播初始指导或开始语音。

准备阶段要求完整覆盖，正式检测沿用原生 95% 维持规则；未知或仅输入失鲜不推断手指未盖住，也不恢复纠正资格。重新覆盖指导与普通纠正共用本次不足去重，恢复后再次不足才可再纠正；加载期间已恢复、进入新阶段或结束，不补播过时指导。帮助仅随既有弹窗，不建立新定时器；进入贴胸后立即撤销帮助，普通纠正与帮助的空闲、去重与不串播规则沿用第 10.1 节。

始终单路播放，阶段改变先停旧指导；正式开始与 20／10／3 秒关键节点可抢占其他声音，不等待长指导结束。低优先级只在距下一关键节点的空档严格大于实际完整录音时长时启动，不排队追播、不延长覆盖丢失宽限。

正常到点后的结束衔接沿用第 10.1.4 节：只有已经实际开始的合并结束音频可跨收尾或收尾失败继续，加载中的候选不能终态新发声；页面仍等待同轮 PPG、ACC 和资源屏障。提前中断立即停声，不播放重新覆盖指导，也不暗示重新放置就能继续；后台、失焦、请求离页、卸载及重试无论是否正常到点都立即停声，不等待相机关闭。旧异步回调不能恢复声音，回前台不补播。
