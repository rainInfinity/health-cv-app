# 采集文件上传对接草案

> 状态：后端已定义原始 PPG、PPG＋ACC 的独立算法及统一场景合同；Native 尚未接入完整测量上传流程。本文区分已定义合同、已确认的指尖入口目标和待联调事项，不表示模型已在目标渠道部署或真实采集已通过算法校验。

## 范围与合同来源

已确认的指尖部位入口为一次采集、返回一组指标，目标使用统一 PPG 场景完成一个任务，不按指标重复上传同一份文件。按指标入口的模型选择、采集复用和任务组织另行讨论，不由本文确定。

后端依据为 `health-service/docs/frontend-integration.md` 第 6 节算法合同及第 7 节任务与文件合同。采集文件的字段、单位和发布条件仍由采集协议维护；HTTP、文件 URI、上传回执与取消语义由[云端请求接口](cloud-client-api.md)维护。

## 产物与输入映射

| 产物 | 已定义的输入关系 | 当前限制 |
| --- | --- | --- |
| `ppg.csv` | 原始 PPG 独立算法、统一 PPG 和统一 PPG＋ACC 场景均使用 `logicalName=ppg`，文件名须带 `.csv` 后缀。 | 原生 `[1,1]` 单块产物与必需列、单位在静态协议上匹配；不表示真实样本已通过采样和质量校验。 |
| 加速度计 CSV | 血压独立算法及统一 PPG＋ACC 场景使用 `logicalName=acc`，文件名须带 `.csv` 后缀。 | 原生产物与必需列、单位在静态协议上匹配；两路采集窗口及跨源时间关系仍须明确。 |
| `frame.csv` | 上述合同均不要求此文件。 | 同会话生成不构成上传理由，不自动附带。 |
| 陀螺仪、磁力计、重力 CSV | 上述合同没有对应输入。 | 不因为属于传感器产物就映射为 `acc`。 |
| RPPG `session.json`、`pulse.csv`、`hr.csv` | 当前原始 PPG 合同不接收这组三件套。 | POS 脉搏和心率窗口不含原始 RGB／YUV 通道，不能冒充 `ppg.csv`；面部本地 RPPG 不套用此上传流程。 |
| 旧 `video.mp4` | 当前无确认的上传用途。 | 不自动上传，也不作为上述算法输入。 |

### 原始 PPG

后端接收 UTF-8 CSV，可带 BOM。`timestampFrame` 必须为有限、严格递增的毫秒数值，通道列只能包含以下一组完整字段：

- RGB：`avgR,avgG,avgB`。
- YUV：`avgY,avgU,avgV`，与当前原生 PPG 产物一致。

表头不得重复，行列数须一致，通道值须有限。`blockIndex` 可省略；存在时只能为整数 `0`。多块产物不能直接用于当前合同：同帧时间戳重复且存在非零块编号，服务端不会自动选块、合并、重采样、插值或补帧。原生格式及同会话 `frame.csv` 的配对关系见 [PPG 协议](../acquisition/android-ppg.md)。

统一 PPG 场景各成员共同的显式采样下限为 `fs > 8 Hz` 且 `N >= max(450, ceil(15 * fs))`。这不是成功保证；滤波条件、信号质量和模型结果仍由各成员独立判定，不能仅按页面经过时间推断文件合格。

### 加速度

ACC 必需列为 `timestampEvent,accX,accY,accZ`，时间单位为毫秒，轴值单位为 `m/s²`；原生格式见[传感器协议](../acquisition/android-sensors.md)。时间戳和轴值须有限，时间严格递增。现有原生产物包含这些列，不需要为了上传在 JS 重写 CSV。

服务端按 PPG 和 ACC 各自时间戳计算采样率，不排序、重采样、归零时钟或自动对齐。两路时间字段来自设备单调时间体系，不是 Unix／UTC 时间；不能仅凭列名或同为毫秒就认定跨源已同步。采集窗口、时间关系和真实输入效果仍须联调确认。

`sessionId`、相机配置、网格和采样配置等元数据不会随单文件上传自动附带。血压使用提交时冻结的服务端资料快照；上述场景不要求额外客户端元数据，不为补充输入关系而随意添加请求字段。

## 方案与模型绑定

| 后端合同 | 算法标识 | 必需输入 | 结果组织 |
| --- | --- | --- | --- |
| 统一 PPG 场景 | `ppg.active.offline.all.v1` | 一份 `ppg` | 固定成员 `hr_br`、`spo2`、`diabetes`，可部分成功。 |
| 统一 PPG＋ACC 场景 | `ppg_acc.active.offline.all.v1` | `ppg`、`acc` | 当前只有 `bp` 成员，不同时产生其他指标。 |

统一 PPG 的三个成员读取同一份原始文件，不上传三份副本，也不上传其他成员的处理后文件。场景固定成员及实现修订，不通过请求参数选择子集，也不自动包含未来算法。

独立 HR／BR、血氧、血压及糖尿病风险算法仍保留各自输入和结果合同，不能把历史独立算法结果强制按场景结构读取；保留这些合同不表示本文已决定按指标入口的方案。

普通渠道模型目录只公开 `modelId`、`modelCode`、`modelName`、版本、`requiredInputs` 和 `isExample`，不公开 `algorithmKey`。调用方须明确确认测量方案与目标渠道实际模型的合同对应关系，不能按名称、逻辑名或字符串拼接猜测算法。`requiredInputs` 仅声明输入逻辑名，不描述文件格式或结果结构。

创建任务使用目录实际返回的 `modelId`，不硬编码示例 ID。创建响应中的固定模型版本是本次任务依据，不能继续以目录缓存版本代替。合同已定义不表示目标渠道已经配置相应场景或制品。

## 目标对接顺序

以下为已明确云端用途并取得相应授权后的目标业务顺序，不是当前应用已自动执行的能力：

1. 读取目标渠道模型目录，确认方案对应的实际模型及 `requiredInputs`。
2. 按方案完成真实采集，等待原生文件收尾，只使用完整发布的产物引用。
3. 创建草稿：`POST /tasks`，请求体 `{ "modelId": number }`，保留返回的任务标识和固定版本。
4. 将方案明确要求的产物按逻辑名逐文件上传，等待响应并保留回执。指尖统一 PPG 场景只上传一份 `ppg`。
5. 必需输入上传均已确认后提交：`POST /tasks/{taskId}/submit`；按合同选择是否提供 `clientMetadata`，资料与输入在提交时冻结。
6. 查询任务详情直到终态；场景还须解析汇总结论和各成员状态，映射实际可用指标。

采集结束、文件定稿、上传确认、任务提交、云端处理完成和指标可用是不同事实。上传进度到 100% 不代表请求成功；列表摘要的 `SUCCEEDED` 也不足以判断测量有效。

## 场景结果解释

统一场景使用两层业务结论：

| 层级 | 含义 |
| --- | --- |
| 任务 `status=FAILED` | 场景自身失败，`result=null`；不展示中间结果或部分指标。 |
| 任务 `status=SUCCEEDED` | 场景执行及合法汇总完成，仍须读取 `result.outcome`。 |
| `result.outcome` | `ALL_SUCCEEDED`、`PARTIALLY_SUCCEEDED` 或 `ALL_FAILED`；统一 PPG＋ACC 当前只有一个成员，不产生部分成功。 |
| `result.results.<成员>.status` | 决定该成员是否可读取数值；失败信息和质量拒绝留在对应成员内。 |

`SUCCEEDED / ALL_FAILED` 是合法汇总：顶层失败字段为空，但没有可展示指标或输出文件。各成员有独立质量结论，不存在通用的场景总质量分数。

读取前先确认对应成员 `status=SUCCEEDED`：

| 成员 | 数值路径 | 解释 |
| --- | --- | --- |
| `hr_br` | `result.results.hr_br.result.hr`、`.br` | 心率与呼吸率；该成员为原子结果，不展示失败成员的部分数值。 |
| `spo2` | `result.results.spo2.result.spo2` | 血氧百分数。 |
| `diabetes` | `result.results.diabetes.result.prob`、`.risk_level` | 概率及后端编码；不重算档位，不解释为血糖浓度或医学诊断。 |
| `bp` | `result.results.bp.result.sbp`、`.dbp` | 收缩压与舒张压，单位 `mmHg`。 |

失败成员不补零、不沿用上次测量值，也不使其他成功成员失效。质量拒绝使用其公开的 `qualityFailure`，区分 `LOW_SCORE` 与 `NO_VALID_SIGNAL`；不自行重算分数或把技术失败解释成低质量。

场景输出只登记在顶层 `result.output_files`，逻辑名带成员前缀，如 `hr_br_processed_ppg`、`spo2_processed_ppg`、`bp_processed_scg`。下载使用对象键，不使用不透明引用值作为 URL 或路径；不把场景逻辑名套用于独立算法输出。

## 上传回执与恢复边界

回执包含 `fileId`、`logicalName`、`sizeBytes`、`uploadedAt` 和 `isSelected`，调用方须保留当前业务会话需要的回执。同逻辑名再次上传会选择新记录，旧记录仍保留；超时重传不是覆盖或幂等重放。

创建没有客户端幂等键，普通用户也没有输入文件列表接口，任务详情不返回输入集合。不能盲目重试不确定写操作，或承诺仅凭任务详情在重启后完整恢复上传状态。SDK 不自动遍历、提交、轮询或重试；取消本地传输不等于服务端撤销任务，当前也没有用户取消或删除任务接口。

## 待联调与产品确认

- 目标普通渠道实际提供的模型、固定版本及场景制品是否可用，方案与目录模型的显式绑定。
- 原生单块 PPG、加速度产物在真实采样条件下的解析、算法质量与结果回显；静态列和单位匹配不是联调通过。
- PPG＋ACC 采集窗口及跨源时间关系；指尖真实启动、截止与展示所需能力不由上传流程替代。
- 实际部署的媒体及大小限制；默认单文件上限为 `52,428,800` 字节，代理限制可能不同，接口没有上限查询能力。
- 云端用途与授权、本地及服务端保留期限、允许删除条件和超时后可执行的处理方式；不由本草案预设自动恢复或清理机制。

## 隐私与本地文件

文件保存在应用私有目录。只上传已授权方案要求的完整产物，不因文件存在就全部上传。采集完成、上传完成、云端成功和允许删除是不同事实；正在写入或上传的文件不能清理，上传成功不隐式删除本地文件。

旧视频包含前摄原始画面，不自动上传；RPPG 三件套也是敏感健康相关数据，不能因其不是视频就省略用途与授权。独立本地面部采集不因引入云端指尖流程就自动转为上传。
