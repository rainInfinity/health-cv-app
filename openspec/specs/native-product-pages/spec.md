# native-product-pages Specification

## Purpose

为心沐原生应用提供可由游客自由访问的中文健康主页、功能目录和用户中心，并将真实账号认证与开发阶段的健康展示数据分开，使空态、账号状态变化及尚未开放的入口具有一致且可验证的行为。

## Requirements

### Requirement: 产品页面可由游客自由浏览
应用 MUST 提供健康主页、功能页和我的页面，游客 MUST 能自由访问，不因未登录强制跳转认证。页面 MUST 沿用已确认设计、品牌资源及浅色主题，不使用网页替代原生交互。

#### Scenario: 游客浏览产品页面
- **WHEN** 无已保存会话的用户完成或跳过首次引导
- **THEN** 能在主页、功能和我的之间切换，我的显示游客身份与登录注册入口

#### Scenario: 缺少云端配置
- **WHEN** 应用未配置云端服务
- **THEN** 本地页面仍可浏览，认证入口说明服务不可用，不模拟登录成功

### Requirement: 健康展示严格由确认认证状态决定
首页与历史 MUST 仅在 authenticated 查询和展示当前账号、渠道的真实健康记录，不再使用固定样例。anonymous、restoring 和 unavailable MUST 清空受保护健康内容；后两者在既有账号区域表达真实状态。数据层 MUST 区分成功无记录、加载与请求失败，并按 Demo 已确认状态展示；首页获取或刷新失败后采用空数据及 Toast，历史首次与刷新共用页面加载及失败重取，不展示旧内容、不使用 Toast。糖尿病风险 MUST 只将后端riskLevel的0／1／2映射为较低风险／中风险／较高风险，以20／26两行居中显示并使用读数主文字色，等级在上、“风险”在下，不显示概率；首页风险刷新圈保留原大小，不随等级文字放大，加载图形与动画保持不变。缺失仍为空态，不按概率重算或生成医学风险结论。不得生成默认健康值、评估、原始编码或技术状态说明。

#### Scenario: 游客空态
- **WHEN** 当前状态为 anonymous，用户查看主页或历史
- **THEN** 不请求受保护健康记录，读数显示 --、时间显示暂无记录且无评估结论；历史筛选仍可浏览

#### Scenario: 认证成功
- **WHEN** 登录已保存凭据并完成账号确认
- **THEN** 首页读取最新有效记录，各指标独立展示自己的 submittedAt；null 保持无记录，不共用样例时间；面部本地读数不混入云端摘要

#### Scenario: 退出时详情仍打开
- **WHEN** 认证失效、退出或换号，而历史或记录浮层仍可见
- **THEN** 所有旧会话健康内容立即清空，迟到响应不恢复旧读数；游客浏览与本地面部／无扰入口不受影响

#### Scenario: 会话恢复暂不可确认
- **WHEN** 恢复因网络故障进入 unavailable
- **THEN** 健康内容保持空，账号区说明暂不可确认，不删除凭据或将其描述为确认退出

#### Scenario: 首页刷新失败
- **WHEN** 最新记录已有成功数据，后续刷新遇到通信错误
- **THEN** 以“刷新失败，请稍后重试”Toast反馈，随后首页读数为 `--`、时间为“暂无记录”、血氧仪表清空；内部旧缓存及错误事实可以保留，但不能继续展示旧值、改成零值或假装刚刚检测

### Requirement: 真实注册登录与退出界面
应用 MUST 提供用户名密码登录和注册，注册确认密码只作前端校验，请求仅含接口公开字段。注册成功 MUST 返回登录并预填服务端用户名，不建立会话；登录成功 MUST 回到我的显示真实账号。请求中 MUST 防止重复提交；失败 MUST 区分凭据错误、用户名冲突、输入校验、网络和安全存储问题，不统一解释为密码错误。

#### Scenario: 已配置 Release 包的登录入口可用
- **WHEN** Android Release 使用完整账号服务地址和 channel 构建并安装
- **THEN** 登录页面识别到账号服务已配置，登录按钮可用，不显示“账号服务暂未配置”

#### Scenario: 注册成功后登录
- **WHEN** 服务端返回注册成功
- **THEN** 返回登录并预填用户名，仍为游客空态，直至另一次真实登录确认成功

#### Scenario: 确认密码不匹配
- **WHEN** 注册的密码与确认密码不一致
- **THEN** 在表单相关位置提示且不发注册请求；密码可显隐，不进入通用请求历史或持久化偏好

#### Scenario: 登录返回非成功
- **WHEN** 登录凭据错误、网络失败或凭据保存失败
- **THEN** 呈现对应可处理的中文错误，保留游客浏览路径，不发布虚假已登录状态

#### Scenario: 退出登录
- **WHEN** 用户执行退出
- **THEN** 按真实会话清理结果反馈；本地删除成功后回游客空态，远端失败不阻塞本地退出，本地安全存储删除失败不显示完全退出成功，非认证偏好仍保留

### Requirement: 未开放业务只保留入口
健康资料引导、健康资料、个人资料和帮助反馈 MUST 仅保留入口及统一未开放反馈，不实现资料表单或反馈提交，不形成首次流程第三步。历史 Tab、首页指标入口及我的健康记录 MUST 进入同一真实记录历史，受认证门控；不得显示固定样例或以任务列表代替健康记录。

#### Scenario: 点击历史或健康记录
- **WHEN** 用户点击历史 Tab、首页指标入口或我的健康记录
- **THEN** 进入同一历史页；首页指标选择对应指标和北京时间当日的日区间，其他入口保留当前筛选；未确认认证时健康内容为空，不生成记录

#### Scenario: 资料与反馈入口
- **WHEN** 用户点击个人资料、健康资料、后续健康资料引导或帮助反馈入口
- **THEN** 保持既有未开放说明，不因接入健康查询新增编辑或假提交

### Requirement: 功能目录直接按检测部位提供入口
功能页 MUST 保留面部、指尖、指尖＋胸口三张部位卡片，不恢复分类切换或指标列表。指尖与血压入口 MUST 在启动设备前完成登录及模型可用性检查，不增加独立云端用途确认弹窗；跳过引导不能绕过门控及系统权限。面部仍显式开始且对游客开放。各入口沿用方式级准备偏好、原有操作指导、真实采集与返回来源；功能页本身不执行上传。

#### Scenario: 游客点击测量入口
- **WHEN** 游客点击功能部位卡片
- **THEN** 面部按原流程进入本地检测；指尖和指尖＋胸口引导登录，不启动相机或 IMU、不创建任务，登录成功回原来源等待用户再次明确开始

#### Scenario: 功能最近测量信息
- **WHEN** 游客或已确认账号访问功能页
- **THEN** 保留三个部位和操作说明，不恢复已移除指标列表的最近测量行；其他已有最近检测提示仅使用相应真实记录时间

#### Scenario: 按检测部位进入
- **WHEN** 用户已确认认证及模型，尚未保存该方式跳过偏好并点击部位入口
- **THEN** 进入对应准备；面部目标仍为面部心率，指尖不预选指标，指尖＋胸口仍为血压；正常收尾后按对应统一场景自动处理

#### Scenario: 指标入口统一方式映射
- **WHEN** 用户从首页检测主按钮或功能部位开始接触式检测
- **THEN** 所有指尖目标共用统一 PPG 场景，血压共用统一 PPG＋ACC 场景；不因目标名称创建独立成员任务，首页指标浏览入口不直接启动检测

#### Scenario: 已保存跳过偏好的功能入口
- **WHEN** 用户已保存跳过准备偏好后再次进入
- **THEN** 仍先检查当前身份和模型；满足后直达对应真实检测，面部保持本地规则；不增加独立上传用途确认，跳过偏好不能替代系统权限

#### Scenario: 返回保留来源
- **WHEN** 用户从功能页经准备或检测返回
- **THEN** 返回同一部位目录；既有准备栈与安全关闭行为不变，不绕到开发页或旧分类

#### Scenario: 新页面不发布健康记录
- **WHEN** 面部或无扰本地采集结束，或接触式采集只有覆盖、波形、心震候选、文件完成事实
- **THEN** 不据此生成健康记录；只有服务端有效任务结果可经健康查询更新首页和历史，不上传面部或无扰产物

### Requirement: 功能页无扰心率开关反映真实被动服务
功能页 MUST 在面部卡片上方展示“无扰心率检测”卡片及“日常解锁使用手机时，自动测量心率”说明。只有右侧图标开关可以启停，卡片空白和文字不触发。开关 MUST 复用真实被动服务，游客及无云端配置也能操作，不存独立演示偏好；启用先完成既有后台活动说明与权限检查，关闭等待真实收尾，失败反馈原因而不显示虚假成功。

#### Scenario: 关闭与开启外观
- **WHEN** 服务处于未启用或已启用的稳定阶段
- **THEN** 关闭为灰色轨道、白色滑块和灰色同源心率图案，开启为青绿渐变轨道、右侧白色滑块、深青图案及青绿双波纹；轨道为柔和内阴影而非硬轮廓，心率滑块以柔和外阴影区分背景，切换沿用约240毫秒过渡，点击目标至少48逻辑单位，不因动效启停服务

#### Scenario: 等待服务确认及防重复
- **WHEN** 用户发起授权、启动或关闭，或服务仍在启动／收尾
- **THEN** 开关表达处理中且不可重复触发，不通过先翻转本地状态宣称成功；取消启用说明不执行命令，拒权或失败保留真实状态并提供必要反馈和设置入口

#### Scenario: 开发页通知和页面返回同步
- **WHEN** 用户在开发页或通知栏改变服务，或从系统设置、后台、其他页面返回功能页
- **THEN** 开关按真实服务状态更新，页面离开只解除展示订阅而不关闭服务；重新进入、应用重启或退出账号不会仅因旧开关偏好自动启用，也不把实时被动读数写入产品健康展示

### Requirement: 首页衔接检测与对应指标当日历史
已确认登录时，首页血压主按钮 MUST 进入血压准备或按偏好直达检测，并遵循统一门控。首页血压详情入口及其他指标卡 MUST 直接进入对应指标的北京时间当日日区间，不再打开指标详情；应用 MUST 移除失效的指标详情入口和中转路径。首页 MUST 在首次无缓存时读取最新记录，返回、重新聚焦及非首次进入不得单独触发重取；后续通过下拉刷新或新有效记录的查询键失效更新。普通重绘不重复获取，不新增手机业务界面的常驻刷新按钮。

#### Scenario: 血压主按钮与详情分工
- **WHEN** 已确认登录用户点击首页血压主按钮或血压详情入口
- **THEN** 主按钮进入受统一门控的检测，详情入口进入血压的当日日区间；返回首页不残留指标浮层，不改变真实采集状态

#### Scenario: 从指标详情查看历史或检测
- **WHEN** 用户点击原本打开指标详情的首页入口，历史仍保留其他指标或日期区间
- **THEN** 历史切换为对应指标和北京时间今天的日区间，而不是沿用旧范围或 Demo 固定日期；只浏览历史，不启动采集

#### Scenario: 返回首页保留缓存并支持下拉刷新
- **WHEN** 已确认登录用户已有首页查询缓存，离开后返回或重新聚焦首页，随后主动下拉
- **THEN** 返回或聚焦不产生请求；下拉显式读取最新数据，重复下拉复用在途同键请求，未登录不请求受保护健康记录

### Requirement: 设计稿无扰开关只模拟确认与启停等待
Demo 的功能页无扰开关和隐私偏好 MUST 共用本地状态及启停流程，明确确认后等待约1秒再更新开启，关闭同样等待。等待中 MUST 保留上次确认外观、显示局部加载并禁用重复操作；取消、关闭说明或仅去设置不启用，切页与重置撤销未完成动作，刷新恢复关闭。Demo MUST 不申请真实权限、不打开系统设置、不启动相机或被动服务，不生成心率或回写健康内容；此本地偏好不得作为原生服务状态来源。

#### Scenario: Demo 明确继续后等待启用
- **WHEN** 用户在 Demo 请求开启并选择“已设置／不适用，继续”
- **THEN** 等待约1秒后才显示开启，期间保持原开关外观并禁止重复；关闭也经过同样等待，已确认的本地状态可在本次标签页内切页保留

#### Scenario: Demo 取消或只去设置
- **WHEN** 用户取消、关闭或点遮罩收起说明，或只选择“打开应用设置”
- **THEN** 不启用；设置动作只进入 Demo 的隐私授权展示，不打开真实系统设置，返回后仍须重新明确确认

#### Scenario: Demo 等待期间离页或重置
- **WHEN** 启停尚未完成时切换页面或重置演示
- **THEN** 撤销未完成动作和局部加载，不让旧计时在新页面翻转状态，也不申请权限、启动服务或改写健康数据

### Requirement: 首页数据加载与空态保持原卡片布局
首页 MUST 在首次获取时于读数和时间位置显示骨架，血氧保留空仪表及原加载外观；刷新时在各读数、仪表中心及时间位置显示旋转加载，直径随被替换内容的实际高度变化并限制在原占位内，不统一固定为18 dp，不推移卡片、单位或图形。Demo MUST 在手机下方演示操作区提供“刷新首页”，仅已登录首页可用，加载期间禁用，离页隐藏并取消未完成演示；手机业务界面不增加按钮。成功无记录 MUST 显示 `--`、暂无记录及空仪表；获取失败 MUST 以“数据获取失败，请稍后重试”Toast反馈后采用相同空展示，不把请求错误转换为成功空响应。

#### Scenario: 首次读取与后续刷新
- **WHEN** 已确认登录用户首次获取最新记录，或已有内容后再次刷新
- **THEN** 前者展示骨架，后者在数据位置旋转；成功后使用实际读数和各自时间，成功无记录则为空，不展示页面级错误卡或新增技术说明

#### Scenario: 首页获取失败
- **WHEN** 最新记录首次请求失败
- **THEN** Toast反馈后显示空数据，保留原检测及历史入口，后续成功读取才恢复数据；不增加常驻重新获取按钮
