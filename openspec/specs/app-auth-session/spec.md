# app-auth-session Specification

## Purpose

为原生 App 提供独立于请求传输和页面的认证生命周期，安全恢复与更新凭据，并向调用方提供可订阅的会话事实；同时约束服务端数据的缓存范围和退出行为，防止网络故障误退出、并发刷新冲突及跨账号数据残留。

## Requirements

### Requirement: 认证状态区分未登录与暂不可确认
应用 MUST 提供可读取和订阅的认证状态，区分正在恢复、没有会话、已确认认证及暂不可确认。状态 MUST 不只由是否存在本地用户对象决定，页面 MUST 不需要直接修改内部状态来推进认证。公开状态 MUST 不包含密码、令牌对或完整健康资料，也不保存已翻译的错误文案。

#### Scenario: 启动期间尚未完成确认
- **WHEN** 应用尚在读取凭据或确认当前账号
- **THEN** 消费者能够识别恢复中的状态，不将其当成确定未登录或已登录

#### Scenario: 网络故障中断会话确认
- **WHEN** 本地存在凭据，但服务端因网络、超时或 5xx 暂时不可达
- **THEN** 应用表达暂不可确认并提供非敏感失败原因，不因为这类失败删除凭据或宣称认证已失效

### Requirement: 凭据安全持久化且隔离作用域
应用 MUST 使用平台安全存储保存令牌对，按服务地址和渠道隔离，并将 Access 与 Refresh 作为一个逻辑记录更新。凭据 MUST 不写入普通偏好、通用服务端数据缓存、日志或 URL。读取、写入和删除失败 MUST 显式反馈，不静默回退到非安全存储。

#### Scenario: 原子替换令牌对
- **WHEN** 登录或刷新取得新的 Access 与 Refresh
- **THEN** 应用更新同一逻辑凭据记录，不对外发布新 Access 搭配旧 Refresh 的状态

#### Scenario: 安全存储写入失败
- **WHEN** 新令牌对未能保存到安全存储
- **THEN** 应用反馈凭据保存失败，不承诺跨重启恢复成功，也不继续把旧 Refresh 当成已轮换的新凭据

#### Scenario: 不同服务地址或渠道恢复
- **WHEN** 应用使用与原登录不同的服务地址或渠道启动
- **THEN** 不读取原作用域的令牌作为当前凭据，不仅更换请求路径继续使用旧会话

### Requirement: 启动恢复以服务端账号确认为准
应用 MUST 在启动恢复时读取当前作用域凭据，并在对外发布已确认认证前取得当前账号。无凭据时 MUST 进入未登录；明确的凭据认证失败 MUST 结束对应会话。恢复请求 MUST 不依赖页面挂载，也不因界面重渲染重复启动相同恢复流程。

#### Scenario: 没有保存凭据
- **WHEN** 安全存储确认当前作用域没有凭据
- **THEN** 应用进入未登录，不发送没有必要的刷新或账号查询

#### Scenario: 恢复可用会话
- **WHEN** 已保存凭据能够通过当前账号接口确认身份
- **THEN** 应用发布当前作用域的已确认认证状态，并将账号数据归入该会话的服务端数据缓存

#### Scenario: 恢复时认证最终失败
- **WHEN** Access 被拒绝且受控刷新返回明确的认证失败
- **THEN** 应用清理对应凭据和受保护缓存，进入未登录，不重复刷新同一旧凭据

### Requirement: 登录与注册不混淆成功条件
注册 MUST 只返回注册结果，不建立会话。应用端登录 MUST 在取得令牌对、成功保存凭据并确认当前账号后发布已确认认证；请求失败、保存失败或身份确认暂不可用 MUST 保留各自的失败语义，不统一解释为密码错误。应用 MUST 不为这些操作自动重试或要求新增认证页面。

#### Scenario: 注册成功后仍未登录
- **WHEN** 注册接口返回新账号
- **THEN** 应用返回注册结果，认证状态不因注册成功自动变为已登录

#### Scenario: 登录取得令牌但账号确认暂失败
- **WHEN** 登录及凭据保存成功，而随后账号查询遇到网络错误
- **THEN** 应用保留已保存凭据并表达暂不可确认，不把它归为用户名或密码错误

### Requirement: 受保护调用共享受控刷新
应用认证层 MUST 仅对受保护调用的 `401 / INVALID_TOKEN` 协调刷新，同一会话并发失败最多共享一个在途刷新。刷新成功后 MUST 同时替换令牌对，再将因认证失败而未执行业务的原操作至多重发一次。注册、登录、刷新和登出 MUST 不进入该循环，其他错误 MUST 不触发通用刷新或写请求重试。

#### Scenario: 多个请求同时遇到过期 Access
- **WHEN** 当前会话多个受保护请求同时返回 `401 / INVALID_TOKEN`
- **THEN** 这些调用等待同一个刷新结果，成功后各自至多重发一次，不重复使用旧 Refresh 并发刷新

#### Scenario: 旧 Access 的错误晚于刷新结果
- **WHEN** 使用旧 Access 的请求稍后才返回 401，而当前会话已经成功替换令牌
- **THEN** 应用使用当前凭据至多重发一次，不为迟到错误再刷新一次

#### Scenario: 登录失败或渠道禁止
- **WHEN** 登录返回 `INVALID_CREDENTIALS`，或业务请求返回 HTTP 403
- **THEN** 应用保留对应错误，不触发刷新，也不将 403 一概视为普通登录过期

#### Scenario: 调用已被取消
- **WHEN** 等待刷新或重发前调用方已经取消当前操作
- **THEN** 应用不恢复该操作或创建新的传输请求，也不影响仍等待同一次刷新的其他调用

### Requirement: 刷新失败区分认证失效与结果不确定
应用 MUST 在刷新明确返回认证失败时清理对应会话；网络、超时和 5xx MUST 不直接证明凭据失效。刷新超时后 MUST 不无限重试可能已被撤销的旧 Refresh，不承诺能够找回已签发但未收到的新令牌；无法恢复时 MUST 允许调用方重新登录或退出。

#### Scenario: Refresh 已撤销
- **WHEN** 刷新返回明确的无效凭据错误
- **THEN** 对应会话失效，等待该刷新的调用不会继续使用旧令牌发送业务请求

#### Scenario: 刷新结果未知
- **WHEN** 刷新请求超时，无法确认后端是否已经完成轮换
- **THEN** 应用表达会话暂不可确认或需重新认证的原因，停止对该次刷新自动重试，不宣称密码错误或服务端已登出

### Requirement: 退出同时隔离本地会话与尽力撤销远端凭据
应用 MUST 在退出时停止接受旧会话的新受保护操作，结束对应观察和在途调用，清理内存凭据、认证状态与受保护缓存，并尽力使用最新 Refresh 撤销远端会话。网络失败 MUST 不阻止本地退出；安全存储删除失败 MUST 显式反馈，不能承诺重启后已无旧记录。退出 MUST 不依赖成功响应具有非空业务载荷。

#### Scenario: 登出成功载荷为空
- **WHEN** 登出接口成功返回 `data=null`
- **THEN** 应用将远端撤销视为成功并完成本地退出，不因载荷为空而判定失败

#### Scenario: 网络故障时退出
- **WHEN** 无法确认服务端撤销结果
- **THEN** 应用仍结束本地会话，但不对调用方声称远端 Refresh 或已签发 Access 已被确认撤销

#### Scenario: 刷新过程中退出
- **WHEN** 用户在刷新仍在途时退出
- **THEN** 应用隔离旧会话并协调最新 Refresh 的尽力撤销，迟到刷新不得重新保存凭据、恢复已登录状态或重发旧业务操作

### Requirement: 旧会话结果不得污染新会话
应用 MUST 用独立于 Access Token 轮换的会话标识隔离异步操作。退出、切换账号或作用域后，旧登录、恢复、刷新、查询、更新与进度回调 MUST 不再发布到当前会话；仅取消请求或清空一次缓存 MUST 不作为充分保障。

#### Scenario: 退出后旧资料响应到达
- **WHEN** 旧账号资料请求在本地退出或新账号登录后才返回
- **THEN** 该结果不重新填入当前缓存或更新当前公开认证状态

#### Scenario: 正常轮换 Access
- **WHEN** 同一会话内成功刷新令牌
- **THEN** 会话缓存作用域不因令牌字符串变化而改变，已有服务端数据不被无故清空

### Requirement: 服务端数据只有一份缓存权威来源
本人账号、健康资料、模型目录和任务等服务端资源 MUST 由应用端服务端数据缓存管理，并按服务地址、渠道和会话隔离；认证状态 MUST 不完整复制这些资源及请求状态。资料更新成功 MUST 使用后端完整响应更新对应缓存。退出与账号切换 MUST 清理旧会话受保护资源，但不清除语言、主题等非认证偏好。

#### Scenario: 资料局部更新成功
- **WHEN** 后端返回更新后的完整资料
- **THEN** 对应缓存以该响应更新，不把局部请求对象当成完整资料覆盖，也不另建一份全局资料状态

#### Scenario: 账号或渠道切换
- **WHEN** 当前登录身份或渠道改变
- **THEN** 旧作用域数据不能被当前身份读取，后续查询使用新的会话作用域，非认证偏好仍保留

### Requirement: 认证敏感载荷不进入通用持久化缓存
应用 MUST 将密码和令牌限定在必要的认证调用及安全凭据管理生命周期内，不将它们作为通用查询或变更历史供其他页面读取、持久化或记录日志。本次 MUST 不持久化健康资料、任务或整个服务端缓存，也不把缓存存在与否当成服务端认证的证据。

#### Scenario: 完成登录调用
- **WHEN** 认证模块处理登录请求并消费令牌对
- **THEN** 普通调用方仅取得非敏感的认证结果，通用请求缓存不留下可继续读取的密码参数或令牌返回值

#### Scenario: 重启后没有业务缓存
- **WHEN** 应用重启且凭据仍可读取
- **THEN** 应用重新确认账号并按需查询服务端资源，不从普通偏好恢复上一进程的健康资料或任务作为权威数据

### Requirement: 认证操作同步反馈过程与结果
用户提交通过本地校验的登录、注册，或确认退出登录后，应用 MUST 同时在操作按钮和顶部 Toast 表达处理中状态，按钮 MUST 禁止重复提交，Toast MUST 不可由用户关闭且不自动过期。过程反馈 MUST 持续到对应操作实际完成，不以固定延时冒充完成；成功或失败 MUST 用实际结果替换过程 Toast，结果不可由用户关闭并在 3.5 秒后消失。按钮 MUST 在完成后退出 Loading，失败时允许重试；成功后的导航 MUST 不清除结果 Toast。按钮进入 Loading 时 MUST 保留 Demo 的完整主题渐变、白色前景与旋转 `LoaderCircle`，不得采用普通禁用态的纯灰外观；未进入 Loading 的普通禁用态仍使用灰色外观。

#### Scenario: 登录过程与成功
- **WHEN** 用户提交通过本地校验的登录表单
- **THEN** 登录按钮显示加载指示和“登录中…”，Toast 显示“正在登录…”；完成凭据保存和账号确认后，Toast 替换为登录成功，按原流程进入“我的”

#### Scenario: 注册过程与成功
- **WHEN** 用户提交通过本地校验的注册表单
- **THEN** 注册按钮显示加载指示和“注册中…”，Toast 显示“正在注册…”；注册成功后 Toast 提示“注册成功，请登录”，返回登录页并预填用户名，不建立登录会话

#### Scenario: Loading 按钮保留 Demo 主题外观
- **WHEN** 登录、注册或退出按钮处于 Loading
- **THEN** 按钮显示完整主题渐变、白色文字与旋转加载图标，同时保持不可重复触发；普通禁用按钮仍使用灰色外观

#### Scenario: 失败后重试
- **WHEN** 登录或注册请求失败
- **THEN** 过程 Toast 替换为对应安全错误提示，按钮结束 Loading 并允许重新提交；再次提交拥有新的过程反馈，旧操作清理不会关闭新 Toast

#### Scenario: 连续触发提交
- **WHEN** 某次认证提交尚未完成，用户连续点击按钮或通过键盘再次提交
- **THEN** 不创建第二个同类在途操作，不重置当前过程 Toast，不产生重复成功导航

#### Scenario: 本地校验未通过
- **WHEN** 用户未填写必填字段、用户名超长或注册确认密码不一致
- **THEN** 对应字段持续显示本地校验说明，按钮和 Toast 不进入请求 Loading

### Requirement: 退出反馈独立于认证状态提前切换
退出登录 MUST 保留事前确认，取消或关闭确认弹窗不得开始退出。确认后按钮 MUST 显示加载指示和“退出中…”，Toast MUST 显示“正在退出登录…”。即使本地认证状态已变为未登录，页面 MUST 在退出操作完成前保留退出按钮过程态，不展示可立即发起新登录的账号入口。完成时 MUST 根据本地凭据删除与远端撤销的真实结果展示成功或安全错误 Toast，恢复与实际会话状态匹配的页面；不得为保持 Loading 延迟本地会话隔离。

#### Scenario: 取消退出
- **WHEN** 用户取消退出确认或通过系统返回关闭确认弹窗
- **THEN** 不执行退出，不展示退出 Loading 或退出过程 Toast

#### Scenario: 本地已退出但远端仍在处理
- **WHEN** 本地会话已清理而远端撤销仍未完成
- **THEN** 账号展示遵循真实未登录状态，但操作区域仍为禁用的“退出中…”按钮；账号登录入口也暂不可触发，顶部退出 Loading 继续显示

#### Scenario: 退出操作完成
- **WHEN** 本地凭据删除及远端撤销均完成且成功
- **THEN** 用退出成功 Toast 替换过程 Toast，结束按钮 Loading，显示未登录页面及可用登录入口

#### Scenario: 部分退出失败
- **WHEN** 安全凭据删除失败，或本地退出完成但远端撤销未确认
- **THEN** 用对应真实错误 Toast 替换过程 Toast，结束按钮 Loading，不宣称全部撤销成功；页面按真实认证状态保留必要说明和恢复入口
