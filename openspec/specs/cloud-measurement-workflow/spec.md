# cloud-measurement-workflow Specification

## Purpose

为登录用户提供指尖和血压的云端测量业务流程，将同轮原生完成文件与固定版本任务关联，按真实上传、提交及成员结果推进报告，并隔离账号变化、重复通知与页面离开造成的旧操作。

## Requirements

### Requirement: 云端检测开始前确认身份及统一模型
应用 MUST 仅在当前账号认证已确认且当前渠道统一模型可用时启动指尖或血压检测。应用 MUST NOT 新增独立云端上传用途确认弹窗，也不得读取或保存其专属确认标记；系统权限、既有准备、声音提醒及操作指导保持原有流程。面部及无扰本地路径 MUST 不因此上传。

#### Scenario: 未确认身份不能开始
- **WHEN** 用户未登录、会话仍在恢复或暂不可确认
- **THEN** 不启动接触式设备或创建任务，提供对应登录／恢复／返回入口；跳过准备偏好不能绕过身份和模型检查

#### Scenario: 已登录账号首次正常开始
- **WHEN** 当前账号已确认认证且用户显式开始接触式检测
- **THEN** 直接检查当前渠道统一模型，成功后继续既有检测流程，不弹出独立用途确认；离页或认证代次变化仍不得继续本次启动

### Requirement: 每种接触方式固定使用对应统一场景
应用 MUST 为所有指尖目标选择统一 PPG 场景，为所有血压目标选择统一 PPG＋ACC 场景。模型 MUST 通过明确的方案编码匹配当前渠道目录取得实际 ID，核对要求输入及非示例标识；入口目标只改变报告重点。无合适模型时 MUST 反馈不可用，不猜测算法、不借用其他渠道或独立模型。

#### Scenario: 从单指标和部位进入指尖
- **WHEN** 用户分别从心率、呼吸率、血氧、风险或指尖部位开始一轮检测
- **THEN** 每轮都只选择同一统一 PPG 方案，不创建三个独立成员任务；开始设备前确认当前渠道方案可用

#### Scenario: 创建固定版本任务
- **WHEN** 场景目录可用且正常采集完成后创建任务
- **THEN** 使用目录返回的实际 modelId，保留创建响应的固定版本；不把目录版本或客户端版本参数作为任务权威版本

### Requirement: 同轮完整收尾后自动上传且只推进一次
应用 MUST 仅在本轮正常达到正式终点、所需文件已定稿、全部本轮资源释放且无错误或离开请求后自动创建任务、上传必需文件并提交，不增加手动提交步骤。重复完成通知 MUST 不重复创建或提交；指尖只上传本轮 PPG，血压再上传本轮 ACC，不读取历史产物补齐，不上传其他文件。

#### Scenario: 指尖和血压正常完成
- **WHEN** 本轮完整收尾满足资格
- **THEN** 指尖上传一份 logicalName=ppg；血压上传同轮 ppg 与 acc，全部上传响应成功后才提交，保留各回执

#### Scenario: 只有截止或单源完成
- **WHEN** 倒计时归零、结束语播放或单个文件已完成，但联合文件或资源仍在收尾，或本轮已中断
- **THEN** 不创建或上传本轮任务，继续显示真实收尾或失败，不提供样例结果

### Requirement: 提交冻结真实采集方式和正式时长
提交 MUST 携带完整 measurement 对象：方式为 fingertip 或 fingertip_chest、来源为 active、durationMs 为本轮原生正式窗口的实际整数毫秒。应用 MUST 不提交 capturedAt，不以目标时长、准备／上传／文件关闭耗时替代实际时长；产品记录时间以服务端 submittedAt 为准。

#### Scenario: 血压提交
- **WHEN** 本轮血压文件全部上传成功且当前身份有效
- **THEN** 提交 fingertip_chest、active 及原生正式经过毫秒；检测日期与最近记录时间读取服务端接受提交的时刻

### Requirement: 不确定写入不自动重放
创建、上传或提交请求失败后 MUST 停止自动推进并区分明确失败与结果未知，不自动重复写入。已知任务提交超时 MUST 先查详情；创建无明确任务ID时 MUST 不根据相似列表项自动接管任务。创建或上传失败／未确认及提交后确认仍为草稿，产品 MUST 展示“任务创建失败”并只提供重新检测；数据层仍保留真实阶段和不确定事实，不声称服务端没有草稿或文件。本地取消不表示服务端取消或文件删除。

#### Scenario: 提交超时但服务端已接受
- **WHEN** 提交响应超时而查询详情已为 SUBMITTED、RUNNING 或终态
- **THEN** 按所查询状态继续展示，不再次提交或新建替代任务

#### Scenario: 创建或上传结果未知
- **WHEN** 未收到创建或上传确认
- **THEN** 显示“任务创建失败／由于未知错误，任务创建失败，请重新检测”，只提供重新检测及既有安全返回；不声称服务端没有草稿／文件，不自动创建或重传，也不伪造可查看的报告

#### Scenario: 上传失败后返回前台
- **WHEN** 任务已创建，但上传失败或未确认，已停止推进的页面进入后台后再回前台
- **THEN** 保留任务创建失败及重新检测，不自动查详情或把失败改为结果获取失败，不重放创建、上传或提交

#### Scenario: 提交响应未知后查得草稿
- **WHEN** 提交响应未确认，随后查询原taskId成功且仍为草稿
- **THEN** 停止本轮自动推进，按任务创建失败提供重新检测，不新增手动提交或自动重放；若详情查询失败则按结果获取失败提供原任务重新获取

### Requirement: 任务查询服从可见性并独立于测量有效性
应用 MUST 仅为当前会话前台可见的 SUBMITTED 或 RUNNING 详情持续查询，前次完成后才安排下一次；终态、后台、离页或登出停止。查询失败 MUST 保留taskId和最后确认状态，展示“结果获取失败／结果查询失败，请稍后重新获取”，只提供原任务重新获取及安全返回，不重测、不重建任务。不支持的结果载荷 MUST 不冒充成功报告，使用结果获取失败；通信失败或等待过久 MUST 不改判任务失败。

#### Scenario: 等待中进入后台后返回
- **WHEN** 已提交任务的页面进入后台再回前台
- **THEN** 后台不持续查询，恢复时先查询真实状态；不重开设备、不重放提交、不保证任务仍在原状态

#### Scenario: 场景合法汇总但指标失败
- **WHEN** 任务为 SUCCEEDED 而 outcome 为 PARTIALLY_SUCCEEDED 或 ALL_FAILED
- **THEN** 部分成功保留有效成员，按已确认的部分成功界面展示；ALL_FAILED展示检测失败且不提供详细报告，不将场景汇总完成当作测量有效

#### Scenario: 服务端任务失败
- **WHEN** 原任务返回FAILED
- **THEN** 展示“检测失败／本次检测未能生成有效结果，请重新检测”，只提供重新检测及安全返回，不展示中间读数、失败详细报告或样例

#### Scenario: 失败后只查询原任务
- **WHEN** 用户在结果获取失败中点击“重新获取结果”
- **THEN** 对原taskId重新读取，按真实状态等待或展示结果，不重复采集、创建、上传或提交，不以固定一秒等待模拟成功

### Requirement: 流程绑定开始时的认证代次与采集轮次
本轮的请求、回执、任务及结果 MUST 绑定开始时的服务、渠道、认证代次和 captureId。退出、换号、重测或真正离开后 MUST 撤销旧流程后续动作及迟到展示，取消本地在途操作；旧采集 MUST 不在新会话上传。原生资源 MUST 继续遵循安全关闭屏障，完成文件不因取消删除。

#### Scenario: 上传途中换号
- **WHEN** 旧账号正在上传，用户退出后登录另一个账号或重新登录同一账号
- **THEN** 新代次不接管旧采集，旧响应不填入新缓存或报告，不继续用新凭据上传旧文件

#### Scenario: 离开已提交任务
- **WHEN** 用户真正离开本轮流程
- **THEN** 停止本地查询和推进，已提交服务端任务仍可执行；后续有效记录可通过健康查询获得，不承诺恢复未提交上传表单或后台上传
