# app-feedback Specification

## Purpose

为原生产品页和开发验证页提供统一的应用内弹窗与短时操作反馈，使未开放说明、详情和确认可访问且可关闭，并将短时 Toast 与必须持续可见的字段、会话及权限错误分开，避免伪成功或提示覆盖必要操作。

## Requirements

### Requirement: 应用内弹窗统一且可恢复交互
应用 MUST 为说明、详情和确认使用一致的弹窗视觉及交互，复用既定主题。弹窗 MUST 阻止背景交互，支持关闭按钮和 Android 返回关闭，长内容可滚动，操作具备可访问名称；关闭后恢复原页面交互及可用的触发焦点。页面切换时 MUST 不残留遮罩。

#### Scenario: 关闭未开放说明
- **WHEN** 用户打开说明弹窗后按 Android 返回
- **THEN** 仅关闭弹窗，不同时退出底层页面，背景重新可交互

#### Scenario: 长内容与大字号
- **WHEN** 弹窗内容在较大字号或小屏幕下超出可用区域
- **THEN** 内容及必要操作可滚动到达，不遮挡系统安全区或裁切按钮

### Requirement: Toast 支持四态与明确生命周期
Toast MUST 提供成功、错误、加载、信息四态，使用屏幕中央196 dp白色正方形圆角卡片、中性边框、64 dp状态图标、居中文字及隔离背景和已有弹层的灰色蒙版，不显示关闭按钮。正文默认包含中文状态名，检测等待只显示“等待检测结果，请稍候…”。MUST 同时只展示一条，替换后重新计时；成功默认1.5秒，错误与信息默认3.5秒，加载等操作结束、替换或代码移除，不自动伪造成功。所有非加载提示（含认证结果）MUST 允许点外部蒙版关闭，点击卡片不关闭，加载不可点外部取消。Android返回 MUST 与外部点击分开控制：普通非加载默认允许，认证过程与结果仍拦截，原生长任务等待保留安全离页。关闭提示不取消业务。错误 MUST 具备告警语义，其他态适当播报；加载沿用主题渐变圆弧和浅色底轨，按主题900 ms周期旋转，减少动态效果时静止。

#### Scenario: 重复触发与替换
- **WHEN** 一条信息 Toast 尚未消失又收到新提示
- **THEN** 旧提示被替换，新提示拥有自己的完整持续时间，不堆叠遮挡页面

#### Scenario: 加载操作未完成
- **WHEN** 加载 Toast 关联的实际操作尚未结束
- **THEN** 不因普通提示计时到期而显示成功，不允许点击外部关闭，保持可见直到代码更新或移除；原生长任务等待保留Android安全离页，离页不冒充服务端任务取消

#### Scenario: Loading 图标沿用 Demo 动效
- **WHEN** 加载 Toast 显示且系统未启用减少动态效果
- **THEN** 使用品牌青绿渐变圆弧和18%透明度浅色底轨，按24×24画布、半径9、线宽2等比缩放至64 dp，按主题900 ms周期旋转，不替换为不同形状的系统指示器

#### Scenario: 减少动态效果
- **WHEN** 系统开启减少动态效果
- **THEN** 加载图标保持静态，用户仍可通过图形和过程文字识别状态

#### Scenario: 认证 Toast 不可手动关闭
- **WHEN** 登录、注册或退出登录的加载 Toast 正在显示，用户点击外部蒙版、卡片或按Android返回
- **THEN** 加载提示不被用户关闭，不存在关闭控件或滑动关闭，等待实际操作完成；认证系统返回仍拦截，不传递到底层页面

#### Scenario: 认证结果 Toast 允许外部关闭
- **WHEN** 登录、注册或退出登录的非加载结果 Toast 正在显示，用户点击外部蒙版、卡片或按Android返回
- **THEN** 允许点外部蒙版关闭，点击卡片不关闭，系统返回仍拦截；关闭仅移除反馈，不取消认证操作或改变导航结果

#### Scenario: 操作结果开始独立计时
- **WHEN** 不自动过期的加载 Toast 被实际成功或失败结果替换
- **THEN** 成功默认显示1.5秒，错误默认显示3.5秒，均可提前点外部关闭；计时从替换时开始，旧计时或旧清理回调不关闭新结果

### Requirement: 持续错误不得仅用 Toast 表达
本地字段校验、会话不可用、权限未满足、相机关闭失败等需要用户持续处理的错误 MUST 在相关表单或页面保留说明及可执行入口，不能仅由自动消失的 Toast 承担。登录、注册、退出登录的请求结果 MUST 以 Toast 反馈，不在认证表单重复展示通用请求错误块；请求导致的会话不可用状态 MUST 仍保留页面说明和恢复入口。未知错误 MUST 安全映射中文提示，不直接展示底层消息、令牌或堆栈，认证请求 MUST 不再使用“操作未完成，请稍后重试”作为通用提示。

#### Scenario: 登录输入错误
- **WHEN** 用户提交未通过必填或长度等本地校验的表单
- **THEN** 对应字段保留错误说明，不只显示短暂 Toast，不发起认证请求或进入请求 Loading

#### Scenario: 被动启用确认
- **WHEN** 用户从开发页主动请求启用被动采集并进入应用确认弹窗
- **THEN** 继续保留取消、打开设置和明确继续的选择，不因统一弹窗而自动启用服务；系统权限框仍由系统管理

#### Scenario: 认证请求失败
- **WHEN** 本地校验通过但认证请求返回账号密码错误、用户名冲突、网络错误或未识别错误
- **THEN** 用安全中文错误 Toast 替换过程 Toast，不新增表单通用错误块；未识别错误使用操作相关的安全兜底文案

#### Scenario: 请求结果与持续状态分离
- **WHEN** 登录请求因身份确认暂不可用而失败，或退出后安全凭据删除失败
- **THEN** 请求结果以 Toast 反馈，同时页面继续表达真实会话状态和可执行的恢复入口，不因 Toast 消失掩盖持续错误
