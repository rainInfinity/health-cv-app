# Proposal

## Why

原生应用已接入真实采集、云端任务及健康记录查询，design-demo 也已补齐云端数据加载、刷新、空态、失败和部分成功的界面设计。需要在保留已完成数据链路的基础上，将这些已确认状态的视觉、文案和操作一比一迁入原生，消除“数据层有状态、产品界面无对应反馈”的缺口。

## What Changes

- **BREAKING**：指尖和血压检测开始前必须完成登录；覆盖首页检测主按钮、功能部位、准备页和跳过引导的路径。登录成功返回发起登录的原页面，保留原Tab、筛选及准备上下文，不自动开始检测。游客浏览、面部本地 RPPG 及无扰服务保持现有边界。
- 接触式入口保留登录及当前渠道统一模型检查，不增加独立上传用途确认弹窗或专属确认偏好；正常采集、文件定稿及资源释放后自动创建、上传并提交任务，不增加手动提交步骤。
- 所有指尖入口使用统一 PPG 场景，一轮只上传一份 PPG；所有血压入口使用统一 PPG＋ACC 场景，一轮上传同源 PPG 和 ACC。入口目标仅影响报告重点，不切换为独立算法。
- 复用现有认证、SDK 和 React Query，增加采集轮次与任务关联、受控查询、场景成员解析及处理后文件展示；删除固定三秒成功等待和产品样例结果路径。
- 首页接入最新有效健康记录，首次无缓存时显示骨架；取消返回、聚焦及非首次进入自动刷新，原生支持下拉刷新，新有效记录通过对应 latest 查询键更新已有缓存。刷新加载圈随原内容尺寸变化，Demo在手机下方演示操作区提供刷新按钮；保留空态及失败 Toast，首次获取或刷新失败后显示空数据，不继续展示旧读数。首页各指标入口直接进入对应指标的北京时间当日日区间，移除不再使用的指标详情路径，检测主按钮保留。
- 历史接入按指标和北京时间日期筛选的真实记录，完整区间加载后统一生成趋势和统计，不按来源、算法或版本拆组。首次获取与刷新共用筛选下方大加载圈，离线暂停读取同样隐藏旧内容，失败共用页面重取，不使用 Toast；保留纯文字空态与文字箭头操作，不显示分页完整度。Demo 同步统一状态，并使历史加载、空态与失败区填满剩余区域。
- 指尖与血压简要结果、详细报告和局部波形按 Demo 已确认设计展示成功、等待、部分成功及失败；区分检测失败、结果获取失败和任务创建失败，按真实状态提供重测或重新获取。已停止的创建／上传失败不因前后台切换重新查询或改成查询失败。血压不拆分双读数，部分成功只修改失败指标，不新增失败详细报告。
- 糖尿病风险在首页、指尖简要结果与详情、历史记录及详情中只将服务端0／1／2编码映射为较低风险／中风险／较高风险，使用20／26及读数主文字色；详细结果的看板与解读完整显示单行等级，其余入口仍为等级与“风险”两行居中。详细结果解读区数值与单位同行，顶部总览卡保持原有上下布局；独立加载圈采用主题渐变与浅色底轨，首页以原生的尺寸计算和线宽比例为准，渐变底按钮内保持白色前景。不显示概率或风险分数，不重算档位，不把缺失或失败默认成低风险。Demo同步排版和加载样式，原始数据及非诊断声明保留。
- 产品检测时间使用服务端 `submittedAt`，质量及失败原因使用真实契约；迁移状态设计不授权复制固定数值、模拟按钮、定时成功、医学结论或后端技术阶段。Toast 保留蒙版外观及背景隔离，成功默认1.5秒、错误与信息默认3.5秒；所有非加载提示（含认证结果）允许点外部关闭，加载不可点外部取消。认证仍拦截系统返回，原生检测等待保留 Android 系统返回安全离页。
- 实现时同步接口、测量、前端、模块及产品说明，保持当前变更已有材料与实现一致；不修改主规格或历史归档。

## Capabilities

### New Capabilities

- `cloud-measurement-workflow`：登录后的接触式测量业务会话，负责统一场景选择、完成文件自动上传、提交、状态查询和会话隔离。

### Modified Capabilities

- `cloud-api-access`：增加健康记录查询及采集属性 DTO，维持单次请求、原始值和错误契约。
- `server-query-lifecycle`：增加健康查询缓存及失效规则，将内部缓存与页面展示策略分开；首页失败后显示空数据及 Toast，历史首次与刷新共用页面加载和失败，支持显式重新获取而不重放写操作。
- `native-product-pages`：以真实最新记录展示健康摘要，迁移首页数据状态，将指标入口改为对应当日历史，接触式检测入口继续遵循登录门控。
- `native-measurement-pages`：以真实云端阶段、成员、质量及文件驱动 Demo 已确认的结果弹层、报告与波形状态；保持成功态原布局、参考信息、血压三级判断和同轮往返。
- `native-health-history`：在现行主规格的筛选、趋势、统计及记录能力上接入真实完整区间，首次与刷新共用加载和失败重取，不使用 Toast；保留空态与原有操作，不增加算法版本说明或分组入口。
- `app-auth-session`：登录成功返回原导航来源并保留上下文，注册返回登录不丢来源；认证结果同步成功1.5秒及非加载外部可关闭规则，系统返回策略不变。
- `app-feedback`：统一成功、错误、信息及加载Toast的时长、外部点击与系统返回规则，删除认证结果不可手动关闭的旧例外。

## Impact

- 目标端以 `apps/native` 为主，首页刷新、历史统一状态及全高布局、风险三档与详细结果排版、共享加载和Toast同步修改 `docs/design-demo`；风险详细结果单行、其他入口两行，不重绘无关页面，不改后端或原生采集算法，不改变覆盖、联合准入、正式时钟和资源屏障。
- 主要涉及 `packages/cloud-client/src`、`apps/native/src/app/{measurement,query,auth,navigation,preferences}`、`pages/{home,features,history,measurement}`、共享反馈及加载组件、`shared/dateTime.ts` 和对应文案与必要回归检查；不要求新依赖或新 workspace 包。
- 复用 `/models`、`/tasks`、文件上传下载、`/measurements/latest` 和 `/measurements`；不新增后端接口。目录不公开 `algorithmKey`，通过显式方案与实际 `modelCode` 绑定取得 `modelId`。
- 前序 `sync-native-design-demo-ui` 已归档，其能力已进入主规格；本变更直接以现行主规格及已完成的真实数据实现为基线，不再要求先同步或归档前序文件。
- 不包含资料编辑、离线队列、重启恢复、任务取消／删除、自动文件清理、已确认血压三级展示以外的评估规则、面部或被动数据入云，以及 Demo 尚未定义的新界面。接口公开不等于目标渠道模型和消费者已完成真实联调；本次仅迁移已确认的数据状态，不重绘无关采集区域或扩展后端能力。
