# Design

## Context

动机与范围见 proposal.md。普通渠道 SDK、SecureStore 认证、QueryClient、健康记录 API 和采集属性 DTO 已接入；本次继续复用现有通信和认证契约，不为状态展示重建数据链路。

`app/measurement` 已串联真实采集、自动上传、任务查询和成员结果；首页、历史及报告已使用真实数据，`ReportWaveform` 已读取关联输出并保留六秒回看。现有页面仍受原规划“不新增状态展示”的限制：查询状态尚未完整映射到 Demo 已确认的加载、失败、部分成功及局部波形界面，首页仍通过 `MetricDetail` 中转。

设计依据为 `docs/design-demo/README.md` 的“数据与结果状态预览”及 `data-states`、`result-states` 的现有实现；接口依据仍为 `health-service/docs/frontend-integration.md` 第 6、7 节。前序 `sync-native-design-demo-ui` 已归档并同步主规格，不再作为待完成依赖；以下保留已实现数据链路的决策，并补充本次状态迁移。

## Goals / Non-Goals

**Goals:**

- 分开原生采集事实、云端请求阶段、服务端任务状态与成员有效性，不用 UI 时间或文件存在推断健康成功。
- 复用现有单次请求、认证代次与查询缓存；页面不编排上传，不复制服务端结果到全局 Store。
- 一比一迁移 Demo 已确认的云端状态视觉、文案和操作，保持成功态及无关采集区域不变；布局、渲染与生命周期使用原生实现，状态推进由真实数据决定。

**Non-Goals:**

- 不创建跨端业务包、通用流程引擎、任务数据库、后台上传服务或持久化恢复队列。
- 不改采集算法、补帧、重采样或跨源对齐；不新增管理端、医学评估及资料编辑。
- 不承诺查询结果为跨请求快照，也不保证网络恢复后自动重放写操作。
- 不新增历史算法／版本说明、可比较分组、常驻刷新按钮或 Demo 未定义的状态；不迁入侧栏衍生路由、外部模拟控制和定时成功，不提供失败详细报告。

## Decisions

### 1. 应用层持有业务流程，SDK 与采集客户端维持原职责

在 `app/measurement` 增加有限的云端流程控制及结果适配；注入现有客户端、认证和 QueryClient，不新建 workspace 包。每轮记录服务作用域、认证代次、`captureId`、方案、已返回的 `taskId`、固定版本与上传回执。过程状态独立于原生阶段，详情数据归 Query；完整 CSV、原始采样和展示点不进入认证 Store 或通用 Query。

不在页面 Hook 内直接串联 HTTP，也不把轮询放入 `cloud-client`。这些替代方案会把页面生命周期、账号隔离和传输职责混合，难以防止重复完成通知造成重复提交。

### 2. 所有接触式入口在启动设备前检查身份及模型

首页检测主按钮、功能部位与跳过准备路径复用同一入口判定；准备页点击开始及真正启动设备前再检查当前认证代次。首页指标入口改为历史浏览，不承担启动设备。未登录引导现有登录，恢复中或不可确认沿用其真实反馈；不创建轮次、任务或相机副作用。登录成功只返回发起登录的原导航页面，保留Tab、历史筛选或准备上下文，不重置到“我的”；从注册返回登录仍保留同一来源。返回后由用户再次明确开始，认证完成回调不启动设备。

不增加独立云端用途确认弹窗，也不读取或保存其专属非敏感确认标记；首次和后续显式开始均在身份通过后直接检查当前渠道统一模型。原有准备页、声音提醒、操作指导和系统权限保持各自语义，不用新增确认代替原生准入。

准备页的既有动作和必要系统权限完成后，正式开窗仍由原生准入决定，不新增采集期间的手动开始或采集后的提交按钮。面部和无扰路径不调用云端流程。

### 3. 显式绑定两个场景，不按指标切算法

方案表绑定后端初始数据文档的稳定编码：指尖对应 `ppg.active.offline.all`，血压对应 `ppg_acc.active.offline.all`；这不是由算法标识截断推导的编码。读取当前渠道目录，必要时继续分页，精确匹配编码并确认 `requiredInputs` 与非示例标志；创建使用目录实际 `modelId`，固定版本以创建响应为准。无匹配或输入不符时在设备启动前反馈不可用，不回退其他渠道、示例或独立算法。

入口目标仅保留报告定位／重点，指尖总是执行 `hr_br/spo2/diabetes`，血压场景当前只有 `bp`。如果目标环境使用其他编码，修改显式方案绑定，不增加按名称或输入猜模型的规则。联调只读取普通渠道目录，不由 App 发布或切换模型。

### 4. 正常完整收尾触发一次自动创建、上传和提交

以本轮 `completed`、`duration_reached`、无错误、资源释放和非空完成引用为资格。指尖只上传当前 artifact 的 PPG；血压还要求同轮 ACC。`frame.csv`、gyro 及其他历史文件不参与，文件引用按 URI 直接交给已有上传方法。

同一业务轮次只允许一个在途推进链，重复快照不重入。先创建草稿，再顺序上传必需输入并保存回执，全部确认后提交。顺序上传便于保持可理解的回执和错误状态，无需为两份短文件增加并发协调。提交携带 `measurement.captureMethod=fingertip/fingertip_chest`、`captureMode=active` 和原生正式窗口 `elapsedMillis` 的整数毫秒，不用目标常量、准备时间、文件关闭时间或 JS 墙钟替代；不发送 `capturedAt`。不为算法新增无用途的 `clientMetadata`。

正常路径自动推进，不显示手动提交按钮。创建或上传失败／结果未知停止推进，在产品中统一展示 Demo 的“任务创建失败／由于未知错误，任务创建失败，请重新检测”，只提供重新检测；数据层仍保留失败阶段、已知 taskId 和回执，不宣称服务端没有草稿或文件。创建无幂等键，不根据相似列表项接管任务。提交响应不确定时先查已知 taskId：已提交或终态进入真实状态，查询失败显示“结果获取失败”并只重新获取，确认仍为草稿则按任务未建立完成展示任务创建失败，不提供手动提交或自动重放。

已停止且归类为任务创建失败的轮次，恢复前台不自动查询、不清除原失败分类，也不将重新检测改为重新获取结果；已提交任务和提交回执未知的状态查询仍按原规则执行。

### 5. 生命周期区分本地取消和服务端继续执行

流程使用开始时的认证代次，所有写调用、下载、查询和回写前检查该身份；同账号重新登录也不接管旧采集。退出或换号立即撤销本地云端流程、取消请求并清除对应受保护展示；原生仍按现有安全关闭屏障释放，不把旧文件传给新会话。

页面后台暂停轮询及反馈；不新发后续创建、上传或提交动作，也不承诺移动系统维持在途传输。在途响应若仍属于原会话可保留真实回执，回前台先查询已知任务；不因恢复事件重放结果未知的写入。正式采集期间后台仍按现有原生中断规则处理。

真正离开检测／本次报告流程时取消本地操作和后续推进、释放本轮展示内存；已提交任务不会被取消，稍后的有效结果可经首页／历史刷新取得。不新增任务管理页，也不承诺离页后恢复未提交表单或失败任务展示。检测页与同轮详情之间的受控往返例外继续保留 `captureId/taskId` 和实时回看位置，不保持相机占用、不重复上传。

详情按 `taskId` 查询权威结果，本轮检测返回交接额外验证 `captureId`，不要求仍存在原生会话的历史轮次。保留现有导航，不为接入数据新增历史完整任务报告按钮；普通导航不能构造虚假结果。

### 6. 可见任务使用受控详情查询，场景按两层结果映射

SDK 继续一次调用对应一次请求；业务观察仅对 `SUBMITTED/RUNNING`、当前账号且前台可见的详情约每两秒查询，前次完成后再安排下一次。终态、离页、后台或退出停止；恢复先立即查询。查询失败停止循环，保留 taskId 和最后确认状态，产品改为“结果获取失败／结果查询失败，请稍后重新获取”，只提供“重新获取结果”；操作只重查原任务，不能重建任务或重新采集。等待过久不改判失败。

删除三秒定时成功门槛，保留420 ms结果弹层动画及同轮一次自动展开。创建、上传、提交、排队和运行共用原等待入口、加载圈与“等待检测结果，请稍候…”Toast，不向产品暴露技术阶段或推理百分比。终态或可处理失败进入对应弹层；重复通知不重开已收起内容，显式重新获取后的新状态仍可在当前弹层更新。

算法解析归结果适配层，不改变SDK的 `Record<string, unknown>` 原始结果契约。已知独立算法历史按其原路径读取，新任务按场景成员路径读取。SUCCEEDED仍必须检查outcome与成员status，失败成员不保留前轮数值，ALL_FAILED无健康读数。HR与BR使用同一成员质量，不造场景总质量。质量拒绝按公开判别字段处理，技术失败与质量拒绝分开；未知或不符合支持契约的载荷映射结果获取失败，不猜字段或另建结果不可用报告。

真实质量读取服务端分数与公开质量拒绝字段，沿用原角标配色和质量说明，不增加阈值解释。成功及指尖部分成功都保持绿色图形、“检测完成”和“可以移开手指，查看本次结果”；失败指标读数为 `--`，卡片底部为“未能生成结果”，明确质量拒绝则为“信号质量过低”，有真实分数才显示角标。HR／BR同源失败及质量一起映射；血氧失败保留半圆仪表和空底轨，清除读数与亮格。部分成功详情保留同源看板，失败项解读只说明未生成，不附正常结论；不新增总状态说明卡。

任务 `FAILED` 或合法场景 `ALL_FAILED` 展示“检测失败／本次检测未能生成有效结果，请重新检测”，只提供重新检测，不允许查看详细结果。指尖全部失败仍沿 Demo 保留失败看板及真实质量，血压失败不显示双读数、参考评估或波形；查询失败和任务创建失败不保留成功看板。不可解释的结果载荷不能套用成功或空的有效报告，应保留结果获取失败及原任务重新获取入口。失败标题与40 dp图标同一行整体居中，说明另行居中。

静态参考区间、血压参考阶梯和通用介绍／建议按原设计保留。血压弹窗及详情共用已确认的三级判断：任一原始双读数达到140／90即偏高；否则任一低于90／60即偏低，其余正常，低高交叉偏高优先。沿用蓝／薄荷绿／粉色及“本次结果”对应标记，不用截断值分级。其他无依据评估用 `--`。风险原始比例与编码保留不变，页面只将服务端 `riskLevel/risk_level` 的0／1／2映射为较低风险／中风险／较高风险，不再展示概率；统一字号20、行高26及读数主文字色。详细结果的看板和指标解读完整显示单行等级；首页、简要结果、历史列表及记录详情仍为第一行“较低／中／较高”、第二行“风险”的两行居中，历史行高自然增高。详细结果解读区数值与单位同行、基线对齐，不在组合内部折行，评估标签可另起一行；顶部总览卡仍保留数值在上、单位在下。首页风险刷新圈保留原直径，不随等级排版改变。缺失或失败仍为 `--`，不复制Demo固定低风险、不按概率重算或生成临床结论。Demo同步相同排版，首页及历史无样例记录时仍为空态。

详细报告读取状态与有效报告内容分开：首次进入无可展示报告时保留“详细结果”顶栏及返回，剩余内容区只显示居中旋转图形，不附说明和声明；查询失败显示上述获取失败文案与重新获取操作，不显示声明。成功／部分成功才展示总览、看板、解读和一次完整声明；本轮失败不形成详细报告，既有 taskId 入口读到失败也返回对应检测失败展示，不渲染失败详情。

### 7. 处理后文件按需读取，与实时脉搏历史隔离

有效报告数值可先展示，进入对应波形卡才通过鉴权下载；使用顶层 `output_files` 的逻辑名键。指尖报告的 PPG 明确取 `hr_br_processed_ppg`，该成员失败则进入局部读取失败，不拿其他成员 PPG 冒充；血压取 `bp_processed_ppg/bp_processed_scg`。历史独立任务使用对应无前缀逻辑名。

按算法 CSV 契约读取：HR/BR 为 `timestamp,ppg`（呼吸输出为 `timestamp,rsp`），时间戳沿用输入毫秒值；血氧／风险为 `timestampFrame,ppg`，血压为 `timestamp,ppg` 和 `timestamp,scgX,scgY,scgZ`，SCG 显示 Z。以文件首个时间点建立报告相对毫秒轴，不改写幅值或以请求 FPS 重造等间隔时间。报告 PPG 的方向已由后端翻转，前端绘图与纵轴范围直接采用后端幅值，不再次取负；SCG 保留处理后 Z 方向。采集阶段实时 PPG／RPPG 的原有展示方向保持不变。

只解析已支持任务和逻辑名；每文件最多5 MiB、20,000行样本，不提供任意大CSV查看器。原164 dp画布内居中展示加载图形与“正在获取波形”；缺文件、无可用样本、超限、下载或解析失败统一为“波形暂时无法获取”，不增加另一种结果不可用报告、说明区或重试按钮。局部状态保持原画布高度，范围及总时长用 `--`；不隐藏有效读数、不截断冒充完整波形、不重跑任务。解析及样本归报告局部，离页释放，不写MMKV、Query或Nano Stores。

保留固定六秒横向回看、164 dp 绘图区及现有主题。真实纵轴从实际有限幅值计算，保留既有留白；窗口总范围取文件真实时间跨度，不强制三十秒，不足六秒允许查看短段且不补点。两种血压波形独立管理视窗；再次进入或回到前台可重新读取，下载／解析失败不重跑推理，不增加单独重试按钮。

### 8. 最新结果与历史采用服务端权威记录

SDK 增加 `measurements.latest/list` 及 `Req/Rsp` DTO；日期字符串、null、读数代码、单位、来源、质量、风险编码和固定版本保持原样。展示适配将无后缀 `submittedAt` 解释为UTC+8，再交日期工具，原DTO不变。首页各指标独立使用对应真实时刻；首次无缓存时显示原数据位置的骨架，后续刷新在读数、仪表中心及时间位置旋转，直径按原内容实际高度计算并限制在占位内，不统一固定为18 dp，不改变卡片或单位位置。原生首页提供下拉刷新，重复触发复用在途请求；Demo只在手机下方演示操作区增加“刷新首页”，仅已登录首页可用，加载期间禁用，以原有模拟重试机制展示约一秒局部刷新后恢复，离页取消。成功为null使用 `--`／“暂无记录”和空血氧仪表；首次或刷新失败分别以“数据获取失败，请稍后重试”／“刷新失败，请稍后重试”Toast反馈，之后首页显示空数据，不继续展示旧值或把错误当成功空响应。

首页各指标及原详情入口直接进入对应指标的北京时间当日日区间，显式更新历史指标与日筛选；检测主按钮仍经门控进入测量。移除产品中不再使用的 `MetricDetail` 路由、调用方、页面及专属文案，不保留隐藏中转或新建其异步状态。历史Tab与我的健康记录仍保留当前历史筛选，游客指标入口仍引导登录。

最新及历史区间 `staleTime` 均为30秒，沿用十分钟无观察者回收及不持久化。首页仅首次无缓存时自动读取；返回、重新聚焦、重新进入、应用回前台及网络恢复不单独触发重取，普通重绘也不请求，后续由下拉或新有效记录的查询键失效更新。首页观察者不随导航聚焦重建，手动刷新不取消在途同键请求。历史首次进入及每次导航重新聚焦仍读取最新完整区间，即使仍在新鲜期内；历史区间key包括服务、渠道、认证代次、指标、起止日期，offset/limit属于同一区间轮次，不独立缓存各页后混拼。首页失败时可以保留内部旧缓存及错误事实，但展示层必须采用失败空态，直到后续成功获取。

历史默认截至北京时间当天七天，保留周期、日历草稿及Tab筛选。首次读取、切换筛选、同一区间刷新与重新获取共用页面加载；离线导致读取暂停时仍视为本轮未完成，同样隐藏缓存内容。保留指标／日期控件，下方剩余区域以36 dp大加载圈居中，不显示旧趋势、统计、记录或声明。成功空区间显示“当前区间暂无{指标}记录”及原辅助文案、“前往检测”主题色文字箭头，目标为功能页，不加图标；任一读取失败统一显示“历史数据获取失败”和“重新获取”文字箭头，隐藏旧内容与声明，不使用 Toast。重新获取从当前筛选第一页重读，不自动改筛选。Demo 同步删除历史刷新及刷新失败独立预览入口，让加载、空态与失败区填满筛选下方至底栏前的空间，成功长内容仍可滚动。

历史每页100条连续取得整个区间，完整后才发布本轮趋势和统计；内部可保留上一轮完整缓存，但不能在加载或失败时继续展示，也不能将本轮部分页认作完整。任一页失败不当空页结束，统一进入上述获取失败。再次进入、显式重新获取或切换筛选从第一页建立新轮，隔离旧页。total改变、重复recordId或已知新有效任务使旧轮失效，可见在线允许一次整段刷新，持续变化保留内部未完成，不无限重取，不暴露“记录未取完整”或分页技术状态。

原始区间结果只缓存一份，组件派生显示顺序、最近十条及统计，不复制全局状态。当前指标和日期范围的全部有效记录统一参与趋势、均值和极值，不按来源、采集方式、算法或版本分组，也不增加相应筛选或说明。列表和详情保留日期、时间、实际结果及通用静态内容。风险只显示由服务端编码映射的两行三档文案，不显示概率、原始编码或医学风险说明，不生成风险趋势或均值。

已知任务终态且存在有效成员时，在该代次失效最新结果和全部已缓存健康区间；对应 latest 键使用 `refetchType: 'all'` 重取已有缓存，不论首页是否正在展示，不靠返回或聚焦触发；尚无缓存时仍由首次进入读取。不向缓存手工拼读数。`ALL_FAILED` 或失败不会用空值覆盖此前最新有效记录；活动历史下一次读取仍遵守完整区间刷新。

### 9. 状态展示复用原生主题与反馈生命周期

按 `docs/development/frontend-development.md` 以RN布局、原生动画、SVG及现有反馈宿主迁移，不复制DOM／CSS或引入WebView。首页骨架复用主题表面和1.6秒渐变语义；独立加载圈统一品牌青绿渐变圆弧与18%透明度浅色底轨，24×24画布、半径9、线宽2，按原生调用尺寸等比缩放，沿用900 ms旋转。Demo首页按原生内容占位计算圈径，不再叠加CSS边框；渐变底按钮内保留白色加载前景。不逐帧写React状态，不改变业务等待时长；沿用至少48 dp触控目标、安全区及既有成功态卡片。

Toast保持196 dp白色正方形、64 dp图标、灰色蒙版及单条替换；成功默认1.5秒，错误与信息默认3.5秒，替换后重新计时。所有非加载提示（含认证结果）均可点外部蒙版关闭，点击卡片本身不关闭；加载不可点外部取消，等待显式结束。历史不使用 Toast，读取及刷新统一为页面状态；检测等待只随真实请求结束，不复制Demo约1秒重试或3秒结果等待。原生长任务等待的蒙版隔离背景但保留Android系统返回的安全离页，认证仍拦截系统返回；外部点击不受系统返回策略影响，关闭提示不取消业务或服务端任务。

页面持有Toast ID，只清理自身反馈；失焦、后台、离页、重测或卸载清理旧提示，迟到回调不关闭新提示、不改变新筛选或新轮展示。恢复遵循已有查询规则，不自动恢复采集或重放写操作。新增状态只由真实查询和任务事实派生，不为生产界面添加模拟入口。


## Risks / Trade-offs

- 目录不提供算法标识、目标环境可能未配置预期编码 → 使用显式方案编码和实际目录响应；编码与版本在联调读取核对，缺失即反馈不可用，不改后端模型选择。
- 创建、上传和提交响应丢失可能已产生写入 → 不自动重放；已知任务先查状态，创建无法唯一对账时明确不确定，不把它扩大成幂等恢复系统。
- 普通 offset 分页无法提供固定快照 → 检测已知变化后整段刷新；不宣称客户端去重已保证完整快照，不追加后端聚合端点。
- 后端无医学评估接口 → 交付真实读数和实际质量，保留未知评估，不复制样例正常结论；这不是医学验证或正式临床开放承诺。
- 报告输出存在采样或存储差异 → 数值与波形独立失败，明确文件来源和有限读取，不因单张波形失败重跑任务。
- 离页或进程结束丢失未提交进度 → 本轮不提供持久化恢复；保留本地文件但不自动上传，已提交的有效结果由服务端健康查询找回。

## Migration Plan

1. 保留已完成SDK、查询、门控及真实任务链路，先补状态投影与查询失败分类，再迁移首页／导航、历史、结果弹层、报告及局部波形；同步移除冲突的旧展示策略和失效调用方，不保留两套产品路径。
2. 原28项完成任务记录数据接入基线；新增未完成任务单独跟踪本次迁移。只为新增行为调整消费者合同和必要回归，最终在常规Android页面检查真实状态与操作，不将编译或Web设计稿检查代替原生验证。
3. 实现时同步 `docs/development` 的前端、测量、查询及上传说明，以及模块职责和产品入口描述，删除冲突的旧状态策略，不写验收流水；历史状态及全高布局同时同步 Demo 和原生，其余页面维持既定边界。
4. 前序已归档，本变更以现行主规格为基线；待新增差量实现后再决定同步或归档，本次不改主规格或历史归档。
5. SDK继续支持后端允许的无请求体提交及既有独立算法历史，不迁移或伪造历史数据、不删除本地文件。回退时只回退本次实现，不撤销服务端任务或健康记录，不把样例作为运行时降级。
