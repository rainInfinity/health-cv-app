# Design

## Context

动机和实施范围见 `proposal.md`。现有 `ppg/camera/CameraSource.kt` 将 `PreviewView`、`Preview + ImageAnalysis`、`STRATEGY_BLOCK_PRODUCER` 和宿主 `ON_STOP` 绑定在一起；`PPGController` 还持有页面及旧 CSV 状态，不能直接作为共用 RPPG 控制器。`FramePipeline` 同步完成统计后释放帧，`PixelStatisticsExtractor` 仅计算全帧／固定网格 YUV，没有动态面部 RGB。

现有 `DataHub` 已提供包含在途消费的容量限制与排空屏障，`AcquisitionFileStore` 和 `AcquisitionPaths` 提供拒覆盖文件操作和集中路径。应用已有 Nitro、Dev 栈、相机离页守卫、Nano Stores 和 `react-native-svg`。被动仍是独立 `LifecycleService` 录像；本提案不改变其执行行为。

本次包含跨模块资源所有权、新模型依赖及新产物契约，必须提供设计，不适用纯重构免设计条件。

## Goals / Non-Goals

**Goals:**

- 一个会话负责人，统一资源、采集窗口、算法状态和结果收尾，避免 UI 与原生各自决定采集成功。
- 原生数值处理可独立验证；持久化完整性与展示流畅性采用不同背压，信号内容保持一致。
- 共用设备层服务原始 PPG 和 RPPG，后续被动只接入会话，不重写算法。

**Non-Goals:**

- 不创建新 workspace 包、通用工作流引擎、事件总线或仅为未来准备的兼容 API。
- 不在第一阶段接入解锁策略、无人脸重试、后台常驻或正式产品页；不实现网络交互。
- 不将数据集一个样本通过解释为精度、医学有效性或跨设备性能通过。

## Decisions

### 1. 按设备、信号、会话和消费边界拆分

原生根目录为 `packages/acquisition/android/src/main/java/com/healthcvapp/acquisition/`。

| 目录 | 职责 |
| --- | --- |
| `camera/` | 相机查询、设备配置、CameraX 帧源和 `ownership/`；从 `ppg/camera/` 抽取实际共用实现 |
| `pixels/` | 从 `ppg/pixels/` 提取通用帧借用和 stride 读取；网格几何仍留在原始 PPG |
| `rppg/model/` | `RPPGConfig`、`RPPGPulseSample`、`RPPGHeartRateWindow`、`RPPGInstantHeartRate`、`RPPGSnapshot`、`RPPGArtifact` |
| `rppg/face/` | 模型适配、目标连续关联和就绪事实 |
| `rppg/roi/` | 模型拓扑上的额头／双颊区域、坐标变换、RGB 统计 |
| `rppg/signal/` | 有界重采样、POS、滤波、频谱及逐搏估计与质量判断，纯 Kotlin 数值计算 |
| `rppg/session/` | `RPPGSession` 资源与阶段，内部 `RPPGProcessor` 串行组织计算 |
| `rppg/output/` | writer、三件套发布与扫描 |
| `rppg/realtime/` | 有界标量批次、订阅和低频通知 |
| `rppg/runtime/` | 主动命令串行化及活动会话引用 |

不复制相机源，也不将必须计算全帧 YUV 的旧 `FramePipeline` 强行用于 RPPG。只迁移真实共用部分并更新所有旧调用和测试导入，不保留转发别名；旧网格、元数据关联、锁确认和 CSV 原始语义不变。设备配置与网格配置分开，避免共用相机层反向依赖原始 PPG 的处理布局。

### 2. 会话持有相机，控制器只持有会话

主动桥接由 `RPPG.nitro.ts`、`HybridRPPG`、`RPPGClient` 接入，公开命令为打开预览、开始测量、停止／关闭、读快照、订阅状态／波形、查询完成产物。生成绑定归 Nitrogen，不手工维护生成代码。React 预览接入必须明确绑定 RPPG 控制器，不能误用旧 PPG 的全局预览归属。

`RPPGSession` 唯一持有本次相机租约、帧源、处理器、输出和停止屏障。预览打开即占用相机，但不创建正式产物；用户开始时建立独立结果会话。为排除预览在途帧，先关闭旧分析入口并等待借用释放，再绑定全新分析用例代次，只接受新代次交付的帧；期间保留租约，预览允许短暂重新协商，不把旧帧队列交接给正式处理器。首个被接受的新代次帧建立结果传感器时间原点，不能仅用开始时最近已观察时间戳推断排除了全部在途帧，也不比较未经确认同源的系统时钟。

阶段为 `opening → preview → observing → measuring → stopping → completed/failed`，关闭到 `closed`。未打开时开始、重复开始、收尾中开始返回状态错误。开始后的观察超时、正式时长到达、手动停止、宿主后台和页面离开均进入同一幂等收尾；测量会话结束后关闭相机，再次测量须显式打开，不自动复采。页面返回／Tab／深链复用现有离页守卫行为：等待命令和原生关闭，失败保留页面及重试。

源接口接受明确的生命周期和可选预览提供者，模型／信号不持有 Activity。第一阶段实际接入的是有预览主动流程，不提前启动无预览服务。宿主停止的策略由主动控制适配，不在通用设备层硬编码“App 后台必失败”。原始 PPG 通过自己的适配继续遵守原生命周期要求。

公共接入点包括：首个正式观察帧到达时的单调时间通知、就绪／阶段通知、终态结果和停止等待。后续被动的首帧周期使用交付时读取的 `elapsedRealtime`，与信号传感器时间域分开；第一阶段不实现周期门控。

### 3. 同帧推理取色，先正确处理输入而不是承诺零拷贝

选择 MediaPipe Face Landmarker 官方模型、固定 Tasks Vision 版本，单目标，不请求表情系数。采用后台串行 `VIDEO/detectForVideo` 调用：相机实时输入不要求先保存成视频，递增毫秒时间戳由本帧传感器时间相对原点转换。保留原始纳秒时间；量化后非递增的输入不得凭空修改采集时间，可拒绝该帧并记录时间原因。

先建立可复用 ARGB 输入缓冲的正确适配，必要的格式转换只做一次；官方 API 示例支持 Bitmap 并不证明 YUV 零拷贝可用。完成定位后映射回当前借用帧，在释放前提取 ROI。保留明确的反变换处理 crop、缩放、旋转及预览镜像；不跨帧保存 `ImageProxy` 或 `PixelFrameView`。源使用 `KEEP_ONLY_LATEST`，原始 PPG 仍保持自身背压设置。

三个内部多边形根据官方模型拓扑定义，避开眼、眉、嘴及区域边缘。单 ROI 无效则本帧无效，不增加部分区域降级。各区域记录有效像素数并按面积加权形成一条 RGB。YUV→RGB 采用显式、版本化的矩阵与值域约定；读取不到可靠颜色元数据时标记为所用转换假设，不宣称设备确认。模型与 ROI 使用的颜色转换要一致，不用旧 YUV 网格均值冒充 RGB。

单目标只做位置／形状连续性检查，不能证明多人场景无目标切换；突变则断开并重新就绪，不用身份识别解决。采用串行而非异步持帧，牺牲部分吞吐换取明确资源生命周期；实测不足时再通过必要分辨率或转换优化改善，不通过无限线程／队列掩盖。

### 4. 时间片段和在线信号算法

有效 RGB 以传感器时间进入固定容量环形缓冲。短间隔线性插值到规则时间网格，长缺口、无效定位导致的超限缺口、目标切换、非递增时间终止连续片段；跨边界重置重采样、POS、滤波及心率窗口，保留本会话递增的 `segmentIndex`、`sampleIndex`。不能按实际收到帧的序号当作固定 FPS 时间。

POS 采用每样本推进的滑窗：按通道窗口均值归一化，投影为 `G-B` 与 `-2R+G+B`，用标准差比例组合并去均值；均值或标准差退化时拒绝该窗口，不输出 NaN。通过有界重叠累加及实际贡献权重归一化定稿，只有后续窗口不再涉及某点时才输出，不向 UI 发布会被未来修订的中间脉搏波。窗口长度造成约一个 POS 窗口延迟；结束时丢弃无法定稿的尾部并记录范围，不补未来数据。

滤波选择一阶高通加一阶低通的因果级联，双线性变换系数按实际规则采样率构造；带宽由配置确定，不使用 `filtfilt`。片段初始化为稳定直流状态，并推荐前 2 秒定稿输入用于滤波启动、不作为有效输出；该启动排除量和实际有效起止写入元信息，测试覆盖阶跃启动和重置。HR 与 UI／落盘共享最终滤波输出，不从另一路临时 POS 值计算。

HR 在足够长的同片段波形上去均值、加 Hann 窗并计算频谱，带内选峰、三点抛物线插值且约束在邻频点及搜索范围；零能量、边界峰或不满足质量规则则拒绝。工程 SNR 定义为主峰 ±0.1 Hz 的带内功率相对其余带内功率的比值；零分母使用显式不可计算／退化规则，不写无穷值。它不是运动伪影排除或医疗置信度。窗口不足只有积累状态，不为凑每秒一行伪造窗口。HR 估计窗口、样本时间及结果发出时间分开，延迟不挪动原始时间轴。

#### 4.1 逐搏初步心率与频谱窗口并行

保留 1.6 秒 POS、2 秒滤波启动排除及 12 秒／1 秒步长频谱估计，不从临时 POS、观察帧或 UI 缓存计算另一条信号。逐搏估计器读取同一条已定稿有效滤波波形，在固定容量状态中识别局部峰，采用自适应峰突出度、不应期、配置心率范围对应的搏间间隔及相邻间隔一致性门控；所有阈值集中版本化，属于待验证工程值，不是医学标准。可用局部插值改善 20 Hz 峰时间量化，但不得用发布时间替换采集时间。

首次输出至少需要三个可信峰形成两个一致间隔；输出最新一个合格间隔的 `60 / RR秒数`，不是两个间隔的平均值。平线、退化波形、过近峰、异常间隔及尚未确认的峰不生成有效 bpm；异常后重新确认。无合格心搏超过版本化期限、片段／有效区间切换、无效 ROI、时间或样本不连续以及会话停止均清空当前值和相关峰历史，不跨无效段配对，不把旧值留作当前读数。

共用模型为 `RPPGInstantHeartRate`：`segmentIndex`、`previousPeakTimestampNanos`、`peakTimestampNanos`、`intervalNanos`、`heartRateBpm`。快照以 `latestInstantHeartRate` 的独立可空字段承载；跨 JS 的纳秒为十进制字符串。只有新合格逐搏结果或失效清空时推送低频更新，不向 JS 发送逐帧检测状态。原 `latestHeartRate`、频谱有效窗口平均及最终 `signalStatus` 仍只依据频谱窗口；存在逐搏初步值不等于频谱已有效。

本次逐搏输出为实时状态，不新增 CSV，也不把逐搏记录塞入 `hr.csv`。`pulse.csv` 仍保存可供离线复核的同源波形；原有三件套 schema、扫描和历史产物保持不变，配置快照补充实际逐搏阈值。重开后不声称可从历史产物查询到逐搏实时序列。

首结果从用户点击开始起算，被动复用时从真实解锁起算，以 6–10 秒为体验目标而非本次验收门槛；本次不包含专门的阶段耗时、参考对照、误差和错误接受率验收。相机启动、找脸和信号质量均影响达成；超出 10 秒仍无合格结果时如实显示积累／信号不足，不伪造结果或后移计时起点。保留 POS 不代表能省去其 1.55 秒定稿等待；没有实际运行证据时不得宣称达到目标。

### 5. 试验参数集中管理且不可冒充已确认标准

以下是本提案供评审的完整试验配置，尚未逐项获用户确认，也没有真实设备有效性证据。实现前随提案评审确定；调整可配置数值不改变本设计边界，实际采用的全部数值和版本写进每次会话，不将它们作为医学阈值。

| 项目 | 推荐基线 |
| --- | --- |
| 相机 | 前摄，640×480、30 FPS 偏好；自动 AE/AWB/AF、不强制锁定、不补光 |
| 观察／就绪／正式时长 | 5 秒／连续 1 秒（相邻有效帧不超过 200 ms）／30 秒，不延长 |
| 面部就绪 | 面宽至少有效画面 25%，yaw/pitch ±20°、roll ±25°，每个 ROI 至少 95% 在有效区域 |
| 重采样／短间隔上限 | 20 Hz／100 ms；实际样本不足不能靠插值伪造信息 |
| POS／滤波启动排除 | 1.6 秒／推荐 2 秒，明确记录额外延迟和有效范围 |
| 带通／HR 窗口与步长 | 0.75–3 Hz（45–180 bpm 搜索范围）／12 秒、1 秒 |
| 质量门槛 | 上述频谱比 3 dB；边界峰、数值退化等原因独立记录 |
| 逐搏初步心率 | 至少三可信峰、两个一致间隔；突出度、不应期、间隔范围、一致性及失效期限集中记录，须经合成边界与真实输入验证 |
| 展示批次／缓存 | 200 ms／15 秒，约 20 Hz 标量数据 |

所有时间使用原生时钟管理。观察期先连续就绪再开始 RGB 正式窗口，不回填就绪前帧。正式期短暂失效只暂停有效采样，超过插值范围或目标突变则新片段重新积累；总截止不顺延。

### 6. 同源双输出，不让 UI 的背压成为存储策略

处理器生成不可再修改的轻量记录，先向本会话完整结果队列提交，成功接受后交给独立实时分发。持久化复用一个会话级 `DataHub<RPPGRecord>`，区分 pulse 和 HR 两种记录，由同一消费者分写两份 CSV；写入不在相机回调上执行。容量包含消费中的批次，不创建无界协程。写入／容量失败使会话技术失败，已经展示的数据不代表磁盘已持久化。

展示流用独立有限缓冲，批次含 `sessionId, segmentIndex, sequence, startTimeMs, sampleIntervalMs, values`；每批不跨片段，不足整批也可按定时或停止发出。无订阅时不跨 JS。慢订阅可丢旧批，保持序号缺口让 UI 断线，不影响完整结果或算法状态。订阅期间不传图像、关键点或逐帧 RGB。

Dev `RPPGScreen` 与 `RPPGWaveform` 位于 `pages/dev/acquisition/`，复用主题和 SVG，不重做产品美术。页面所属环形缓存仅保留最近 15 秒，不入全局增长 Store；波形按采集时间滚动，纵轴缩放仅显示，不逐批归一化原始结果。状态、最新频谱 HR 和独立逐搏初步 HR 进低频 Nano Store；平均值只按有效频谱 HR 累加和计数，空时为空，不长期保存整条 HR 数组。逐搏缺值显示等待／信号不足，历史频谱值不得替代逐搏当前值。原生关键点如需叠加在原生预览侧完成，不为此开启 JS 帧流。

### 7. 三件套格式与可见发布

私有路径为 `acquisition/rppg/<sessionId>/`，由 `AcquisitionPaths` 集中维护，先写临时会话目录，关闭三份文件后同文件系统目录提升；查询只扫描最终目录且检查三件套及元信息完整标记，不能逐文件提升后提前列出。

- `pulse.csv`：UTF-8，`segmentIndex,sampleIndex,timeMs,value`；样本号会话内递增，时间相对首个正式观察帧的传感器原点，信号起点可以晚于 0。
- `hr.csv`：UTF-8，`segmentIndex,windowStartNs,windowEndNs,heartRateBpm,valid,reason,spectralSnrDb`；窗口边界取所用样本的首末采集时间，CSV 纳秒为十进制整数，无效值留空。有效行的 `reason` 为空。
- `session.json`：`schemaVersion, algorithmVersion, sessionId, source, sensorTimeOriginNs, startedAt, finishedAt, config, cameraSummary, termination, signalStatus, sampleCounts, segmentRanges`。`source` 为 active/passive；绝对纳秒为字符串；墙上时间只用于可读展示，不替代信号及超时单调时间。`termination` 区分 target_duration/user_stop/page_left/app_background/observation_timeout 等；`signalStatus` 区分有有效 HR、无有效 HR、未形成波形，技术失败另作命令／状态错误，不伪装为无信号。

只有收到正式观察帧才建立可发布结果的事实；文件初始化失败或首帧前相机失败返回结构化错误，不制造空成功会话。已开始但无脸时写 header-only CSV 和观察超时元信息。用户停止、页面离开等合法中断可完整发布并标注 interrupted，而非 target_duration。进程死亡、写入或发布失败遗留临时目录不列为完成产物，不自动删除既有完成结果。完成记录跨重开可查，默认查询按来源过滤但内部格式统一。

收尾顺序：拒绝新正式帧→使旧代次失效→解绑本次源并等待已交付帧退出→输出已经可定稿的记录→排空完整队列→关闭文件并写最终元信息→发布／报告失败→关闭模型并释放本次租约。释放错误不假装成功；重复停止共享屏障，不能释放其他会话的租约。

### 8. 验证与后续接入边界

永久回归覆盖非连续像素与坐标变换、同帧借用释放、短／长缺口、POS 数值退化／定稿不回写、因果滤波重置、已知频率窗口估计及拒绝、发布失败／中断、队列容量、旧回调和展示断线；不为源码文字、转发或默认值写断言。

逐搏回归覆盖已知频率下的 RR 与 bpm、三个峰前不出值、平线／低突出度、不应期和重复峰、异常间隔后的重新确认、无心搏超时、片段／有效区间切换及停止清空；时间断言使用采集时间，不以测试运行速度当首结果时延。本次不要求专门的端到端时延与参考对照验收；已有模拟器、合成波形和素材播放记录只证明各自覆盖的行为，不外推人体准确性。

使用 `docs/development/android-development.md` 中已经下载的 MCD 单样本。先确认模拟器实际播放、方向、时间戳和真实帧，必要转码只修输入并记录影响；不降低质量门槛换取数字。运行 Dev 全流程，观察波形、停止和读回三件套，抽取同批样本与 UI 输入一致；验证无脸、丢脸、早停、重入和导航释放，再检查原始 PPG 及现有被动录像未改变。

模拟器完成后通知用户进行主动真机测试，列出取色、性能和心率对照尚未验收项。正式精度对照必须先解决原视频／模拟器播放／参考 PPG 的时间映射，不能直接将模拟器经过时间匹配源文件。后续被动提案只有在这个主动闭环完成后实施，不让第一阶段以“共用基础已搭好”提前结束。

## Risks / Trade-offs

- [模型与颜色转换增加延迟、丢帧或发热] → 固定版本、官方资产许可和哈希可追溯；复用必要转换缓冲，记录实际 FPS／间隔，不能承诺零拷贝或目标吞吐。
- [公开模型许可或分发条款不清] → 接入前核实官方模型资产的许可和归属，与依赖源码许可区分；无授权资产不复制，未解决时如实阻断该接入而不以假模型替代。
- [单目标模式不能可靠排除多人切换] → 连续性不明则重置，文档注明边界，不宣称身份跟踪或多人可靠性。
- [自动曝光／AWB、运动或压缩产生强周期伪影] → 保留实际配置与质量原因，拒绝明显退化，模拟器过关不代表生理准确；不把频谱比当医学信心。
- [严格缺口上限使慢设备频繁重置] → 在试验评审和实测中调整配置并记录版本，不静默放宽或插值长缺口。
- [定稿、滤波启动和 HR 窗口叠加首次出值延迟] → UI 区分波形积累与有效心率，元信息记录延迟，不回填或伪造即时结果。
- [逐搏早期峰被运动、光照或谐波误导] → 先做峰和间隔质量确认，界面明确“初步”，与频谱独立展示，不以高频输出或凑足 6–10 秒代替正确性；功能验证不能作为人体准确性证明。
- [UI 已展示而后续磁盘写入失败] → 展示标为实时观察，最终产物成功以关闭和发布为准，状态明确失败。

## Migration Plan

先迁移共用设备／像素代码并保持旧调用语义，再接入完整原生 RPPG、文件和桥接，最后接入 Dev 页面及验证。第一阶段不修改被动配置或把被动服务切到新内核。后续实现同步更新 `docs/architecture/code-organization.md` 的旧“仅录像”边界说明（明确第二阶段尚未接入）、新增 RPPG 采集契约及更新 Android 测试记录；不把计划标为已完成。

回退只撤销新增入口、绑定和本阶段实现提交，保留用户完成产物及旧视频，不引入运行时旧／新算法开关。提案评审通过和用户明确要求 apply 前，不改应用代码；试验参数的评审状态不得被创建提案或 CLI 校验通过代替。

## Open Questions

- 目标真机的实际持续 FPS、内存／发热、颜色解释和单目标连续性表现，由后续运行证据补充，不影响本地输出与资源边界。
- 上述试验数值是否需按样本或真机调整，随配置版本评审记录；不能因此删除失败语义、缩小完整流程或改变同源定稿契约。
