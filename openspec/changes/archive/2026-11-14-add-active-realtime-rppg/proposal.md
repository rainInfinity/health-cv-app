# Proposal

## Why

现有主动相机链路仅输出固定网格 YUV 统计和相机元数据，尚不能在设备上实时估计面部脉搏；被动录像后处理也不能承担主动式实时展示。先完成可由页面操作、可实际绘制脉搏波并交付本地结果的主动闭环，再由独立提案接入被动触发，避免同时改动两套生命周期。

## What Changes

- 在现有 `packages/acquisition` 内新增共用 Android RPPG 内核：前摄帧、人脸定位、额头与双颊 ROI RGB、POS、因果滤波、脉搏波和窗口心率；类、类型和组件统一使用 `RPPG` 前缀，目录使用 `rppg/`。
- 在保留 1.6 秒 POS、2 秒滤波启动排除和 12 秒频谱窗口的基础上，增加同源波形的逐搏瞬时心率；至少三个可信峰形成两个一致搏间间隔后输出最新间隔对应的初步 bpm，质量不足、切段或超时清空，不沿用旧值。
- 将设备相机与像素读取能力从原始 PPG 专属路径抽为共用能力，不复制相机源，不把原始网格统计作为 RPPG 的前置计算；保留旧 PPG 配置、锁确认及双 CSV 行为。
- 完成主动预览、显式开始、有限找脸、正式计时、到时结束、手动停止、页面离开及异常收尾；资源及算法状态由原生会话管理，不由 UI 定时器管理。
- 在 Dev 导航下新增主动 RPPG 验证页，展示真实预览、引导、脉搏波、独立的逐搏初步心率、最新频谱心率与有效频谱读数平均值，不接入正式产品测量入口。
- 原生同时产生完整持久化结果和独立有界展示流；UI 与文件使用同一份定稿信号，波形为任意幅值单位，不等同于心率曲线或真实血流量。
- 每次已实际启动的会话输出 `session.json`、`pulse.csv`、`hr.csv`；区分目标完成、中断、无有效心率及写入失败，不补造样本或成功结果。
- 先用已经下载的一个 MCD-rPPG 样本完成模拟器闭环，必要时才补第二个；模拟器完成后通知用户进行真机测试，分开记录功能可用性和真实信号／精度证据。
- 以用户点击开始至首个合格逐搏结果 6–10 秒为体验目标，不作为本次验收门槛；本次不包含专门的首结果时延、参考对照、误差和错误接受率验收。该目标不是所有输入的出值保证，不降低质量门槛凑数，不将未验证的准确性宣称为已通过。
- `android-rppg` 的逐搏结果通过独立低频快照字段输出，包含片段、前后峰采集时间、搏间间隔和 bpm；不混入频谱平均或最终频谱有效结论，不新增逐搏 CSV，不改变既有三件套 schema。
- 本次不改变现有被动录像的执行路径、触发策略或产物，不删除录像及已有相关代码，不引入后端、认证、上传、task API、WebSocket 或数据集级评测。

## Capabilities

### New Capabilities

- `android-rppg`：原生实时面部脉搏处理、主动会话、Dev 实时展示、结果产物与分阶段验证；内核不依赖页面，可由后续被动会话复用。

### Modified Capabilities

- `native-acquisition`：为新 RPPG 增加独立、受控的定稿标量波形展示通道；原始 PPG、像素、相机元数据和文件记录批次仍不得进入 JS。

## Impact

涉及采集包的共用 `camera/`、`pixels/` 和新增 `rppg/{model,face,roi,signal,session,output,realtime,runtime}`，以及 Nitro 绑定、`RPPGClient`、可选预览接入和应用 Dev 页面／导航离页守卫。引入固定版本的 MediaPipe Tasks Vision 与经许可核实的官方模型资产；不使用来源不明的第三方模型文件。绘图复用已有 `react-native-svg` 和主题，不新增图表框架。

后续实现同步更新 `docs/architecture/code-organization.md`、相关采集／开发说明及依赖许可记录。本文只创建规划；推荐采样、窗口及人脸阈值在设计中标为待评审的工程试验基线，不宣称经过验证，也不因提案生成而授权实现。

执行顺序：本提案先完成主动式端到端实现与模拟器验收，再实施 `add-passive-realtime-rppg`。真机测试由模拟器闭环完成后的明确通知交接；真机项目未验证时保留未验收状态。
