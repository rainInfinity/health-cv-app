# Spec Delta

## Purpose

提供 Android 端可独立于云端运行的实时面部脉搏采集、频谱窗口心率估计、逐搏初步心率、受控实时展示与本地结果交付。主动 Dev 页面完成端到端流程，处理内核不依赖页面和展示订阅，为后续被动接入提供同一套信号与产物语义；工程处理成功不等同于医学有效。

## ADDED Requirements

### Requirement: 主动入口仅在用户操作后使用前摄
系统 MUST 在 Dev 导航提供独立主动 RPPG 入口，不要求登录或后端配置。进入页面或创建客户端 MUST NOT 自动打开相机；显式打开时使用前摄和原生预览，权限拒绝、前摄缺失、配置不兼容或相机忙 MUST 如实反馈，不换镜头、不抢占已有会话。

#### Scenario: 无云端进入页面
- **WHEN** 未登录且未配置服务地址的用户进入主动 RPPG 页
- **THEN** 页面提供显式操作入口，不发网络请求、不打开相机或创建测量产物

#### Scenario: 请求前摄但设备不可用
- **WHEN** 用户打开前摄而权限、设备或相机占用条件不满足
- **THEN** 页面显示可判别原因，不报告预览成功，不影响已有相机会话

### Requirement: 预览与正式会话有明确边界
系统 MUST 将预览与用户显式开始的 RPPG 会话分开；预览帧不进入正式波形及心率文件。正式会话 MUST 先执行有界人脸观察，满足连续就绪条件后才建立测量窗口并按原生单调时钟计时。重复开始及收尾中开始 MUST 被拒绝。

#### Scenario: 只打开预览
- **WHEN** 用户打开预览但未点击开始
- **THEN** 可观察画面和就绪提示，但不产生正式测量波形或结果文件

#### Scenario: 人脸稍后出镜
- **WHEN** 用户开始后，人脸在观察超时前连续满足就绪条件
- **THEN** 从条件满足后开始正式测量，不回填之前的观察帧，不把找脸耗时计入目标测量时长

#### Scenario: 无脸观察超时
- **WHEN** 已收到相机帧但观察时间内没有满足条件的人脸
- **THEN** 结束本次会话并释放本次相机资源，以无结果原因发布完整收尾的三份文件，不伪造心率

### Requirement: 面部区域由同帧几何与有效像素确定
每个纳入信号的样本 MUST 使用相同相机帧的人脸定位及面部 ROI 像素，处理实际裁剪、旋转、缩放和镜像映射；不得在图像释放后读像素。就绪条件 MUST 包含连续性、大小、姿态和 ROI 有效范围。目标无法连续关联或 ROI 无效时不生成有效颜色样本，不进行身份识别。

#### Scenario: 前摄镜像预览
- **WHEN** 显示画面存在旋转、镜像或非零裁剪
- **THEN** ROI 仍映射到正确原始像素，取色不读取填充区或已释放内存

#### Scenario: 人脸目标突变
- **WHEN** 人脸位置或形状变化导致目标连续性无法确定
- **THEN** 不将新旧目标的颜色拼为同一连续片段，重新评估就绪

### Requirement: 算法使用采集时间且不跨长缺口补造信号
RGB 与脉搏波 MUST 依据相机采集时间而非回调到达时间。系统 MUST 记录实际采样与请求参数的差异；只按配置允许的短间隔重采样，长缺口、无效 ROI 或时间异常形成片段边界。新片段 MUST 重置相关算法状态，心率窗口不得跨片段。

#### Scenario: 推理导致分析丢帧
- **WHEN** 实际帧间隔不均匀且与目标 FPS 不同
- **THEN** 按真实时间轴处理并记录采样事实，不以目标 FPS 推导虚假的均匀采集时间

#### Scenario: 长时间离开画面
- **WHEN** 两个有效样本间的缺口超出允许插值范围
- **THEN** 波形断开并开启新片段，不补零、不跨缺口延续滤波或心率窗口

### Requirement: 波形输出定稿且具有明确延迟
系统 MUST 从面部 RGB 生成经实时处理和带通滤波的 RPPG 脉搏波，输出其采样时间、片段及任意单位幅值。只发布不再被未来窗口修改的样本，MUST 明确算法延迟和启动有效区间；结束时不通过虚构未来数据生成尾部波形。不得使用播放动画或固定正弦替代真实算法结果。

#### Scenario: POS 窗口继续推进
- **WHEN** 后续帧使处理窗口重叠
- **THEN** 已发送给 UI 和写入结果的波形数值及时间不被回写或重复输出

#### Scenario: 停止发生在窗口中途
- **WHEN** 当前尾部缺少定稿所需上下文
- **THEN** 仅保存可定稿样本，并在会话中记录实际信号范围，不填充未来数据或复制尾值

### Requirement: 心率是带质量语义的窗口估计
频谱心率序列 MUST 标明所属片段、估计窗口和 bpm 值，窗口完整且通过质量规则才为有效频谱读数。数据不足、运算退化、采样不合格或频谱质量不足 MUST 给出稳定原因，数值为空而非零；不得用上一次有效值冒充当前结果，不输出未经校准的置信度百分比。独立逐搏初步值不替代频谱窗口，也不参与有效频谱平均。

#### Scenario: 有波形但心率窗口不足
- **WHEN** 已形成脉搏波但尚无完整合格的心率窗口
- **THEN** 频谱位置显示积累或不足状态，保留波形；只有独立逐搏规则已通过时，逐搏位置才可显示标为初步的读数

#### Scenario: 心率被质量规则拒绝
- **WHEN** 完整窗口未达到当前工程质量条件
- **THEN** 该窗口记录无效原因和可计算的质量指标，心率值留空，不参与有效平均值

### Requirement: 逐搏初步心率与频谱结果独立
系统 MUST 保留 1.6 秒 POS、现有滤波启动排除和频谱窗口行为，从相同定稿有效滤波波形独立估计逐搏心率。至少三个可信峰形成两个一致搏间间隔后才可首次输出最新间隔对应的 bpm；峰突出度、不应期、间隔范围、一致性和超时阈值 MUST 集中版本化。逐搏结果 MUST 标明片段、前后峰的采集时间及间隔，纳秒跨 JS 使用十进制字符串，不以结果发布时间计算 RR。

#### Scenario: 尚未形成两个可信间隔
- **WHEN** 仅有两个峰，或峰／间隔未通过质量检查
- **THEN** 当前逐搏值为空，显示积累或信号不足，不输出零值、固定值或旧值

#### Scenario: 先于频谱形成逐搏结果
- **WHEN** 同片段已有三个可信峰及两个一致间隔，但频谱窗尚未积满
- **THEN** 可独立显示逐搏初步心率，频谱仍显示积累；逐搏值不进入频谱平均，不据此将最终频谱信号结论标为有效

#### Scenario: 无效片段或心搏过期
- **WHEN** ROI 无效、片段或有效区间改变、样本／时间不连续、心搏超过配置期限或会话停止
- **THEN** 清空当前逐搏值与相应峰历史，后续重新确认，不跨边界配对峰或沿用旧值

### Requirement: 首结果时延可验证且不以速度替代质量
点击开始至首个合格逐搏结果 6–10 秒是体验目标，不作为本次验收门槛；本次不包含专门的分阶段耗时、参考对照、误差和错误接受率验收。系统 MUST NOT 将该目标解释为所有输入必然出值或医学准确性保证，不得通过回填观察帧、放宽质量规则或改变计时起点伪造达标。

#### Scenario: 质量不足导致首结果超时
- **WHEN** 点击开始 10 秒后仍未形成合格逐搏结果
- **THEN** 如实显示积累或信号不足，不强制生成 bpm

#### Scenario: 逐搏值已实时显示
- **WHEN** 后续会话完整收尾或应用重开
- **THEN** 既有三件套格式保持不变，hr.csv 仍仅保存频谱窗口；不将未持久化的逐搏实时序列宣称为可查询历史结果


### Requirement: 实时脉搏波与保存结果同源
系统 MUST 提供独立于文件批次的有界实时脉搏波订阅，包含会话、片段、批次序号及样本采集时间。订阅获得的样本 MUST 与本地波形对应样本的值及时间一致；展示缩放不修改结果。未订阅时不进行无用 JS 分发，不停止算法或文件输出。

#### Scenario: UI 订阅实时波形
- **WHEN** 有新定稿样本且存在订阅者
- **THEN** UI 按有界批次收到同源波形，无需反复读取结果文件或等待磁盘刷新

#### Scenario: 页面消费较慢
- **WHEN** 展示缓冲耗尽或出现批次序号缺口
- **THEN** 允许丢弃旧展示批次并断线，不拖慢完整结果写入、不无限积压或补造中间点

### Requirement: Dev 页面正确展示波形与测量状态
Dev 页面 MUST 展示真实原生预览、操作引导、找脸／积累／测量状态、目标进度、脉搏波、独立的逐搏初步心率与频谱窗口有效性和心率，平均值仅按本会话有效频谱心率点算术平均。逐搏缺值不得以旧值冒充；波形缓存 MUST 有界且不作为全量结果 Store，曲线遇片段或数据缺口断开，状态不能仅靠颜色表达。

#### Scenario: 脉搏波开始输出
- **WHEN** 波形已可定稿但首个心率估计尚未就绪
- **THEN** 曲线正常绘制，心率位置显示积累状态而非虚假 bpm

#### Scenario: 展示上一次有效值
- **WHEN** 当前窗口无效但 UI 仍显示先前有效读数
- **THEN** 明确标注其为上次有效结果，不更新为当前心率，不重复计入平均值

### Requirement: 会话形成三份可解释本地产物
每个已实际收到正式会话相机帧且文件系统正常的会话 MUST 输出独立私有目录中的 `session.json`、`pulse.csv`、`hr.csv`，分别保存元信息、完整定稿波形及心率窗口。无脸、无有效心率或合法中断也 MUST 保留可解释结论，空序列使用表头文件；默认不新增视频、图像、关键点或逐帧 RGB 文件，不发网络请求。

#### Scenario: 正常完成一次测量
- **WHEN** 达到目标测量时长且全部结果正常收尾
- **THEN** 三份文件可读取且会话记录实际范围、目标完成与信号结论，不以文件存在推断心率有效

#### Scenario: 观察超时或全程无有效心率
- **WHEN** 会话已有相机帧但没有可接受心率
- **THEN** 仍有元信息及两份 CSV，空序列只有表头，无效原因可追溯，不补占位行

### Requirement: 结果格式与时间精度稳定
`pulse.csv` MUST 使用 `segmentIndex,sampleIndex,timeMs,value`，`hr.csv` MUST 使用 `segmentIndex,windowStartNs,windowEndNs,heartRateBpm,valid,reason,spectralSnrDb`。波形时间相对会话采集原点；心率窗口保留原始传感器纳秒时间。元信息 MUST 包含格式与算法版本、来源、原点、配置、实际相机信息和结束原因；JSON 中绝对纳秒时间使用十进制字符串。

#### Scenario: 使用结果还原时间轴
- **WHEN** 读取元信息、波形及心率文件
- **THEN** 能通过原点还原对应时间范围，区分片段、采集时间和结果发布时间，JS 不因大整数丢失纳秒精度

#### Scenario: 无效心率落盘
- **WHEN** 某个窗口被拒绝且部分质量指标无法计算
- **THEN** CSV 对应数值字段留空并保存原因，不写 NaN、Infinity 或零心率冒充测量值

### Requirement: 结果写入完整有界且发布可见性一致
结果存储 MUST 有界、顺序、至多一次接收定稿记录，文件 I/O 不阻塞相机生产回调。容量不足、处理或写入失败 MUST 阻止完整产物发布；停止须等待在途处理、已接收尾批、文件关闭及元信息完成。只有三份文件全部完整时才可查询为完成产物，应用重开后仍可查到，不覆盖或隐式删除既有文件。

#### Scenario: 写入缓慢导致容量耗尽
- **WHEN** 尚未完成消费的记录达到容量上限
- **THEN** 当前会话报告存储失败并收尾，不静默丢失结果后仍报告成功

#### Scenario: 发布期间应用退出
- **WHEN** 文件尚未完成发布时进程终止
- **THEN** 重开后未完成文件或目录不被当作完整三件套列出，之前完成的会话仍可查询

### Requirement: 主动停止与导航等待真实资源收尾
到时、用户停止、页面离开或宿主后台 MUST 结束主动会话；返回、Tab 切换及深链跳转须等待相机和结果收尾，失败保留可见错误及重试入口。合法中断已接收的数据在正常收尾后可发布为中断产物，但不得标为达到目标。旧回调不得重启会话或写入新会话，资源释放不删除完成产物。

#### Scenario: 测量中离开页面
- **WHEN** 用户返回、切换 Tab 或跳转到其他页面
- **THEN** 等待本次关闭和三件套收尾，成功后离开；关闭失败不宣称资源已释放，也不自动启动另一个相机

#### Scenario: 停止后旧回调到达
- **WHEN** 新会话已经建立而旧帧、状态或结果回调迟到
- **THEN** 旧结果不进入新算法、文件、UI 或相机租约，不改变新会话状态

### Requirement: 共用内核不改变既有采集行为
RPPG 处理 MUST 独立于页面及 UI 订阅，引入主动 RPPG MUST NOT 自行切换被动服务的执行路径或触发规则。原始 PPG 的相机查询、显式参数、锁确认、网格、双 CSV 和文件保留 MUST 保持；所有相机会话互斥，不通过全局关闭误停其他采集源。被动实时接入遵循独立规格，不得通过共用算法隐式启用。

#### Scenario: 新 RPPG 与现有采集竞争
- **WHEN** 旧 PPG 或被动录像已占用相机而用户请求 RPPG
- **THEN** 请求明确忙状态，不抢占、不清空已有会话；结束 RPPG 不关闭独立传感器或被动等待

### Requirement: 验收先证明模拟器闭环再交接真机
开发 MUST 先用已下载的一个人脸样本在模拟器实际运行主动流程并检查 UI 和三份文件，必要时才补第二个样本。模拟器闭环完成后 MUST 明确通知用户进行真机测试，注明尚未验证的真实曝光、色彩、性能及心率准确性；素材解码、相机重采样和参考信号时间对齐须有实际证据，不使用合成成功结果替代。

#### Scenario: 模拟器主动闭环完成
- **WHEN** 实际前摄输入、操作、波形展示、停止和文件内容均已检查
- **THEN** 记录素材、环境、实际处理事实和未验证项，并通知用户真机测试；不宣称设备精度或后台可行性通过

#### Scenario: 素材无法播放或无有效信号
- **WHEN** 模拟器不支持素材编码或处理结果不满足质量条件
- **THEN** 记录具体失败与可验证的转码或输入修正，不跳过人脸／算法、不放宽门槛伪造验收
