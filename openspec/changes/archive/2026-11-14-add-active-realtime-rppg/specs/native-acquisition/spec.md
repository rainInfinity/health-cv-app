# Spec Delta

## MODIFIED Requirements

### Requirement: JS 只接收控制结果和低频信息
原始 PPG 采集接口 MUST 只向 JS 提供相机／处理能力、配置查询和应用结果、运行状态、锁定状态、经验提示、结构化错误和完成会话文件引用等低频信息，MUST NOT 传递原始像素、单块／单帧 PPG 记录、逐帧相机元数据、文件记录批次或共享像素缓冲区。预览 MUST 使用原生视图，不以 JS 图像流实现；结果确认在原生进行。新 RPPG 唯一的波形例外 MUST 是遵循 `android-rppg` 的独立、有界、可解除订阅的定稿标量展示批次，不放开原始采集记录或以业务 Store 累积全量信号。逐搏心率 MUST 作为独立、可空的低频结果提供，保留片段与峰采集时间，不复用频谱窗口字段或跨桥发送逐帧峰检测状态。

#### Scenario: 采集持续运行
- **WHEN** 相机连续交付图像并保存多块 PPG 与相机元数据
- **THEN** JS 只观察低频状态和必要提示，不接收逐块／逐帧记录或不断增长的样本数组

#### Scenario: 主动 RPPG 展示定稿波形
- **WHEN** 新 RPPG 会话存在 UI 波形订阅
- **THEN** JS 仅收到带会话、片段、序号和采集时间的有界标量波形批次及低频结果，不收到像素、逐帧 RGB、关键点或相机元数据；展示缓冲不承担完整结果存储

#### Scenario: 新逐搏结果或结果失效
- **WHEN** 原生确认新的合格搏间间隔，或当前逐搏结果因切段、超时或停止失效
- **THEN** 低频快照分别更新或清空 latestInstantHeartRate，原频谱 latestHeartRate 字段与平均语义保持独立；无效期不重复发送旧值冒充当前结果
