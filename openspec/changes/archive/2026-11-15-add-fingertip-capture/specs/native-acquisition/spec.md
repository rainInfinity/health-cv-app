# Spec Delta

## MODIFIED Requirements

### Requirement: Android 采集入口独立于云端与认证
应用 MUST 提供可手动操作的 Android 主动相机采集入口，默认选择后摄，并允许用户显式选择采集链路支持的单个前摄或后摄；不要求登录、云端环境变量或成功的网络请求。创建采集客户端、仅渲染界面、枚举或查询能力 MUST NOT 自动打开相机或开始保存数据。产品指尖页可承接用户明确进入本轮检测的动作执行授权及预览准备，但正式保存 MUST 等待本轮真实覆盖稳定就绪，不得将页面挂载本身视作采集命令。

#### Scenario: 无云端配置进入采集界面
- **WHEN** 应用没有配置服务地址和渠道且用户尚未登录
- **THEN** 用户仍能进入独立采集界面并手动查询、配置和请求打开相机，采集路径不要求先执行云端请求；用户明确发起产品指尖本地检测也不依赖云端

### Requirement: JS 只接收控制结果和低频信息
原始 PPG 采集接口 MUST 只向 JS 提供能力、配置、状态、锁定、经验提示、覆盖估计、错误和完成文件等低频信息；MUST NOT 传递原始像素、逐帧 PPG 行、相机元数据、文件记录批次或共享像素缓冲区，预览使用原生视图。波形例外仅限独立、有界、可解除订阅的定稿展示脉搏标量：RPPG 遵循 `android-rppg`，指尖遵循本规格的同轮真实样本及批次隔离要求；不得因此放开原始采集记录或在全局业务 Store 累积全量信号。逐搏心率仍为独立、可空的低频结果，保留片段与峰采集时间，不复用频谱窗口字段或跨桥发送逐帧峰检测状态。

#### Scenario: 采集持续运行
- **WHEN** 相机连续交付图像并保存多块 PPG 与相机元数据
- **THEN** JS 只观察低频状态和必要提示，不接收逐块／逐帧原始记录；独立手动采集不因新增指尖展示协议而自动推送波形

#### Scenario: 主动 RPPG 展示定稿波形
- **WHEN** 新 RPPG 会话存在 UI 波形订阅
- **THEN** JS 仅收到带会话、片段、序号和采集时间的有界标量波形批次及低频结果，不收到像素、逐帧 RGB、关键点或相机元数据；展示缓冲不承担完整结果存储

#### Scenario: 新逐搏结果或结果失效
- **WHEN** 原生确认新的合格搏间间隔，或当前逐搏结果因切段、超时或停止失效
- **THEN** 低频快照分别更新或清空 latestInstantHeartRate，原频谱 latestHeartRate 字段与平均语义保持独立；无效期不重复发送旧值冒充当前结果

#### Scenario: 指尖展示真实脉搏
- **WHEN** 正式指尖轮次存在展示订阅且原生形成有效脉搏样本
- **THEN** 只推送该轮有界脉搏批次，保留真实采集时间、片段及序号，不发送原始 PPG 行、不套用面部会话或生成健康指标

## ADDED Requirements

### Requirement: 指尖覆盖估计保留空间比例及未知语义
系统 MUST 从真实后摄像素对与取景一致的有效区域进行空间覆盖估计，区分未评估、未覆盖、部分覆盖及完整覆盖，并提供可空的 0–100 覆盖估计百分比。比例 MUST 来源于有效区域的空间判定，不是等待进度、置信度或旧经验提示布尔值；无有效输入不得报告完整覆盖。该值不得描述为精确物理面积或医学质量评分。

#### Scenario: 部分覆盖持续不变
- **WHEN** 用户只覆盖部分取景区域并保持该位置
- **THEN** 覆盖估计反映当前真实区域，不随等待时间自动填满，也不因旧经验提示未触发而显示 100%

#### Scenario: 覆盖尚未评估
- **WHEN** 后摄尚无可用于空间判定的有效图像
- **THEN** 覆盖值为空且不就绪，不以 0、100 或上轮估计替代未知

### Requirement: 覆盖稳定就绪仅开启一次正式指尖采集
指尖轮次 MUST 先观测覆盖，在真实完整覆盖连续保持至少 3 秒且输入新鲜、预览及必要锁定准备完成后，才自动开启一次正式采集；等待、抖动和准备期不得计入正式时长或写入正式文件。稳定就绪 MUST 由原生依据真实图像与单调时间判断，不依赖 UI 动画、JS 通知或请求 FPS；中途非完整覆盖、输入失效、时间回退或超过 200 ms 的帧缺口 MUST 清除稳定累计。达到三秒门槛不等于已正式开始，必要锁定及 writer 准备完成后仍须检查就绪。独立手动 PPG MUST 保留原有手动开始及经验提示不阻断的行为。

#### Scenario: 短暂满覆盖后移开
- **WHEN** 图像曾达到完整覆盖，但连续保持不足 3 秒，或在正式开始前已移开手指
- **THEN** 保持或返回覆盖观测，不开启正式窗口、不用旧就绪值触发保存；恢复完整覆盖后重新累计三秒

#### Scenario: 稳定覆盖自动开始
- **WHEN** 当前轮次真实完整覆盖连续保持至少 3 秒、输入新鲜且所有正式开始条件已就绪
- **THEN** 原生只开启一次正式窗口，重复就绪通知不创建第二会话，UI 由真实开始状态切换至检测中

### Requirement: 指尖原生窗口与计时拥有同一依据
正式指尖采集 MUST 以原生单调窗口定义目标、截止及已用／剩余时间，默认目标三十秒。入口检查上下界，到时停止接收并等待在途帧、元数据、队列及文件；不得依赖 JS 定时器、订阅或动画决定截止。覆盖观测、授权、准备和收尾耗时 MUST 不计入正式窗口。控制窗口与相机原始采样时间 MUST 分别保留，不能冒充同一时钟事实。

#### Scenario: JS 未及时消费计时
- **WHEN** 正式窗口达到目标而页面尚未处理最新通知
- **THEN** 原生仍封闭本轮入口并开始收尾，页面恢复后读取真实进度，不补采或延长窗口

#### Scenario: 用户提前结束
- **WHEN** 用户在目标前停止或通过返回结束本轮
- **THEN** 保留真实结束原因和实际时间，等待完整屏障，不显示采满目标或把实际剩余量强制改为零

### Requirement: 覆盖丢失结束当前轮次且不自动续采
正式采集中系统 MUST 持续检查覆盖新鲜度与维持条件，并将完整覆盖准入与本轮维持分开。准入要求完整覆盖连续 3 秒且帧间隔不超过 200 ms；采集中有效覆盖比例不低于 95% 可维持本轮，不能因此把实际百分比或部分覆盖分类改为完整。连续低于维持门槛或未知达到 1.5 s，或连续 1.5 s 无新帧，MUST 中断本轮、停止正式入口并释放相机与补光；短暂失效不得立即终止，但不得暂停计时或补足目标。失效区间不生成展示脉搏，超过 200 ms 的真实信号缺口仍断段；参数为固定工程起点，不表示医学质量。后台或销毁仍立即停止并保留真实原因；返回前台或重新放回手指 MUST NOT 自动恢复已结束轮次。

#### Scenario: 采集中移开手指
- **WHEN** 用户移开手指且达到覆盖丢失判定条件
- **THEN** 原生以覆盖丢失中断本轮并收尾，重新放回不会恢复旧倒计时，用户必须明确发起新轮

#### Scenario: 采集中小幅覆盖抖动
- **WHEN** 本轮已经正式开始，真实覆盖不是完整但仍不低于维持门槛
- **THEN** 不因完整覆盖布尔值变假而结束或反复重置展示脉搏，覆盖比例和分类仍呈现真实值，不冒充 100%

#### Scenario: 短暂低覆盖或采样停顿
- **WHEN** 低覆盖或无新帧尚未达到退出宽限后恢复
- **THEN** 本轮仍按原截止运行，失效样本不进入波形，真实采样缺口断线且重新建立滤波状态，不暂停或补时

#### Scenario: 持续无帧达到退出宽限
- **WHEN** 正式采集中持续没有新帧达到 1.5 s
- **THEN** 原生无需 JS 或后续图像触发即可中断收尾，不使用准入的 200 ms 门槛提前结束

#### Scenario: 等待覆盖或采集中进入后台
- **WHEN** 指尖仍在覆盖观测或正式采集时宿主进入后台
- **THEN** 本轮自动开始资格取消、资源释放且文件按实际情况收尾；返回前台只显示真实终态，不重开预览或续采

### Requirement: 指尖展示脉搏来自同轮真实样本
指尖展示脉搏 MUST 在原生由同轮正式接收、精确配对的 PPG 样本提取，经去直流及因果滤波后提供，保留真实采集时间。预览样本、滤波启动无效段、覆盖无效段及时间缺口 MUST NOT 用模拟、补零、插值或周期函数填充。处理不得改变原始 PPG／frame CSV 或输出健康指标，也不得把读取文件伪装为实时信号。

#### Scenario: 尚无稳定波形
- **WHEN** 正式采集刚开始、输入为常量，或滤波尚未形成可发布输出
- **THEN** 不输出虚构脉搏，页面保持真实空态，不因倒计时开始就展示预设波峰

#### Scenario: 信号时间不连续
- **WHEN** 输入时间回退、出现明显采集缺口或有效覆盖中断
- **THEN** 展示脉搏断段并重新建立滤波状态，不跨缺口连接或将后续点改写为连续采样

### Requirement: 指尖实时脉搏批次有界并独立于保存
指尖展示订阅 MUST 提供本轮标识、原始会话标识、片段、递增批次序号、各点相对采集时间及脉搏幅值，批次大小和订阅队列 MUST 有明确有限上限。慢订阅允许丢弃旧展示批，但缺口必须可识别，且不得反压原始记录和文件保存。订阅解除或 UI 隐藏 MUST NOT 停止采集、改变截止或清空原生文件；旧轮批次不得进入新轮。

#### Scenario: 页面暂不绘制波形
- **WHEN** 用户切到说明分页或展示消费者处理落后
- **THEN** 正式采集和文件保存继续，展示内存保持有界，恢复后不补造已漏批的历史

#### Scenario: 上轮波形迟到
- **WHEN** 新轮已经创建而旧轮批次到达
- **THEN** 按轮次丢弃该批，不恢复旧覆盖、计时或曲线

### Requirement: 指尖关闭只控制本轮所有资源
指尖命令 MUST 绑定调用方及确切轮次，遵守现有相机互斥，不接管或停止其他所有者。关闭 MUST 先阻断尚未执行的自动开始，再等待本轮在途命令、正式数据、双文件和相机释放；并发关闭共用屏障，失败保留可再关闭的真实错误。旧停止、截止及异步回调不得作用于后来轮次；独立传感器或被动服务不受本页关闭影响。

#### Scenario: 关闭与自动开始相遇
- **WHEN** 覆盖准备即将触发正式开始时调用方关闭本轮
- **THEN** 尚未发出的开始不再执行，已发出的命令及资源完整收尾后才报告关闭完成

#### Scenario: 外部客户端停止当前相机
- **WHEN** 非本轮所有者通过原有 PPG 停止或关闭入口请求改变当前指尖会话
- **THEN** 请求不能停止本轮或释放其租约，本轮仍由所有者或宿主生命周期收尾

### Requirement: 指尖完成事实区分文件与资源屏障
本轮结果 MUST 保留轮次及 PPG 会话身份、冻结配置、结束原因、目标／实际窗口、实际帧数、首末采样时间及两份原始文件引用。正常完成要求有数据、文件已定稿且本轮相机已释放；写入、关联或资源释放失败不得显示正常完成。提前结束及中断可保留已正常完成的文件，但不得冒充采满目标；离页、清空展示或失败 MUST NOT 隐式删除完成文件或选取旧产物。

#### Scenario: 文件完成但关闭失败
- **WHEN** 两份 CSV 已正常定稿但本轮相机关闭失败
- **THEN** 保留真实文件事实及关闭错误，不发布整体正常完成，允许再次关闭

#### Scenario: 截止后仍有尾批
- **WHEN** 原生窗口已结束但元数据关联、尾批或文件关闭尚未完成
- **THEN** 保持收尾且不启动下一轮，完成引用不指向临时或仍在写入的文件
