# Design

## Context

目标见 `proposal.md`。本次是现有原生指尖 UI 的数据接入，不是新建采集测试页。

- `FingertipMeasurementScreen` 使用 `fingertipDisplay.ts` 的 `ready / covering / running / completed`、模拟覆盖值和整轮模拟曲线；当前没有打开预览、手动开始、停止或重测的大按钮。重测通过返回后重新进入完成。
- `FingertipPreview` 用 SVG 绘制假画面与覆盖环；`FingertipPulseWave` 已通过 `PulseWaveHistory` 实现局部刷新、六秒回看和外层分页手势隔离。应替换数据源，不删除这些现有体验。
- `CoverageHintProcessor` 只有全帧亮度／颜色比例经验布尔值，不能提供空间覆盖比例或稳定就绪事实。`PixelStatisticsExtractor` 已在原生处理真实 YUV、裁剪、步长和分块，可在同一像素处理链增加有限的空间统计。
- 原始 PPG 已有配置冻结、锁确认、精确帧元数据配对、双 CSV、命令及关闭屏障，但没有覆盖门控、目标时长和实时指尖脉搏协议。
- 面部实时批次与因果滤波可参考其时间、缺口和背压规则，但现有实现依赖 `RPPGConfig`、POS 输入及面部会话，不能直接给指尖创建 RPPG 会话。
- 页面前置已归档，当前主规格是迁移基线。血压维持未接入；不改 `SensorRuntime`、传感器合同或被动服务。

## Goals / Non-Goals

**Goals:**

- 现有覆盖环、百分比、操作提示、自动开始、正式计时和脉搏波各有真实原生来源。
- 将覆盖观测、正式采集及完整收尾分开，采集控制不依赖页面定时器或动画。
- 保留已有指尖布局、分页、回看及返回路径，以最小应用适配接通真实源。

**Non-Goals:**

- 不实现血压 UI、ACC 或双源协调、measurement 包、云端、健康指标、语音和健康历史。
- 不声明临床质量、解剖学真实覆盖面积或适用于所有设备的识别准确率；本次必须实际验证基本手指覆盖与真实脉搏展示，而非仅证明 CSV 存在。
- 不添加工程参数表单、文件详情面板、模拟模式、跨轮波形回放、恢复数据库或自动清理。

## Decisions

### 1. 保留产品流程，由明确入口启动本轮准备

用户确认指尖引导、选择跳过后进入，或点击已有跳过偏好的指尖卡片，均属于本轮显式入口。页面有效且前台时申请相机权限，挂载真实 `CameraPreview`，同时取得 Nitro 引用和正尺寸布局后打开后摄，再启动本轮覆盖观测。构造客户端、仅挂载原生视图或订阅本身没有设备副作用。

选用真实枚举到的后摄，查询预览＋分析组合；偏好 720×720、30 FPS，原始保存固定 `[1,1]`。补光是可选辅助能力：能力明确支持时设 `torchEnabled=true`，不支持或未知时设为 `false`，继续真实预览、覆盖观测和满足条件后的正式采集，不单独阻断检测或放宽覆盖门控。曝光、白平衡和对焦沿用现有能力驱动默认构建与校验，不增加手动调参。后摄不支持时如实失败，不换前摄；通用采集显式配置校验不变，已请求开启但实际应用补光失败仍按真实错误处理，不自动重试。请求、提交及真实帧摘要仍由原合同记录。

不新增“打开预览／开始采集”的两次按钮。准备、稳定等待及正式开始由同一原生轮次驱动；现有返回是用户提前结束入口，完成后保留本轮曲线，返回重进开始新轮。拒权、设备忙等错误使用已有反馈弹窗提供必要重试／返回，重试重建本轮，不在原对象上恢复半轮采集。

替代方案：保留工程测试页两步按钮会改变已确认 UI；进入即开始保存则跳过真实覆盖判定，均不采用。

### 2. 覆盖百分比来自空间估计，稳定性独立判断

在 PPG 原生像素处理链增加指尖覆盖估计，不复用 `showCoveringTip` 的布尔值作为比例。算法使用真实有效图像，采样 ROI 与圆形预览采用同一归一化裁剪映射，不因预览布局尺寸变化改变判定范围。

- 用固定 16×16 空间网格的有效采样单元估计覆盖。仅统计 ROI 内实际可读像素，按有效面积加权；尊重原有 YUV 行步长、像素步长和裁剪，不复制整帧或跨桥传图。
- 各单元按 YUV 转换后的红色占优特征判定，并排除纯黑／全通道过曝等无判别输入。旧经验阈值只作实现起点，不能把“未触发旧提示”当作全覆盖。空间统计与 `[1,1]` CSV 网格相互独立，不改变原始文件内容。
- `coveragePercent` 表示本次图像采样得到的 ROI 覆盖估计，范围 0–100；未评估或输入失效为 `null`。UI 在未知时显示占位，不补成 0 或 100。100 仅在所有有效采样单元通过时出现，不是置信度、等待进度或医学质量分。
- `coverageReady` 与百分比独立：达到完整覆盖条件并连续保持 3 秒后才为真；采用原生单调时钟，不以帧数或动画完成代替持续时间。稳定等待不把非完整覆盖强行补满；中途不再完整覆盖则重新累计。三秒达到后仍须完成必要锁定及 writer 准备，不承诺从 UI 显示 100% 到正式开始恰好三秒。
- 同一轮观测中一旦输入失效、采集时间回退或出现超过 200 ms 的帧缺口，稳定累计清零；旧画面的 100% 不能在无新帧时触发开始。

低频快照提供覆盖值、未评估／未覆盖／部分覆盖／完整覆盖状态、稳定就绪及必要操作建议。正常最多每 250 ms 合并通知，关键阶段变化立即通知，原始采样及原生计时不降频。覆盖数字和环最多按该频率消费最新值，普通提示对应的覆盖分类稳定 300 ms 后才切换；正式开始、结束、错误和取消立即呈现。相机子树与覆盖／提示局部刷新隔离，不以每次完整快照触发整页更新或重建相机。未知仍为未知，防抖不生成完整覆盖或控制自动开始。

阈值必须以真实后摄＋补光的未覆盖、部分覆盖和完整覆盖输入校准，固定为可追溯的本地算法配置，不给产品添加阈值表单；不采用任意物品遮挡即视作手指的亮度单条件算法。不以本次基本验证承诺全机型准确率。

### 3. 原生拥有覆盖门控及三十秒正式窗口

在现有 `Acquisition` Nitro 对象和 `AcquisitionClient` 增加一套指尖会话入口，不另建相机 HybridObject 或通用协调器：

| 接口 | 语义 |
| --- | --- |
| `openCamera(config)` | 沿用现有预览准备，不写正式 CSV。 |
| `startFingertipCapture({ durationMillis })` | 在本调用方持有的真实预览上建立 `captureId` 并进入覆盖观测，返回启动确认；不等待三十秒，也不立刻开启正式窗口。 |
| `getFingertipSnapshot()`、`subscribeFingertip()` | 获取本轮阶段、覆盖、原生进度、结束原因、错误及本轮文件事实，不包含原始样本。 |
| `subscribeFingertipPulse()` | 独立订阅同轮有界脉搏标量批次，解除订阅不停止采集。 |
| `stopFingertipCapture(captureId)` | 提前结束指定轮次并等待其收尾；准备中也可取消，不误停新轮。 |
| `closeCamera()` | 先取消覆盖观测及尚未开始的动作，再等待本调用方已发命令、本轮数据和相机关闭。 |

原生阶段为 `observing / starting / capturing / stopping / completed / interrupted / failed`，未建立轮次时为空。展示只映射既有等待、调整／准备开始、检测中、已结束提示；收尾、失败及中断提供必要真实反馈，不新增诊断参数面板。

稳定就绪后只触发一次开始，完成必要相机锁确认和 writer 准备。准备完成再检查覆盖仍新鲜且就绪，才建立 `elapsedRealtimeNanos` 窗口 `[T0,T0+30s)`；准备时覆盖失效则撤销本次未开启的准备，返回同轮观测，不保存准备帧。关闭意图优先于自动开始，不能在返回或后台之后又打开正式窗口。

PPG 沿用处理入口单调时间判断上下界，Camera2 原始时间仍用于精确配对；不把控制时间冒充曝光时间。截止任务先封闭入口，再等待已入窗帧的元数据、尾批和双文件关闭，最终释放本轮相机／补光。即使 JS 没消费进度也按原生窗口结束。

`elapsedMillis / remainingMillis` 由原生求差得到。文件结果保留 `captureId`、PPG `sessionId`、冻结配置、目标／实际窗口、结束原因、实际帧数及首末采样时间。跨桥绝对纳秒使用十进制字符串，控制时间与相机时钟语义分开；不以旧起止字段推算采满时长。

原始手动 `startCapture / stopCapture` 仍不带覆盖门控或自动截止。覆盖经验提示不阻止该独立手动路径；新门控仅作用于明确启动的指尖轮次。

### 4. 采集中覆盖丢失结束本轮，不拼接两段采集

正式采集持续评估覆盖，与准入完整覆盖分开：已开始后，有效空间覆盖比例不低于 95% 可维持本轮和同帧脉搏输入，百分比与部分覆盖分类仍保留真实值，不能显示成 100%。低于维持门槛或未知的区间不生成展示脉搏；连续不满足维持条件达到 1.5 s，或持续 1.5 s 没有新帧，才以 `coverage_lost` 中断并收尾。恢复有效覆盖清除尚未确认的丢失累计，不能恢复已经终止的轮次；三十秒绝对窗口不暂停、不补时。准入须完整覆盖连续 3 秒且输入不超过 200 ms 陈旧；展示信号超过 200 ms 的真实采样缺口仍断段并重新启动，不因延长结束宽限而跨缺口连线。95% 与 1.5 s 为待真机校核的固定工程起点，不表示医学质量。图像异常、写入或关联失败按技术错误结束，不伪装成覆盖丢失。

中断不暂停倒计时后自动续采，不把移开前后拼成一轮三十秒。统一反馈说明重新放置并重新检测；用户返回重进，或在失败反馈中明确重试，才创建新轮。首次覆盖观测可以继续等待手指，不设置终止观测的超时；十五秒指导提示不结束或暂停本轮。

提前返回、后台和宿主销毁分别保留真实原因；覆盖观测期间同样必须释放相机和补光。后台恢复只读取终态，不再次触发授权、预览、覆盖观测或采集。

正常完成要求有正式数据、两份 CSV 已定稿且相机已释放。提前停止／覆盖中断可以保留已正常定稿的原始文件，但必须带真实原因，不显示采满三十秒。文件完成与资源释放失败分别保存，关闭失败可再关闭，历史错误不能冒充本次关闭失败。

### 5. 从真实 PPG 形成独立展示脉搏，不调用面部算法

展示算法在原生消费同轮已进入正式接收序列、通过精确元数据配对的 `[1,1]` 全帧 YUV 统计，按原始采集时间顺序处理，不读取文件装作实时流。选用由 YUV 派生、未截断的红色通道作为固定展示输入，经去直流、0.75–3 Hz 因果带通形成任意单位脉搏幅值；不计算峰值心率或其他健康指标。后摄补光条件下绿色通道可能接近颜色处理地板，不能以固定使用绿色替代真实输入校核；不逐帧切换颜色通道，不添加任意展示增益。

滤波按真实相邻采集时间计算系数，不假定请求的 30 FPS 就是实际频率，不为了批次等间隔而补帧。启动后的首个连续一秒只建立滤波状态，不向 UI 发布未稳定的输出；预览及覆盖等待的样本不填入正式历史。输入不有限、时间不递增、覆盖低于正式维持门槛或未知、缺口超过 200 ms 时断段、重置滤波并重新排除启动区间；常量信号不生成周期波形。

可将既有因果高通／低通的纯数学部分提取到实际共用位置，保持面部现有参数、结果和启动语义不变；若不能直接复用，则实现仅服务指尖的窄处理器，不复制整套 POS、人脸就绪、频谱或 RPPG 会话结构。真实后摄展示必须验证所选红色通道的脉动可见性，不能以正弦测试信号或通道存在变化就当作人体脉搏交付。启动按首个有效输入建立滤波初值，覆盖失效或时间缺口后重新建立；不以未经校准的峰谷对称性规则拒绝真实脉搏，也不承诺滤除所有真实运动或压力变化。

展示算法不改写 `ppg.csv / frame.csv` 的字段、YUV 均值或时间，不新增波形文件与跨进程回放承诺。原始文件存在但尚无可用展示波形时保持曲线空白，不制造样点、零值或伪造健康结论。

全帧 POS 仅作为离线候选对照：从同一录制素材逐像素 YUV 转换后统计全帧 RGB，保留呈现时间，交给既有重采样／POS 数学处理，并与当前红通道处理比较输入可用性、启动和输出。不能先从 YUV 均值转换并截断，再冒充逐像素 RGB 均值；不得仅因“去掉人脸 ROI”就替换产品算法。接触式补光下绿／蓝通道接近颜色处理地板时，归一化可能放大量化误差。离线比较不证明人体脉搏有效，不向产品增加算法切换、备用假波形或指标推理。

### 6. 指尖有界波形是显式的桥接例外

修改 `native-acquisition` 的低频约束，只允许新的指尖展示脉搏标量例外，原始像素、原始 PPG 行和相机逐帧元数据仍不跨桥。该协议与面部 RPPG 分开标识来源，不能拿面部会话 ID 代替指尖轮次。

每批包含 `captureId`、PPG `sessionId`、片段号、递增批次序号、各点相对本轮正式采集首帧的毫秒时间及脉搏幅值。使用显式时间数组，不套用面部等间隔批次字段；绝对相机纳秒不由 JS 相减。批次最多 64 点，正常每 50 ms 发布，终止前提交不足一批的真实尾部。

每订阅最多缓存四批，慢订阅丢弃旧展示批并通过序号缺口可见，不反压原始保存。原始数据流继续遵守已有的容量不足显式失败规则。解除订阅、页面切到说明页或 React 暂停绘制都不控制原生采集、截止与保存。

页面局部保留当前三十秒内实际收到的本轮展示历史，丢批、断段和时间缺口断线，不用文件或样例补造遗漏历史；绘图只取六秒窗口及边缘邻点。重测、离页释放历史，旧轮迟到批次不能恢复旧数据。

### 7. 在现有布局内替换数据，不增加测试控制台

| 现有区域 | 接入后的数据与行为 |
| --- | --- |
| 圆形镜头区域 | 真实原生预览，去掉模拟红色覆盖层，保留圆形构图、装饰与中央轻量提示。 |
| 覆盖环与百分比 | 消费原生覆盖估计；未知占位，未满不显示满覆盖，完整覆盖后的稳定等待由原生确认。 |
| 状态和倒计时 | 沿用当前布局；覆盖期间保持 `00:30`，正式窗口开始才倒数，到时为 `00:00`，中断保留真实剩余量。 |
| 说明／波形分页 | 保留说明图、连续横向分页、点击替代和开始时自动切至波形；切页不重置采集与回看。 |
| 脉搏波 | 复用既有 ECharts 原生 SVG、原生位移、六秒回看和回到最新；面部及指尖均只由正在查看的六秒可见窗口决定纵轴，窗口外历史极值、预绘区与外部邻点不扩展范围。回看绝对窗口不因新数据在窗口外产生极值而缩放；原始样本和缺口不变，保持 10%–85% 留白与左侧 14% 渐隐。空窗不生成波形，常量窗口使用有限非零显示范围。 |
| 完成与重进 | 完整收尾后显示既有完成提示，冻结本轮曲线和结束覆盖快照；相机已释放，不以冻结值宣称正在识别。返回重进清空旧值并重新准备。 |

原生所有脉搏波（指尖、面部及开发页）共用展示取负规则：`displayY = -rawY`。原始样本、页面历史、算法、心率及 CSV 不变；绘图层只翻转一次，纵轴以相同的显示极性计算，保留产品当前窗口及既有留白、缺口。

保留主题、品牌顶栏、全宽白色面板、提示浮层尺寸、圆角、操作图比例和分页手势。只调整真实状态所必需的中文文案，拒权、忙、覆盖丢失和关闭失败使用已有反馈宿主。不得把文件路径、采样参数或结果核查面板加入首屏。

镜头内提示使用半透明毛玻璃，约 72% 白色叠层、浅色边框，保持 14 dp 圆角、14／22 dp 文字和 600 字重、水平 16 dp／垂直 12 dp 内边距，最大宽度为镜头的 80%，最多两行且每行水平居中。`expo-blur` 的 `BlurTargetView` 仅包裹相机与装饰背景，文字放在模糊层之上；Android 使用 `dimezisBlurViewSdk31Plus`，后摄 PPG 预览使用 COMPATIBLE／TextureView，Android 12 及以上支持真实相机背景模糊，旧版保持半透明外观。不逐帧截图或跨桥处理图像，不改变面部预览模式。

### 8. 所有权、导航与权限按本轮交接

离页先取消权限之后尚未发出的动作和预览就绪等待，再等待已发命令、指定轮次和相机／文件屏障；不能等待一个只能由即将卸载的页面完成的布局 Promise。系统权限弹窗不能取消时，返回后检查页面仍有效且应用前台，关闭意图已生效就不得继续。授权弹窗造成短暂失活后，仍有效的显式入口可以继续准备，不恢复已终止轮次。

## Risks / Trade-offs

- [有限采样覆盖估计不是精确物理面积] → 明确比例语义与未知状态，用真实三种覆盖输入校准；不以旧布尔提示或固定动画冒充百分比。
- [真实信号弱或滤波启动期没有曲线] → 保持空白和真实时间，不填假波峰；以实际后摄脉搏展示验证本次功能，不宣称医学有效。
- [自动开始与离页／后台竞态] → 关闭意图优先，自动触发与在途命令绑定轮次，原生负责取消及收尾，页面不补发开始。
- [有界展示漏批影响回看完整性] → 显式序号及片段断线，不影响原始文件，不承诺读取文件修复本轮展示。
- [另一个编排提案仍依赖旧双源合同] → 本次只改已确认的当前提案；该提案采用新入口和覆盖门控前须独立修订，不能据旧名或血压假定开始实施。

## Migration Plan

1. 基于已归档页面变更及现行主规格，先增加指尖原生覆盖与脉搏处理，保留独立手动 PPG。
