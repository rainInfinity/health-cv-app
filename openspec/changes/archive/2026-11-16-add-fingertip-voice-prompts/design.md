# 指尖检测语音接入设计

## Context

动机和范围见 [proposal.md](proposal.md)。现有 `useFingertipMeasurement.ts` 在同轮 `onSnapshot` 中分别更新展示和放置提醒；`FingertipSnapshot` 已提供 `captureId`、阶段、覆盖百分比、剩余时间及资源释放事实。普通原生状态最多每 250 ms 合并通知，不能用剩余毫秒数恰好等于阈值来触发语音。

`useContactMeasurementSession.ts` 已管理明确入口、代次、前台资格、离页意图、关闭屏障和重试；血压也使用此会话，不能在共享层无条件播放指尖提示。现有十五秒放置指导有自己的真实观测计时和可见性回调，不应再建立语音专用十五秒计时。

应用使用 Expo SDK 57，尚无音频播放依赖。`app.json` 已禁止 `RECORD_AUDIO`；七个用户 MP3 已位于 `apps/native/assets/audio/fingertip/`。本设计需要新增播放依赖和跨越页面、调度及播放器的接入，因此保留独立 design 工件。

## Goals / Non-Goals

**Goals:**

- 由现有原生事实驱动单路播放，异步加载、抢占及取消均不能让旧轮提示复活。
- 调度规则可独立检查，播放器不参与相机准入、原生计时和页面完成判定。
- 用完整现有音频实现最后三秒提示，接受音频自然节奏和状态通知延迟，不建立精确逐秒同步机制。

**Non-Goals:**

- 不建立跨检测方式的语音业务框架、全局队列、跨轮缓存或新的 measurement 业务包。
- 不进行音频剪辑、逐字时间标注、在线合成、原生播放区间控制或采样级同步。
- 不修改声量、准备跳过偏好、现行布局、视觉状态或采集协议。

## Decisions

### 1. 将本地资源、播放适配和指尖规则分开

应用测量适配目录维护七个静态 `require()` 资源映射；指尖目录维护纯语音调度模块，`useFingertipMeasurement` 负责组装。播放适配隔离 `expo-audio`，只提供本次所需的播放、停止、完成通知与释放，不提前建设全局服务。控制器按真实快照而非防抖后的界面文字更新。

| 语义 | 现有文件 |
| --- | --- |
| 初始放置指导 | `placement-guide.mp3` |
| 正式开始提示 | `starting.mp3` |
| 剩余二十秒 | `remaining-20s.mp3` |
| 剩余十秒 | `remaining-10s.mp3` |
| 最后三秒与完成 | `countdown-3s.mp3` |
| 覆盖纠正 | `cover-camera.mp3` |
| 十五秒帮助 | `placement-help.mp3` |

`countdown-3s.mp3` 是包含结束语的完整音频，并非总长三秒；不改名、不裁剪、不另行合成完成语音。此前的试听 WAV 不参与打包引用。

不采用在多个组件内分别播放的方案，避免重复触发和抢占竞争；不把音频能力下沉到 acquisition，避免采集层依赖产品文案与页面生命周期。

### 2. 采用 Expo Audio 的单播放器

添加 SDK 57 对应的 `expo-audio`。插件显式关闭 Android 录音权限、后台播放及后台录音，保留现有录音权限禁用项；运行时仅播放随包资源，不请求麦克风、不注册锁屏控制、不改变系统媒体音量。播放使用短提示适用的音频会话模式，不为了播报切换到录音会话。

为本页所需短音频进行本地准备，切换时先暂停旧音频，再替换资源并从头播放。准备、定位与播放完成回调均携带轮次和播放令牌，执行前重新核对页面有效性；失效操作不得在停止后重新发声。页面结束后释放本页持有的播放器和订阅，不清除其他所有者的音频资源。

音频加载或播放失败不阻塞原生检测，不用合成语音或示例音频兜底，也不自动重复播报；现行视觉提示继续表达检测状态。选择此库而非新增 Android 播放模块，是因为已确认不需要精确播放边界与逐秒同步。

### 3. 原生阶段和剩余时间驱动关键提示

- 首次真实进入本轮 `observing` 后播放初始放置指导，每轮一次；授权、预览布局和打开相机期间不提前播放。
- 首次进入 `capturing` 播放“保持稳定，即将开始检测”，可打断尚未播完的放置指导。沿用文档既有触发点，不增加“播完再开始”的条件。
- 消费原生剩余量的区间变化，在跨过 20 秒、10 秒和 3 秒的首个有效快照触发相应提示，每轮一次，不比较精确相等。多个较早节点已过时时不排队追播，只保留当前适用节点。
- 剩余时间首次进入三秒区间且本轮仍处于 `capturing` 时，从头播放整段 `countdown-3s.mp3`；不跳播、不调整语速，不要求数字与屏幕每秒对齐。已经终止后不得补播整段结束音频。

不从 JS 发起另一套三十秒倒计时，也不拿语音时长决定原生截止。未收到触发事实时，不能仅按进入页面经过的时间播放。

### 4. 保留合并结束语，不等待收尾

用户已确认“检测完成”仅表示正式检测阶段结束，不表示文件保存或资源释放成功。结束音频启动后连续播放；随后进入 `stopping`、正常 `completed` 或发生正式窗口结束后的收尾失败，均不因等待资源或处理该失败而暂停、回撤或重播结束语。现有页面仍按真实文件、资源屏障和错误处理更新，音频完成回调不得修改其成功状态。

正式窗口尚未结束时发生覆盖丢失、技术失败或其他中断，仍须停止本轮声音。判断依据是本轮是否已实际达到正式窗口终点及真实结束原因，不能把所有 `failed` 都解释为后续收尾失败；后台、离页或重测无论处于哪个收尾阶段都停止播放。

不采用在“一”后等待或拆出独立完成文件的方案，因为这会改变已确认的声音含义与完整播放要求。`docs/development/measurement.md` 第 10 节关于严格逐秒对齐、迟到跳播及资源释放后才播结束语的旧条款，实施时替换为本设计，不改变其他方式的完成语义。

### 5. 覆盖纠正与放置帮助只在合适空档尝试

准备阶段只在真实覆盖已知且不足完整覆盖时纠正；覆盖未知时不猜测不足。正式阶段按原生维持门槛判断，当前为覆盖至少 95%，不把允许的轻微缺角当成需要纠正。稳定累计尚未就绪也不等于覆盖不足。

同一次连续覆盖不足只允许一次纠正；恢复当前阶段所需覆盖后，再次不足才能重新播。开始、20 秒、10 秒及结束音频优先于纠正和帮助；纠正一旦开始即消费本次不足资格，被打断也不立即重播。低优先级内容不插播、不积压，通道空闲后按最新覆盖、阶段和轮次重新判断。

十五秒帮助直接消费原有指导的实际可见性：只在指导仍显示且本轮尚未正式开始时尝试，每轮最多一次；确认收起或进入正式采集后不补播。纠正与通用帮助同时适用时优先纠正，不将两条相近指导紧挨着自动串播。

低优先级开始前比较其实际音频时长与距离下一定时关键节点的原生剩余量，空档不足不启动。不得让低优先级加载或播放阻挡关键提示；通知与准备迟到时仍以最新事实丢弃过时操作。

### 6. 复用现有轮次与取消边界

用现有页面代次及 `captureId` 绑定语音，不新增业务会话身份。只在指尖组装层创建控制器；共享接触式会话仅提供必要的生命周期通知，不硬编码指尖素材或规则，血压路径维持无语音。

请求离页时立即取消语音，而非等待相机关闭成功；后台、失焦、卸载、准备失败及明确重试同样撤销旧播放资格。恢复前台只刷新真实状态，不补播旧内容；新一轮重置关键节点、覆盖纠正资格和帮助消费状态。停止不要求等待正在进行的音频加载完成，加载结果返回后必须因令牌失效而丢弃。

## Risks / Trade-offs

- 完整结束音频的数字及结束语可能与界面秒数、资源收尾时刻不同步 → 按已确认语义接受，不引入暂停、裁剪或额外时钟；界面继续保留真实收尾屏障。
- 异步资源准备可能在离页或抢占后返回 → 使用轮次及播放令牌核对，防止旧声音复活。
- 新音频插件默认可能声明录音或后台播放能力 → 显式关闭相关选项，检查生成的 Android 配置；仅为播放重建开发包。
- 共用会话生命周期调整可能误影响血压 → 指尖控制器只由指尖组装，定向检查血压不播放指尖声音，不扩大为其他检测方式语音实现。
