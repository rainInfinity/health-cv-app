# Design

## Context

动机与范围见 `proposal.md`。产品入口使用健康功能双分类，现有根栈已提供准备、面部及指尖页面，产品底栏与 Dev 子栈仍共用单一导航容器。面部产品页必须显式接入既有在途命令和相机／文件关闭屏障，不能仅依赖页面卸载。

主动面部实现位于 `packages/acquisition`，产品与 Dev 共用 `src/app/rppg/` 的频谱摘要与批次连续性规则。产品面部与指尖共用 `src/shared/components/PulseWaveHistory/` 和 `PulseWaveChart/`，Dev 保留 `RPPGWaveform/` 的有限窗口适配。产品外观与会话编排独立于 Dev 诊断页面，不整体嵌入 Dev 控制界面。

主动 RPPG 最终接口决定真实状态、逐搏／频谱隔离和文件收尾；产品层只处理入口、视觉、偏好及本地展示，不补完算法或桥接协议。本轮只验收产品核心流程，不扩大为 Dev 适配或医学验证。

## Goals / Non-Goals

**Goals:**

- 页面布局与采集事实解耦：Demo 决定外观，原生会话决定面部状态；指尖展示独立运行，不挂接任何真实数据源。
- 保留根栈、主题、统一反馈、设备偏好及原生预览约定；只提取实际被产品与 Dev 共用的展示逻辑。
- 用实际 Android 产品页面和核心交互检查布局、动效与流程，不用样式常量、源码断言或占位页面代替；运行结果仅在交付回复说明。

**Non-Goals:**

- 不建立通用检测流程引擎、统一所有采集源的状态机或新的桥接协议。
- 不调整逐搏／频谱算法、门槛、正式时长、三件套格式或被动运行策略；不要求被动 RPPG 提案完成。
- 不展示新的产品逐搏读数，不将其放进“平均心率”；不接历史、上传、账号健康记录或新的结果页。
- 不改首页入口及现有认证策略；不把既有主页入口与规格之间的历史差异算作本次已修复。

## Decisions

### 1. 明确依赖，而不是在产品页补完算法

实施以主动 RPPG 的最终公开接口及协议为前置条件，不以 OpenSpec 规划状态代替能力交付。依赖完成不要求提前归档，本变更不承担逐搏算法或被动 RPPG 实施。

正式会话、结束原因、质量结论、目标时长及逐搏／频谱隔离以依赖最终契约为准。若最终接口变化，先在本变更内更新接入说明再实施，不改变已确认的视觉和业务边界。

实际接入契约由 `packages/acquisition/src/rppg/client.ts`、`src/native/RPPG.nitro.ts` 和 `src/react/RPPGPreview/RPPGPreview.tsx` 定义：

- 使用 `requestCameraPermission()`、`openPreview()`、`start()`、`stop()`、`close()` 及独立的状态／实时批次订阅；创建客户端或挂载预览不打开相机。
- `latestHeartRate` 是带片段和起止纳秒身份的频谱窗口，独立的 `latestInstantHeartRate` 不参与产品平均；`measurementStartedAtElapsedNanos` 只提供原生单调起点，当前没有跨时钟同步或权威进度接口。
- 原生 `HybridRPPGPreview.kt` 在视图构造时同步注册预览；权限获准后挂载真实 host，包装层同时等待 Nitro `hybridRef` 回传真实实例与正尺寸 `onLayout`，两者均满足后才向页面报告就绪，再等待 `openPreview()` 返回后开始。Fabric 布局计算可以早于原生挂载，单独的布局事件不能证明 registry 已可用。该屏障不宣称相机已出首帧或进入 STREAMING，不增加猜测延时或重试。
- 采集协议及当前接入说明统一见 `docs/acquisition/android-rppg.md`，运行方法见 `docs/development/android-development.md`。产品有值状态必须使用真实输入，不将界面正常或依赖已交付外推成医学有效性。

### 2. 三个根栈路由，一套入口映射

使用 `MeasurementGuide`、`FaceMeasurement`、`FingertipMeasurement` 三个根栈路由，页面位于 `apps/native/src/pages/measurement/`，沿用 `index.ts`、组件实现与 `styles.ts` 组织。路由类型及注册仍在 `src/app/navigation/`，不新增导航容器、产品 Tab 或公开深链。

检测方式使用 `face | fingertip | chest`，与 Demo 对齐；指标目标使用已有 `HealthMetric` 的单项或指尖心率／呼吸率联合目标的有限类型，不把任意 UI 文案作为控制字段。部位入口只绑定方式和必要目标，指标入口通过固定映射进入同样的流程；指尖部位入口不预选指标。

分类状态保留在仍挂载的 `FeaturesScreen` 中，冷启动默认按检测部位，不新增分类持久化。入口解析同时读取方式级跳过偏好：未跳过时进入准备页，面部确认后替换准备页，指尖确认后保留准备页供返回；已跳过时直接进入对应检测页，不挂载隐藏准备页或补弹声音提醒，指尖返回也直接到原功能分类。尚未接入的血压在跳过入口直接反馈，不构造检测页。

选择根栈而非功能 Tab 子栈，是因为 Demo 检测页没有底栏，且可减少切换到 Dev 时绕过资源交接的路径。底层已有 Dev 主动相机若仍占用，打开产品面部相机须通过既有互斥如实报告 busy，不为产品页面抢占设备。

### 3. 引导共享布局、按方式保存偏好

一个引导组件承载三份静态配置，照片来源固定为 face→`op3.png`、fingertip→`op1.png`、chest→`op2.png`。保留原图并生成卡片 480×480、引导 828×828 PNG，分别由卡片和准备页选择，避免小区域解码原始大图；不裁切或改色生成源图。

使用现有 `src/app/preferences` 持久化引擎保存三方式跳过标记，缺失或非法值回到不跳过；不改变语言和首次引导偏好，退出账号不清除，不按指标重复保存。复选框立即更新该方式；当次点击开始不再提醒，后续入口同时跳过引导和声音提醒，跳过不代表相机授权或真实采集已开始。

声音提醒由引导页内状态和 `useGuideDialog` 持有，复用 `FeedbackDialog` 的统一外观，不使用全局原生窗口承接声音确认。采用与 Android 原生 Modal `fade` 一致的 200 ms 加速透明度曲线及原生动画驱动；页面内弹层开启整层透明度合成与硬件纹理缓存，让遮罩、面板及 `elevation` 投影一同淡入淡出，避免半透明阶段的矩形阴影。纹理仅随弹层挂载存在，代价是一张页面大小的 GPU 纹理。

淡出完成后才执行用户动作，关闭期间忽略重复操作，减少动态效果时直接完成；关闭、遮罩或 Android 返回只收起提醒。标题、正文与操作沿用 Demo，不增加音频权限、音量控制或播报资源。面部确认仅到待开始页，血压确认只反馈尚未接入，不扩展设备或云端任务。

### 4. 面部页面只负责产品编排与展示

产品页挂载不申请权限、不打开相机。第一次“开始检测”串行执行授权、原生预览挂载确认、`openPreview()` 和 `start()`；React 挂载不等于原生预览已经可用，不以固定延时猜测就绪。命令在途时禁用重复操作；真实错误通过既有统一反馈显示，不在正常面板增加诊断段落。

系统相机授权弹窗可能使宿主短暂进入后台。权限获准、页面仍有效且应用当前已回前台后，清除授权期间遗留的后台标记并继续本次显式启动；导航取消或仍在后台时不继续。原生预览布局、打开预览及正式开始后的后台中断检查保持不变，不因权限弹窗而自动恢复已开始或已终止的检测。

主动 `HybridRPPG` 直接订阅 React 宿主生命周期，暂停时通知 `RPPGActiveRuntime` 在自身协程和既有串行屏障中执行 `stop(APP_BACKGROUND)`，排空相机与文件后再发布终态；不能只冻结 JS 计时，也不能用普通用户停止伪造后台原因。宿主恢复不自动重新打开或开始，关闭完成或宿主销毁时注销本对象的监听，销毁经同一关闭屏障释放所有权。相机宿主原有 ON_STOP 处理保持不变，不修改共享 CameraSource、被动采集或传感器行为。

| 原生／操作事实 | 产品显示与操作 |
| --- | --- |
| 未开始 | 相机图标、--、00:00、待开始、空曲线、开始检测 |
| 打开／启动中 | 检测中／获取信号中；主按钮忙碌，正式计时为零 |
| observing | 检测中／获取信号中；保持 Demo 的面部入镜提示，正式计时仍为零 |
| measuring 但无有效频谱 | 检测中／获取信号中；真实计时和波形推进，平均仍为 -- |
| measuring 且有有效频谱 | 检测中／保持稳定；更新本会话去重均值与真实波形 |
| stopping | 保持检测中，主按钮忙碌；不允许重测或提前离开 |
| 正常终态 | 已结束／检测已结束；冻结读数、时间和曲线，主按钮为重新检测 |
| 技术失败 | 沿用统一错误反馈及重试能力，不新增正常页面状态或说明 |

面部正常状态仅为“待开始／检测中／已结束”，提示原文为“点击开始／获取信号中／保持稳定／检测已结束”。原生阶段、终止原因与有效性仍内部保留，不额外上屏。指尖文案及状态同样沿用 Demo，包括其原有完成提示，不另加说明。面部进行中及指尖覆盖／检测中的状态圈复用 `LoadingIndicator`，900 ms 匀速旋转；待开始、结束或减少动态效果时不旋转。

重测在用户操作时立即清空均值、计时、图形和旧会话代次，然后重新打开；不等新波形到达才清旧图形。模型加载失败可能保留预览，恢复动作应按最终原生阶段决定继续启动还是重新打开，不能盲目重复打开。`close()` 后的 runtime 不再复用，下一次需要新客户端。

计时在原生进入正式测量后才推进。优先使用依赖最终提供的权威进度；只有现有起点／阶段时，以 measuring 通知建立页面单调展示计时，明确它只是 UI 经过时间，不把 JS 时钟与未经证明同源的绝对原生纳秒直接相减。原生决定截止；页面停止或后台终止后冻结，不把 JS 倒计时当会话控制。观察、权限及打开耗时不计入。

主展示仍为“平均心率”，只使用频谱唯一有效窗口的算术累计；逐搏初步值即使更早到达，也不替换该槽位。结束后平均是本次会话摘要，不是持续实时值，不新增历史恢复或摘要落库。

### 5. 本轮历史与有限绘图分离，不引入全量信号 Store

沿用已迁到 `src/app/rppg/` 的 RPPG 频谱摘要、批次连续性规则及 Dev 有限缓存。产品页使用独立的本轮波形历史，共享绘图复用 `src/shared/components/PulseWaveChart/`，不保留旧路径转发，不为复用重写 Dev 特有的诊断控制或状态展示。

面部只接收与定稿文件同源的标量批次，以首个真实样本为显示时间零点；会话、片段、序号或采集时间缺口用空值断开，不补造历史。当前三十秒会话的展示坐标原位追加到页面局部 ref，按批次通知刷新，避免反复复制整轮历史或把原始 PPG、完整文件放入全局 Store。回看与结束后保留本轮收到的历史，重测或离页释放，不反复读取文件补齐漏批；Dev 原有十五秒／300 点有限缓存不变。

面部与指尖共用 `src/shared/components/PulseWaveHistory/` 管理标题范围、跟随／回看与返回最新浮层；每屏固定六秒，起始右对齐、左侧留空。用二分定位当前窗口，绘图范围仅包含窗口、两端邻点及左侧最多 200 ms 预绘区，保留边界空值断线，不让图表持续处理整轮数据。ECharts 与 `@wuba/react-native-echarts/svgChart` 只注册折线图、Grid 和 SVG 渲染器，不加载 Skia 或 WebView。Dev 的 `RPPGWaveform` 保留原有限坐标转换；指尖直接使用自身模拟历史，不伪装成真实 RPPG 批次。

图表在有效尺寸后初始化，数据与主题更新复用实例，尺寸变化调用 `resize()`，卸载时 `dispose()`。关闭符号、ECharts 内置手势及全部曲线入场／更新插值，直接平移坐标窗口，不对旧波峰做形状过渡。RN responder 只处理绘图区水平平移，不缩放；指尖触摸绘图区期间暂停外层分页，标题滑动和分页按钮仍可切页。回看记录绝对起始时间，采样继续追加而视窗不随最新时间漂移；右侧 48 dp 圆形按钮相对实际绘图区垂直居中，点击回到最新并隐藏，结束后仍可使用。

采样刷新与连续滚动分离：ECharts 仅在批次、坐标或主题更新时重绘有限 SVG；`ScrollingSvgChart` 使用同一个 `Animated.Value` 和 native driver 维护绝对横向位移。连续批次只提交新的向左目标，由原生当前值继续；不使用 JS 时钟估计动画当前位置，也不在每批到达时重置位移。每次 `init()`、`resize()` 或 `setOption()` 前，通过 `prepareUpdate()` 锁定本次绘图参数；SVG patch 与对应的静态坐标补偿同批提交，避免用尚未绘制的参数移动旧图层，重复 SVG 提交不重启动画。

横向比例在六秒视窗内固定，静态坐标补偿与原生绝对位移相加，使同一历史样点在新旧批次交接时保持位置连续。补偿层使用浮点 `transform`，不使用会按物理像素取整的动态 `left`；画布只扩展有限预绘区，不按整轮时长扩宽，也不为整张画布额外缓存硬件纹理。代价是约一批的展示延迟，不改变样本时间或数据内容。首帧、回看、结束、后台、减少动态效果、尺寸变化、时间回退或不连续大跳时直接定位，不播放追赶动画。

产品保持单基线及按视窗宽度计算的左端 14% 渐隐，绘图区高度及上下 8 dp 坐标间距不变。以底边为 0%，通过纵轴将数据映射到高度 10%–85%，不改写原始幅值。面部使用本轮累计原始极值确定显示包络，不按回看窗口自动缩放；新极值可扩展包络，因此历史波峰的显示高度可能变化，这是保留真实幅度范围的明确取舍。指尖已知模拟幅度上界为 1.01，固定纵轴跨度为 `1.01 / 0.75`，下界为跨度的 `-0.1`、上界为跨度的 `0.9`。

基线和渐隐覆盖层不参与画布平移。渐隐范围始终为可见坐标宽度的左侧 14%，两端使用同一表面色，分别显式设置 `stopOpacity={1}` 和 `stopOpacity={0}`；不依赖 `stopColor` 中的 RGBA alpha，因为当前 `react-native-svg` 会用 `stopOpacity` 重写渐变透明度。渐隐在跟随、回看和完成后均保留，不变成整块白色遮挡。

均值仅保留累计和、计数与去重所需窗口身份，不缓存整条心率序列；本轮标量展示历史不进入持久 Store 或 React Query，也不扩展成跨轮历史恢复。产品与 Dev 不同时持有可见原生预览，页面失焦／退出及时取消展示订阅；重测及旧回调用会话身份隔离。

### 6. 指尖是明确、完整且可重进的本地展示

指尖不创建采集客户端，不使用后摄 `showCoveringTip` 推算百分比。未跳过时以引导页提醒确认作为进入意图，已跳过时功能卡片就是进入意图；页面完成布局后从 ready 推进至 covering，不等待真实手指或让用户触碰预览假装硬件确认。

- ready：0%、00:30、流程说明和空波形；中央提示“请将指腹轻覆后置摄像头”，状态“准备检测”，辅助说明“指腹轻放，不要按压”。
- covering：沿 Demo 时序约 2.4 秒推进至 100%，再保留约 0.4 秒确认停顿，剩余时间仍为 00:30。实际动画进度 1%–99% 时提示“手指未完全覆盖镜头，请调整位置”、状态“调整手指”、辅助说明“让指腹完整覆盖后置镜头”；实际达到 100% 才提示“已完全覆盖，即将开始检测”、状态“准备开始”、辅助说明“保持轻覆，检测即将开始”。这两种呈现仍属于 covering，不增加流程阶段。
- running：单独开始 30 秒倒计时并自动切到波形页；中央提示“正在检测，请勿移动手指”，状态“检测中”，辅助说明“自然呼吸，保持手指稳定”。覆盖环保持满环，按 30 Hz 从零秒起只追加稳定模拟采样，保留本轮全部三十秒历史，每屏仍为六秒；刷新与采样分离，不对曲线做形状补间。
- completed：00:00，冻结本轮模拟历史与满覆盖环，仍可回看及回到最后窗口；中央提示“检测完成，可以移开手指”，状态“检测完成”，辅助说明“本次检测已结束”。只结束展示，不生成指标，也不在业务页面追加演示或保存结果的说明。

完成后通过返回重新进入可创建全新展示；未跳过时返回引导再确认，已跳过时返回功能页后直接再进。Demo 手机外部的“模拟放置指尖”和“模拟未检测到手指”工具不移入原生页面；后者单独触发的等待提示不构造为原生识别分支，不增加摄像头切换或虚构识别结果，保留本地自动展示和无额外操作按钮的界面。

本地展示用页面单调时间计算 elapsed，不按定时回调次数累加。AppState 隐藏期间暂停，回来从原进度继续；离开取消绘图、计时和分页监听并释放历史。该策略只用于展示，不能复用于面部真实会话。减少动态效果时降低曲线刷新频率，保留实际可见时间内的模拟采样、倒计时和阶段，不用预填未来六秒样例替换历史；原有装饰动效开关保持不变。

覆盖阶段只更新局部 Animated 节点，不以每个快照重绘整页。覆盖环、红色渐入及说明图局部动作共享线性进度，百分比读取实际动画值；页面只在覆盖呈现跨越零值、未满、满环边界时更新相应提示，避免满环前显示 100% 或“准备开始”。黑色预览底色使用主题语义色，静态预览、红色径向渐变和动态覆盖环分层；红色层缓存后只调整透明度，水纹沿用原生动画。SVG 动态变换使用数值数组，避免 Fabric 将字符串变换作为原生 View 属性更新时崩溃。

操作提示放在圆形镜头区域中央，采用白色表面、边框与 14 dp 圆角，不拦截手势；文字为 14／22 dp，水平内边距 16 dp、垂直 12 dp，含内边距与边框的宽度不超过镜头直径的 80%。提示随文字自然收缩，最多两行，溢出省略，不使用固定满宽说明条。删除圆形下方的旧提示与准备态相机占位图标，用释放的文字及间隔空间等比放大预览，保留底部状态／波形面板的布局位置和高度。百分比标签固定宽 88 dp，居中叠在预览底缘，数字变化不改变标签或预览尺寸。

运行阶段的高频模拟波形通过私有 `FingertipPulseWave` 局部订阅更新，父页只按阶段或倒计时秒值刷新；不让每批样本触发预览、状态与分页整页重绘。波形分页不可见时暂停绘图消费但继续本地采样，重新可见时读取当前快照并保留回看位置；应用进入后台仍按前述展示规则暂停采样和计时。

底部采用原生横向分页滚动，分页标识跟随实际滚动位置；状态和倒计时置于分页外。标题区域滑动或有名称的分页按钮可切页，非当前页隔离读屏；绘图区内水平手势专用于波形回看，不传给外层分页，切页不重置计时或回看位置。指尖说明的背面／正面 SVG 从 Demo 几何移植，不引用真实会话的波形缓存。

### 7. 资源与视觉逐项映射

继续使用现有主题、浅色背景、`AppText`、`ActionButton` 和 SVG 图形出口；只补充实际缺失的检测渐变／布局语义，不另建 token 系统。新增 TS／TSX 模块及命名组件遵守现有中文模块注释、JSDoc 和组件目录规范。

照片卡片选择 480×480 资源，保持右侧约 44% 图片区域、对应裁剪与横纵透明渐隐；隔离卡片使用原生 multiply 和 SVG alpha 蒙版，不用白色遮罩掩盖融合差异，不依赖未实现的 SVG `FeImage`。

准备照片选择 828×828 资源，使用原生 Image 与圆形容器裁剪。照片、边框和水纹共用固定 360 坐标画布，父布局变化只整体缩放，不反复调整图片解码尺寸；静态组合缓存合成，减少入页绘制。双水纹预计算路径和端点分段透明度，替代 SVG 图片裁剪和离屏水纹蒙版。其他 SVG 的渐变／蒙版 ID 按实例唯一化，保留既有品牌、五项指标及持机插画，不重新建立视觉系统。

面部画面保持 5:4，可用高度不足时整块等比缩小。四角以画面内侧 24×2 dp 实色线段还原，避免居中描边被容器裁半；构图圆不是实际识别区域。真实相机仍在原生预览层。下部面板全宽白底、顶部 22 dp 圆角；波形在读数、标题和主按钮之间弹性伸展，按实际布局高度绘图，100／128 dp 只作为最小高度，不留下固定画布外的空区。

应用全局固定竖屏，不实施或验收横屏。安全区只分配一次：根栈页面自己负责状态栏与底部系统区域，不绘制网页假状态栏、9:41 或手势条；功能页继续由产品 Tab 分配底部空间。后续按常规设备、默认字号和正常显示设置对齐布局，保留已有滚动及字号适配，不追加专项适配或验证。

健康、功能、历史、我的四个产品 Tab 复用 Demo 对应的 SVG 几何，选中采用实心图形与 `#0AB6C0`，未选中采用描边图形与 `#666666`，标签颜色与当前状态一致。仅替换底栏图形和配色，不新增产品 Tab、不改变路由、状态保留或资源交接；开发入口继续可见，历史继续只弹出未开放说明且不切页。

### 8. 根栈退出接入同一资源屏障

面部页注册现有 RPPG 离页协调，使用 `usePreventRemove` 处理 Android／页内返回，并覆盖已有深链跳转。等待顺序为在途命令、关闭 runtime、原生相机及文件收尾，成功后执行待离开动作；失败留页重试。卸载兜底关闭不是主要资源交接机制。

产品面部页只关闭自己持有的 runtime，指尖页只清理本地展示；不全局停止其他采集。本轮不再适配或验收 Dev，后续独立删除，不在本次顺带删除。

桥接只在命令被拒绝且没有显式错误时回退到会话快照错误；成功命令不能把历史 `CAMERA_BUSY` 重抛为新的关闭错误。当前命令的真实失败始终优先，离页屏障仍须等待并阻止失败放行。关闭态快照中的历史诊断不再作为新的页面提示反复弹出。

`RPPGSession.close()` 对已处于 FAILED 且资源已释放的会话直接生成成功命令结果，再进入 CLOSED，历史错误仅保留在会话快照中；不能复用 `stopLocked()` 的历史拒绝结果作为本次关闭失败。其他阶段仍等待原有关闭屏障，本次真实关闭错误继续优先，`stop()` 的失败语义不变。相机忙时本会话不得取得或释放其他所有者的租约，首次关闭不要求用户再次返回才能成功。

### 9. 视觉与行为分别验收

后续使用现有只读 Demo 服务与实际 Android 产品页面，在常规设备、默认字号和正常显示设置下检查。比较时对齐逻辑内容区域，排除 Demo 标签、外框和系统栏；截图仅作为必要的临时对照工具，不要求建立截图矩阵、录屏或证据归档，也不修改网页样式迁就原生。

检查功能双分类、三种引导与声音提醒，以及面部待开始／检测／结束和指尖覆盖／检测／完成的主要布局与切换动效。真实相机和实时波形只比较区域布局；字体渲染差异不能掩盖错位、裁剪错误、图片白边、波形区挤压或必要操作不可达。不另做多尺寸、大字号或专项无障碍验证，保留已有适配和减少动态效果行为。

面部只用真实链路走通授权、预览、正式计时、波形和有效均值、结束及重测，检查直接影响使用的拒权、busy、后台和离页收尾路径。有效均值无法取得时如实说明该部分未验证，不注入健康数值冒充真实接入；不扩展为信号质量、医学精度或全部终止组合的验收。指尖走完覆盖、独立 30 秒倒计时、完成和返回重进，确认切页不改计时、后台暂停及无权限申请、采集产物或上传。

优先复用已有摘要、有限缓存、展示计时和离页协调测试。只有核心行为或具体回归缺少覆盖时才补永久测试，不测试文案、静态 SVG 路径、组件接线或默认值。各节已取得的验证不重复执行；交付时在回复中说明实际检查和未覆盖项，项目文档只维护现行功能、运行方法及接入约定，不保存验收记录。

验证复用已完成的类型、确定性行为及实际产品运行检查；对转场、覆盖环、波形追加和弹窗阴影等已报告问题，只检查对应交互、动画中间帧及必要的绘制统计。单次设备结果不代表所有环境无掉帧，不扩展为 CPU／内存／功耗矩阵、压力或医学验证。未覆盖的拒权／busy、完整资源交接及界面对照继续保留未完成，不借局部优化标记全部通过；项目文档不保存验证日志或截图。

## Risks / Trade-offs

- [原生与网页混合／蒙版的渲染不完全一致] → 在三张照片卡片阶段先实际验证 multiply、alpha 及裁剪，修正组合而不是改原图或接受明显白底。
- [依赖最终接口或时序改变] → 以已确认的最终契约和原生状态接入，不改算法或协议；桥接仅修复已确认的历史错误回填。
- [逐搏早出值但平均仍为空] → 保留频谱平均定义；等待时仅显示 Demo 的“获取信号中”，不混合两类结果或承诺三秒出数。
- [指尖纯展示被误认为采集成功] → 严格沿用 Demo 状态和原有完成文案；全程不调用采集、不生成指标、不更新健康记录，不额外增加展示说明。
- [导航离开时相机或文件尚未关闭] → 产品面部页通过既有屏障等待本会话收尾，验证在途返回与关闭失败不放行，不继续验收 Dev。
- [原生与 Demo 的可用内容区域不同] → 常规设备、默认字号下对齐内容区域，排除外框与系统栏后比较，不通过缩小字体掩盖布局差距。

## Migration Plan

1. 主动 RPPG 实施及接口交付完成后，固定 Demo 参考状态和逻辑视口，实施功能分类、根栈路由、偏好与准备流程。
2. 移植照片融合与 SVG，完成指尖无采集副作用的完整展示，再提取实际共用的 RPPG 展示逻辑并接入产品面部页。
3. 更新全部迁移调用、测试导入、中文文案与导航离页协调，不保留旧帮助函数转发路径；保留已完成的共享迁移，不继续适配或验收 Dev。
4. 运行受影响检查及实际界面／采集验证，结果与未覆盖项在交付回复中说明；在 `docs/development/` 及 `docs/acquisition/android-rppg.md` 仅维护现行入口、运行方法、图形复用和均值语义，不保存验收记录或将 UI 验收写成医学精度验收。
5. 回退以撤销本变更新增页面和入口为界，不回退已完成的主动 RPPG、不删除任何完成产物、不改变被动设置，不新增旧／新运行时开关。
