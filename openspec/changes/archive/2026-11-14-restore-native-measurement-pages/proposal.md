# Proposal

## Why

`docs/design-demo` 已确定健康功能双分类、三种检测引导及面部／指尖检测页。本变更将原生五项说明入口还原为完整产品流程，并同步已确认的跳过提醒、分辨率资源和动效优化，明确面部真实检测与指尖纯展示的边界，避免将演示数据当成测量结果。

## What Changes

- 健康功能页默认显示“按检测部位”，提供面部、指尖、指尖＋胸口三张照片卡片；“按指标”保留五项 SVG 卡片，两种分类共用入口映射和方式级偏好，返回后保留分类。
- 提供面部、指尖、血压三种检测引导，复用操作照片、正圆水纹、准备提示及“以后不再提示”。未跳过时，声音提醒只在引导页内显示，采用统一淡入淡出并整体合成面板与投影，淡出后才执行确认动作；勾选后当次不再提醒，后续同时跳过引导和声音提醒。
- 新增面部心率产品页，按 Demo 还原 5:4 取景、平均心率／计时／状态、固定六秒脉搏波视窗及开始／结束／重测；保留本轮真实波形历史，支持检测中和结束后回看。接入已完成的主动 RPPG 链路，不复制算法，不以逐搏初步值代替有效频谱平均。
- 提供指尖纯展示页，还原圆形黑底／模拟红色预览、覆盖环、独立 30 秒倒计时、流程说明／波形分页及完成状态。操作提示改为预览中央的白色轻量浮层，最多两行；使用原圆形下方说明与间隔的空间等比放大预览，不推移底部状态及波形面板。按等待、覆盖未满、满环待开始、检测中及完成更新提示，覆盖内两个展示状态不新增流程阶段；移除多余的演示说明。覆盖环与说明图局部补间，静态预览、红色渐变和动态圆环分层，减少整页重绘。不请求权限、不启动真实采集、不接算法、不保存或上传结果；确认或已保存跳过偏好的入口均可启动本地自动展示。Demo 外部模拟按钮及其单独触发的未检测手指提示不迁入原生，不虚构识别结果。
- 面部与指尖脉搏波统一采用 ECharts 原生 SVG 渲染器，关闭入场及更新插值，以原生连续位移衔接采样批次，不让历史波峰在批次交接时反向跳动；仅追加本轮采样，每屏固定六秒，开始时从右侧累积且左侧留空。水平拖动回看时继续采样并保持所选时间段，右侧居中图标可回到最新并恢复跟随；波形手势不触发指尖外层分页。单基线与左侧 14% 渐隐固定在视窗上，渐隐从不可见平滑过渡到正常线色，不退化成硬遮挡。绘图区高度不变，通过纵轴映射保留底部 10%、顶部 15% 的数据留白；面部按本轮累计原始幅值范围显示，新极值可扩展纵轴，指尖使用固定纵轴。重测或离页清空历史，不补造样本、跨缺口连线或混用真实／模拟数据，不使用 WebView 或 Skia。
- 健康、功能、历史、我的四个产品 Tab 的图标及选中／未选中颜色对齐 Demo；选中使用对应实心图形与 `#0AB6C0`，未选中使用描边图形与 `#666666`。只调整底栏视觉，保留开发入口和历史未开放反馈，不新增 Tab 或历史业务页。
- 血压仅实现引导和检测尚未接入反馈；跳过引导时在功能入口直接反馈，不新增血压检测页、联合采集或估计算法。首页、历史、健康数据及账号功能不扩展。
- 引导与检测使用现有根导航栈且不显示产品底栏；面部退出等待真实资源收尾。未跳过时指尖返回引导，已跳过时直接返回原功能页；开发验证页独立保留。
- 应用全局固定竖屏，不实施或验收横屏。正常页面文案和状态严格沿用 `docs/design-demo`，不新增阶段、结束原因或演示说明；进行中的状态指示器使用 900 ms 匀速旋转 spin，减少动态效果时静止。
- 本轮只交付并验收产品页面，不继续适配或验证 Dev；Dev 后续单独删除，本次不顺带删除。
- 在常规 Android 设备、默认字号和正常显示设置下检查产品核心流程、必要失败路径及相关布局动效；针对已报告的转场、覆盖环、波形卡顿和弹窗阴影进行定向检查，不追加尺寸矩阵、专项无障碍、长时间压力或医学验证。实际结果和未覆盖项仅在交付回复中说明，不将验收记录或截图证据写入项目文档，不将局部改善宣称为全面性能保证。

## Capabilities

### New Capabilities

- `native-measurement-pages`：产品检测准备、面部真实检测和指尖展示的页面交互、资源复用及视觉验收边界。

### Modified Capabilities

- `native-product-pages`：将功能页的单一五项说明入口改为双分类和准备页导航；仅面部接通本地真实检测，保留现有健康展示与认证隔离。
- `native-app-shell`：新增根栈产品准备／检测导航，确保产品面部页退出及既有导航事件等待本会话相机和文件收尾；对齐四个产品 Tab 的图标与选中配色，不改变现有入口行为。

## Impact

- 实施前置条件：`add-active-realtime-rppg` 完成实施及其接口、文档和验证交付后，才开始本方案实施；不以“规划产物齐全”代替实施完成，也不要求为此提前归档。若依赖接口改变，按最终契约接入，不回退成演示面部检测。
- 应用范围：`apps/native/src/pages/features/`、新增产品检测页面、`src/app/navigation/`、现有偏好存储与中文文案；必要的会话展示逻辑从 Dev 模块迁到产品与 Dev 可共用的位置，更新全部调用，不建立第二套控制协议。`packages/acquisition/src/react/RPPGPreview/` 同时等待真实 Nitro HybridRef 与正尺寸布局后才报告就绪，修复快速重进时布局事件提前放行的问题，不改变 Nitro 协议或增加猜测延时、重试。
- 图形范围：保留 `apps/native/assets/op1.png`、`op2.png`、`op3.png` 原图，派生卡片 480×480 与引导 828×828 PNG，并按页面选择资源；复用既有主题、图形出口、水纹及指尖说明 SVG。准备照片改用原生图片圆裁，静态与动态层分离；图表仅注册折线图及必要组件，不引入 WebView 或 Skia。
- 不修改 RPPG 算法参数、Nitro 协议字段、产物格式及被动采集策略。原生改动限于已确认的命令结果与主动 RPPG 宿主生命周期缺口：成功命令不重抛旧快照错误，已释放资源的失败会话首次关闭返回成功并保留历史诊断，真实关闭失败仍阻止离页；React 宿主暂停时以 APP_BACKGROUND 走本会话停止与文件收尾屏障，恢复前台不自动重启，关闭或销毁时注销监听。不修改共享 CameraSource 或其他采集能力，不释放其他所有者的相机租约；补充对应直接回归。不新增指尖接口、云端任务、健康记录或指标落库；产品均值只在本次会话内展示。
- 同步现有提案、设计、增量规格和任务状态，已完成项以实际实现及验证依据为准，未覆盖项继续保留未完成；更新 `docs/development/` 及受影响图形／RPPG 文档的现行入口、使用方法与接入约定，不保存验收流水。本次不更新主规格、不归档变更。
