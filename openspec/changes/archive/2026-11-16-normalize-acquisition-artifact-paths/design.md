# Design

## Context

动机见 `proposal.md`。PPG、四种传感器及血压组内输出均通过 `AcquisitionPaths` 构造路径，输出器无需自行拼接新目录。该共享路径合同涉及多个采集模块，因此用本设计明确统一切换点和保持不变的行为。

现有测试中既有通过 `AcquisitionPaths` 解析路径的断言，也有直接写死旧目录的断言；后者必须同步，否则部分失败断言会因检查不存在的旧路径而失去作用。

## Goals / Non-Goals

**Goals:**

- 只改共享路径构造，使临时文件、完成文件及返回引用自然使用同一新布局。
- 同步直接依赖旧路径的测试期望和开发文档，不增加采集流程改动。

**Non-Goals:**

- 不统一各源 sessionId，不修改 TypeScript／Nitro 协议、输出器发布顺序或血压协调器。
- 不迁移、扫描、兼容或清理已有文件，不修改 RPPG 或历史视频存储。
- 不新增或运行测试，不安排模拟器、真机或实际产物验收。

## Decisions

### 在统一路径入口直接切换

`ppgSessionDirectory()` 增加固定 `ppg/` 层；`sensorSessionDirectory()` 去掉 `sensors/` 层并使用现有 `kind.wireName`。删除由此失效的 `SENSOR_DIRECTORY` 常量，沿用现有路径安全校验。

不在各输出器中重复修改路径，不新增通用目录路由或配置开关：这些做法会增加重复实现或可变状态，而两处路径构造已覆盖本次范围。

### 保持文件交付合同

PPG 仍先写双 `.part`、关闭后提升；传感器仍在关闭且有实际样本后提升。绝对路径继续从实际文件对象生成，无需修改消费者。各源独立标识和业务轮次标识均保留；本次不形成业务检测目录或跨源文件事务。

RPPG 目录与临时目录不变，现有内部／外部 RPPG 查询逻辑原样保留，不把“不考虑已有文件”扩展为删除其他能力的历史查询。

### 只同步受影响的现有约定

更新已有路径合同断言及 PPG、传感器失败路径中的硬编码位置，不新增测试。同步 `docs/acquisition/android-ppg.md`、`docs/acquisition/android-sensors.md` 和 `docs/development/android-development.md` 中的路径与命令示例。按用户要求，本次不运行测试，也不把设备采集列为完成门槛。

## Risks / Trade-offs

- [外部脚本写死旧路径] → 在文档中更新示例并明确路径变更，不增加旧路径兼容层。
- [硬编码失败断言仍指向旧目录] → 随实现同步现有断言，避免检查错误位置；本次不声称具备运行测试证据。

## Migration Plan

代码更新后，后续新会话直接使用新路径。已有文件不在本次处理范围，不执行搬移或删除，也不新增恢复逻辑。
