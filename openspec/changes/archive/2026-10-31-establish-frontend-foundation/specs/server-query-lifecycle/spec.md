# 服务端查询生命周期规格增量

## Purpose

为应用已有的认证门控服务端资源提供明确的新鲜期、回收和原生生命周期刷新行为，使调用方能够复用缓存、区分首次加载与刷新失败，并确保网络恢复或语言变化不会重复提交业务操作或破坏账号隔离。

## ADDED Requirements

### Requirement: 查询新鲜期按资源语义确定

应用 MUST 对本人资料使用 1 分钟、模型目录 30 分钟、历史列表 30 秒的新鲜期。任务详情在 `SUCCEEDED` 或 `FAILED` 时 MUST 使用 5 分钟新鲜期，其他或未知状态 MUST 使用 0。新鲜期 MUST 不等同自动轮询间隔或删除时间，状态变化后 MUST 按最新响应重新确定策略。

#### Scenario: 新鲜资料重复读取
- **WHEN** 同一会话在 1 分钟内重复读取已成功缓存且未主动失效的本人资料
- **THEN** 可复用缓存而不无故重复请求，主动刷新仍可请求最新数据

#### Scenario: 活动任务进入失败终态
- **WHEN** 任务详情从 `RUNNING` 更新为 `FAILED`
- **THEN** 之后按终态的 5 分钟新鲜期复用详情，不将任务失败误当作查询通信失败

#### Scenario: 服务端引入未知状态
- **WHEN** 任务详情返回尚未识别的状态值
- **THEN** 保留原始状态并采用 0 新鲜期，不自行判断成功、失败或启动轮询

### Requirement: 无观察者缓存有界回收且不持久化

服务端资源缓存 MUST 仅保存在内存，无观察者时 MUST 以 10 分钟为回收基线；重新观察 MUST 结束该次无观察者等待。缓存回收 MUST 不删除采集文件、清除语言偏好或判定认证失效，进程重启 MUST 不把偏好存储当作服务端缓存恢复源。

#### Scenario: 缓存回收不触及产物
- **WHEN** 无观察者资源达到回收期限且本地已有完成 CSV 或视频
- **THEN** 对应缓存可被回收，但产物和语言偏好仍保留，认证状态不因此变化

### Requirement: 前台和网络恢复只刷新允许的查询

应用 MUST 统一反映宿主前后台与网络可用性；返回前台或网络恢复时，只有已启用、允许自动刷新且已过期的活动查询可刷新。首次网络状态未知 MUST 不作为已断网的确定事实。该机制 MUST 不自动恢复采集、不启动任务轮询、不重放写操作或被取消的旧会话请求。

#### Scenario: 返回前台刷新已过期资料
- **WHEN** 当前已认证会话仍观察资料查询，资料已过期，应用从后台返回且网络可用
- **THEN** 触发允许的资料刷新，新鲜模型目录不因此重新请求；没有观察者的查询不因该事件全部加载

#### Scenario: 网络恢复不重放提交
- **WHEN** 一次写操作因离线或结果未知结束，随后网络恢复
- **THEN** 不自动重试创建、上传提交、资料修改或其他写操作，用户或业务会话仍需按原操作协议决定下一步

### Requirement: 查询刷新失败保留已确认数据

查询已有成功数据时，后续刷新失败 MUST 保留旧数据及最后成功时间，消费者 MUST 能区分刷新失败和首次加载失败；MUST 不用空列表、零值或成功状态覆盖失败。通用查询和变更 MUST 不自动重试，不自动做乐观成功。

#### Scenario: 有缓存的历史刷新失败
- **WHEN** 历史查询已有记录，刷新遇到网络错误
- **THEN** 消费者仍可读取旧记录并识别刷新错误，不将该结果表达为无记录或首次加载空屏

### Requirement: 参数与身份共同隔离查询

查询 MUST 沿用服务地址、渠道和会话代次隔离，并包含实际请求的资源标识及支持的筛选、排序和分页参数。语言只影响展示且响应本身不变时 MUST 不产生第二份缓存。退出或换号 MUST 继续取消旧请求、清理旧缓存并阻断迟到回写，不清除语言偏好。

#### Scenario: 分页切换和语言变化
- **WHEN** 用户先切换任务列表分页，随后仅切换界面语言
- **THEN** 不同分页使用不同缓存身份，而同一分页不因语言产生重复数据缓存

#### Scenario: 账号切换时旧响应迟到
- **WHEN** 旧会话查询尚未返回就退出或登录另一账号，之后旧响应到达
- **THEN** 旧响应不能重新填充当前或已清理的旧会话资源，当前身份无法读取旧账号数据，语言偏好保留
