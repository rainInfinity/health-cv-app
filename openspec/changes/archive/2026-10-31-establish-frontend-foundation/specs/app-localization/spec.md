# 国际化规格增量

## Purpose

为原生应用提供可预测、跨重启保留且不依赖云端的语言选择，使用户在简体中文、英文和跟随系统之间切换时，导航、功能文案、状态提示和格式化保持一致，而业务数据、单位及认证作用域不被语言改变。

## ADDED Requirements

### Requirement: 翻译资源使用分类 JSON

所有用户可见译文 MUST 从随应用打包的 locale JSON 文件加载，并按稳定 namespace 分类：`app/navigation`、`settings/language`、`acquisition/active`、`acquisition/passive`、`sensors/capture`。各受支持 locale MUST 提供完全相同的 namespace 与 message key 集合。TypeScript 模块 MUST NOT 存放译文；MAY 注册 JSON 文案 Store，或将稳定状态／错误码映射到 message key。加载 MUST 不依赖网络。

#### Scenario: 离线切换语言
- **WHEN** 用户在离线状态启动应用或切换 `zh-CN` 与 `en-US`
- **THEN** 应用从当前 locale 对应的 JSON namespace 显示文案，不等待远程下载

#### Scenario: locale 资源键集不匹配
- **WHEN** 不同 locale 的 JSON 资源缺少 namespace 或 message key
- **THEN** 资源一致性回归检查报告不匹配，不将不完整的资源集视为通过

### Requirement: 首次启动默认简体中文

应用 MUST 支持 `zh-CN` 和 `en-US`，默认及回退语言 MUST 为 `zh-CN`。没有保存语言设置的首次启动 MUST 显示中文，即使设备首选语言为英文；首屏 MUST 不先显示另一种语言再切换。首批文案 MUST 随应用打包，不依赖网络下载。

#### Scenario: 英文设备首次离线启动
- **WHEN** 英文系统设备尚无已保存偏好且离线启动应用
- **THEN** 首个可交互页面及导航显示简体中文，不出现短暂英文页面，也不等待远程翻译

### Requirement: 显式语言选择持久保留

语言设置 MUST 提供简体中文、英文、跟随系统三个选项；显式选择中文或英文后 MUST 立即应用并跨重启保留，不被后续系统语言变化覆盖。偏好保存失败 MUST 不宣称跨重启保存成功；退出账号 MUST 不清除语言选择。

#### Scenario: 英文选择跨重启和退出保留
- **WHEN** 用户选择英文，退出登录并重启应用
- **THEN** 页面继续使用英文，未登录的采集入口同样使用该语言

#### Scenario: 显式中文遇到英文系统
- **WHEN** 用户明确选择中文后将系统语言改为英文并返回前台
- **THEN** 应用保持中文，不把显式选择变为跟随系统

### Requirement: 跟随系统保存选择语义

用户选择跟随系统时，应用 MUST 保存 `system` 而非当时解析出的 locale；MUST 按设备首选语言列表顺序匹配中文或英文语言族，无匹配时回退中文。Android 返回前台 MUST 重新解析系统语言；最终显示语言 MUST 由偏好与系统语言派生。

#### Scenario: 首选不支持而后续英文受支持
- **WHEN** 用户选择跟随系统，设备语言列表依次为法语和英国英语
- **THEN** 使用 `en-US` 文案，保存的偏好仍为 `system`

#### Scenario: 系统中文语言族和无匹配
- **WHEN** 跟随系统的设备首个受支持语言为繁体中文，或列表仅包含不支持语言
- **THEN** 两种情况下均显示首发支持的 `zh-CN` 文案，不引入未提供的繁体翻译

#### Scenario: 后台修改系统语言
- **WHEN** 跟随系统的应用进入后台，系统首选语言由英文改为中文，然后应用返回前台
- **THEN** 当前页面及导航更新为中文，重启后仍处于跟随系统选项

### Requirement: 全部现有展示文案实时切换

应用 MUST 国际化入口、导航、语言设置、三个验证页及相机查询与配置面板，包括状态、权限说明、确认提示和错误。切换语言 MUST 更新仍显示的状态和错误，不重启采集、不重置输入或将译文写入业务实体。通用组件 MUST 接收展示文本而非绑定具体业务翻译键。

#### Scenario: 失败状态下切换语言
- **WHEN** 页面保留一个已知错误码的失败状态，用户切换语言并返回该页
- **THEN** 失败提示使用新语言，原始错误码与会话不变，不重复执行失败操作

#### Scenario: 保留参数草稿
- **WHEN** 用户修改了尚未提交的配置草稿并切换语言
- **THEN** 若该页面仍保留于导航中，草稿值不因翻译刷新而回到默认值；仍沿用正常离页生命周期的页面不额外承诺草稿持久化

### Requirement: 安全错误展示与原始事实分离

已知状态和错误 MUST 通过原始码及参数生成本地化提示。未知错误 MUST 显示通用安全提示，并在可用时提供请求标识；MUST NOT 直接展示底层异常或服务器原始消息，不使用译文判断业务分支。错误原因码 MUST 保留以便排查，不因文案切换改变失败语义。

#### Scenario: 服务器未知错误
- **WHEN** 收到含未知错误码、内部消息和请求标识的失败响应
- **THEN** 用户看到当前语言的通用失败说明及请求标识，不看到内部消息、堆栈或令牌

### Requirement: 格式化不改变业务语义

日期、时间与数字 MUST 按当前 locale 格式化；原始值 MUST 保留数值和时间语义。单位、服务地址、渠道和会话缓存作用域 MUST 不因语言切换改变；原生单调时间 MUST 不作为 Unix 日期显示，缺失值 MUST 不补为零或健康默认值。

#### Scenario: 英文展示传感器产物
- **WHEN** 用户切换英文后查看传感器记录数、时间区间与物理单位
- **THEN** 展示按英文格式化且单位、坐标和毫秒／微秒含义不变，不将单调时间格式化为日历日期
