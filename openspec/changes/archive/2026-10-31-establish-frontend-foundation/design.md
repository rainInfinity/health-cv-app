# Design

## Context

动机见 [proposal.md](proposal.md)。实施依据为 `docs/development/frontend-development.md`、`docs/architecture/technology-stack.md` 和 `docs/architecture/code-organization.md`。

已观察到的基线：

- `App.tsx` 以条件渲染切换三个页面，旧页面会卸载；它同时处理被动深链和顶层安全区。
- `index.ts` 在注册根组件前导入 `app/bootstrap.ts`；后者创建已有云端客户端、认证会话和 QueryClient，并发起恢复。无云端配置时 `appServices` 为 null，本地采集仍独立可用。
- `app/query/client.ts` 已关闭 query／mutation 重试，但未设置本次约定的回收和资源新鲜期。`resources.ts` 已有认证门控、完整资料写回和代次保护；`keys.ts` 已包含服务、渠道、代次及现有分页参数。
- `closeAcquisitionScreen` 解除订阅并等待关闭主动相机。被动页和传感器页清理订阅不停止原生会话；传感器在宿主后台由原生中断。
- `ActionButton` 已由相机与传感器页面跨功能复用；旧页面仍有硬编码样式和中文状态映射，部分错误适配保存了原始消息，需要展示边界迁移。
- 文档中的视觉值已确认，但不等于已实现；Expo localization、NetInfo、Lucide、SVG 尚需安装和当前 development build 兼容验证。

这是跨初始化、导航、样式、存储、查询和原生生命周期的变更，因此需要独立设计，不将这些职责塞入根组件。

## Goals / Non-Goals

**Goals:**

- 应用基础设施每进程稳定组装一次，React 重渲染不重建认证或 QueryClient，不增加恢复流程副本。
- 先在一个真实页面证明主题、文案和导航组合，再迁移所有既有验证界面。
- 页面视觉迁移不改变原生协议、采样所有权、文件保留和真实完成语义。

**Non-Goals:**

- 不新增服务端或业务层，不将验证入口解释为产品首页。
- 不预建通用组件库、事件总线、全局错误流程框架、第二套主题或状态镜像。
- 不为验证缓存而引入登录／历史页面、演示图表或假健康数据。

## Decisions

### 1. 显式初始化顺序与进程级服务复用

`index.ts` 负责启动顺序：先执行专用偏好初始化模块，注册 MMKV persistent 引擎，再创建语言偏好与派生 locale，之后才加载会消费文案的应用模块。该初始化模块内部显式创建 Store，不依赖兄弟模块静态 import 的偶然先后。保留现有 bootstrap 的认证恢复职责，不在页面 effect 再次 restore。

`app/providers` 组合 SafeAreaProvider、浅色 ThemeProvider、应用服务上下文，以及存在云端服务时的 QueryClientProvider。查询消费者必须先取得可用服务；无配置时不创建假客户端或另一份 QueryClient，根导航及本地页照常挂载。云端资源消费者订阅现有 auth 状态后取得当前代次的查询选项，避免只在首次渲染读取 enabled。

语言只依赖非敏感偏好，不等待远端认证完成。偏好缺失或保存内容不在三个支持选项内时按中文默认；真实存储访问失败保留可辨识失败，不静默改用内存 Map 后承诺持久化成功。

备选是让每页按需初始化，拒绝：会引入首屏闪烁、重复监听和缓存／认证多实例。

### 2. 验证导航而非产品导航

`app/navigation` 使用类型化 native-stack，路由为验证入口、主动 PPG、被动录像、传感器、语言设置。入口只列真实功能，语言设置可从入口进入，不创建底部导航或产品占位页。

统一处理初始 URL 与运行中 Linking 事件，删除 App 原有深链监听，避免双重跳转。被动深链解析为同一个目标，不因重复事件 push 新实例；冷启动导航历史包含验证入口，保证返回路径。已有 intent-filter 不改为新的地址。导航标题由当前 locale 派生。

原生 header 负责顶部安全区和返回；页面容器负责左右／底部安全区及滚动内容；无 header 的表面才自行负责顶部 inset。应用层统一系统栏浅色策略，移除各页重复 StatusBar 配置。输入页面使用适合当前 Android 键盘模式的避让和可滚动容器，不一律增加固定键盘高度。

备选是保留手工页签，拒绝：会继续自行维护返回栈、标题及深链。使用底部 Tabs 则会过早固定产品一级信息架构。

### 3. 主动相机离页作为异步资源交接

页面失焦清理不能代替异步导航阻断。返回、入口切换和深链跳转共用主动页离开保护：有打开、启动、采集或收尾中的主动资源时，先阻止导航，复用现有 closeCamera 路径并等待完成；同一次离开只允许一个在途关闭，成功后执行已确认的目标导航。保护使用导航移除阻断与应用路由入口共同覆盖返回和 push 型跳转，不仅监听 blur。

关闭失败时不执行目标导航，主动页显示结构化原因并保留再次关闭入口。重复请求同一深链合并；新的明确导航意图替换尚未执行的目标，但不再创建第二个关闭操作。迟到结果不得导航回旧页面或关闭后来新建的会话。

主动页订阅只负责低频状态，离页交接与最终卸载清理协调，避免两次关闭误伤；卸载仍保留兜底释放，不能作为正常导航的唯一关闭点。App 后台不走“自动导航”路径，继续由原生生命周期决定资源状态；回前台重新核对，不宣称支持主动后台持续采集。

被动和传感器页面离开仅处理展示订阅／局部刷新，不停止会话；返回订阅时读最新原生快照。被动服务后台行为、传感器宿主后台中断、相机互斥均保持既有实现。

备选是只用 useFocusEffect 在 blur 时异步关闭，拒绝：不能保证关闭完成先于下一页使用相机，也易与卸载清理重复。

### 4. 已确认 token 直接落地，交互角色仅作映射

`shared/theme` 类型化实现文档第 2.1 节全部已确认的颜色、字体尺度、间距、圆角、图标、动效及表面层级；ThemeProvider 仅提供浅色对象，不创建 ThemeMode Store。导航主题也从同一对象映射。文档中的示例名称不另造第二套 token，正式键以已确认表格为准。

尚未命名的控件角色以现有值组合，不新增色板：主要按钮底色／按压色映射 `brand.action`／`brand.pressed`，前景映射 `surface.default`；次要按钮使用 `surface.default`、`brand.action`；禁用表面和文字映射 `surface.subtle`、`text.muted`；焦点边界映射 `brand.action`。普通错误采用清晰的图标、标题与说明，文字保持 `text.primary`，不借用仅供评估结果的 status 色。分隔线不作为交互边界的唯一识别方式。

这些映射是本次设计的控件默认值，实施时补入开发约定；不改变已有基础 token。若可访问性验证证明需要新的色值或新的产品视觉语义，应提出范围变更，不由实施者私自扩大色板。

普通表面无阴影。主题集中定义浮起／浮层的平台映射，组件只引用语义层级；未使用的浮层不新增 UI。系统字体及数字等宽属性按已有平台能力应用。Lucide 显式导入真实入口和反馈所需图标，默认 24 dp、紧凑 20 dp、线宽 2 dp，按钮触控区域至少 48 dp。

不重新运行 skill 的设计系统生成以替换现有 token；仅参考其可访问性、触控、反馈和键盘规范。小组件样式就近，复杂面板按职责拆样式文件；原生预览尺寸和必要 Animated style 仍可直接传入，不强制包装。

`apps/native/tsconfig.json` 配置 `@/*` 指向 `src/*`。跨模块或跨功能的应用源码引用使用 `@/`；同一组件目录内的 `./styles` 等局部导入保持相对路径。每个原生 UI 组件位于同名目录，公开入口为 `index.tsx`，styled-components 定义放在同目录 `styles.ts`；非视觉应用壳没有样式时不创建空文件。

### 5. 基础组件按当前使用场景提取

提供当前页面真正使用的文本、按钮、输入项、卡片、状态反馈和页面容器；跨功能复用者进入 `shared/components/<ComponentName>/index.tsx`。ActionButton 全部调用方一次切换到共享按钮，移除旧路径和旧组件，不保留别名。

按钮支持明确语义变体、loading 和 disabled，加载时阻止按压并向辅助技术提供状态；业务命令保留独立在途保护。输入受控、标签可见、错误就近，长文案使用最小高度而非固定高度。状态反馈通过文字和图标表达，不把失败、无数据和进行中合为一个空态。

相机查询／配置面板迁移样式和展示，不删除高级参数或改变合法范围。既有文件列表保留查询范围说明；可持续增长的产物列表使用合适的虚拟化列表或有界展示，不借此新增历史业务分页协议。

### 6. 语言状态单源与安全提示映射

`app/storage` 仅提供 MMKV 偏好引擎；`app/preferences` 保存一个 `zh-CN | en-US | system` 选择；`app/i18n` 从偏好和 expo-localization 的语言列表计算最终 locale。匹配顺序为设备列表顺序，中文语言族统一映射首发简体中文，英语语言族映射 en-US，其余跳过，无匹配回退中文。语言设置明确提供三个选项，system 保存其语义而非解析结果。

共用的应用前台监听同时通知语言来源刷新和 Query 焦点更新，但各模块拥有各自计算规则；不把 locale 和选择维护成两个可独立写入的 Store。

用户可见译文统一保存在 `apps/native/src/app/i18n/locales/zh-CN.json` 与 `en-US.json`，按 `app/navigation`、`settings/language`、`acquisition/active`、`acquisition/passive`、`sensors/capture` namespace 分类。两个 JSON 作为静态打包资源注册到现有 `@nanostores/i18n` cache；`defineFeatureMessages` 以对应的中文 JSON namespace 提供类型化基准，资源回归检查保证各 locale 的 namespace 与 key 集合一致。TypeScript 功能模块只注册文案 Store，并将状态／错误码映射到稳定 key，不保存译文。原有语言派生、偏好和安全错误展示语义保持不变；若应用适配层只保留 `errorMessage`，则在 JS 侧保留必要的 `errorCode`／参数／`requestId`，原始底层 `message` 不直接进入用户文案，也不修改原生错误协议。已显示错误从原始错误事实派生，语言切换不重新执行命令。

日期／数字用 Intl；传感器单调时间仍显示明确单位的持续量，不转 Date，后端未含时区的时间按既有 Asia/Shanghai 契约处理，不用语言推断时区。单位、服务地址和渠道保持原始配置。

### 7. 查询生命周期补齐而非重建

复用 AppServices.queryClient、AppQueries 和 auth 的代次保护；统一配置 `gcTime = 600000`，保持 query／mutation `retry: false`，内存缓存不持久化。资源选项应用资料 60000、模型 1800000、列表 30000 毫秒新鲜期。本人账号 `me` 保持现有身份确认语义，不为它额外定义一份资料缓存策略。

任务详情使用依赖最新缓存数据的 staleTime 策略，SUCCEEDED／FAILED 为 300000，DRAFT／SUBMITTED／RUNNING／未知状态为 0。后端集成文档确认当前只有 SUCCEEDED、FAILED 两类终态；不增加前端自定义取消终态，不解析中文消息判断状态。本次不设置 refetchInterval，不建立 MeasurementSession 或页面轮询。

应用级安装 AppState 和 NetInfo 监听并可清理：初始焦点取当前 AppState，网络初始未知不直接判离线；明确未连接或可达性为 false 时标记离线，有连接且可达性未知时允许请求。由 Query 的 enabled、观察者、新鲜期及资源刷新选项决定是否刷新，避免全库 invalidate。没有云端服务也可初始化本地语言监听，不要求查询 Provider 存在。

明确采用 mutation `networkMode: 'always'`，避免离线时排队并在恢复网络后自动执行；失败保持原始错误，不调用全局 resumePausedMutations。查询可按网络状态暂停和恢复，但退出后不能恢复旧会话。focus／online 事件不调用任何业务写命令。

查询键覆盖当前 DTO 实际支持的参数，不凭空新增筛选／排序；将来协议增加参数时必须同时加入 key。当前切换语言不改变请求响应内容，因此不加入 locale。刷新失败让消费者保留 data 并识别 error，不另存一份页面列表缓存。

备选是新增 QueryClient 或把查询结果复制进 Nano Stores，拒绝：会破坏既有账号清理及单一权威来源。

### 8. 依赖与验证边界

通过 pnpm 安装与 Expo 57 匹配的 expo-localization、NetInfo、Lucide 和 SVG，锁定实际组合并使用 development build 验证。宿主配置通过 app.json／现有 config plugin 表达，不手改生成宿主作为唯一配置。不安装 ECharts、Reanimated 或第二套图标库。

使用现有 TypeScript 与 node:test 约定。永久回归只覆盖语言解析边界、导航交接竞态、资源隔离和缓存行为；不为 token 字面值、包装转发、文案或默认配置快照新增测试。查询生命周期通过真实 QueryClient、受控时间和可取消的异步结果验证，不能只断言配置字段。

应用 UI 使用模拟器实际操作及截图检查；新增原生依赖必须实际构建并启动。查询用临时联调脚本调用已有服务与 QueryClient，观察网络／焦点事件、缓存与身份隔离，不增加永久调试页。没有实际服务时继续完成本地部分，记录真实未验收项，不能将 mock 回显充当接口联调通过。

## Risks / Trade-offs

- 导航离页与异步关闭竞态 → 正常离开先阻断并等待，同一资源只运行一次关闭，覆盖返回、深链、重复点击和失败路径。
- native-stack 保留页面导致隐藏副作用 → 显式区分订阅可见性和原生会话所有权，不统一 stop-on-blur。
- persistent 顶层导入抢先创建 Store → 初始化模块在注册引擎后显式创建偏好，首屏前完成 locale 计算。
- 原始错误已有中文字符串 → 迁移 JS 展示事实与所有消费者，未知码使用安全通用提示，不重写采集协议或掩盖失败。
- 新依赖的 Expo／RN 兼容未证明 → 构建和实际表面验收作为交付条件，记录具体版本，不以安装或 typecheck 成功替代。
- 本阶段查询尚无产品 UI → 用临时真实联调验证基础设施，不扩建登录和历史页面；后续页面必须消费 data 与刷新 error，不能将本次称为历史页已实现。
- 模拟器不能证明厂商后台录像和真实人体信号 → 本次记录导航迁移回归与模拟器证据，不扩大既有真机可行性结论。

## Migration Plan

1. 锁定依赖组合，实现主题和有序偏好／语言初始化，组装 Provider；保持认证、客户端和本地采集模块不变。
2. 在主动 PPG 真实页接入基础组件及国际化，同时实现导航离开保护；先完成实际验证再迁移其他页。
3. 切换入口与深链到统一导航，迁移被动页、传感器页、相机查询和配置面板，移除旧切页逻辑、重复系统栏和旧按钮路径。
4. 补齐查询策略和统一原生生命周期接入，验证既有会话隔离与非敏感偏好保留。
5. 完成 development build 的实际操作与必要回归；更新 docs 中实施状态、运行方式和证据。提案本身不标记任何实施项通过。

本变更没有后端或文件格式迁移，也不修改安全凭据记录。若需回退，应在单独确认后回退本变更相关代码与依赖组合并重新构建，不删除采集文件、不清空 SecureStore 或 MMKV 全库；不保留运行时新旧导航双轨开关。
