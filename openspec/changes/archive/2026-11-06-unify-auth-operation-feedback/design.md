# Design

## Context

动机见 `proposal.md`。本次跨越认证页面、共享反馈主机与开发预览，需要统一约定 Toast 关闭能力和认证过程状态。

- `AuthScreen` 已有提交锁、`submitting` 和按钮 Loading，但请求错误分散在字段和 `formError`，没有过程 Toast。
- `UserScreen.signOut` 直接等待认证服务，仅显示结果 Toast；按钮是否存在由 `authenticated` 决定。
- `app/auth/session.ts` 的退出命令先推进会话代次并发布 `anonymous`，随后等待凭据删除、缓存清理与远端撤销。UI 不能用“是否仍登录”推断退出命令是否完成。
- `FeedbackHost` 位于应用根部，支持单条 Toast 替换；`SingleToastLifecycle` 已屏蔽过期计时回调，Loading 不自动计时。所有 Toast 当前都带关闭按钮，加载图标为静态 `LoaderCircle`。
- 当前主规格要求各态可关闭、持续错误不能只用 Toast，本变更通过 `app-feedback` 增量显式区分认证请求结果与持续状态，不修改后端契约。
- TSX 自绘功能插画位于 `pages/features/FeatureIllustration`，首页指标图形位于 `pages/home/HealthIndicatorArtwork`，品牌 TSX 组件位于 `shared/components/XinmuLogo`，导航还含内联图标，多处页面和共享组件直接引用 `lucide-react-native`。独立 `.svg` 文件不属于本次迁移并保留原路径；其中 `assets/xinmu-logo.svg` 仍由 `docs/design-demo/server.mjs` 提供给设计 Demo，Expo 开屏配置使用 PNG。

## Goals / Non-Goals

**Goals:**

- 单次操作的按钮、Toast 与真实异步完成状态一致，不以认证状态枚举代替页面命令状态。
- 复用根反馈主机、现有按钮及安全错误映射，不新增认证状态库或通用异步任务框架。
- 认证 Toast 不可由用户关闭，普通 Toast 的关闭能力不回退；减少动态效果时仍可读出过程状态。
- 为原生 TSX 插画、图标和品牌组件建立统一归属与具名导出入口，完整迁移使用方，不改变既有视觉和数值语义；独立 `.svg` 文件不迁移。

**Non-Goals:**

- 不改认证服务成功条件、超时、刷新、取消、凭据存储及远端撤销策略，不增加自动重试。
- 不增加全屏加载遮罩，不将 Loading Toast 变成阻塞页面的模态弹窗。
- 不改设计 Demo、其他业务页的错误提示或全局导航规则。
- 不抽离按钮、卡片和背景的 SVG 渐变渲染实现，不将动态指标图形转换为静态图片，不新增 Web 与原生共用的渲染层。

## Decisions

### 1. 显式声明 Toast 的用户关闭能力

在现有 `FeedbackToastOptions` 增加可选 `dismissible`，默认可关闭，三项认证操作的过程和结果均显式传 `false`。主机仅为可关闭 Toast 渲染关闭控件，不增加点击或滑动关闭。代码移除和替换不受该属性限制；非 Loading 沿用 3.5 秒默认计时。

不按 `tone === 'loading'` 全局禁止关闭：认证结果也不可手动关闭，而现有非认证加载预览仍需保留原行为。`dismissible` 只表达用户关闭权限，不等于禁止代码清理。

加载 Toast 沿用 Demo 的 `LoaderCircle` 图形，并按现有 `theme.motion.loadingCycle` 周期旋转；系统开启减少动态效果时保持静止。继续复用反馈 token、安全区、明确过程文字与读屏语义。

### 2. 页面拥有单次认证操作状态

登录与注册复用现有提交锁和 `submitting`。先执行本地校验，再加锁、切换按钮文案并显示不可关闭的过程 Toast；按钮加载时保留 Demo 的完整主题渐变、白色前景，并以旋转 `LoaderCircle` 替换装饰箭头；按钮仍不可重复触发，普通禁用态保持灰色。使用同一次服务调用的结果替换成功或失败提示，最后只释放按钮状态和提交锁，不在 `finally` 无条件关闭 Toast。

保留当前成功导航和用户名预填。由于主机位于导航上方，成功提示跨导航持续显示；旧页面卸载不得清掉结果。每次操作的异步收尾只能处理自身反馈，必要时以当前 Toast 序号或操作标识核对，不能由旧清理覆盖更新的提示。不引入全局队列或重试机制。

不为等待效果添加最短展示时间，快速成功允许直接进入结果。页面返回和模式切换不新增全局阻塞；若原页面已卸载，不再对其写状态或执行过期页面导航，完成反馈仍由根主机按真实结果收尾，不能遗留永久 Loading。

### 3. 分离本地字段校验与请求失败

本地必填、长度和确认密码不一致继续使用字段错误。请求返回的 `INVALID_CREDENTIALS`、`USERNAME_EXISTS`、网络或超时、安全存储失败等统一通过错误 Toast 呈现，不再写入用户名、密码错误或 `formError`。移除因此失效的通用错误状态、展示和导入。

复用结构化错误分类，不回显服务端正文；未知错误按当前操作使用“登录失败，请重试”或“注册失败，请重试”等安全兜底，移除旧通用提示。会话 `unavailable` 的页面说明和恢复入口保留，不把它当作一次请求 Toast 的替代品。

### 4. 退出按钮优先展示命令状态

`UserScreen` 增加独立退出命令状态和同步提交锁。确认弹窗保持原行为，只有确认后才加锁、展示“退出中…”按钮与过程 Toast。

渲染操作区时优先判断退出命令是否仍在途，再判断会话是否已登录；账号卡片登录入口也遵循同一过程状态。即使服务已发布 `anonymous`，完成前也不能展示可触发新登录的按钮或入口。账号内容仍按真实会话状态显示，不保留虚假的已登录身份。

沿用现有结果优先级：安全凭据删除失败优先，其次远端撤销未确认，否则显示成功；意外拒绝使用安全退出错误。所有路径替换过程 Toast 并结束按钮状态，不延迟本地会话隔离，不改动认证服务内部时序。

### 5. 用行为与原生交互验证边界

沿用 Toast 生命周期测试模式，验证加载不自动过期、结果重新计时、旧回调隔离；针对消费者可见行为覆盖认证错误映射、重复提交和退出提前切换。关闭按钮是否存在、按钮加载、Android 返回和跨页结果展示通过实际原生界面验证，不用源码文本断言代替交互。

开发反馈预览补充不可关闭过程到结果的受控演示，保留普通可关闭预览；演示结果须标识为预览而非真实认证成功。开发说明更新到 `docs/development/native-auth-session.md`，记录字段校验与请求错误的边界。

### 6. 集中管理 SVG 插画与图标

以 `apps/native/src/shared/graphics/` 为唯一归属，根 `index.ts` 通过具名导出提供 `@/shared/graphics` 入口，内部按以下职责分类：

- `illustrations`：迁移功能插画和首页指标图形。每个 React 组件使用同名目录、`index.ts`、实现文件及必要的 `styles.ts`，保留原有类型契约、尺寸和布局边界。
- `icons`：收纳自绘业务图标、从导航抽出的内联图标，以及实际使用的第三方图标具名导出。第三方图标仍来自 `lucide-react-native`，不复制源码、不全量导出图标库、不为简单转导出增加包装组件。
- `brand`：管理 `XinmuLogo` TSX 组件。`apps/native/assets/*.svg` 不属于本次迁移并保留原路径；其中 `xinmu-logo.svg` 由设计 Demo 消费，不为独立文件增加伪运行时导出。

所有原生页面、导航和共享组件从统一入口导入插画与图标，不再跨页面引用资源实现或直接引用第三方图标库。图形内部用同目录或内部模块导入，不能反向导入聚合入口形成循环依赖。完成迁移后移除旧实现、旧路径转发和重复定义，不保留兼容别名。

不建立字符串到全部图标组件的运行时注册表，不增加 SVG 加载依赖，不将所有路径塞进单个大文件；统一的是归属和公开入口，不是将独立图形合并为一个组件。按钮、卡片与背景中的 SVG 继续属于各自渲染实现，`ActivityIndicator` 等原生控件也不属于 SVG 资源。

迁移保持 token、`viewBox`、渐变实例唯一标识、尺寸、动画与减少动态效果、血氧数值驱动和无障碍语义；不为集中管理重绘图形。仅合并语义、形状及行为均一致的重复定义，不能因外观相近合并不同业务含义。

在 `docs/development/native-graphics.md` 记录目录分类、具名导出和导入示例、TSX 图形组件清单及新增规则，并注明独立 `.svg` 文件排除范围和现有消费路径。通过 Android 对首页、功能、我的、认证、引导、底部导航与反馈浮层进行迁移前后截图检查，动态指标同时检查空值和有效值；不为目录组织或转导出新增永久测试。

## Risks / Trade-offs

- [不可关闭 Loading 在异常路径遗留] → 每项操作成功、失败和页面离开后的收尾均须覆盖；Loading 不设置假超时，不伪装业务结束。
- [退出状态先变为游客导致按钮丢失] → 页面命令状态优先于认证状态渲染操作区，实际验证延迟远端响应。
- [结果只用短时 Toast，用户可能错过] → 保留原输入以便重试；本地字段校验和持续会话故障继续留在页面。
- [旧异步收尾关闭新提示] → 沿用序号隔离，不使用无条件 `finally` 移除提示，并覆盖迟到回调。
- [默认关闭能力影响其他调用方] → 新选项默认保持原行为，仅认证调用方显式关闭用户关闭能力。
- [资源迁移导致尺寸、渐变引用、动画或动态指标回退] → 保留图形契约和实例标识，逐项比较原生截图，并覆盖空值、有效值和减少动态效果。
- [统一导出引入循环依赖或全量图标注册] → 图形内部不反向引用根入口，第三方仅具名导出实际使用项，不建立运行时全量映射。

## Migration Plan

先完成图形资源集中归属、所有使用方迁移及视觉回归，再扩展共享主机并迁移登录、注册、退出页面和预览；同步去除旧表单请求错误路径，补充验证与开发文档。图形迁移不改变现有规格行为，两份认证相关规格增量保持原范围。无后端或持久化数据迁移。若回退，整体回退资源目录及其调用方，或主机选项及其调用方，不保留旧路径转发和两套认证错误展示路径。
