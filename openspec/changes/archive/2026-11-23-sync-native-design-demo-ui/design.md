# Design

## Context

动机与范围见 [proposal.md](proposal.md)。本次覆盖原生产品导航、结果展示、历史与真实被动服务入口，并同步对应 Demo 的展示交互；先固定数据与生命周期边界，再按平台实现相同设计语义。

变更发起时的实现基线与承接点如下；下列旧名称用于说明迁移来源，不代表继续保留其调用或占位限制：

- `FingertipResults` 已有看板、质量角标、解读和 `ProcessedPulseWave`，`FingertipResultSheet` 已处理自然高度、遮罩、约420毫秒展开及 Android 返回；剩余卡片差异主要是详情中的 `surfaceElevation.raised` 和缺少细边框。
- `FingertipMeasurement/fingertipResultsLifecycle.ts` 已将三秒可见等待、一次自动展开和明确同轮详情交接独立于采集。`ContactMeasurement/useContactMeasurementSession.ts` 通过可选 `presentationLifecycle` 保留已释放轮次的展示；血压 Hook 尚未使用此扩展。
- 血压通过 `app/measurement/bloodPressureCapture.ts` 维持同轮 PPG、IMU 和联合关闭屏障。其低频完成事实已经可用，不需要新的原生采样出口。
- 历史目前只有 `HistoryUnavailableScreen`，Tab 拦截；首页 `MetricDetailScreen` 只读，主按钮与详情复用打开详情动作。`UserScreen` 的健康记录仍走未开放反馈。
- `app/passive-capture.ts` 持有唯一 `passiveCaptureClient` 和只读快照。开发页已有启停、后台活动说明及权限错误处理；`enable()` 包含权限申请，`disable()` 等待收尾。原生状态区分 disabled、starting、waiting、observing、measuring、stopping、failed，没有独立的启用偏好可作为事实来源。
- 现有主题、styled-components/native、SVG、ECharts原生SVG和页面组件可满足界面需要。Demo 的DOM、模拟时钟、假授权、标签页偏好不进入原生。

现行规格的冲突在六份增量中显式处理：功能双分类与历史未开放、产品被动开关禁令、血压完成后无结果／重测、指尖详情轻阴影，以及只允许指尖详情往返的导航限制。真实采集协议不变。

## Goals / Non-Goals

**Goals:**

- 同步原生与 Demo 已确认的视觉层级和核心交互，原生布局、坐标、手势与安全区按原生实现，Demo 使用 DOM、CSS 与本地状态，不追求跨端逐像素复制。
- 将结果样例、历史样例、真实采集及被动服务状态分开，让采集完成、服务启用和健康结果成为不同事实。
- 只提取指尖与血压实际共用的结果展示能力，不引入完整测量业务包或通用报表框架。

**Non-Goals:**

- 不接结果后端、不上传、不推理指标、不读取真实文件补齐样例，不让本轮结果更新首页或历史。
- 不修改覆盖及贴胸准入、原生正式时钟、语音调度、相机所有权、联合文件屏障或被动解锁周期。
- 不复制Demo资料与反馈表单、演示登录、设置偏好及外部模拟控制；不改变原生真实认证和权限页职责。
- 不扩大为医学准确性、长期后台可靠性、多设备／极端字号验证，也不增加未使用依赖或持久化。

## Decisions

### 1. 保留三类展示来源，认证只控制产品健康摘要与历史

历史在 `pages/history` 内维护独立、只读、带稳定指标标识及测量日期时间的样例模块，数值对应 `docs/design-demo/data.js` 的32日序列。按现有命名约定使用 `bloodPressure`、`heartRate`、`respirationRate`、`oxygenSaturation`、`diabetesRisk`，不把Web的数组下标作为跨页面协议；心率记录保留主动来源，风险无记录。

历史过滤、统计、图表、最近10条、全部列表和详情都从同一筛选结果派生。以北京时间日历日期过滤，区间包含首尾；固定周期仅为1、7、30天，周期运算不受设备时区和夏令时影响。第四分段为“自定义”，提交后保持该分段与滑块选中，不再保留90天。默认基准日2026-10-31、7天，不将今天或最近一条日期当作基准日。均值等先用原数值计算，最后格式化。

原生首页与历史通过 `shared/dateTime` 统一显示北京时间中文日期与24小时制，避免 Hermes 的地区数据回退为英文或 AM/PM；正文短时间为“10月31日 08:30”，完整时间为“2026年10月31日 08:30”，趋势轴保留紧凑日期或时间。只格式化展示，不改变 ISO 时刻、日历运算或原生计时。

首页及指标详情仍使用现有 `selectHealthPresentation` 的固定摘要，不因为新增历史序列或一次采集改写其既有数值和时间。指尖、血压结果各持有自己的固定样例；血压118/73与历史中118/76并非同一真实记录，不要求相互覆盖。健康参考声明保留，不在业务页面额外重复演示说明。

历史页面及记录浮层都消费当前认证状态，只有 authenticated 可获得样例；退出或 unavailable 时立即清除可见读数，详情改为空态或关闭。检测内独立样例维持现有本地检测不要求登录的边界。所有样例不进入Query、账号资料、MMKV或采集客户端。

**替代方案：** 不把静态Web数据模块直接导入RN（它混有Web路由与第二套token）；不通过伪HTTP接口或Query模拟请求；不把历史扩展成采集文件浏览器。当前只读固定数据不需要这些层次。

### 2. 历史筛选归页面，外部入口只传一次指标选择

以 `HistoryScreen` 替换历史占位页，筛选保留在Tab仍挂载的页面状态中，不建立全局筛选Store。首次初始化固定默认值，普通Tab切回及“我的健康记录”只激活同一Tab而不重置。

指标详情进入历史时，仅通过有限路由参数传入目标指标；历史消费并清除此入口参数，避免以后普通切Tab又把用户选择重置成旧指标。当前日期区间不变，指标映射不依赖译文。

历史指标入口接入可复用的 `shared/components/SelectionSheet`，原生窗口高度的60%包含底部安全区，遮罩淡入、白色顶部圆角面板从底部滑入。固定头部为左取消、居中标题、右确认，选项区域独立滚动；打开时由已提交指标建立草稿，以主题色、浅青底和勾选表达选择，确认关闭完成后才提交。取消、遮罩或 Android 返回丢弃草稿，离页直接撤销本次窗口与动画；两侧相邻指标仍直接切换，均保留日期区间。Demo 复用其弹层宿主与 `selection-sheet.js`，高度按手机预览屏幕计算，不使用浏览器原生下拉框。

日期选择、全部记录和单条详情归历史页面受控，不新增导航容器。点击“自定义”或日历入口都从已提交范围建立日期草稿，打开弹窗不改变筛选。只有明确点选日期并确认合法范围才提交，自定义用既有自定义标识保留选中态并隐藏周期箭头；未选日就确认、取消或其他关闭均原样返回，仅浏览年月不算选日。反向范围留在弹层内反馈，点击固定周期恢复对应模式并沿用基准日。

日期标题加粗居中，移除关闭图标，缩短与正文间距；底部左取消、右确认，使用横向等宽按钮。年月头显示“2026年10月”，年份范围显示“2016至2027”，可分别进入十二年分页和十二月选择，选年后进月份、选月后回日期；当前入口与选中年月使用主题色。日期网格固定七列、六行，星期标题另计，不足六行补空白，不因切月跳高。日期背景与单元格分开：原生日格保留4 dp内边距，背景按可用宽度居中且宽高比1:1，最大边长为触控目标减8 dp，不拉伸原触控格；年月背景仍四边内缩。Demo 保留其日期背景内缩方式，按同一日历语义控制草稿。内容超出可用高度时内部滚动，不裁切必要操作。

列表和详情保存当前指标与区间上下文，详情返回先回原列表，最外层关闭才回历史。沿用白色圆角、原生 Modal 返回语义与虚拟化完整列表，不借浏览器控件或将可交互原生 UI 塞入字符串模板，不新增分页网络协议。

**替代方案：** 不为只在历史内部使用的三种浮层增加独立Tab或导航容器；不全局化筛选或持久化日期。现有Tab保留已足够支持本轮往返。

### 3. 历史趋势单独封装，复用绘图库而非脉搏波行为

在历史功能内建立只接收当前区间记录、主题及文案的趋势组件，沿用ECharts6和原生SVG适配，按需注册折线、网格、时间轴、图例／提示及极值能力。更新时按读数组件编号保留系列身份，以 `replaceMerge: ['series']` 移除旧系列而非 `notMerge` 整图重建；只有尺寸实际变化才resize，离页销毁实例和监听。Demo 同样保留实例与稳定系列标识，不新增WebView、Skia或其他图表依赖。

`PulseWaveChart` 会执行 `displayY = -rawY`，隐藏轴并面向六秒信号窗口，不能直接用于正向健康读数和日期坐标。历史保持实际值与测量时刻，右侧Y轴、起点X标签、232逻辑单位区域和图内右上图例按平台内容坐标布局。原生提示使用白底、无边框的柔和阴影 View，按选点及自然尺寸限制在图内，不拦截触摸；保留完整中文时间和所有读数，切换筛选、图例或尺寸时撤下旧内容。

原生按下时显示最近实际记录，确认横向意图后才接管拖动，纵向仍交给页面滚动；以按下坐标加绝对位移定位，不依赖SVG子元素坐标。仅跨到新记录时更新浮层，保留同一个提示节点与已测量尺寸，松手保留最后选中点，不平移或缩放坐标。Demo 用指针事件和横向捕获实现等价查看，保留纵向触摸滚动，并在关闭或离页释放监听，不复制浏览器事件到原生。

统计和记录不从图表内部状态读取，图例显隐只影响曲线、面积和极值；最高最低由同一筛选记录计算，重值取首个，相等合并。曲线平滑和面积只作用于显示，单条、空区间不造连线或零值。原生首次正尺寸绘制完成后执行一次350毫秒透明度渐入；原生与Demo在指标、日期和图例变化时执行约350毫秒 `cubicOut` 趋势过渡，拖动指示线即时更新，不叠加跟随延迟。动画不改写记录、统计或最终坐标，不重播原生首屏渐入，也不改变实时脉搏波的无面积、无曲线形状补间规则。

原生历史保持24 dp页面边距，指标标题为20／28 dp深青主题文字，各区域分别管理间距。历史周期与无扰开关共用 `InsetTrack`：原生底色／渐变上叠加真正模糊内阴影，不用SVG描边做硬轮廓；历史选中滑块只有品牌渐变和柔和外阴影，文字通过稳定的原生透明度节点与滑块同组执行240毫秒过渡。Demo 历史使用与原生同源的健康页渐变配方，账户背景不变。两端只在记录下方居中显示“检测仅供健康管理参考，非医学诊断依据。”。

**替代方案：** 不将趋势图硬塞进处理后波形组件，也不自行手绘第二条图表路线。有限固定记录不需要下采样或大文件方案。

### 4. 结果共用展示外壳，方式数据和采集控制保持独立

将现有 `FingertipResultSheet` 迁到 measurement 内共用的结果面板边界，正文由调用方提供，保留动画、自然高度、安全区滚动、独立边缘箭头、遮罩与返回处理；两方式分别组合完成文案、主卡及操作。既有调用方全部迁移，不保留旧名转发层或两套面板动画。

将 `ProcessedPulseWave` 的六秒报告视窗提取为同一功能内共用组件，接收标题、样本、总时长及固定显示纵轴。三处使用方为指尖PPG、血压PPG及血压SCG，各自持有窗口状态；复用底层 `PulseWaveChart` 的原生SVG、164高度、品牌细线和内边缘效果，不引入实时跟随或改变真实波形缩放。

PPG复用现有负向原始样例和固定显示范围。SCG参照Demo生成独立100Hz三十秒正负振动展示样例，在样例生成边界按统一绘图方向准备原始输入，并按最终显示值一次计算全轮固定纵轴，使数据占绘图区高度10%–85%；不在视窗适配中重复翻转，不读取ACC，不改真实缓存或文件。

指尖卡片去掉外部轻阴影并加浅色边框，保留现有网格、16内边距、图形、质量角标、参考行及解读。血压主卡独立实现阶梯带与双读数，弹层／详情同源，参考带用主题SVG绘制；薄荷绿评估及固定标记只是指定样例，不提取医学分级函数。质量82分不复用指尖梯形角标。

指尖与血压简要结果的短声明居中，与下方主按钮间距统一12逻辑单位，仅由按钮组顶部留白提供，不叠加声明底部外边距；Demo 使用对应12px间距。详细结果的声明位置与间距保持不变。

**替代方案：** 不复制指尖整个结果目录为血压专用版本；也不创建可任意配置医学报表的模型。共用范围只覆盖已经出现两种使用方的面板和报告波形。

### 5. 血压复用结果生命周期，但资格来自联合收尾

将现有指尖结果生命周期迁到接触式共用边界，输入只包含本轮身份、正常目标完成、资源已释放、错误及离开意图等最小事实；详情目标由方式提供，不再硬编码 `FingertipResults`。指尖和血压各创建自己的实例，不共享结果状态或captureId。

指尖适配沿用现有资格判定；血压由 `useBloodPressureMeasurement` 将真实联合完成快照投影为资格输入，再使用 `useContactMeasurementSession` 已有 `presentationLifecycle` 扩展接入。只有正常到达目标、PPG双CSV与ACC定稿、全部本轮资源释放且无错误或离开请求，才允许开始结果等待。原生正式30秒、语音、stopping和覆盖投影不变。

结果等待只累计前台且本检测页可见的单调三秒，只有这一处计时驱动结果；loading Toast跟随等待状态并按自己的ID清理。重复快照不重置，收起后不自动重开。后台仅暂停已经开始的展示等待，不让真实采集暂停续演。

正常完成后点击详情登记明确的方式和captureId交接；失焦只在已释放且匹配的目标详情保留展示，仍取消声音、暂停不可见绘图并注销采集订阅，不持有相机或IMU。详情返回恢复简要结果且不重等；普通失焦、离开、重测及卸载撤销资格和迟到回调。重测使用现有先关闭旧轮再prepare路径，复位覆盖、00:30及第一页指引。

**替代方案：** 不以计时归零、音频结束、单源文件或导航页名推断正常完成；不把样例放进全局结果缓存；不让两个详情页反向重建一次真实检测完成状态。

### 6. 检测与历史入口统一复用既有导航

功能页移除双分类、分类动画和指标卡片，保留三张 `CapturePhoto` 部位卡。首页血压主按钮与指标详情的测量动作统一调用 `app/measurement/entry.ts` 的方式映射和 `resolveMeasurementEntry`，保持跳过偏好；部位指尖不预选指标，指标入口携带有限目标但不改变算法。

指标详情发起新动作时先关闭自身浮层，再操作现有根栈或ProductTabs，不把整个Tab容器替换成新的实例。血压主按钮和独立详情按钮不再共用同一onPress。原生根栈增加 `BloodPressureResults: { captureId: string }`，不传样本或文件，不发布新产品深链；指尖路线保持同一语义。

检测返回依赖现有来源栈：未跳过时指尖／血压先回准备页，已跳过或当次跳过直接回原来源；面部沿用准备页替换语义。删除只服务旧双分类的局部状态、分支和文案，指标方式映射仍供首页使用，不误删首次引导仍使用的插画。我的健康记录改为激活历史，其余未开放菜单不动。

**替代方案：** 不给首页维护第二套方式映射，不添加隐藏准备页来伪造返回路径，不把开发Tab隐藏或顺带重构启动认证导航。

### 7. 无扰开关使用真实服务快照和共用命令

在功能页增加原生开关卡片，沿用首页心率SVG轮廓、健康卡渐变、柔和内阴影轨道、白滑块与青绿波纹，不绘制硬边轮廓。白色心率滑块增加柔和外阴影，与位移一起提交到实际原生 `style`，不只放在可能被合并丢失的 `attrs.style`。图形比例参照Demo，触控外框按原生至少48逻辑单位适配。只有右侧开关触发，文案与空白不触发，装饰动画不逐帧更新React。

开启稳定态由waiting、observing、measuring决定；disabled、failed显示未开启并按需反馈真实失败。starting、stopping以及权限／命令未完成期间显示忙碌并禁用切换，不能把启动请求或授权成功当作已启用，也不能在关闭收尾前宣称已完成。开关不展示实时bpm，不写首页或历史。

`app/passive-capture.ts` 继续作为唯一客户端和快照来源，将产品与开发实际共用的启停调用、瞬时命令防重及错误映射放到该边界，后台活动说明复用为两入口共用的应用交互。开发页现有配置和产物查询保留，两个UI入口不维护独立服务布尔值或并发启动路径。命令忙碌只表示当前共享操作，不持久化成启用偏好；通知的关闭仍通过原生快照同步。

后台设置说明从上至下固定为“已设置／不适用，继续”（主按钮）、“打开应用设置”、“取消”，原生产品、开发入口与Demo顺序一致。确认后调用既有 `enable()`，沿用相机、Android版本对应的通知授权和通知总开关／渠道检查；取消或只打开设置不启用。拒权和失败反馈安全中文及设置入口，不乐观显示成功。`disable()` 先阻断新触发并等待既有原生收尾，不扩大成全局关闭相机。

功能页聚焦及回前台刷新快照，展示订阅只负责低频状态更新；订阅的清理不能关闭服务。进程内多个页面订阅独立清理，不建立自动enable effect。启用成功等待新解锁，重启后核对实际状态而非恢复旧开关。真实解锁、后台相机和本地产物行为沿用既有实现，不增加周期设置或结果推送产品功能。

Demo 无扰开关与隐私偏好共用本地确认及启停流程：明确继续后等待约1秒再更新状态，关闭同样等待；等待中保持上次确认外观、显示局部加载并禁用重复操作。取消、仅进入Demo隐私设置或关闭说明不启用，切页或重置撤销未完成动作，刷新恢复关闭。不申请真实权限、不打开系统设置、不启动相机或服务，不生成心率或回写健康内容；此本地状态绝不迁入原生事实来源。

**替代方案：** 不复制Demo的 `passivePreference` 或在隐私页另建本地开关；不将开关点击变成进入开发页；不修改原生被动调度或提供绕过权限的快捷路径。

## Risks / Trade-offs

- [共享结果生命周期迁移可能破坏指尖往返] → 保留现有消费者生命周期验证，新增血压正常完成／联合收尾失败／往返与重测的核心契约覆盖；两方式实例与详情目标隔离。
- [原生趋势触摸、SVG文字和安全区与Web不同] → 用常规Android实际页面对照同状态、等价内容区域，并操作提示、图例、日期及记录；浏览器截图和类型检查不代替原生界面证明。
- [真实服务开关可能因系统授权、渠道或厂商后台设置而无法启用] → 复用现有知情和错误路径，如实展示快照，不添加假成功、自动重试或后台永久常驻承诺。
- [固定样例与真实检测同时存在容易混淆] → 样例模块、结果资格和采集状态严格分离，保留一次健康参考声明；不发布健康记录、不回写摘要，详细技术边界写入既有文档而非页面重复说明。

## Migration Plan

1. 在本地新增历史固定样例与筛选／统计逻辑；迁移结果面板、报告波形和结果生命周期的实际调用方，指尖保持原契约并统一卡片外观。
2. 血压接入联合完成后的结果资格、主卡和详情；保留原生资源屏障与重测路径。
3. 落地历史页面及浮层，替换历史Tab拦截；衔接首页、指标详情和我的健康记录，移除旧分类及占位路径。
4. 功能页加入真实无扰开关，将产品与开发启停收口到共用应用边界，原有配置、深链及产物查询不变。
5. 同步Demo的历史背景、底部单选菜单、自定义日历、趋势交互、结果声明间距与无扰确认等待；同步前端、测量、Demo说明和中英文资源键，以及提案、设计、增量与现行主规格。只记录产品和实现约定，不写验收流水；没有持久化数据或API迁移，不删除本地产物。

验证范围为受影响的核心成功路径、正常收尾资格、必要拒权／失败反馈及页面往返。历史日期和同源统计新增小型确定性验证，结果复用已有测试覆盖，产品开关检查真实启停与通知同步；不新增全量测试矩阵或长期后台验收门槛。原生不可达的真机行为如实说明，不能用假原生完成事件冒充真实闭环。
