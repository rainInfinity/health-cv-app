# Proposal

## Why

现有被动服务在解锁后直接保存前摄视频，没有人脸出镜判断和本地实时脉搏／心率结果。主动式完成后，应复用同一套 RPPG 内核，让解锁触发一个有界观察和测量机会，而不是继续依赖录制后上传处理。

## What Changes

- **BREAKING**：被动服务的新解锁执行路径从 `VideoCapture` 切换为无预览的 `ImageAnalysis` 与共用 `RPPGSession`；被动阶段、原因码和新产物引用不再伪装成录像状态或视频文件。
- 解锁仅触发候选机会；周期满足且相机可用时立即尝试，App 前后台不作门禁。首个相机帧实际交付时建立周期起点，无脸也计入；首帧前失败或相机忙不计入。不新增冷却、不排队、不自动重试。
- 有限观察人脸，连续满足共用就绪条件后才开始正式测量计时；观察超时结束，丢脸按共用规则分段，不无限延长会话。
- 原生前台服务继续拥有广播、通知、周期与启停；单次资源由共用会话拥有，不依赖页面、隐藏预览、JS 定时器或 UI 波形订阅。
- 复用共用逐搏瞬时心率，独立通过被动低频快照输出当前会话的初步值；不依赖页面或波形订阅，不另建被动算法，不逐搏刷新持续通知。
- 被动会话使用与主动相同的 `session.json`、`pulse.csv`、`hr.csv` 格式，标记 `source=passive`；无结果和合法中断可保留完整收尾的可解释产物，不伪装成达到目标时长。
- 保留旧录像实现和已完成视频查询，不新增视频／RPPG 双执行模式开关，不自动上传，也不删除已有相关代码或用户产物。
- 保留明确启用、权限和通知检查、厂商设置说明、锁屏中断、不自动恢复、相机互斥及真实设备证据边界；同步迁移 Dev 被动页和通知的语义。
- 以真实解锁至首个合格逐搏结果 6–10 秒为体验目标，不作为本次验收门槛；本次不包含专门的首结果时延、参考对照、误差和错误接受率验收。不足或超时不强制出值，短时配置与完整频谱窗口分别解释。逐搏值不进入频谱平均和最终频谱有效结论，不新增 CSV 或更改历史产物格式，不将未验证的准确性宣称为已通过。

## Capabilities

### New Capabilities

无；复用前置提案定义的 `android-rppg`，不重复定义算法、波形字段或文件格式。

### Modified Capabilities

- `android-passive-capture`：将解锁后的运行模式、周期起点、找脸／测量、收尾及结果交付迁移到共用实时 RPPG，同时保留历史视频。
- `native-app-shell`：被动 Dev 入口和真实产物展示改为实时采集状态及结果，保留历史视频可查；页面切换不终止被动服务。

## Impact

涉及 `passive/{service,runtime,trigger}`、`PassiveCapture.nitro.ts`、`src/passive/client.ts`、应用 `app/passive-capture.ts` 及 Dev 被动页面，调用主动阶段已经完成的 `RPPGSession`、结果存储和类型。通知与配置字段的语义、原因码及结束条件要同步迁移，不添加保留旧错误语义的别名。

不重新实现人脸、ROI、POS、滤波或输出 writer，不修改原始 PPG 双 CSV，不接入后端，不扩展正式产品入口。实施时更新现有被动协议、Android 测试说明和代码组织文档，不把历史录像验收误记为实时 RPPG 验收。

## 前置依赖与实施顺序

本提案依赖 `add-active-realtime-rppg`：先完成共用内核、主动 Dev 流程、完整三件套和主动模拟器闭环，并通知用户进行真机测试，再开始被动接入。提案文件现在创建不代表两个实现并行启动；主动真机证据未取得时须如实保留，不能由被动模拟器结果替代。若前置公共契约评审调整，本提案须在实施前同步，不维护第二套兼容接口。
