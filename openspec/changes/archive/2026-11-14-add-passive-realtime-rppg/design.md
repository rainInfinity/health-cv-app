# Design

## Context

动机与迁移范围见 `proposal.md`。当前 `PassiveCaptureService.beginCapture()` 获取租约并创建视频临时文件，`runCapture()` 调用 `PassiveVideoRecordingSession`，依赖 `VideoRecordEvent.Start` 记周期和时长，完成 Finalize 后发布视频。`PassiveCapture.nitro.ts` 的 `recording`、`durationSeconds` 和产物字段均具有录像语义；页面及通知直接使用这些状态。

本设计以 `add-active-realtime-rppg` 已完成为前提，公共契约参见其 `specs/android-rppg/spec.md` 和 `design.md`。前置公共对象采用 `RPPG` 命名；不得将本提案实现成另一套算法。此时主规格仍描述录像是当前行为，这正是本提案需要完整迁移的冲突，不以只新增旁路掩盖。

服务、客户端、通知、配置和旧视频保留构成跨模块行为迁移，故本提案必须包含设计。

## Goals / Non-Goals

**Goals:**

- 将解锁机会控制与单次共用 RPPG 执行分开，周期、正式时长和信号采集各有明确时间语义。
- 原生后台所有权独立页面，停止与结果发布竞争可收敛，历史视频仍可查询。
- 先完成模拟器真实调用闭环，再通知用户进行被动真机验证，证据不能借用旧录像记录。

**Non-Goals:**

- 不补写第一阶段未完成的主动流程，不并行启动两个实现阶段。
- 不维护双模式录像开关、自动降级回录像、额外找脸冷却、排队或重试。
- 不增加后端、自动上传、身份识别、隐藏预览、自动恢复服务或新的权限类型。

## Decisions

### 1. 显式前置门槛，不以规划状态代替功能完成

实施本提案前核对主动提案已经实现共用 `RPPGSession`、同源波形／HR／三件套、主动 Dev 全流程和模拟器证据，并已通知用户进行真机测试。前置提案仅文件齐全、编译成功或任务部分完成不满足门槛。主动真机尚未完成时保留待验收，不用被动模拟器结果补写主动真机通过；被动自己的后台可行性还要独立真机证据。

本提案复用公共模型、版本化试验参数、writer、ArtifactStore、源和算法；如果第一阶段评审修改接口，先同步本提案，不能建立别名或第二套文件格式。两份 delta 无同一 requirement 的并行修改：第一阶段新增 `android-rppg` 并修改原始输出限制，本阶段修改 `android-passive-capture` 与被动导航展示条目。

### 2. 服务只管理机会，会话独占单次资源

保留 `passive/service/` 的 `LifecycleService`、广播及通知，`runtime/` 的启停与实际状态核对，以及 `trigger/PassiveCycleGate` 的周期职责。新 `ActivePassiveCapture` 只持有 attemptId、共用 `RPPGSession` 引用、停止信号及代次；不再携带视频临时文件和独立相机 lease。

服务在候选机会通过门控后创建 `RPPGSession`，传入服务生命周期、无预览提供者、`source=passive` 和独立配置。相机租约仅由会话获取、释放，避免 service 与 session 双重获取。相机忙返回跳过原因，不改周期、不抢占、不自动重试。

本阶段将共用相机源真正用于仅 `ImageAnalysis` 的组合，并按该组合重新确认支持尺寸／FPS，不能复用主动 Preview+YUV 的支持结论。service 生命周期停止才影响此相机会话，React 页面卸载或 App 可见性不影响它；不创建任何隐藏 Surface 来满足旧相机接口。

备选的“服务直接拿帧并跑处理器”会绕过共用停止和结果屏障，因此不采用。

### 3. 三个时钟边界明确且只有一个触发周期

1. 解锁事件：核实启用、权限／通知、真实解锁状态、当前 attempt 及周期。亮屏、打开页面、周期到期不独立触发，不添加解锁后固定延迟。
2. 首个观察帧：共用会话首次实际交付帧时读取 `elapsedRealtime` 并通过绑定 attemptId 的一次性通知交给 service；这里调用周期 `recordStarted()`。不拿传感器时间直接与服务时钟比较，也不等待人脸或 HR。
3. 人脸连续就绪：由共用会话开始正式测量截止，观察耗时不占正式测量时长。

没有额外冷却。已交付首帧后无脸、信号不足或中断均占用该周期；首帧前打开失败、相机忙不占用。等待期间不打开相机，周期到期仍需新的解锁事件。首次启用的第一个机会无须先等待周期。开机时间回退或进程重建不恢复旧服务周期，保持显式重新启用规则。

服务周期和共用算法配置分开：`PassiveCaptureConfig.intervalSeconds` 保留周期含义，原 `durationSeconds` 迁移为明确的 `measurementDurationSeconds`，不保留旧字段别名；观察／就绪和信号参数引用共用 `RPPGConfig`。持久配置迁移时将合法旧时长保留为正式测量时长，非法或不足成窗的值在 Dev 页明确提示并要求用户修改，不能静默替换成另一时长或拒绝所有短时无结果验证。不得把旧启用偏好当作服务运行；迁移配置本身不启动服务。

试验推荐沿用第一阶段的观察 5 秒、连续就绪 1 秒及正式 30 秒；这些仍是评审中的工程基线，周期值沿用用户配置，不擅自设置新的采集频率。POS 保留 1.6 秒，逐搏确认和质量规则引用公共配置。短时配置可能先产生逐搏初步值但没有完整频谱窗口，也可能只有波形或无结果；页面分别说明，不把频谱最低时长解释为所有心率输出的最低时长，不承诺有效心率。

### 4. 状态表达实际工作，不保留录像假语义

服务对外阶段采用 `disabled/starting/waiting/observing/measuring/stopping/failed`。`starting` 覆盖服务启动和单次打开的细节由 reason 区分；持续通知分辨等待、找脸、测量和收尾。没有当前会话时 `sessionId=null`，合法结束的 `lastReason` 与完整产物信号结论分别保留，不把无脸或质量拒绝等同于服务技术崩溃。

Nitro、Kotlin runtime、TypeScript client、i18n、Dev 页和通知一次性迁移状态及字段，移除新路径中的 VIDEO_* 原因和对 Finalize 的等待。不会添加 `recording` 到 `measuring` 的兼容映射。旧视频内部类及错误仍保留在旧录像模块，因为用户明确要求暂不删除，不再由新的解锁执行调用。

不新建被动算法目录，不创建被动专属 writer。页面默认不订阅高频波形，离开只解除订阅，不停止服务；有无订阅均不改变结果。

#### 4.1 被动逐搏快照复用公共契约

`PassiveCaptureSnapshot.latestInstantHeartRate` 复用主动变更定义的可空 `RPPGInstantHeartRate`，独立保留当前会话、片段和峰采集时间，不重复定义峰算法或阈值。service 接受当前代次的合格逐搏结果和失效清空，交给 runtime 低频快照；即使阶段没有变化也能更新结果，但持续通知仍只按阶段变化更新，不按逐搏频率刷新。

无页面、无 JS 订阅时原生逐搏检测仍运行。无效 ROI、切段、心搏超时、停止、会话结束及新会话开始均清空当前值，旧代次结果不得污染下一会话或恢复已停止状态；Dev 页只将测量阶段的合格值显示为“逐搏瞬时心率（初步）”，没有当前结果时显示等待／不足而非历史 bpm。页面离开不影响后台计算。

首结果从真实解锁事件起计，以 6–10 秒为体验目标而非本次验收门槛，不从人脸就绪后重新计时来声称达标。目标不覆盖无脸、相机拒绝或低质量必然出值，也不改变周期、默认正式时长或提前结束策略。本次不包含专门的阶段耗时、参考对照、误差和错误接受率验收；不能用合成峰确认时间冒充真实解锁首结果时间，也不能据此宣称人体准确性。

逐搏结果仅为实时快照，三件套和历史查询保持公共契约；存在初步值不能把没有有效频谱窗口的 `signalStatus` 改为有效。`hr.csv` 仍仅存频谱窗口，不增加被动专属文件或逐搏 CSV，不将应用重开后的历史文件展示为当前逐搏结果。


### 5. 关闭／锁屏与首帧／发布的竞争

attempt 由 service 的事件互斥及代次控制，单次取消和定稿由 `RPPGSession` 控制，不能两边各维护一个独立“成功”事实。收到关闭先将 `acceptingEvents=false`，再唤醒本次停止，等待会话关闭和存储屏障，最后结束 service／通知。锁屏只停止当前机会，启用状态仍可回到等待。

首帧回调和取消在同一串行控制上下文判定：首帧事实先被当前有效 attempt 接受则计周期，即使紧接着取消；取消先使 attempt 失效则迟到回调不建立新周期、不创建结果或恢复等待。结束回调必须匹配当前 attempt；旧会话不能修改下一次的状态或释放其相机 lease。

目标时长、用户关闭、锁屏等终态只能选择一次；目标到达与关闭相遇时，以终态提交前实际接受的停止事实决定，关闭先被接受就不标 target_duration。合法已采记录可完整收尾并发布 interrupted 三件套；文件写入失败、首帧前失败或进程死亡不伪装成合法中断成功。服务关闭等待真实资源释放，必要的超时按错误报告，不能仅吞异常后显示已关闭。

### 6. 新结果与历史视频并存，但不是双执行模式

新会话使用 `acquisition/rppg/<sessionId>/` 和公共三件套，`source=passive`；查询时按来源区分主动／被动，但算法及 CSV schema 完全相同。观察超时已有帧时保存 no-result、header-only 文件及实际观察范围；测量中断只保存可定稿内容，不能跨段补信号，也不把无有效 HR 的产物删除。

当前视频结构继续在原 `passive-capture` 路径，由 `PassiveVideoArtifactStore` 查询并保留其媒体校验规则。API 将 `listArtifacts()` 定义为新 RPPG 结果，增加明确 `listVideoArtifacts()` 查询历史视频；类型采用共用 `RPPGArtifact` 与视频专属类型，不能用带一堆 nullable 字段的单一对象混合。这是有意的历史能力保留，不是为旧状态创建 alias。现有调用方、Dev 页产物区域同步迁移，标签明确实时结果和历史视频。

不删除 `PassiveVideoRecordingSession`、旧视频存储实现、文件或已有相关上传实现；但新服务执行不调用录像和上传，不新增上传能力。本阶段观察到的采集包没有自动上传调用，不能在实现／文档中虚构已有上传行为。

### 7. Dev、权限和验收保持一致

UI 继续在 `apps/native/src/pages/dev/acquisition/PassiveCaptureScreen/`，用于配置周期、正式时长、启停及真实阶段／结果查询，不扩展产品导航。保留可见页面的显式授权，通知可用性、厂商后台设置提示和关闭入口；不能通过 ADB grant、自动弹页面或隐藏通知绕过。系统停止、进程死亡、重启不自动恢复。

回归重点是首帧前后周期、边界时刻、无脸占周期、重复解锁 busy、观察到测量的计时、无 UI／无订阅、主动竞争、锁屏／关闭／首帧／发布竞争，以及历史视频仍可查询。永久测试覆盖状态和文件行为，不测文案或转发。

逐搏增量验收还须覆盖阶段不变时的新结果／清空、无页面仍计算、旧会话隔离和停止后无当前值；实际检查主动与被动复用同一算法且阈值一致。本次不要求专门的真实解锁首结果时延与参考对照验收；已有模拟器记录只证明实际覆盖的功能，不能将此前三件套或后台验证等同于人体准确性通过。

模拟器使用同一个 MCD 样本，验证真实 `USER_PRESENT` 和采集／产物，不把按钮手动开始或直接广播当成解锁证明。无脸变体仅检验状态，原素材参考对齐规则沿用主动设计。模拟器完成后通知用户真机测试；后台可行性必须在真机记录真实解锁、目标周期等待、重复打开、通知关闭及文件内容，不用旧录像记录替代。

## Risks / Trade-offs

- [Android 与 OEM 拒绝后台相机] → 保留可见授权和厂商设置说明，实测失败如实记录，不改为自动弹页面或持续持有相机。
- [短观察窗口错过出镜] → 参数作为可追溯试验配置评审，超时后计周期并结束，不增加隐藏重试。
- [旧 durationSeconds 被误当总持机时间] → 显式迁移为正式测量语义，UI 分辨观察上限和正式时长，记录升级规则与短时无结果边界。
- [旧视频保留易被误认为新模式仍录像] → 新通知和产物分区明确命名，服务不再调用录像，不提供双模式开关。
- [主动与服务因共用实现共享状态] → 一次会话一套处理器／配置／队列，仅设备互斥共用，回归旧代次释放和跨源停止。
- [取消时已有展示或文件记录被错误判成功] → 使用公共会话屏障和单次终态提交，区分完整文件、中断及有效心率三个维度。

## Migration Plan

先确认主动依赖门槛，再迁移配置与类型、service 执行、状态／通知／页面和历史视频查询；同一批更新所有调用方，不发布中间半迁移版本。配置迁移不启动服务，旧文件不改名、不覆盖。

实现后更新 `docs/acquisition/android-passive-capture.md`、`docs/development/android-development.md`、`docs/architecture/code-organization.md` 的当前行为及新证据。规格归档／同步时还须将 `android-passive-capture` 的旧录像 Purpose 更新为实时机会式采集，不能在本次仅规划阶段直接改主规格。先主动、后被动归档，确保公共 `android-rppg` 契约已进入主规格。

回退本阶段代码时停止当前服务，保留完整三件套和历史视频；不自动恢复旧录像服务、不删除已发布结果，不把回退作为运行时自动降级。

## Open Questions

- OEM 目标周期等待后的实际相机可用性和功耗，由用户真机测试补充；失败不改变“不抢占、不重试、不绕过授权”的边界。
- 第一阶段实际采用的可配置试验阈值以其评审版本为准，本阶段不另行调一套；若公共行为变更，先同步规划再实施。
