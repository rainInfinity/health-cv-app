# Spec Delta

## MODIFIED Requirements

### Requirement: Android 采集入口独立于云端与认证
应用 MUST 提供可手动操作的 Android 主动相机采集入口，默认选择后摄，并允许用户显式选择采集链路支持的单个前摄或后摄；不要求登录、云端环境变量或成功的网络请求。创建采集客户端、仅渲染界面、枚举或查询能力 MUST NOT 自动打开相机或开始保存数据。产品指尖页及血压页可承接用户明确进入本轮检测的动作执行授权及预览准备，但正式保存 MUST 等待本轮真实准入条件，不得将页面挂载本身视作采集命令；指尖保持真实覆盖稳定就绪自动开始，血压还须满足本规格的贴胸准备准入，不增加主动确认或手动开始按钮。

#### Scenario: 无云端配置进入采集界面
- **WHEN** 应用没有配置服务地址和渠道且用户尚未登录
- **THEN** 用户仍能进入独立采集界面并手动查询、配置和请求打开相机，采集路径不要求先执行云端请求；用户明确发起产品指尖或血压本地检测也不依赖云端

#### Scenario: 仅创建血压客户端或渲染页面
- **WHEN** 尚无用户明确发起本轮血压检测的动作，仅创建客户端、订阅或渲染界面
- **THEN** 不打开相机、不注册 IMU 监听、不创建正式文件；挂载及订阅不替代本轮启动命令

### Requirement: JS 只接收控制结果和低频信息
原始 PPG 采集接口 MUST 只向 JS 提供能力、配置、状态、锁定、经验提示、覆盖估计、错误和完成文件等低频信息；MUST NOT 传递原始像素、逐帧 PPG 行、相机元数据、文件记录批次或共享像素缓冲区，预览使用原生视图。波形例外仅限独立、有界、可解除订阅的定稿展示脉搏标量：RPPG 遵循 `android-rppg`，指尖遵循本规格的同轮真实样本及批次隔离要求；不得因此放开原始采集记录或在全局业务 Store 累积全量信号。逐搏心率仍为独立、可空的低频结果，保留片段与峰采集时间，不复用频谱窗口字段或跨桥发送逐帧峰检测状态。血压仅新增同轮阶段、覆盖就绪、姿态、稳定性、心震候选、计时、错误、文件与释放事实等低频信息，MUST NOT 输出血压波形或原始 IMU 样本。

#### Scenario: 采集持续运行
- **WHEN** 相机连续交付图像并保存多块 PPG 与相机元数据
- **THEN** JS 只观察低频状态和必要提示，不接收逐块／逐帧原始记录；独立手动采集不因新增指尖展示协议而自动推送波形

#### Scenario: 主动 RPPG 展示定稿波形
- **WHEN** 新 RPPG 会话存在 UI 波形订阅
- **THEN** JS 仅收到带会话、片段、序号和采集时间的有界标量波形批次及低频结果，不收到像素、逐帧 RGB、关键点或相机元数据；展示缓冲不承担完整结果存储

#### Scenario: 新逐搏结果或结果失效
- **WHEN** 原生确认新的合格搏间间隔，或当前逐搏结果因切段、超时或停止失效
- **THEN** 低频快照分别更新或清空 latestInstantHeartRate，原频谱 latestHeartRate 字段与平均语义保持独立；无效期不重复发送旧值冒充当前结果

#### Scenario: 指尖展示真实脉搏
- **WHEN** 正式指尖轮次存在展示订阅且原生形成有效脉搏样本
- **THEN** 只推送该轮有界脉搏批次，保留真实采集时间、片段及序号，不发送原始 PPG 行、不套用面部会话或生成健康指标

#### Scenario: 血压观测与正式采集
- **WHEN** 血压轮次正在观测 IMU 或保存 PPG 与 ACC
- **THEN** JS 仅取得同轮低频事实，不接收原始或滤波后三轴数组、逐事件状态或脉搏批次，不因复用指尖采集而开放血压波形

## ADDED Requirements

### Requirement: 血压轮次阶段与准入事实可观察
血压轮次 MUST 具有独立轮次标识，并如实区分指尖覆盖观测、贴胸准备、正式启动准备、正式采集、收尾及真实终态。原生 MUST 提供本轮覆盖估计及就绪、屏幕倾角、IMU 稳定性、心震候选及其是否已评估等低频事实；无有效或新鲜输入不得冒充已就绪。阶段、计时与准入 MUST 由本轮真实原生状态决定，不由分页、动画、JS 定时器或上轮快照推进。

#### Scenario: 尚无有效 IMU 输入
- **WHEN** 已进入贴胸准备但当前轮次尚无足够有效 IMU 观测
- **THEN** 未评估项保持未知且不满足准入，不把默认倾角、旧稳定值或旧心震候选当作当前结果

#### Scenario: 切换说明分页
- **WHEN** 血压页面切换可见指引或暂不消费状态通知
- **THEN** 原生观测继续，业务阶段及自动开始资格不由分页或动画结束改变，恢复后可读取当前真实快照

### Requirement: 血压完整覆盖稳定后进入贴胸准备
血压 MUST 复用指尖真实空间覆盖估计与原生三秒门控：完整覆盖连续至少三秒且输入新鲜后，才从指尖阶段进入贴胸准备，不直接开始正式保存。非完整覆盖、输入失效、时间回退或超过 200 ms 的帧缺口 MUST 清除准入稳定累计。覆盖与贴胸准备不计入正式三十秒，独立指尖轮次仍按既有单源规则自动开始，不增加贴胸条件。

#### Scenario: 指尖覆盖达到门槛
- **WHEN** 血压本轮真实完整覆盖连续至少三秒且输入新鲜
- **THEN** 进入贴胸准备并开始本轮 IMU 准入观测，倒计时仍为三十秒，准备样本不进入正式文件

#### Scenario: 覆盖短暂完整
- **WHEN** 完整覆盖不足三秒即失效，或期间出现超过 200 ms 的帧缺口
- **THEN** 留在指尖覆盖观测并清除累计，不用累计等待或动画满环替代连续真实覆盖

### Requirement: 血压按稳定性与两条替代条件自动准入
血压正式开始 MUST 同时满足本轮覆盖就绪、IMU 稳定以及“屏幕平面相对水平面倾角至少 30° OR 心震候选成立”，并完成必要相机锁定及各源准备后重新确认条件，才自动建立唯一正式窗口。倾角 MUST 按平放 0°、竖直 90°解释，不要求经历竖起动作。IMU 稳定 MUST 基于本轮真实 ACC 与陀螺仪的有限时间观测，不以单个姿态值或页面动作代替；准入仅为工程条件，不保证贴胸位置或医学质量。

#### Scenario: 进入时已经竖直持机
- **WHEN** 屏幕倾角已经至少 30°、覆盖就绪且当前 IMU 稳定，但未观察到竖起过程且心震候选未成立
- **THEN** 所有正式准备完成并重新确认条件后自动开始，不要求用户先平放再竖起或手动确认

#### Scenario: 小倾角但有心震候选
- **WHEN** 屏幕倾角小于 30°，当前心震候选成立且覆盖就绪、IMU 稳定
- **THEN** 可经相同准备及复核自动开始，不把倾角与心震误写成必须同时满足

#### Scenario: 姿态满足但持机不稳定
- **WHEN** 倾角至少 30°或心震候选成立，但当前 IMU 不稳定
- **THEN** 保持准备观测，不因替代条件之一成立跳过稳定性要求，不创建重复正式会话

### Requirement: 心震候选在贴胸准备与正式采集中持续观测
系统 MUST 从进入贴胸准备起直至正式采集结束持续使用真实 ACC 观测心震候选，检测适用于任意倾角，不因倾角至少 30°、已走姿态准入路径或页面不可见而关闭。候选 MUST 来源于有限时间内的真实加速度变化，仅表达本地工程候选，不表示确认胸口接触、有效心搏或血压结果；实际采样不足以支持候选所需频带时 MUST 表示未知，不通过缩窄频带或伪造输入放行。正式开始后，单次候选或稳定性失效 MUST NOT 暂停、补时或重启本轮窗口。

#### Scenario: 大倾角路径正式开始
- **WHEN** 血压在倾角至少 30°时通过准入并正式采集
- **THEN** 心震观测在准备及正式阶段均继续，当前低频候选可随真实输入更新，不因姿态分支已成立停止检测

#### Scenario: 正式采集中候选消失或稳定性变化
- **WHEN** 正式窗口中一次心震候选不成立或 IMU 稳定性变为不满足，且没有采集错误或其它中断条件
- **THEN** 保留当前观测事实，仍按原三十秒截止运行，不回到准备、不暂停、不补时、不重开正式窗口

#### Scenario: 实际采样不足以评估心震候选
- **WHEN** 当前实际 ACC 采样不足以支持心震候选所需频带，但 ACC 与陀螺仪真实可用且倾角和稳定性仍可有效评估
- **THEN** 心震候选保持未知且观测继续，不静默缩窄频带；覆盖就绪、IMU 稳定及倾角至少 30°仍可独立满足准入，不把候选未知伪装为成立

### Requirement: 血压正式开始前条件失效重新观测
贴胸准备或正式启动准备期间，覆盖不再就绪 MUST 退回指尖覆盖阶段并清除本轮 IMU 准入累计及旧候选；再次完整覆盖需重新稳定三秒并建立新的有效 IMU 观测。仅稳定性或两条替代准入条件不再满足时 MUST 保持或返回贴胸准备，等待当前有效条件重新成立。未开窗准备 MUST 可撤销，不发布准备文件为正式产物；迟到准备结果不得凭旧条件开窗。

#### Scenario: 准备写入器期间移开手指
- **WHEN** 正式文件或必要锁定正在准备，但覆盖就绪已经失效
- **THEN** 撤销本次未开窗准备，退回指尖阶段并清除 IMU 准入；旧准备完成通知不能开启窗口，重新放回后重新累计

#### Scenario: 准备期间稳定性失效
- **WHEN** 覆盖仍就绪，但正式开窗前 IMU 不稳定或两条替代条件均不成立
- **THEN** 不接收正式样本并继续贴胸准备观测，不把准备期消耗计入正式时长，不用曾经成立的快照放行

### Requirement: 血压共同接收窗口由原生统一控制
血压 MUST 在本轮 PPG 与 ACC 都完成正式准备且准入复核通过后，以原生启动后单调时间建立共同半开接收窗口 `[T0,T1)`，目标三十秒，统一开始、截止及已用／剩余时间。PPG MUST 按处理入口时间、ACC MUST 按回调接收时间检查共同上下界，ACC 还须排除原始事件时间早于 T0 的历史事件。两源保留各自原始采样时间、队列及文件，准备数据及窗口关闭后的新输入不得进入正式记录。该窗口 MUST NOT 被描述为硬件同步、精确曝光同步或相机帧与 IMU 事件逐条对齐。

#### Scenario: 两源准备耗时不同
- **WHEN** PPG 已完成准备但 ACC 尚未准备完成，或相机仍待必要锁定确认
- **THEN** 两源均不开始正式接收；全部准备完成且当前准入复核通过后，才采用同一正式控制边界，准备耗时不扣倒计时

#### Scenario: 共同窗口已经截止
- **WHEN** 原生共同窗口达到三十秒而 JS 尚未处理通知
- **THEN** 原生封闭两源正式入口并开始收尾，不等待 JS 停止、不接受截止后的新记录、不延长窗口；已经接受的在途配对与尾批继续完成

#### Scenario: 正式窗口收到延迟历史 ACC 事件
- **WHEN** ACC 监听回调在开窗后到达，但事件原始时间早于共同正式开始边界
- **THEN** 该事件不进入正式 ACC 文件，不改写事件时间，也不以共同控制窗口声称两源样本已精确对齐

### Requirement: 血压覆盖丢失与中断结束整组且不续采
正式血压轮次 MUST 复用指尖覆盖维持合同：有效覆盖不低于 95% 可维持，连续低于该门槛、未知或无新帧达到 1.5 s 时中断本轮 PPG 与 ACC 并关闭组内资源。宽限期不暂停或补时，不把部分覆盖改报完整。用户提前结束、后台或销毁 MUST 结束本轮并保留真实原因；恢复覆盖、回前台及重开页面 MUST NOT 自动续采，明确重试须先完整关闭旧轮。

#### Scenario: 短暂覆盖抖动后恢复
- **WHEN** 正式血压轮次短暂低覆盖或无新帧尚未达到 1.5 s 后恢复
- **THEN** 保留原共同截止与真实覆盖值，不因抖动回到准备、不暂停或补采

#### Scenario: 持续覆盖丢失
- **WHEN** 正式血压采集连续低于维持门槛、未知或无新帧达到 1.5 s
- **THEN** 无需等待 JS 或下一帧即封闭整组正式入口并收尾，释放本轮相机、补光和 IMU；放回手指不自动创建新轮

#### Scenario: 后台中断后返回
- **WHEN** 血压仍在覆盖观测、贴胸准备、启动准备或正式采集时宿主进入后台
- **THEN** 取消本轮自动开始资格并完整收尾，回前台只读取真实终态；用户明确重试且旧轮已完整关闭后才能重新准备

### Requirement: 血压命令与关闭限定本轮所有权
血压命令 MUST 绑定调用方、轮次及组内源的确切身份，遵守相机互斥和传感器类型占用，不接管或停止组外资源。关闭 MUST 先撤销未执行的自动开始，再等待本轮在途命令、PPG 配对、两源队列、全部文件及相机／补光／IMU 释放；并发关闭共用同一屏障。关闭失败 MUST 保留真实错误并允许再次关闭，旧停止、截止与回调不得控制后来轮次。

#### Scenario: 关闭与自动开窗竞态
- **WHEN** 血压满足准入即将正式开窗时调用方请求关闭
- **THEN** 尚未执行的自动开始被阻断，已执行的组内准备或采集完整收尾后才报告关闭完成，不遗留稍后启动的 ACC 或相机

#### Scenario: 组外命令与迟到关闭
- **WHEN** 外部客户端尝试停止血压组内源，或旧轮关闭在新轮存在时恢复执行
- **THEN** 不能停止非目标资源或释放后来所有者的占用；本轮关闭也不得停止独立传感器、组外相机或被动服务

### Requirement: 血压失败级联仅作用于本轮采集组
血压本轮任一必要设备、注册、像素处理、PPG 配对、样本校验、容量、写入、文件定稿或运行资源失败 MUST 封闭整组成功路径，撤销待开窗并结束组内运行，不留另一源继续正式采集。错误 MUST 保留源、轮次及可判别根因，已正常定稿文件与失败事实分别保存。两源保持独立有界处理与文件定稿，不引入共享文件事务，不回滚或删除已完成文件，也不影响组外会话。

#### Scenario: ACC 写入失败但相机仍有输入
- **WHEN** 正式血压 ACC 文件写入失败，而 PPG 仍可接收相机帧
- **THEN** 本轮 PPG 入口同样封闭并完整收尾，不继续采满后宣称联合成功；组外传感器与其它所有者不因该错误被停止

#### Scenario: 启动中仅一路成功取得资源
- **WHEN** 血压准备已取得一部分本轮资源，但另一路设备注册或准备失败
- **THEN** 取消自动开始并关闭已取得的本轮资源，不能留下单源运行或把启动请求返回当作联合开始成功

### Requirement: 血压组合完成同时具备真实文件与资源释放
血压结果 MUST 绑定本轮及 PPG／ACC 会话身份，保留冻结配置、目标／实际控制窗口、真实结束原因、各源实际记录数和首末采样时间、同轮 PPG 双 CSV 与 ACC 文件事实及资源释放状态。只有采满目标、有实际数据、三份文件均正常定稿且所有组内运行资源释放后，才整体正常完成；任一缺失或失败不得用旧文件、临时路径或补造记录替代。提前结束可保留已正常定稿文件，但不得冒充采满目标、血压估值或上传成功。

#### Scenario: 同轮三份文件与资源均完成
- **WHEN** 本轮共同窗口正常达到目标，PPG 双 CSV 与 ACC 文件均有实际数据且已关闭可读，组内资源均已释放
- **THEN** 返回引用同轮三份完成文件的组合结果，计数取自真实记录，原始 PPG／frame／ACC 列协议不变，不混入准备数据或其它轮次

#### Scenario: 文件完成但组内监听释放失败
- **WHEN** 三份 CSV 已定稿，但本轮相机或任一 IMU 监听释放失败
- **THEN** 保留文件事实及释放错误，不发布整体正常完成或允许重试开启新轮，允许继续关闭旧轮

#### Scenario: 仅一路文件完成或提前结束
- **WHEN** 本轮缺少任一正常定稿文件、任一路无样本，或用户在目标前结束
- **THEN** 分别保留真实文件、错误和实际窗口事实，不从完成列表挑选旧产物补齐，不把部分结果标为联合正常完成，也不隐式删除已经完成的文件
