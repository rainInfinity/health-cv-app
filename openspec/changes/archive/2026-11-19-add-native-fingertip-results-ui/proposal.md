# Proposal

## Why

Design-demo 已提供指尖检测结束后的结果等待、简要结果弹层和独立详情页，原生目前只保留本轮真实采集完成状态与脉搏回看。先迁移完整 UI 和页面流转，以便在接入真实结果服务之前对齐体验，并通过截图对比检查迁移效果。

## What Changes

- 仅面向 `apps/native` 的指尖检测：本轮原生正常完成且文件、相机资源收尾成功后，模拟等待 3 秒，显示“等待检测结果”，随后自动展开简要结果。中断、失败不进入结果流程，不改变原生覆盖准入、正式三十秒计时及语音。
- 迁移 Demo 底部面板展开的结果弹层、收起／重新展开、查看详情和重新检测；保留真实采集波形回看。
- 增加无产品底栏的指尖详细结果页，展示四项结果看板、各指标信号质量角标、参考信息、独立处理后波形、指标解读及健康参考声明。
- 使用与 Demo 一致的固定样例读数、质量评分、时间、解读和处理后波形；样例与真实采集数据隔离，不接入结果请求、推理或上传，不更新首页、历史、最近测量时间和健康记录。
- 复用已有原生 SVG 图形及 Demo 对应路径，按原生主题、逻辑尺寸、安全区、滚动和动画实现；不使用网页截图或 WebView 承载界面。
- 保留检测页与详情页往返的同轮展示状态；重测或真正退出本流程时清理。使用常规 Android 实际界面截图与 Demo 等价内容视口对照，覆盖等待、结果弹层、详情及返回后的核心状态，不建立截图矩阵或像素一致性门槛。

## Capabilities

### New Capabilities

无；结果 UI 属于现有产品检测页面能力，不另建近义能力。

### Modified Capabilities

- `native-measurement-pages`：从仅展示真实采集完成状态扩展为独立样例结果 UI；补充三秒等待、简要结果、详情、重测、同轮数据边界和截图对比要求，明确不产生真实健康结果。
- `native-app-shell`：在根栈增加指尖详情目标，保持无产品底栏、无公开产品深链及既有退出返回语义，允许详情往返保留已完成轮次的展示状态。

## Impact

- 涉及 `pages/measurement/FingertipMeasurement`、相关结果组件／页面、`ContactMeasurement/useContactMeasurementSession.ts` 的焦点与清理边界，以及根导航路由和注册。
- 复用 `shared/graphics`、主题、按钮、加载指示器与 ECharts 原生 SVG 绘图层；需要适配图形尺寸、结果用血氧图标和质量角标，不预期新增依赖。
- 同步维护原生开发约定与测量说明中的结果展示及生命周期边界；不修改 design-demo，不新增接口、环境变量、持久化或采集算法。
- 现有规格的“不生成健康结果”仍约束真实业务能力，但不再排除本次明确授权的固定样例结果 UI；不能将样例解释为本轮采集的算法输出。
