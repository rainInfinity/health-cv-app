# Design

## Context

动机与范围见 proposal.md。当前 `RootNavigator` 只有 Entry、Acquisition、PassiveCapture、Sensors、LanguageSettings；`src/features` 存放这些验证页面。`app/bootstrap.ts` 已组装唯一认证会话和查询服务，缺配置时服务为空但本地页面可用。Demo 已有主页、功能、账户、认证、静态开屏及三步引导；其完整历史和资料表单不属于本次迁移。主题已在 `shared/theme/theme.ts` 收敛，基础按钮、文本、输入框、卡片和内联反馈可继续使用。

本变更跨导航、原生启动资源、认证展示、权限和目录边界，存在深链及相机离页风险，因此需要设计文档。已有语言规格要求公开中英与跟随系统，本次用户决定覆盖该发布行为，增量规格必须明确修改而非仅隐藏入口。

## Goals / Non-Goals

**Goals:**

- 产品展示与真实账号、系统权限、原生验证事实分层，避免页面复制会话或把权限授权当作服务启动。
- 使用一个导航容器，集中控制开发 Tab，保留既有相机收尾、服务所有权与深链语义。
- 页面按产品入口组织，基础服务仍独立于页面挂载；在 Android 模拟器上完成实际运行验收。

**Non-Goals:**

- 不建立测量领域编排、指标评估、历史数据库、上传队列或新的后端契约。
- 不将静态 mock 作为服务端数据缓存、真实测量失败兜底或账号健康资料保存。
- 不重构无关原生采集模块，不新增英文资源、深色主题、品牌动画或真机验收要求。

## Decisions

### 1. 单容器、产品 Tab 与开发独立栈

复用现有 NavigationContainer 和 native-stack，增加底部 Tab 导航；顺序为健康、功能、历史、我的、开发。开发 Tab 下使用独立栈组织旧验证入口及采集页面，根栈承载开屏和首次引导。采用与现有 React Navigation 版本匹配的底部导航依赖，通过 pnpm 管理；不手工维护另一套导航状态或引入第二个容器。

历史 Tab 只作为交互入口：拦截激活并显示未开放弹窗，保留当前选中页面，不建立伪历史业务页。相关入口定义和说明归 `pages/history`。

开发 Tab 默认在本阶段显示，用单一应用配置决定可见性，后续可隐藏，不新增公开环境变量或每页分散判断。本次不实施后续隐藏。无云端配置、游客和认证恢复中均可访问开发页面。

运行中从主动相机页切到其他 Tab 时，必须经现有离开协调等待命令及关闭；仅依赖 usePreventRemove 不足以覆盖失焦而未卸载的 Tab 场景。关闭失败取消切换并留在可重试页面。被动和传感器不沿用主动相机的离页即停止策略。

被动深链继续定位开发栈唯一 PassiveCapture 页面，返回开发入口。冷启动深链在开屏结束后优先交付到被动页，本次不让首次产品引导阻塞通知入口；不将该操作标记为已完成引导，下次普通启动仍展示尚未完成的引导。重复 URL 不堆栈、不启用服务。该规则是保留既有深链能力的保守选择。

### 2. `pages` 目录清洁迁移

`src/pages` 一级目录固定为 home、features、history、user、dev：

- home：主页、指标详情及当前两步引导；引导从本版主页入口链路组织，不创建额外一级目录。
- features：五项产品功能卡片、插画包装及说明。
- history：未开放历史入口定义与反馈，不迁移 Demo 趋势实现。
- user：我的、登录、注册、通知、隐私授权和仅中文语言说明。
- dev：现有验证入口、主动 PPG、被动录像、传感器、旧语言验证页，以及只服务这些页面的配置、查询面板和文案映射。

组件以同名目录组织，index.ts 为对外入口，组件实现为命名 .tsx，样式在 styles.ts；迁移时更新所有页面引用和测试路径，不保留 `src/features` 转发文件或别名。app 中认证、采集适配、查询、偏好和生命周期不移动；共享弹窗、Toast、按钮和主题属于 shared。启动状态机属于 app，静态启动展示可作为 home 页面组件。

### 3. 中文发布策略与旧偏好兼容

保留现有 i18n 基础、旧英文资源及可独立使用的解析工具，但当前应用有效 locale 固定为 zh-CN；旧 en-US/system 偏好不影响首屏、产品页或开发页，不需要破坏性删除旧偏好。所有新文案进入分类中文 JSON，不补英文；资源校验只要求当前开放 locale 完整，不再强制旧英文资源与新中文 key 相等。

我的语言入口仅显示“简体中文”并说明当前仅支持中文。开发区保留旧语言页面入口和相关代码，但当前构建不提供可生效的英文或跟随系统切换，页面显示中文状态说明。这样符合“保留旧界面”与“本版只开放中文”，而不出现产品与开发导航混合语言。

### 4. 认证事实驱动展示，不复制身份状态

页面经 useAppServices 获取现有 auth 并订阅四态。登录注册直接调用 register/signIn，不进入通用 mutation 缓存，不在页面存令牌；登录必须等原有凭据保存及本人确认完成后才转 authenticated。注册只提交 username/password，确认密码仅前端比较，成功回登录预填服务端返回的用户名；登录成功回“我的”，返回或取消不限制游客浏览。

主页、详情和功能时间提示通过同一纯展示选择器消费认证状态：仅 authenticated 返回固定 mock，其余返回空健康展示。anonymous 显示游客；restoring/unavailable 显示对应账号状态和可执行操作，不标为游客，不展示 mock。缺配置时本地产品及开发界面仍可用，认证入口明确服务未配置，不伪成功。

Android Release 的 JavaScript bundle 必须携带构建时配置的账号服务地址和 channel。Gradle 的 `createBundleReleaseJsAndAssets` 任务跟踪 `.env`、`.env.local`、`.env.production` 与 `.env.production.local`；`android:release` 对 Gradle 子进程清除 `CI` 并使用一次性 Gradle daemon，使环境文件变化后 bundle 重建时 Expo 能重置 Metro 缓存。缺少配置时仍允许本地浏览并如实说明认证服务不可用，不提供默认服务地址。

mock 模块保留数值、单位、固定测量时间与缺失语义，使用 Demo 已确认的血压、心率、呼吸率和血氧值；风险和面部独立记录继续为空。不进入 QueryClient、MMKV、账号资料或原生采集状态；界面不加示例数据标签。退出或会话变化时当前已打开详情也重算空态，清除旧展示，不能只更新主页。

### 5. 静态开屏与两步引导

复用现有心沐图标、LOGO 和启动图片，Expo 配置及 Android 生成资源同步更新应用名“心沐”和桌面自适应/单色图标，包名和深链不改。使用适配当前 Expo 的启动屏插件/依赖衔接系统屏与应用静态品牌页，不用模拟桌面页，不增加动画库。

应用品牌页首次实际可见后计时 2 秒；不在原生屏和应用屏各额外等待 2 秒。JS 初始化和系统启动耗时不属于承诺的总启动时长。前后台切换不重置或重播；若在计时期间退到后台，返回后只在应用前台完成一次导航，不重复入栈。认证恢复并行启动，不阻塞开屏结束或浏览。

普通启动在计时结束后根据设备级引导完成标记进入两步引导或主页。功能引导可跳过全部步骤，授权说明可返回，完成或跳过才保存标记；中途退出不算完成。保存失败如实说明，允许进入主页，但不承诺下次不再展示。健康资料引导不保留第三步空壳：其后续完善入口放在“我的”的资料说明弹窗中，与健康资料入口共用未开放反馈。引导只解释权限，无系统授权调用。

### 6. 独立权限设置，不复用服务启用

在 app 层建立最小的相机与通知权限适配供 user 页面读取、申请及返回刷新。Android 相机和 33+ 通知运行时权限可复用系统 API；通知总开关与已有渠道状态必要时用窄原生查询接口补齐，不安装整套推送 SDK，也不把 POST_NOTIFICATIONS 已授权等同于通知总开关和渠道均可用。

只在明确点击授权时申请；永久拒绝或系统侧关闭提供系统设置跳转。设置返回和页面聚焦重新查询，未知/查询失败显示无法确认，不沿用演示布尔值。OS 不提供应用内直接撤销权限时跳系统设置，不做可关闭权限的假开关。

不得为请求通知调用 passiveCapture.enable，因为它同时申请相机并启动录像服务。权限设置不自动打开相机、开始采样、调度提醒或启用被动服务；已运行服务仍按原生既有条件核对规则处理系统权限变化。

### 7. 共用反馈与视觉迁移

新增 shared 弹窗/Toast 组件与单一展示宿主，样式消费现有主题。普通说明、详情、确认共用弹窗容器，长内容滚动、Android 返回先关弹窗、背景不可交互、焦点/读屏可用；关闭后恢复触发位置。现有被动启用的应用内 Alert 迁移时保留取消、设置、继续及显式启用语义，系统权限框由 Android 管理。

Toast 使用 success/error/loading/information 四态，顶部定位按真实安全区而非 Demo 固定 60px；单条替换，普通提示 3.5 秒后消失，加载态由操作结束或手动关闭，不伪造完成。表单校验靠近输入，权限和会话等持续错误保留页面恢复入口。开发区增加反馈预览便于验收，不增加产品页组件展示入口。

本地 SVG 插画和 LOGO 使用 react-native-svg 包装，保留渐变 ID 唯一性，避免复制浏览器 DOM/CSS。主页、功能页还原已确认背景、布局和免责声明；隐藏原生导航头的页面自行明确顶部安全区归属。

### 8. 与设计 Demo 的原生视觉对齐

以 `docs/design-demo/README.md`、`styles.css` 与 `pages.js` 的产品页为视觉基准，复用原生现有浅色 token；仅将 Demo 插画专属装饰色纳入 `colors.illustration`，不另建页面色板。主页、功能、账户与认证页面使用对应的柔和渐变背景；血压主卡和五项功能卡使用既有渐变配方、22 dp 圆角和轻微阴影，其他卡片保持白色表面。

主页在血压主卡下展示心率、呼吸率、血氧饱和度与糖尿病风险四张等高卡片，排列为两行两列。沿用心率面性图标、肺部图形、85–100% 血氧仪表和血滴风险图形；风险没有结果时显示空态，不绘制分数。读数仍严格遵循认证状态，游客不得出现 mock。

功能页按单列横向卡片排列五项入口，卡片约 112 dp 高，插画框为 96×84 dp；移植 Demo 的五幅本地贴纸风 SVG，保留等比缩放、渐变和白色描边。标题与免责声明同列排布，免责声明位于标题右侧。所有卡片仍只打开现有说明，不启动测量。

“我的”使用独立柔和背景、真实账号状态行和分组菜单卡片；菜单图标与 Demo 语义一致。保留真实登录、注册、退出、权限和语言入口；健康资料、个人资料仍仅作未开放说明，不显示 Demo 示例姓名或可编辑资料。

首次引导保持两步：第一步复用功能页插画构成血压主视觉和三项功能图形，第二步将权限说明集中在一张卡片中。保留返回、跳过、设备级完成标记；不加入 Demo 的健康资料第三步，也不请求权限。

登录／注册使用 Demo 的自定义返回与模式切换栏、居中品牌组合和表单卡片层级；认证请求、字段验证及错误反馈保持现状。指标详情使用居中遮罩弹层，提供关闭按钮及 Android 返回关闭；底层页面恢复，详情仍只读，不增加历史查询。

底栏健康、功能、历史、我的四个图标与 Demo 对齐；当前变更要求的第五个“开发”Tab 及其独立入口保留。

## Risks / Trade-offs

- [Tab 失焦不卸载导致相机持续占用] → 所有离开主动页的 Tab、返回和深链统一走可等待守卫；失败不放行，模拟器实际检查 CameraService 和页面状态。
- [中文策略与旧规格、偏好冲突] → 显式修改 localization 增量，当前 locale 固定中文而保留旧资源；更新应用层行为断言，不重钉文案测试。
- [真实账号旁展示 mock 被后续误接入服务端] → 固定展示数据源与真实 Query 缓存隔离，文档说明范围；UI 按已确认要求不加标签。
- [Android 系统屏与应用开屏叠加等待或图标缓存] → 统一品牌资源，计时从应用品牌页可见算一次；重建安装后实际检查桌面和冷启动录像/时间证据。
- [模拟器不代表实体设备后台和传感器能力] → 本阶段验收明确使用 AVD、允许自行启动；记录虚拟输入和未覆盖项，不声称医学或真机有效性。
- [真实注册产生测试账号] → 联调创建一个可识别测试账号，只保留必要信息，不记录密码或令牌；后端无删除接口，不承诺清理远端账号。

## Migration Plan

1. 先迁移 pages/dev 和所有引用，保留原有路由行为；按需取得导出符号引用后调整，不建立兼容层。
2. 接入单容器 Tab、相机切页守卫、深链和中文发布策略；再落共享反馈与产品页，避免把旧验证入口直接扩成业务中心。
3. 接通现有认证、权限状态、静态启动和设备级引导；同步原生资源并生成开发构建。
4. Android 模拟器作为本阶段验收设备，可自行启动可见 AVD。实际操作游客空态、登录后 mock、退出清空、注册返回、权限拒绝/设置返回、五个 Tab、弹窗 Toast、首次/后续启动及原采集回归；记录 AVD/API、构建命令、测试服务渠道、步骤和观察。
5. 执行一次相关类型检查及现有测试，新增测试仅覆盖游客到登录再退出、开屏/引导单次推进、权限变化、导航守卫等真实回归风险；不为静态文字或文件路径写测试。单元测试不替代模拟器操作。
6. 实施完成后更新 docs 中开发流程、页面结构、中文策略、认证文档过时描述和实际验收结果。回退使用上一可运行构建与对应代码版本；不删除安全凭据、本地引导外的偏好或采集文件，无后端数据迁移。
