# Spec Delta

## Purpose

为原生产品页和开发验证页提供统一的应用内弹窗与短时操作反馈，使未开放说明、详情和确认可访问且可关闭，并将短时 Toast 与必须持续可见的字段、会话及权限错误分开，避免伪成功或提示覆盖必要操作。

## ADDED Requirements

### Requirement: 应用内弹窗统一且可恢复交互
应用 MUST 为说明、详情和确认使用一致的弹窗视觉及交互，复用既定主题。弹窗 MUST 阻止背景交互，支持关闭按钮和 Android 返回关闭，长内容可滚动，操作具备可访问名称；关闭后恢复原页面交互及可用的触发焦点。页面切换时 MUST 不残留遮罩。

#### Scenario: 关闭未开放说明
- **WHEN** 用户打开说明弹窗后按 Android 返回
- **THEN** 仅关闭弹窗，不同时退出底层页面，背景重新可交互

#### Scenario: 长内容与大字号
- **WHEN** 弹窗内容在较大字号或小屏幕下超出可用区域
- **THEN** 内容及必要操作可滚动到达，不遮挡系统安全区或裁切按钮

### Requirement: Toast 支持四态与明确生命周期
Toast MUST 提供成功、错误、加载、信息四态，沿用白底、边框、图标及状态文字，顶部位置适配真实安全区。MUST 同时只展示一条，新提示替换旧提示并重新计时；成功、错误、信息在 3.5 秒后消失，加载由操作结束、替换或手动关闭，不自动伪造成功。各态 MUST 可关闭，错误具备告警语义，其他态适当播报。

#### Scenario: 重复触发与替换
- **WHEN** 一条信息 Toast 尚未消失又收到新提示
- **THEN** 旧提示被替换，新提示拥有自己的完整持续时间，不堆叠遮挡页面

#### Scenario: 加载操作未完成
- **WHEN** 加载 Toast 关联的实际操作尚未结束
- **THEN** 不因普通提示计时到期而显示成功，允许手动关闭且关闭不冒充业务取消

#### Scenario: 减少动态效果
- **WHEN** 系统开启减少动态效果
- **THEN** 加载状态仍能识别，但不依赖旋转动画传达状态

### Requirement: 持续错误不得仅用 Toast 表达
字段校验、会话不可用、权限未满足、相机关闭失败等需要用户处理的错误 MUST 在相关表单或页面保留说明及可执行入口，不能仅由自动消失的 Toast 承担。未知错误 MUST 安全映射中文提示，不直接展示底层消息、令牌或堆栈。

#### Scenario: 登录输入错误
- **WHEN** 用户提交不合格表单
- **THEN** 对应字段或表单内保留错误说明，不只显示短暂 Toast

#### Scenario: 被动启用确认
- **WHEN** 用户从开发页主动请求启用被动采集并进入应用确认弹窗
- **THEN** 继续保留取消、打开设置和明确继续的选择，不因统一弹窗而自动启用服务；系统权限框仍由系统管理
