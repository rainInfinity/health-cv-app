# Tasks

本清单只规划实施；创建提案不代表以下任务已经执行。行为依据 `specs/android-passive-capture/spec.md`，技术决策依据 `design.md`。目标是交付真实可运行的权限、解锁触发、后台录像与视频产物闭环，不以 mock、手动录像或持续占用摄像头替代。周期和时长暂按提案默认 7200 秒／10 秒，可在未启用时配置。

## 1. 权限、原生服务与用户可控通知

- [x] 1.1 在 `packages/acquisition` 新增独立的被动采集 Nitro 契约和 JS 门面，定义配置、启停、真实快照、低频原因与视频引用，原生运行组件只依赖应用 Context；生成绑定并完成类型检查，确认主动 `Acquisition` 和双 CSV 契约没有被视频语义替换。
- [x] 1.2 新增非导出的相机类型原生前台服务和必要生命周期依赖，通过库 manifest、Expo 源配置／必要的 config plugin 声明权限；在 CNG 重建后的合并 manifest 与 APK 中检查 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_CAMERA`、`POST_NOTIFICATIONS` 及服务类型，不添加麦克风、共享存储或悬浮窗权限。
- [x] 1.3 在 `apps/native` 增加轻量被动功能入口，提供用途说明、周期／时长配置、启用／关闭、真实状态与产物区域；实际操作证明首次进入、修改配置和启用完成不立即打开相机，权限拒绝、渠道禁用和服务启动失败不显示已启用，且不要求登录或云端配置。
- [x] 1.4 实现同一服务通知的等待／录像状态、安静渠道、点击状态入口及原生“关闭无扰采集”操作；在真机观察无声音、无振动、无悬浮提醒，通知操作不依赖页面执行，并区分通知划除、通知权限／渠道禁用和系统停止应用。
- [x] 1.5 以用户在可见页面授权并启用为起点，实际观察退到后台后服务及通知存在、等待时相机关闭、从通知关闭后服务结束；在 `docs/development/android-development.md` 记录该阶段实际设备、命令和权限操作，不使用 ADB grant 代替用户流程。
- [x] 1.6 仅在用户点击被动采集的“授权并启用”时展示厂商后台活动说明、应用设置入口及“已设置／不适用后继续”确认；确认后继续原有相机／通知运行时授权流程，不把 OEM 设置当作可自动授予或验证的系统权限；在 Honor 真机确认提示时机和启用行为。

## 2. 解锁周期、无预览录像与第一条真机闭环

- [x] 2.1 添加同版本 CameraX `camera-video:1.6.2`，实现仅绑定前摄 `VideoCapture` 的无声录像会话，不绑定 Preview／ImageAnalysis、不启用补光、不经过 PPG DataHub／CSV；实际生成的视频需包含前摄画面且无音轨，不以固定配置值冒充实际尺寸或帧率。
- [x] 2.2 在服务中实现动态解锁事件接收、单调周期判断、实际 Start 计时、原生目标时长停止及有界打开／收尾；用虚拟时钟行为测试覆盖首次机会、周期前／恰好到期、墙上时间变化、开始失败与开始后中断、重复事件和收尾中事件，不测试源码文本或默认值拷贝。
- [x] 2.3 接通独立会话的私有临时视频、Finalize 成功和媒体可读检查后的完成文件发布，实际文件查询返回路径、大小、时长和尺寸；存储／发布失败不得返回成功，未完成文件不得混入完成列表。
- [x] 2.4 构建并安装不依赖 Metro 的内部测试 Release APK，在实体手机由用户启用后退到后台、锁屏、真实解锁，完成第一段录像和短周期后的第二段录像；观察相机在两段之间释放、没有预览或页面弹出，使用媒体探测和完整解码确认两份视频可用。此项优先验证核心平台假设，失败时记录系统错误，不改为手动触发冒充通过。
- [x] 2.5 在第一条真实闭环之后新增 `docs/acquisition/android-passive-capture.md`，记录当前直接录像、无本地内容筛选、解锁加周期而非定时任务、配置及时间语义；补充开发记录中的真实事件到 Start 延迟、文件信息与该阶段尚未完成的验证，不声称 rPPG 有效。

## 3. 关闭、中断与产物持久性

- [x] 3.1 实现关闭时先停事件入口、取消未开始请求、终止当前片段、等待设备及文件收尾再结束服务；用确定性状态／会话测试覆盖打开中关闭、录像中关闭、收尾与关闭竞争、重复关闭和旧 Finalize 迟到，证明取消片段不发布成功且不影响新运行。
- [x] 3.2 接通屏幕关闭／锁屏核对、权限或通知条件失效、相机与编码错误及超时收尾；在真机分别执行重新锁屏、切换其他 App 和权限／渠道变更，确认锁屏终止未完成片段、普通页面切换不终止被动录像、条件失效不继续接受采集。
- [x] 3.3 完成最终视频目录扫描与真实媒体信息查询，应用重开后可查看完成产物，不依赖仅进程内列表；用临时目录行为测试覆盖会话不覆盖、发布失败和临时文件排除，并在真实重开后检查同一视频仍存在且可解码。
- [x] 3.4 使用非自动恢复服务语义，配置与实际运行状态分开；从系统停止应用后重新进入，观察不会自动开相机或假报后台运行，重新启用由用户明确操作，既有视频保留。
- [x] 3.5 在上述实际检查后更新被动采集协议与开发记录，说明提前结束片段、关闭完成、权限失效、系统停止、通知划除与无自动恢复的区别，以及私有视频没有自动清理／上传的存储边界。

## 4. 主动 PPG 兼容与页面解耦

- [x] 4.1 在原生相机打开／关闭边界加入最小持有者占用保护，两种模式使用独立会话与终态，已有占用则忙／跳过，不抢占、不并行、不排队；用行为测试证明旧会话释放不会解除新持有者，失败不会残留占用，不引入基于 App 前后台的模式互斥。
- [x] 4.2 调整应用组装与页面订阅清理，使主动页面仅结束自身相机，被动页面仅解除订阅；实际离开页面、切换应用和重新进入，确认不会把被动等待误关，原生仍能处理下一次有效解锁。
- [x] 4.3 实际回归主动后摄打开预览、开始、停止、双 CSV 检查、关闭和再次打开，同时检查必要的忙状态；确认旧提示、时间戳对应和文件保留不变，且被动视频不会进入 PPG 目录或产物类型。
- [x] 4.4 在兼容性实际验证后更新 `docs/architecture/code-organization.md` 和 `technology-stack.md`，明确页面主动采集与服务被动录像的边界、JS 低频控制及当前未实现的像素／人脸路径，不把新增能力描述成所有原生采集都已后台化。
