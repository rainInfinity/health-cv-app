# Design

## Context

动机与业务范围见 `proposal.md`。本变更涉及资源迁移、两种调度器与共用播放底座，需在实施前明确阶段往返、抢占和录音替换边界，因此编写本设计。

现有指尖调度器 `FingertipMeasurement/fingertipVoice.ts` 只消费真实快照与帮助可见性；`app/measurement/fingertipVoicePlayback.ts` 已提供单实例、异步加载／定位、令牌取消和真正发声前的资格复核。`fingertipVoicePlayer.ts` 使用现有 `expo-audio` 配置前台播放，不请求录音权限或修改系统音量。

血压 `useBloodPressureMeasurement.ts` 已收到同轮未经展示防抖的快照，但尚未持有语音。`BloodPressureSnapshot` 已有 `captureId`、`phase`、覆盖、原生剩余时间、正式窗口和结束原因；控制器已按轮次过滤。共享 `useContactMeasurementSession.ts` 已提供 `cancelRound`、`resetRound`、`disposeRound`，可在离页意图、失焦、后台、重试和卸载时立即取消声音，不必改原生或共享生命周期协议。

原生血压有两种不同往返：覆盖就绪失效会从 `awaiting_chest / starting` 退回 `observing_finger`；联合启动复核未通过也可能从 `starting` 退回 `awaiting_chest`。后者不是一次新的贴胸引导机会。正式采集确认覆盖丢失则结束整轮，不退回等待自动续采。

主规格目前仍记录指尖旧文案，并要求血压不播放指尖语音。增量规格将显式更新这些冲突，不把共用音频等同于共用调度器。

## Goals / Non-Goals

**Goals:**

- 两种方式共用实际相同的录音和播放能力，各自只消费本轮合法语音节点。
- 血压阶段提示跟随真实阶段，覆盖恢复后再次进入贴胸阶段再次指导，旧阶段的加载与完成回调不能恢复过时声音。
- 迁移所有受影响的指尖资源及导入，保留原生准入、正式计时、完成屏障和既有指尖调度语义。

**Non-Goals:**

- 不修改 Web Demo、页面文案、布局、手势、十五秒弹窗计时或引导跳过偏好。
- 不新增贴胸识别、贴胸丢失、光照、心跳识别或健康结果语音，不把工程准入宣称为已确认贴胸。
- 不新增原生接口、依赖、在线合成、录音、音量控制、后台播放、自动重试或语音队列。

选择独立 `common/` 而不是让血压继续引用 `fingertip/`，是为了让资源归属与两种实际使用方式一致；不复制相同录音到血压目录。

### 2. 共用播放底座，不制造通用检测状态机

将 `fingertipVoiceTypes.ts`、`fingertipVoicePlayback.ts`、`fingertipVoicePlayer.ts` 中实际共用的播放契约、取消／加载逻辑及音频模式设置提升为 `measurementVoiceTypes.ts`、`measurementVoicePlayback.ts`、`measurementVoicePlayer.ts`。工厂接收方式专属资源表，节点类型限制在该表可用的提示集合，避免指尖误用血压独有提示。

底座仍然只提供 `durationMillis / play / stop / dispose`，只管理本页独占播放器。迁移全部调用方和测试导入，删除被替代的指尖专属播放底座，不留下旧接口转发。`fingertipVoiceResources.ts` 和指尖业务调度器保留其方式专属职责。

新增 `BloodPressureMeasurement/bloodPressureVoice.ts`，使用与指尖一致的 `update / setHelpVisible / cancel / dispose` 入口，但独立处理血压阶段。相比把血压快照强行投影成指尖阶段，这能保留贴胸往返语义；相比重写播放器，这可复用已经处理过的异步取消边界。

### 3. 页面接入不扩展采集控制接口

在 `useBloodPressureMeasurement.ts` 中持有本轮语音实例。第一条当前且前台有效的血压快照到达时创建并绑定其 `captureId`；不为此新增控制器 `onCapture` 回调。后续只接收同一轮快照，拒绝旧轮通知。

与指尖一样，原始快照同时送往展示投影和语音，语音不读取防抖后的 React 展示状态。放置提醒的可见性回调同时更新界面和 `setHelpVisible`，先处理当前快照，再处理提醒可见性，避免用旧阶段启动帮助。

向共享生命周期传入本方式的取消、重置和释放回调。页面永久取消调用调度器 `dispose()`：先撤销本轮资格与异步令牌，再停止并释放原生播放器；不只调用暂停，因为 Expo Audio 会在回前台时自动恢复其后台标记为暂停的播放器。正常到点收尾不走永久取消，保留已实际开始的结束语。权限弹窗期间没有预先创建的语音，授权回前台后按真实首个观测快照启动，不播授权提示。已取消的实例不因恢复前台而重新启用。

### 4. 阶段提示按轮次和贴胸段去重

- 初始指导仅在首次真实 `observing_finger` 播一次。授权、布局和打开预览不播；首条快照已越过该阶段时不补播。
- 将 `awaiting_chest` 与 `starting` 视为同一个贴胸准备段。从指尖阶段进入该准备段时播贴胸指导；首条快照已在等待贴胸时可播放当前指导，不补放置指导。
- `starting → awaiting_chest`、重复快照和手动分页不建立新准备段，不重复贴胸指导。进入 `starting` 本身不播正式开始。
- 覆盖失效从贴胸准备段退回 `observing_finger` 时结束旧准备段，立即撤销旧贴胸指导；重新稳定并再次进入贴胸准备段时重新播报，不设整轮只播一次的限制。
- 首次进入 `capturing` 后，根据当前原生剩余区间选择正式开始、20 秒、10 秒或最后倒计时之一。跳过的更早节点只消费、不追播；重复快照不重播。

阶段提示真正发声前复核当前轮次、准备段身份和阶段；如果加载期间已进入正式检测或再次退回，旧指导失效。

### 5. 重新覆盖与普通纠正不连播

准备期按完整覆盖判断，正式期沿用原生 95% 维持规则。未知覆盖既不推断不足，也不重置连续不足的去重资格；不因单独的 `stable / tiltDegrees / scgCandidate` 变化要求用户重新覆盖。

普通纠正沿用指尖规则：持续不足只播一次，真实恢复后再次不足才重新获得资格；声道必须空闲，且距下一定时节点的空档严格大于完整录音时长。其他播放期间只保留最新事实，不排队保存纠正事件。

贴胸准备退回指尖阶段且明确覆盖不足时，优先使用 `restore-cover`，将本次连续不足标记为已纠正，不再追加 `cover-camera`。仅因输入失鲜而退回、覆盖仍未知或完整时不据此断言手指未盖住；若随后明确不足且仍处于同次退回的指尖阶段，可播放重新覆盖指导。恢复、再次进入贴胸、正式开始或终止都会使过时指导资格失效。

十五秒帮助只响应既有弹窗实际可见，血压仅在 `observing_finger` 适用，不另建语音定时器。纠正与帮助同时适用时优先纠正，低优先级结束不自动串播帮助；后来新显示的帮助仍可按当前可见性与每轮一次规则播放，不要求此前连续不足先恢复。

### 6. 单路抢占与定时提示

正式开始、20 秒、10 秒及结束倒计时优先级最高，可以打断准备指导、覆盖纠正与帮助。准备阶段切换提示可以替换已过时的旧指导或普通纠正，但不能延迟正式开始。切换先停止旧播放，再启动新录音。

阶段不再适用时立即停止旧指导；不等待它自然结束，也不在完成回调补播已失效的阶段。低优先级只在空闲时判断，不以播报结束回调推进检测。

20／10／3 秒全部消费原生 `remainingMillis` 的跨区间变化，不建立 JS 检测时钟。低优先级空档使用实际录音完整时长，不按文案长度估算。播放失败释放声道并消费当前机会，不自动重试，不阻塞采集。

### 7. 到点收尾与提前中断分开处理

沿用指尖合并结束音频：仍在正式采集中首次进入三秒区间时从头播放完整音频，不裁剪、跳播或等待文件定稿后再说结束语。正式截止不等待声音。

仅当快照明确 `endReason = duration_reached`，正式窗口已建立、正式经过时间达到目标且剩余量为零时，保留已经实际开始的结束音频，允许跨越后续 `stopping / completed / failed` 收尾状态。未开始发声、仍在加载的旧候选不能在终点后新启动；未到三秒节点便已终止也不补播。

正式覆盖丢失、技术失败或其他提前结束立即停止；正式期间不播 `restore-cover`，不暗示重新覆盖就能继续。本轮达到终点后发生文件／资源收尾失败不回撤正在播放的结束语，但页面仍按联合屏障和真实错误反馈，不因声音产生完成状态。

后台、失焦、请求离页、卸载和重试始终立即停止，包括正在正常收尾的结束音频，不等待关闭成功。语音结束只释放声道，不改变页面状态。

## Risks / Trade-offs

- 新放置指导和贴胸指导分别长于三秒覆盖稳定门槛，原生可能在播完前推进阶段 → 接受按真实阶段抢占，不增加等待、重播或延长窗口。
- 覆盖纠正录音长于正式覆盖丢失宽限，可能被提前终态截断 → 立即停止是正确行为，不为播完录音改变原生宽限。
- 同名 `starting.mp3` 的两种内容容易引用错 → 两种方式保留独立资源表与独有路径，共用提示只引用 `common/`。
- 当前只核对了录音文件与元数据，文件名不是音频内容证明 → 实施时核听六条实际录音，并在常规 Android 页面确认真实播放；不把模拟器信号当成人体检测结果。

## Migration Plan

1. 将六条新录音导入目标目录，迁移现有四条共用录音，按上表替换指尖三条内容；更新全部资源表、静态导入及真实时长，再移除项目内失效旧资源。
2. 提升共用播放底座并迁移指尖调用方和测试，保留指尖原有调度行为；新增血压资源表、独立调度和页面生命周期接入。
3. 执行受影响的定向测试、原生 TypeScript 检查与常规 Android 页面播放检查。复用现有开发工具或临时可撤销输入验证血压主要阶段，不新增正式产品模拟按钮；无真实输入时不宣称验证了人体信号或联合准入。
4. 更新 `docs/development/measurement.md` 第 10 节与 `frontend-development.md` 的语音边界，记录最终资源映射和业务规则，删除旧“尚未接入／新音频待提供”描述，仅修正本变更关联内容。不保存验收记录。

资源与引用作为同批改动交付，不提供旧路径兼容期。若需撤回，整体撤回本批资源、导入与语音接入改动，避免仅撤回资源造成悬空引用；不触碰采集文件、偏好或其他业务数据。本轮提案阶段不执行以上迁移。
