# Spec Delta

## Purpose

提供加速度计、陀螺仪、磁力计和重力传感器的独立 Android 采集入口，使 JS 能按需编排多源控制，而高频样本始终在原生侧有界处理并保存为可解释的持久 CSV。明确单源隔离、真实设备可用性、前台生命周期、停止完成与文件交付边界，不承担跨源同步、上传或医学有效性判断。

## ADDED Requirements

### Requirement: 四种传感器具有独立入口且默认不采集

系统 MUST 分别支持 `accelerometer`、`gyroscope`、`magnetometer`、`gravity` 的独立配置、启动、停止、状态和产物查询，不依赖登录、云端配置、相机或其它传感器已启动。创建客户端、进入验证页、查询能力和订阅 MUST NOT 注册采样监听或创建会话文件。

#### Scenario: 未登录且只查询设备
- **WHEN** 用户未登录且无云端配置，进入传感器页并查询四种能力
- **THEN** 页面呈现各类型真实可用性，但不开始采集、不创建输出文件，也不要求打开相机

#### Scenario: 未知传感器类型
- **WHEN** 调用方传入四种约定类型之外的标识
- **THEN** 操作以 `INVALID_SENSOR_KIND` 失败，不选取其他设备、不创建会话

### Requirement: 设备可用性与注册失败如实报告

系统 MUST 查询对应标准类型的默认设备；能力结果提供可用性及可用时的设备名称、最小采样间隔。设备缺失 MUST 报告 `SENSOR_UNAVAILABLE`，注册被拒绝或失败 MUST 报告 `SENSOR_REGISTRATION_FAILED`，且不得显示正在采集、保留已注册监听或交付成功产物。

#### Scenario: 设备缺少陀螺仪
- **WHEN** 当前设备没有默认陀螺仪且调用方请求启动它
- **THEN** 能力查询表示不可用，启动返回 `SENSOR_UNAVAILABLE`，不以加速度或应用算法生成替代样本

#### Scenario: 注册失败但输出已准备
- **WHEN** 设备存在但系统注册返回失败或抛出错误
- **THEN** 当前启动失败，输出及运行资源被收尾，没有正常完成文件引用，其他类型的采集不受影响

### Requirement: 采样配置使用明确微秒请求且不承诺实采速率

调用方 MUST 显式提供整数 `samplingPeriodMicros`，范围为 5,000 至 1,000,000 微秒；非法值以 `INVALID_SENSOR_CONFIG` 失败。系统 MUST 分别报告请求间隔与实际注册参数，后者不快于请求值、设备正的最小间隔及 5,000 微秒限制，不得描述为实际稳定频率或增加高采样率特权。

#### Scenario: 请求快于设备能力
- **WHEN** 请求 5,000 微秒而设备最小间隔是 10,000 微秒
- **THEN** 请求值仍为 5,000，注册参数为 10,000，真实事件时间保留，界面不宣称稳定达到 200 Hz

#### Scenario: 超界或延时常量输入
- **WHEN** 调用方提供 0、非整数、非有限数、低于 5,000 或高于 1,000,000 的间隔
- **THEN** 启动报 `INVALID_SENSOR_CONFIG`，不将这些值解释为平台预设常量，不创建采样会话

### Requirement: 同类型单活动会话与异类型隔离

每种类型 MUST 只有一个活动采集会话；该类型开始或收尾期间再次启动 MUST 返回 `SENSOR_BUSY`，不重复注册设备。不同类型 MUST 拥有独立状态、配置、会话、有限缓冲、停止结果和文件，任何类型的停止或采集失败不得自动停止或发布其他类型。

#### Scenario: 同类型从两个客户端重复启动
- **WHEN** 一个客户端已启动加速度计，另一个客户端请求启动同类型
- **THEN** 后者取得 `SENSOR_BUSY`，前者的监听、参数和会话继续，不被替换

#### Scenario: 停止一路不影响另一路
- **WHEN** 加速度计与陀螺仪同时采集，调用方仅停止加速度计
- **THEN** 只完成加速度计文件，陀螺仪继续接受其后实际事件，直到它被单独停止

### Requirement: 原生正式窗口与迟到回调隔离

系统 MUST 用本源原生单调时间建立正式起止边界，并将回调绑定到创建它的会话；只接受入口开放且事件时间属于该窗口的记录。开始前历史事件、入口关闭后的事件以及旧会话迟到结果 MUST NOT 写入新会话。窗口不构成收齐全部硬件事件或跨源同步的承诺。

#### Scenario: 注册后收到历史事件
- **WHEN** 新会话开始后收到事件时间早于其正式开始边界的样本
- **THEN** 该样本不进入本次文件，不伪造新的事件时间使其进入窗口

#### Scenario: 前次回调晚于下次开始
- **WHEN** 第一次采集已停止，第二次已开始，第一次的回调迟到
- **THEN** 它不能写入第二次的队列或文件，也不能改变第二次的运行状态

### Requirement: 样本快照与异常数据处理

系统 MUST 在有效系统回调内提取独立的三个轴值与时间，不在异步消费时继续读取系统事件或其可变数组。缺少三个轴值、轴值非有限或事件时间无效 MUST 以 `SENSOR_DATA_INVALID` 终止本源成功路径，不补零、不补造样本。

#### Scenario: 系统复用事件数组
- **WHEN** 已接收样本的系统数组在后续回调被更新，而前一条仍等待写入
- **THEN** 文件中的前一条保留原来接受时的值，不变成后续事件的值

#### Scenario: 输入缺轴或非有限
- **WHEN** 某次回调少于三个轴值或包含 NaN／无穷值
- **THEN** 本源明确失败并收尾，停止不返回看似正常的 CSV 产物

### Requirement: CSV 时间与类型专属列协议

每次正常采集 MUST 原生保存 UTF-8 六列 CSV，前三列依次为 `timestamp,timestampEvent,timestampSystem`，末三列依次保留加速度计的 `accX,accY,accZ`、陀螺仪的 `gyrX,gyrY,gyrZ`、磁力计的 `magX,magY,magZ` 或重力的 `graX,graY,graZ`，不得统一为 x/y/z 或增加别名列。前三列分别为回调接收的启动后单调时间、系统事件原始时间和回调时的单调系统时间，均为保留小数的毫秒，MUST NOT 当作 Unix 时间、相互替代或由 JS 收集后生成文件。

#### Scenario: 分数毫秒与三种时间不相同
- **WHEN** 一条实际事件的接收、事件和系统时间不同，且包含不足一毫秒的部分
- **THEN** CSV 在约定各列保存各自的毫秒小数，不截断为整数、不用同一个时间填满三列

#### Scenario: 四种类型沿用旧表头并保持轴值位置
- **WHEN** 四种类型分别完成采集，且每份文件内同一条记录的三个原始轴值互不相同
- **THEN** 四份 CSV 的完整表头依次为 `timestamp,timestampEvent,timestampSystem,accX,accY,accZ`、`timestamp,timestampEvent,timestampSystem,gyrX,gyrY,gyrZ`、`timestamp,timestampEvent,timestampSystem,magX,magY,magZ`、`timestamp,timestampEvent,timestampSystem,graX,graY,graZ`；每条记录的原始 X、Y、Z 值依次进入对应的类型轴列，不混用类型前缀、不交换位置

### Requirement: 物理单位与设备坐标保持原始含义

各类型的三个轴列 MUST 保存标准 Android 默认传感器三轴值：加速度计含重力、重力传感器为 m/s²，陀螺仪为 rad/s，磁力计为 μT。坐标 MUST 基于设备自然方向，X 向右、Y 向上、Z 向屏幕外，不随屏幕旋转重映射，不在应用内去重力、滤波或校准；产物 MUST 明确类型、单位和坐标标识。

#### Scenario: 旋转屏幕但不旋转设备坐标定义
- **WHEN** 采集期间屏幕显示方向改变
- **THEN** 文件轴顺序与 Android 自然设备坐标保持一致，不静默交换 x/y，也不把加速度单位换成 g

### Requirement: 缓冲有界且消费顺序不丢失

每个源的未消费记录 MUST 有限，并将正在消费的记录计入占用；已接受记录 MUST 按接收顺序至多一次写入，不因数量／时间触发并发重复写入。容量不足 MUST 以 `DATAHUB_CAPACITY_EXCEEDED` 使本源失败，不静默覆盖、丢弃后仍发布成功文件，亦不得由逐样本无限任务绕过容量限制。

#### Scenario: 磁盘阻塞时容量耗尽
- **WHEN** 一个源的写入未完成且新增事件使其有限容量耗尽
- **THEN** 该源明确失败，内存积压有界，不发布部分成功文件；另一源的独立队列与状态不被清空

### Requirement: 停止成功包含回调收尾尾批与文件关闭

停止 MUST 关闭本会话入口、注销监听、等待已进入处理的回调退出及所有已接受记录尾批写入、关闭输出并完成路径提升后才返回产物。产物 MUST 包含类型、会话、可读路径、字节数、实际记录数、单调起止边界、请求／注册间隔与单位／坐标；实际记录数不得由请求频率推算。

#### Scenario: 停止时消费者尚未返回
- **WHEN** 用户停止而一个批次仍在写入，或队列存在不足整批的尾部记录
- **THEN** 停止结果继续等待；成功返回后文件已关闭可读，sampleCount 与实际写入的数据行数一致

### Requirement: 重复停止和异步命令不误停新会话

同一会话的并发停止 MUST 等待同一收尾结果；未开始下一会话时的重复停止 MUST 返回相同产物或失败。停止请求 MUST 绑定调用时的目标会话，迟到执行不影响后续会话。没有当前或已结束会话时停止 MUST 报 `SENSOR_NOT_CAPTURING`。

#### Scenario: 重复停止跨越异步收尾
- **WHEN** 同一源被并发请求停止，第一次收尾结束后又开始了新采集
- **THEN** 先前的停止等待者都取得旧会话结果，不因恢复执行而注销新会话监听或关闭新文件

### Requirement: 无样本和文件错误不得冒充成功

正常停止前没有接受任何样本 MUST 报 `SENSOR_NO_SAMPLES`，不得发布只有表头的完成文件。文件打开、写入或完成发布失败 MUST 分别报告 `FILE_OPEN_FAILED`、`FILE_WRITE_FAILED`、`FILE_FINALIZATION_FAILED`，封闭本源成功路径并释放监听、回调执行资源及句柄；失败临时文件不得进入完成列表。

#### Scenario: 注册成功但没有事件
- **WHEN** 设备注册成功，用户停止前没有实际接受到样本
- **THEN** 返回 `SENSOR_NO_SAMPLES`，不以非空表头文件作为成功证据

#### Scenario: 关闭或路径提升失败
- **WHEN** 数据已写入但关闭输出或完成路径提升失败
- **THEN** 停止报告收尾失败而非返回产物，保留可判别根因，不通过返回临时路径绕过失败

### Requirement: 文件持久且会话路径隔离

系统 MUST 在应用私有持久目录为每个源的每次会话分配独立临时与完成路径，拒绝覆盖已有文件。停止、页面卸载、关闭其它源或进程退出 MUST NOT 删除已完成文件。完成列表 MUST 按类型仅返回当前进程已完成引用；进程重启后无扫描恢复时不得伪造旧引用或声称旧文件被删除。

#### Scenario: 同类型连续采集与进程重启
- **WHEN** 同一类型完成两次采集，随后进程重启
- **THEN** 两个文件路径不同且仍然保留；新进程完成列表可为空，界面明确只查询本进程记录

### Requirement: JS 只接收控制与低频状态

JS 接口 MUST 仅提供能力、配置结果、状态转换、结构化错误和文件引用，不传递单条传感器样本、批次或持续增长数组。状态 MUST 如实区分 idle、starting、capturing、stopping、failed，不能将准备文件或收到请求当作采集已经启动；解除订阅 MUST 只移除该订阅。

#### Scenario: 四路运行且页面解除订阅
- **WHEN** 多个可用类型正在采集，其中一个页面解除状态订阅
- **THEN** 不再向该订阅发送状态，但不因此停止任何源；其他订阅继续，JS 不接收逐样本数据

### Requirement: 前台生命周期显式中断且不自动恢复

本能力 MUST 仅在宿主可用前台状态启动；暂停／进入后台时以 `APP_NOT_FOREGROUND`、运行上下文销毁时以 `RUNTIME_DESTROYED` 封闭正在进行的会话并收尾，不将中断发布为正常手动完成。恢复前台或重开应用 MUST NOT 自动重新采集；单纯页面切换不等同宿主后台。

#### Scenario: 启动后切换页签再进入后台
- **WHEN** 用户启动传感器，先在本应用前台切换到 PPG 页，之后将应用切入后台
- **THEN** 页签切换不停止传感器；宿主后台中断时注销并失败收尾；返回后显示未运行和原因，需用户再次启动

### Requirement: 联合采集由 JS 编排且不改变其他能力

各源 MUST 允许 JS 分别发出控制命令；原生不得提供自动组合 PPG 与传感器的联合启停、失败级联或共享文件事务。新增能力 MUST 保持既有 PPG 双 CSV、相机页面清理、被动录像及相机互斥行为，不新增相机、通知、共享存储或高采样率授权要求。并发启动命令不得被描述为跨源同步。

#### Scenario: 传感器与 PPG 前台并行
- **WHEN** 用户先启动可用传感器，再在前台主动 PPG 页打开后摄、完成采集并关闭相机
- **THEN** 两路分别形成自己的原生记录，关闭 PPG 不停止传感器；由 JS 决定何时另行停止传感器，不宣称样本已对齐

### Requirement: 独立验证入口与真实采样证据

应用 MUST 提供无需登录的传感器验证入口，分别展示四类型可用性、参数、状态、错误和完成引用并独立启停。验收 MUST 实际运行 UI、取得真实系统回调并读取 CSV，覆盖四类型、双源隔离、PPG 并行及后台中断；缺失类型需补充支持环境的正向证据，不能用 mock 或不支持结果代替全部采样通过。

#### Scenario: 环境只具备部分类型
- **WHEN** 当前设备缺少磁力计，但其它类型可用
- **THEN** 记录磁力计不可用路径及未完成的正向验收，继续验证其它类型；使用支持磁力计的环境补齐，不生成假数据或宣称四类型全部通过

#### Scenario: 模拟器产生系统传感器事件
- **WHEN** 在模拟器操作传感器输入并完成采集、停止和文件检查
- **THEN** 证据注明模拟器及输入方式，检查表头、数值、时间和实际行数，不推定实体设备性能、稳定采样率或医学有效性
