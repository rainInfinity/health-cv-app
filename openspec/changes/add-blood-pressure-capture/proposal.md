# Proposal

## Why

血压检测的双阶段界面已在 design-demo 完成，但原生入口仍提示未接入，现有指尖覆盖后自动开始的单源会话也不能直接交付血压所需的 PPG＋ACC 联合采集。本次将设计迁入 Android 原生，以简单的姿态、稳定性与心震候选判定自动开启真实采集，先验证正常操作效果，再决定后续优化。

## What Changes

- 新增原生血压检测页，复用真实后摄、覆盖环、毛玻璃提示、指尖指导与原生分页；第二页迁移现有贴胸双图六帧动画，不挂载脉搏波、不增加主动确认或手动开始入口，不修改 Web 设计稿。
- 覆盖完整且连续稳定三秒后进入贴胸准备；由原生执行 `覆盖就绪 AND 持机稳定 AND（倾角 >= 30° OR 心震候选成立）`。倾角指屏幕平面与水平面的夹角，平放为 0°、竖直为 90°，不是偏离竖直的角度；不要求先完成一次竖起动作。
- 用 ACC 与陀螺仪做有限滑窗稳定判定；从 ACC 屏幕法线轴经因果带通、能量与包络重复性形成心震候选。心震检测在贴胸准备及正式采集期间持续运行，与倾角、分页及另一条准入路径无关；不因单次稳定或心震候选消失暂停、补时或重启正式窗口。
- 新增本轮 PPG＋ACC 的原生协调、共同三十秒接收窗口、确切所有权、截止与完整收尾；准备数据不进入正式文件，组合结果仅引用同轮真实文件，任一路失败不能作为联合成功。
- 接通现有血压准备页、方式级跳过偏好及功能双分类入口，沿用权限、原生预览就绪、离页屏障和必要重试／返回；覆盖丢失或后台中断不自动续采。
- 明确替换主规格中“血压未接入”及禁止原生联合启停的限制，仅对显式血压轮次开放协调例外；独立指尖、相机、传感器与被动能力保持隔离。
- 本次不引入 IMU 动作模型、前摄识别、空间位置积分、云端上传、血压估值、健康历史、语音或 measurement 业务包重构。判定仅是本地工程准入，不保证解剖学接触识别或医学质量；接受姿态合理但未贴胸的稳定持机仍可能放行，阈值效果在真机验证后评估。

## Capabilities

### New Capabilities

无，沿用既有采集、传感器、产品检测及导航能力边界。

### Modified Capabilities

- `native-acquisition`：增加血压独立轮次、持续 IMU 准入、原生联合窗口、确切所有权和组合完成事实；保留指尖现有自动开始及展示脉搏。
- `android-sensor-acquisition`：允许显式血压轮次取得本轮 ACC／陀螺仪并进行原生观测和有限采集协调，保持独立入口、原始 CSV、单类型互斥及组外隔离。
- `native-measurement-pages`：开放真实血压页面和双阶段提示，保留设计稿布局与贴胸动画，并区分观测、正式计时和收尾。
- `native-app-shell`：将血压页接入现有根栈、返回和离页屏障，明确组内 IMU 不等同于独立传感器会话。
- `native-product-pages`：血压部位／指标入口按已有跳过偏好进入准备或真实检测，不再反馈未接入，不发布健康记录。

## Impact

- 影响 `packages/acquisition` 的 Nitro／TypeScript 控制合同及 Android PPG、传感器会话和本轮协调；复用独立队列、CSV writer 与相机互斥，不引入跨源共享文件事务或原始样本 JS 流。
- 影响 `apps/native/src/app/measurement`、根导航、血压页面及实际复用的指尖展示／图形；同步中文资源及既有对应资源键，不改变面部和指尖产品行为，不改造 Dev 页面。
- 实施以 `add-fingertip-capture` 已交付的真实覆盖、PPG 准备／开窗及收尾合同为基线。当前主规格尚含旧指尖展示措辞，增量必须保留该已完成变更的语义；本次不修改或归档其文件。
- `add-local-measurement-orchestration` 仍引用旧的手动开始及已不存在的前置合同，不作为本次依赖，不同步修改其规划文件，也不据其旧描述反向改变本次行为；后续实施该编排变更前须另行对齐。
- 实施完成后更新 `docs` 下受影响的前端、图形、架构及采集协议说明；核心验证覆盖原生页面、两条准入路径、真实双源产物及必要中断，不扩展临床准确率、多设备矩阵或长期压力要求，不保存验收流水。
