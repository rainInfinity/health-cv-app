# Design

## Context

动机和范围见 `proposal.md`。这是跨包及页面职责迁移，包含新的可调用会话合同，因此编写设计；不只是为代码搬家增加规格。

- 当前 `useFaceMeasurement` 同时持有原生客户端、命令防重、关闭、心率累计、预览等待、导航和波形历史；`app/measurement/entry.ts` 只负责入口映射。
- `app/rppg/rppgHeartRateSummary.ts` 已有去重后的有效频谱算术累计，被产品面部页、Dev RPPG 页和行为测试使用。窗口摘要是本轮收到的低频通知累计，不是从文件完整重建的最终结果。
- `add-fingertip-blood-pressure-capture` 将交付有限 PPG／PPG＋ACC 采集、原生正式窗口、低频进度、按 captureId 停止、组内所有权和完整组合引用。它目前仍是前置规划，不能在本提案中假设已经可调用。
- 前置采集变更已规定两步预览／正式开始、产品级指尖／血压采集 UI、原生截止、离页收尾和不产生健康指标。本次只迁移业务所有权，不重新设计这些行为。
- 用户已明确先做本地编排，云端以后另行考虑；不存在当前必须解决的登录、模型绑定、上传恢复或任务轮询设计。

## Goals / Non-Goals

**Goals:**

- 一轮业务会话拥有自己的方案、身份、命令、低频状态和结果关联，页面不能通过改状态推进流程。
- 三种方案共享明确相同的命令和生命周期规则，面部与原始采集保留各自的结果解释；不硬套一套无限可配置的状态机。
- 通过真实应用适配器接入设备，包级测试能在无 React、无 Android 宿主时验证业务行为，实际采集仍在产品页验收。

**Non-Goals:**

- 不重新实现有限时长、双源 ready gate、软件窗口、资源租约、队列、算法或文件发布。
- 不改变面部平均定义、原生时长、波形来源、指尖／血压产品视觉及准备动作，不引入第二套实际运行路径。
- 不接 cloud-client、Axios、React Query、认证或环境变量；没有云端字段、上传占位接口和虚构指标结果。
- 不将被动服务纳入主动会话，不实现被动产品入口、语音、健康历史、跨进程会话恢复或文件清理。

## Decisions

### 1. 一个业务包，按实际职责分文件

`packages/measurement` 使用现有 pnpm workspace，公开入口为 `src/index.ts`，不提供 React 专用入口。

| 文件 | 职责 |
| --- | --- |
| `types.ts` | 业务方案身份、会话快照和本地结果的可判别类型。 |
| `plans.ts` | 三种固定方案与各自允许的驱动种类、准备方式、结果类型。 |
| `ports.ts` | 面部 RPPG 与有限原始采集的必要注入合同；不复制整套 SDK。 |
| `session.ts` | 每轮身份、只读状态、业务命令串行、订阅及关闭屏障。 |
| `face.ts` | 面部真实阶段与本轮摘要结果解释。 |
| `capture.ts` | 指尖和血压有限采集的阶段、模式和完整产物解释，二者不重复一份编排。 |
| `heartRateSummary.ts` | 迁入现有纯摘要函数和类型，保持规则并供所有实际使用方调用。 |

这些模块先保持同级，职责增长后再按实际需要拆目录；不预建 domain／state／data／contracts 层。包采用 TypeScript 与现有 Nano Stores 表达低频只读状态，不依赖 React。采集协议类型通过 acquisition 公共入口 `import type` 复用；运行时不导入 acquisition 工厂、RN、Nitro 或任何云端包。

不在 package.json 中引入无使用方的云端、播放器或原生运行时依赖。TypeScript 目标沿用工作区 ES2022／严格模式；自身 `src` 根 alias 及实际使用它的构建／测试解析遵守前端约定，同目录模块可以使用相对路径，不把应用 `@/` 指向业务包源码。

### 2. 方案只描述本地业务选择，不携带平台配置表

| 方案 | 采集来源 | 准备／开始行为 | 本地结果 |
| --- | --- | --- | --- |
| `face-heart-rate` | 主动 RPPG | 保留现有一次明确开始内授权、预览准备及启动 | 本轮已观察有效频谱摘要及真实 RPPG 产物事实 |
| `fingertip` | 有限单块 PPG | 用户先准备预览，再明确正式开始 | 本轮 PPG 双文件和有限采集事实 |
| `blood-pressure-capture` | 有限 PPG＋ACC | 同样先预览后开始，由原生协调两个源 | 本轮完整组合引用、各源事实，不是血压估值 |

方案不使用任意字符串拼接执行步骤，也不由页面传入伪造读数。设备配置、720×720／30 FPS 偏好、补光、5,000 微秒 ACC 请求和 30 秒工程窗口沿用前置采集配置，不在业务包中再维护第二份参数或调整医学门槛。

`target` 仍是入口说明上下文，不因为选择血氧或风险入口就在本次执行不同算法；按指标入口未来的云端组织不在此决定。

### 3. 会话以一轮为单位，不建立全局 currentMeasurement

公开工厂 `createMeasurementSession({ planId, driver })` 返回一轮会话。方案与驱动采用可判别类型配对：面部只能接面部驱动，指尖／血压接有限采集驱动并核对预期源模式，不能静默降级。

工厂创建只分配本进程业务身份和空状态，不初始化原生客户端。身份只需在当前进程内区分轮次，不要求 UUID、落盘或跨进程恢复。原生 RPPG sessionId、有限 captureId、PPG 和 ACC 各源 sessionId 分别关联，不互相冒充。

每轮持有一个只读状态出口。状态包含方案、业务身份、业务阶段、在途命令、当前原生身份／必要事实、本轮结果及稳定错误；不镜像一份完整设备 Store，不增加多套 isRunning／isComplete 标记。可操作状态从同一快照派生，页面不能直接写 atom。

一轮完成后展示可以继续持有冻结结果。重测必须先成功关闭旧轮，再创建新的业务会话并立即清空旧展示；不在同一对象上反复切方案或让旧异步回调更新新轮。

### 4. 两类必要驱动，由应用完成真实依赖组装

驱动是 application 提供的实际对象，不是另一套采集实现。公开低频输入优先复用 acquisition 类型；只定义业务所需的方法和准备约束，不复制相机配置、传感器 DTO 或全部错误协议。

| 能力 | 应用侧实现 | 业务包使用方式 |
| --- | --- | --- |
| 可取消的预览准备 | 显式授权、宿主前台判断、挂载原生预览、等待有效布局、打开真实预览 | 在明确业务命令内调用，关闭可阻断尚未发出的后续启动 |
| 面部低频状态与命令 | `RPPGClient` 的状态／订阅、start、stop、close | 解释观察／正式测量／收尾及频谱摘要，不参与帧处理 |
| 有限原始采集 | 前置变更的 bounded 状态／订阅、开始、按 captureId 停止和关闭 | 选择 PPG 或 PPG＋ACC，关联本轮结果，不重新顺序启停两个源 |

客户端按实际命令惰性创建；已关闭的面部 runtime 不复用。`app/measurement` 组装真实驱动及产品方案，保留照片映射、导航入口和页面适配职责，不成为新的泛用 services 桶。

权限与原生宿主必须留在应用，不能要求业务包访问 `Platform`、`AppState`、`onLayout`、navigation 或反馈宿主。预览准备接受关闭信号；系统权限弹窗本身不能被取消时，弹窗返回后也不得继续已失效的打开／开始。当前面部权限弹窗造成短暂后台后恢复的正常显式启动规则保持不变。

替代方案：业务包直接创建 Nitro 对象会导致包级业务测试必须加载设备宿主；让页面继续协调原生命令又不能移出当前职责，二者均不采用。

### 5. 命令串行与关闭屏障只管理业务意图

会话公开 `prepare()`、`start()`、`stop()`、`close()` 和只读状态：

- `prepare()` 在用户意图下执行预览准备；指尖／血压准备后等待另一次明确开始。面部 `start()` 可以按现有语义先完成本轮准备，再执行真正开始。
- `start()` 只代表发起并确认本轮原生启动，不等待三十秒测量结束。状态订阅驱动后续业务阶段，不由 Promise 返回或动画完成直接设置 completed。
- `stop()` 绑定当前轮次的原生身份，等待其真实停止结果；不能因当前没有会话就伪造完成。重复在途操作共用结果或明确拒绝，不另发一组设备命令。
- `close()` 优先设置本轮关闭意图并取消可取消准备，阻断尚未发出的后续启动，再等待已发出的命令及驱动完整关闭。不能先无条件 await 一个只能由即将卸载页面完成的布局等待。
- 并发关闭共用本轮关闭屏障；失败保留该会话和真实错误，允许明确再关闭。成功后拒绝再次准备或开始，保留已冻结的本轮摘要和文件事实。

本轮异步处理绑定会话对象、操作代次和原生身份。命令失败不擦除已定稿文件；原生关闭快照的空当前身份也不能擦除已经结束的业务结果。

这里不复制 acquisition 的租约、截止任务、文件事务或跨源失败联动；业务 close 等待的是原生已有完整屏障。导航是否继续由应用在 close 成功后决定，不把 NavigationAction 存进业务包。

### 6. 面部摘要迁移而不升级结果含义

将现有 `rppgHeartRateSummary.ts` 的类型和纯函数迁入包并保持名称、去重和累计规则，全部调用方改从包根导入。删除旧文件，不保留 re-export；Dev 仅迁移直接受影响调用，不改其控制流程。

纯累计器原有“closed 空快照重置”的使用语义可以保持，业务会话像当前产品 Hook 一样只对属于本轮的有效原生身份累计，关闭后的冻结结果另由业务会话保存。因此保留原有函数测试，同时增加会话关闭不丢失结果的核心回归，而不是为了新实现重写既有均值定义。

平均仍为本轮实际观察到的唯一有效频谱窗口算术平均，不采纳逐搏值，不以零、旧值或样例补齐。原生文件可能有订阅未观察到的窗口，本次不读取文件补齐，也不新增原生最终摘要接口；页面不得把此值宣传为完整产物的权威最终平均或正式健康记录。

### 7. 指尖与血压仅映射完整采集事实

指尖和血压共用有限采集业务处理，不分别维护两份开始／停止逻辑。区分期望源模式，直接保留原生完成引用中的本轮身份、源身份、时长、终止与文件，不从历史数组取最后一项，不重新组合不同轮次的文件。

结果类型区分面部本轮摘要与原始采集结果，不建立一个包含所有可选健康指标的空对象。血压单源文件已经完成、整组却失败时，状态保留可核查文件与失败，不生成成功组合结果。提前结束可以有完整文件，但终止原因保留，不宣称采满目标或通过算法质量。

不创建云端状态、modelId／taskId 字段、上传进度、HTTP 端口、认证上下文或未来处理器占位。后续明确要做云端时另行扩展方案和合同，而不是在本次实现不可运行分支。

### 8. 页面保留平台交互与产品设计质量

`useFaceMeasurement` 及前置指尖／血压页面 Hook 改为连接业务会话。页面仍负责 React 订阅、导航焦点与返回守卫、预览挂载、中文文案、安全区、动画和实际布局。业务错误保持稳定代码，由应用映射统一反馈，不在包中保存翻译文本。

面部本轮波形历史与实时标量订阅留在应用／页面，不经过 measurement atom。`app/rppg/rppgWaveform.ts`、`PulseWaveHistory`、`PulseWaveChart` 及其渲染机制不随摘要搬迁。面部展示计时仍从原生 measuring 通知建立页面单调计时，原生截止不变；指尖／血压直接显示前置原生 elapsed／remaining，不增加业务层第二套计时器。

离页守卫调用当前会话 close 并等待成功后执行导航，不再绕过业务会话直接用页面另一条路径停止同一客户端。应用失焦／卸载兜底仍只处理本页会话；解除单个展示订阅不停止采集。后台停止由原生负责，应用只刷新真实终态，不调用用户 stop 冒充后台原因。

原有主题、圆角、操作图、品牌主按钮、次级技术详情、准备偏好及返回规则保持。没有布局需求就不重绘页面，实际 Android 表面用于证明接入没有破坏产品视觉和可操作性，不以测试能跑为由退化为裸按钮列表。

### 9. 被动 RPPG 只说明边界，不增加空接口

当前被动服务由原生真实解锁和周期门控产生独立会话，离页不停止、无需 JS 持续订阅。未来业务接入应区分长期服务控制和每次已完成结果，不能挂进主动页面的一轮 start／close 生命周期。

本次不为它创建 passive session、服务 Store、产品路由、结果导入器或新的原生摘要查询。主动与被动目前共用 RPPG 低层算法，不表示 JS 的主动观察窗口平均能够用于后台最终结果；未来有明确需求时再定义结果来源，不先实现无使用方抽象。

### 10. 用现有工具验证本地业务，再验证真实产品接入

包级使用 TypeScript、`node:test` 和现有 pnpm 命令习惯；同目录模块保持简单解析，不引入测试框架或原生模拟运行时。受控驱动只用于测试，以明确的低频事件、完成结果和可控 Promise 证明用户可见规则，不接入产品运行路径。

核心测试聚焦：重复开始不会创建两轮、关闭能解除准备并等待已发命令、旧轮结果不污染新轮、关闭失败仍能处理、面部有效窗口规则及冻结、血压不能用单源成功拼成整组完成。直接复用或迁移已有摘要与离页测试，不测试源码文字、导出接线或无意义 not-throw。

集成在三个实际产品页面走通原有主要路径：面部真实开始、停止／结束与重测；指尖及血压准备、原生采集、完成引用与重测；定向检查进行中返回及必要失败反馈。检查前置产品视觉没有回退，不重复证明前置的全部原生队列、双源窗口或算法，不扩展尺寸矩阵、压力或医学准确性。

前置采集未完成时可以审阅提案，但不能用受控驱动交付产品适配或勾选端到端任务。仅模拟器可用时说明实际设备接入与文件范围，不能宣称人体信号有效。此轮无任何服务端测试或外部写操作。

## Risks / Trade-offs

- [前置采集接口仍为规划] → 以其实际交付的公开合同和核心验证完成为实施前置；不同步修改两个提案或用空驱动替代，必要的合同差异先同步本提案。
- [业务与原生各维护一套冲突状态] → 原生拥有采集事实，业务仅保留本轮关联和操作意图；展示从同一低频事实映射，不再调度设备计时或两源停止。
- [关闭等待预览准备造成离页挂起] → 先取消可取消等待并阻断后续动作，再等已发出的原生命令；关闭失败留在同轮处理。
- [摘要搬迁被误当成最终结果升级] → 保持观察窗口平均及现有去重规则，明确不重建文件、不发布健康记录。
- [引入包后仍保留页面旧编排] → 三个产品页面全量迁移命令路径，删除旧摘要私有路径和过时控制逻辑；只保留真正属于 React／平台的部分。
- [为未来云端和被动过度抽象] → 本次无这些运行时接口、状态或任务，设计只说明其不能混入本地主动会话的边界。

## Migration Plan

1. 依次完成现有页面提案和指尖／血压采集前置，不代验其未完成项，以实际交付的公开接口和产品行为为基线。
2. 新增业务包及有限方案、会话、驱动合同、结果处理与包级测试；迁入现有摘要，保留规则。
3. 在应用组装真实驱动，分别接入面部、指尖和血压产品页面，保留现有导航和视觉；更新所有摘要调用方及测试，删除旧实现和转发路径。
4. 完成受影响包检查及三个实际 Android 产品表面验证后，更新架构、前端开发与采集接入文档，不保存验收日志。
5. 如需回退，撤销本次业务包接入并恢复前置已交付的页面编排，不回退前置采集能力、不删除产物、不改变被动服务，不保留长期新旧双路径。
