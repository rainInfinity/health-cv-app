# Proposal

## Why

本地面部测量的业务控制仍混在页面 Hook 中，指尖和血压采集前置完成后也需要统一的本轮身份、命令、结果关联和收尾语义，不能让每个页面继续各写一套。新增独立 `measurement` 包承接这些本地业务职责，在不改变已确认采集和产品行为的前提下，使编排能脱离 React 与设备实现进行测试。

## What Changes

- 新增 `packages/measurement`，提供主动面部心率、指尖原始 PPG、血压所需 PPG＋ACC 三种有限本地方案，以及每轮独立的业务会话、命令、只读状态与结果引用；不预建通用流程引擎。
- 通过应用组装层注入采集能力，统一准备、开始、停止和关闭的业务语义，隔离重复操作、旧轮回调及结果；真实采集、截止、双源所有权和文件收尾继续由 acquisition 负责。
- 面部沿用当前唯一有效频谱窗口的算术累计，只形成本轮展示摘要；指尖和血压本次只关联真实原始采集产物，不产生心率、血氧、血压或风险指标。
- 将产品页面的业务控制及 RPPG 摘要迁到所属模块，页面 Hook 保留 React 订阅、权限／预览宿主连接、导航、展示计时、波形历史及 UI 映射；更新摘要全部实际调用方，不保留旧路径转发或第二套实现。
- 保留采集前置提案交付的产品视觉、引导、跳过偏好、显式开始及离页屏障，不因引入业务包重新设计页面、不降低测试 UI 的产品级视觉要求。
- 不涉及云端：不依赖 cloud-client、Axios 或 React Query，不增加创建任务、上传、轮询、登录要求、环境变量、服务端结果解码及空的云端接口；不更新首页、最近测量时间或健康历史。
- 被动 RPPG 只明确未来的所有权边界：原生服务独立触发与运行，服务不等于一次主动业务会话。当前不迁移被动服务、不新增被动业务接口、摘要查询或产品接入任务，也不实现语音系统。

## Capabilities

### New Capabilities

- `measurement-session`：可由应用注入真实采集能力的本地业务会话，拥有有限方案、每轮身份、命令防重、真实阶段和完成／失败结果解释，以及主动采集的可等待关闭语义。

### Modified Capabilities

无。既有面部、指尖与血压的外部采集及页面合同保持不变；本变更新增业务包的可调用合同和产品接入，不重写已由采集前置变更定义的原生时长、数据协议与页面行为。

## Impact

- 实施依赖 `restore-native-measurement-pages` 和 `add-fingertip-blood-pressure-capture` 完成实际实施及必要验证。前置提案目前尚未全部实施，本次规划不等于其采集接口已可用，也不修改其文件或代替其验收。
- 新增业务包清单、TypeScript／测试配置和必要依赖；使用现有 pnpm workspace，不引入中央 contracts、跨端 UI 包或新测试框架。
- 影响 `apps/native/src/app/measurement`、产品测量页面 Hook、必要导航连接、`app/rppg/rppgHeartRateSummary.ts` 及其调用方和测试；保留波形展示模块与共享图表，Dev 仅更新受影响摘要调用，不扩大为 Dev 重构。
- acquisition 的公开类型可按类型复用，运行时只调用注入对象，不从其他包私有源码深层导入；acquisition 不反向依赖 measurement。
- 实施后同步架构、前端开发及相关采集接入文档，区分原生事实、业务状态、局部展示和当前未接云端的范围；不把提案或测试结果写成健康指标已经有效。
