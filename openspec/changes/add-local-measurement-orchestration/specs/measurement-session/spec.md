# Spec Delta

## Purpose

为主动面部心率、指尖原始 PPG 和血压所需 PPG 加加速度提供可复用的本地业务会话，使应用通过明确命令与只读状态完成一轮操作，并保持原生采集事实、文件完成、会话摘要和健康指标之间的区别，不依赖页面生命周期代管设备或引入云端行为。

## ADDED Requirements

### Requirement: 本地方案有限且业务会话创建无设备副作用
系统 MUST 提供面部本地心率、指尖原始 PPG、血压原始 PPG 加加速度三种明确方案；每轮选择一个方案并冻结本轮上下文。创建业务会话、读取状态和订阅 MUST NOT 授权、打开设备、写入文件或发起网络请求。方案名称不得成为健康结果已可用的依据，不支持的方案不得静默替换为其他采集方式。

#### Scenario: 创建指尖业务会话
- **WHEN** 应用为指尖页面创建一轮会话并订阅
- **THEN** 会话处于待操作状态，尚无原生采集、文件或健康指标，用户仍须明确准备和开始

#### Scenario: 三种方案的数据来源
- **WHEN** 应用分别执行面部、指尖和血压本地方案
- **THEN** 面部使用主动 RPPG，指尖使用单块原始 PPG，血压使用本轮 PPG 加加速度；本次不创建云端任务或推理其他指标

### Requirement: 业务身份与原生身份明确关联
每轮业务会话 MUST 拥有独立身份，并分别关联该轮实际产生的原生会话／有限采集标识及完成引用，不将业务身份与设备身份混用。只有属于本轮、当前执行代次的状态、摘要和产物才能更新会话；旧轮迟到结果、其他源结果及历史列表末项 MUST NOT 被当作本轮结果。

#### Scenario: 重测后旧结果到达
- **WHEN** 旧轮已经关闭、页面建立新轮，而旧轮状态或停止结果随后返回
- **THEN** 新轮保持自己的阶段、摘要与文件关联，不恢复旧值或把旧文件作为本轮产物

#### Scenario: 血压产生多个原生标识
- **WHEN** 本轮有限采集包含独立 PPG 与加速度会话
- **THEN** 同一个业务身份关联本轮组合标识及各源身份，不要求三者相等，也不从其他会话列表猜测配对

### Requirement: 业务状态只读且区分采集文件与结果事实
业务会话 MUST 提供只读的当前阶段、在途操作、本轮原生事实、结束原因、稳定错误及可用本地结果。消费者 MUST 通过业务命令推进，不能直接改写内部状态。采集结束、文件定稿、资源释放和有效面部摘要 MUST 分别表达；正常停止不等于达到目标，完成文件不等于生理信号或健康指标有效。

#### Scenario: 到时但仍在收尾
- **WHEN** 原生报告已停止接收数据，而文件或资源屏障尚未完成
- **THEN** 业务会话仍表达收尾且不能开始新轮，不因页面计时归零显示整体完成

#### Scenario: 本地文件已完成但关闭失败
- **WHEN** 部分或全部文件已定稿，但本轮资源关闭失败
- **THEN** 状态保留真实文件事实和关闭错误，不宣称资源释放完成，不丢弃文件或用成功状态掩盖失败

### Requirement: 业务命令防止重复执行与在途交叉
业务会话 MUST 提供明确的准备、开始、停止及关闭操作，合并或拒绝同轮重复的在途请求，不重复取得资源或创建本轮采集。指尖与血压必须先准备预览再明确开始；面部保留一次明确开始内完成准备及启动的行为。停止仅作用于本轮已启动采集，不将准备失败或未开始状态伪装成成功停止。

#### Scenario: 连续点击开始
- **WHEN** 用户在同轮开始尚未完成时再次开始
- **THEN** 不创建第二轮原生会话或第二组文件，消费者可观察同一个在途操作及其实际结果

#### Scenario: 指尖尚未准备预览
- **WHEN** 指尖会话处于待操作且尚未完成预览准备
- **THEN** 正式开始不能绕过准备阶段；页面保持明确准备操作，不以进入页面自动开始替代

### Requirement: 关闭先阻断后续启动再等待本轮屏障
关闭请求 MUST 使本轮尚未发出的后续启动失效，解除可取消的准备等待，再等待已经发出的设备命令和本轮资源／文件收尾。并发关闭共享同轮屏障；成功后该会话不再启动设备。关闭失败 MUST 保留会话及再次关闭能力，不放行资源交接、不停止其他所有者，也不把当前失败替换为旧诊断。

#### Scenario: 等待预览布局时请求离开
- **WHEN** 本轮仍在可取消的预览准备等待中而用户请求关闭
- **THEN** 等待被解除，之后不再打开或开始本轮设备；已经发出的命令仍按真实结果收尾，关闭不因等待一个已离开页面的布局而永久挂起

#### Scenario: 关闭失败后再次关闭
- **WHEN** 本轮真实关闭失败，调用方随后明确再次请求关闭
- **THEN** 会话仍可完成原有资源屏障，不先建立新会话、不释放其他所有者的资源；成功后才允许应用继续导航

### Requirement: 正式采集事实由原生负责且不暂停续采
业务会话 MUST 使用注入采集能力提供的真实阶段、截止、终止与产物事实，不建立第二套设备计时、覆盖判定或双源停止调度。有限 PPG 进度直接使用原生相同窗口的时间；面部保持现有原生阶段驱动的展示计时边界。宿主后台按原生中断，恢复或重新订阅 MUST NOT 自动续采。

#### Scenario: 页面显示时间晚于原生截止
- **WHEN** 页面尚未处理最新展示通知而原生已经截止
- **THEN** 会话按原生进入收尾，不延长采集、不发额外开始命令，页面随后读取真实状态

#### Scenario: 后台返回
- **WHEN** 已启动的主动会话因后台被原生中断，随后页面回到前台
- **THEN** 会话保留真实中断事实，不使用旧模拟流程的暂停后继续策略，也不把中断改写为用户正常停止

### Requirement: 面部摘要保持唯一有效频谱窗口语义
面部业务会话 MUST 只累计本轮实际收到的唯一有效频谱心率窗口，按原生会话、片段和窗口时间去重，忽略无效、重复、迟到及非有限数值；逐搏初步值不得进入平均。无有效窗口时摘要为空。该摘要只代表本轮已观察窗口，不宣称文件中全部窗口的权威最终平均，不写入首页或健康历史。

#### Scenario: 波形或逐搏值先到
- **WHEN** 面部已出现波形或逐搏初步值，但没有有效频谱窗口
- **THEN** 会话平均仍为空，页面保持既有缺值显示，不用逐搏或模拟值补齐

#### Scenario: 关闭快照不擦除本轮展示结果
- **WHEN** 本轮结束后关闭设备，收到没有当前原生会话标识的关闭快照
- **THEN** 已冻结的本轮摘要和结果不被当作新轮清空；只有应用明确建立新轮才重置本轮展示关联

### Requirement: 指尖与血压仅交付本轮原始采集结果
指尖结果 MUST 引用本轮 PPG 双文件及真实有限采集元信息；血压结果 MUST 引用本轮完整 PPG 加加速度组合及其源信息。组合是否完整由原生前置合同决定，业务层不得重新拼接、改写或补齐文件。任一路失败不生成成功血压采集结果；这两种方案本次均不产生心率、呼吸率、血氧、血压估值或风险结果。

#### Scenario: 血压一源失败而另一源有文件
- **WHEN** 原生组合因一个源失败而未发布完整组合引用
- **THEN** 业务会话保留失败及已有分源文件事实，不从旧列表补文件、不把单源成功解释为整体采集完成

#### Scenario: 指尖原始采集正常完成
- **WHEN** 原生确认本轮 PPG 文件、时长和资源均按合同完成
- **THEN** 业务结果只表达本轮原始采集完成及文件引用，不计算或展示任何云端指标，不更新最近健康测量时间

### Requirement: 订阅与文件生命周期不扩大为持久业务恢复
解除业务状态订阅 MUST 只移除该订阅，不等同于停止设备；主动页面必须明确等待关闭后离开。业务会话不读取、写入或删除采集文件，不将完整波形／采样存入业务状态，不持久化整个会话或承诺重启恢复。清空旧轮展示不得删除原生产物。

#### Scenario: 重建展示订阅
- **WHEN** 当前页内组件解除并重新建立同轮订阅，未发出关闭命令
- **THEN** 可读取同轮当前真实状态，原生不会因订阅变化停止或重新开始，业务层不重建采集

#### Scenario: 文件保留
- **WHEN** 本轮关闭后页面清空状态或建立新轮
- **THEN** 已完成原生产物继续按 acquisition 策略保留，不因本地会话释放或缓存变化被删除

### Requirement: 本地业务接口可脱离页面和原生宿主执行
业务接口 MUST 接收应用提供的必要采集能力并仅在明确命令下调用，不自行创建平台设备、导航、认证或网络服务。相同会话规则必须能够在无页面及无原生宿主的环境中由受控采集事件驱动验证；正式应用必须注入真实实现，不得用测试输入作为运行时回退。

#### Scenario: 隔离验证业务状态
- **WHEN** 测试环境提供受控的采集阶段、完整产物及失败结果
- **THEN** 可以验证同轮身份、命令竞争和结果解释而不启动设备；这些验证不被声明为真实采集、医学结果或产品端到端验收
