# Spec Delta

## RENAMED Requirements

- FROM: `### Requirement: 联合采集由 JS 编排且不改变其他能力`
- TO: `### Requirement: 独立传感器与显式组合采集各自保持所有权`

## MODIFIED Requirements

### Requirement: 独立传感器与显式组合采集各自保持所有权
各源 MUST 保留 JS 独立控制能力；同时允许用户明确发起的 PPG 加加速度原生组合采集，仅在该组合内部协调启停、截止、失败收尾与完成关联。独立会话 MUST NOT 被组合请求接管，独立调用方也不得停止组合持有的加速度会话。既有 PPG 双 CSV、独立传感器文件、相机互斥、被动能力和权限边界 MUST 保持；并发控制或共同截止不得描述为硬件同步。

#### Scenario: 传感器与 PPG 前台并行
- **WHEN** 用户先启动可用传感器，再在前台主动 PPG 页打开后摄、完成采集并关闭相机
- **THEN** 两路分别形成自己的原生记录，关闭 PPG 不停止传感器；由 JS 决定何时另行停止传感器，不宣称样本已对齐

#### Scenario: 组合采集不停止无关类型
- **WHEN** PPG 加加速度组合失败或停止，而独立陀螺仪、磁力计或重力会话仍在运行
- **THEN** 只收尾本轮组合持有的源，无关类型在宿主仍处前台时继续按原会话采样

#### Scenario: 独立加速度已在运行
- **WHEN** 组合启动请求遇到已有独立加速度会话
- **THEN** 请求取得可判别的资源忙结果，不改变原会话的参数、监听、文件或停止结果

#### Scenario: 独立入口尝试停止组合占用
- **WHEN** 组合拥有当前加速度会话，而独立传感器入口发出停止请求
- **THEN** 独立请求被拒绝，不注销组合监听、不关闭其文件；组合仍由本轮所有者或原生宿主生命周期收尾

## ADDED Requirements

### Requirement: 组合传感器准备与正式采集窗口可区分
组合采集 MUST 能区分源的资源准备、监听注册和正式数据接收。加入本轮的加速度记录 MUST 只来自本轮正式窗口，仍保留系统事件原始时间、物理单位、坐标和实际样本数。关闭组合须等待该源原有的回调、队列和文件屏障，不以停止命令已发送作为完成。

#### Scenario: 准备期间已有传感器事件
- **WHEN** 加速度监听已经准备但本轮组合尚未进入正式窗口
- **THEN** 准备期间事件不进入本轮正式 CSV，也不改写时间戳补进窗口

#### Scenario: 请求频率与实际频率不同
- **WHEN** 组合请求采样间隔与设备实际事件间隔不同
- **THEN** 结果保留请求／注册间隔及真实样本数和采样时间，不按请求频率填充记录或宣称实采稳定频率
