# Design

## Context

动机和范围见 `proposal.md`。本变更同时涉及原生控制、Nitro 合同及产品页面，符合需要设计文档的跨模块条件。

- `PPGController` 已拥有相机查询、冻结配置、预览、锁确认、原始双 CSV 会话及关闭屏障；`startCapture()` 没有时长，正常 `stopCapture()` 通常返回预览，并不释放相机。
- `PPGCaptureSession` 在输出准备前取得起点，现有结束字段又不等于文件完成时刻；`SensorCaptureSession` 的起止边界与 PPG 也不完全同义，不能以两份旧产物时长证明共同采满三十秒。
- `SensorRuntime` 按类型共享控制器，`SensorController.stopCapture()` 绑定调用时的活动／最近会话，但没有调用方所有权。组合遇到忙后无条件停止 ACC 会误停已有独立会话。
- 现行 `android-sensor-acquisition` 明确禁止原生联合启停，本次增量显式修改该约束，仅开放有限 PPG＋ACC 采集组；独立源行为和既有文件事务边界继续保留。
- 产品入口和准备资源已经存在。指尖页依赖 `fingertipDisplay.ts` 模拟覆盖、计时和波形；血压入口仍返回未接入。前置页面提案交付的规格是本次页面迁移基线，不能只按尚未同步的主规格实施。

## Goals / Non-Goals

**Goals:**

- 提供后续 measurement 可直接调用的有限采集控制、同一原生窗口进度和本轮文件关联，不把这些职责留给页面定时器。
- 将“单块 PPG”及“单块 PPG＋加速度”作为两种明确的设备组合，不以健康指标命名原生模式，不建立任意节点流程配置。
- 真实采集测试页沿用产品视觉和交互质量，只聚焦采集能力；通过实际设备状态和文件检查支撑后续业务编排。

**Non-Goals:**

- 不实现 measurement 包、HTTP 编排、医学指标、质量评估、历史、自动上传、语音或被动 RPPG 产品接入。
- 不新增覆盖面积估计、实时 PPG／脉搏波协议，不把现有经验提示升级为质量门禁。
- 不建立传感器硬件同步、跨源重采样、跨文件原子事务、进程重启恢复或自动清理。
- 不为本次改造建立新的主题、图表、通用 Hook 层或开发控制台，不更改 design-demo。

## Decisions

### 1. 复用现有采集入口，增加有限原生协调器

在 `Acquisition` Nitro 对象及 `AcquisitionClient` 上增加有限采集命令和低频状态，内部新增小型 `BoundedCaptureController`，通过既有 `PPGRuntime`、`PPGController` 与 `SensorRuntime` 取得确切源会话。保留现有单源手动接口，不另建相机控制器、HybridObject、writer 或 DataHub 实现。

建议公开合同如下；名称在实现时保持同一套，不同时建立等义入口：

| 接口 | 语义 |
| --- | --- |
| `openCamera(config)` | 保留明确打开预览；本次产品使用本页创建的客户端和冻结配置，不打开正式采集入口。 |
| `startBoundedCapture(request)` | 请求 `ppg` 或 `ppg_acc`、正的目标秒数及组合所需 ACC 配置，准备各源并返回本轮 `captureId`；源参数不承载健康指标或云端模型。 |
| `getBoundedCaptureSnapshot()`、`subscribeBoundedCapture()` | 读取／订阅同一原生轮次的阶段、进度、源状态、错误及本轮完成引用，不传样本。 |
| `stopBoundedCapture(captureId)` | 绑定指定轮次，提前关闭正式窗口并等待本轮资源和文件屏障；已结束轮次返回同一结果，不误停新轮。 |
| `closeCamera()` | 对本调用方持有的有限轮次先完成组内收尾，再关闭预览；未开始时只关闭自己取得的相机。 |

`stopBoundedCapture` 的调用结果不只提供成功路径：运行快照保留已正常定稿的分源文件与真实错误，使解锁／关闭失败时不丢失“文件已完成但资源释放失败”的事实；只有正常组合完成才提供组合成功引用。

替代方案：JS 顺序或并发调用两个已有 `startCapture()` 只能表达命令时序，无法保证统一入口、原生截止和双源停止顺序，因此不采用。另建完整原生测量业务框架会与未来 measurement 重叠，也不采用。

### 2. 所有权检查覆盖原有控制入口

每个 Nitro 控制实例具有内部调用方身份；控制器在既有命令锁内记录当前相机／采集轮次的所有者。有限协调器取得本轮 PPG 及 ACC 的确切句柄，传感器句柄包含所有者与目标会话身份。

- 原始 PPG 的开始、停止、关闭入口也必须识别有限轮次占用，不能让另一客户端绕过组合协调器停止相机。
- ACC 已被独立入口持有时拒绝组合启动；失败清理只操作本轮成功取得的句柄，不执行无归属的公共 `stopCapture()`。
- 组合持有 ACC 时，独立入口开始或停止均拒绝改变该会话。旧停止、旧截止及异步失败回调绑定旧轮身份，不重新查询当前会话作为目标。
- `CameraUseGuard` 继续提供 PPG／RPPG 的硬件互斥；它不是调用方命令授权，不能替代控制器所有者检查。
- 宿主原生生命周期仍可中断其负责的会话；独立传感器和被动服务不被产品页关闭动作级联停止。

替代方案：仅在新协调器外部加锁无法防止旧公开停止入口介入，因此不采用。

### 3. 先准备源，再一次发布正式软件窗口

将 `PPGCaptureSession.start()`、`SensorCaptureSession.start()` 中的输出／队列准备与正式接收拆成内部职责：先完成资源取得、必要相机锁确认、writer 准备与 ACC 注册，入口保持关闭。全部必需源就绪后，以一次原生 `elapsedRealtimeNanos` 读取建立 `T0` 和 `T1=T0+目标时长`，向所有本轮源发布同一个窗口 `[T0,T1)`。

- PPG 沿用处理入口单调时间判断控制窗口，不将它冒充曝光时刻；正式帧的 Camera2 metadata 继续按精确时间戳关联。
- ACC 同时要求接收时刻与原始事件时刻属于本轮正式窗口，继续拒绝注册后的历史事件。
- 在接收入口检查上下界，原生截止任务到时先同时封闭两源，再并行等待各自收尾；不能先等待 PPG 落盘再停止 ACC。
- 定时唤醒仍按单调时钟确认剩余量，不因调度延迟接收截止后样本。已在窗口内进入的帧、配对元数据和队列记录继续完成。
- 提前停止将有效窗口缩短并保留 `user_stop`；后台／技术失败按真实中断结束，不自动续采。无样本不是成功组合。

这是软件接收窗口，不是硬件同步；不同源的首末原始采样时间可能不同。相机时间域不能确认时记录未知，不把 Camera2 时间直接与 ACC 事件时间相减解释为采样同步。

### 4. 同一原生事实提供状态、进度和终态

有限快照区分待操作、准备、预览、启动、采集、收尾、完成、失败／中断，包含当前 `captureId`、模式、目标、原生计算的 `elapsedMillis`／`remainingMillis`、各源状态、结束原因及错误。计时低频通知，不逐帧刷新 JS；目标截止和 UI 时间使用同一正式窗口。

本轮关联记录还需包含正式窗口实际关闭时刻、文件／资源屏障完成时刻及各源真实首末采样时间，避免混用当前 PPG、ACC 的旧起止字段。内部原始纳秒保持整数；跨桥绝对纳秒使用十进制字符串，展示时间在原生先求差再以毫秒数提供，页面不直接相减绝对时钟。

正常完成必须同时满足必需源实际有数据、各自文件已定稿及本轮相机／传感器已释放。写完文件但关闭失败时保留文件事实和可再次关闭的错误，不显示整体成功。合并本轮的并发停止和关闭屏障，收尾期间不允许新一轮。

### 5. 组合结果引用既有文件，不复制或建立跨源事务

继续使用原有路径：PPG 的 `ppg.csv`、`frame.csv` 与加速度的 `accelerometer.csv` 各由原输出器定稿。组合结果只增加低频元信息和原文件引用：轮次标识、模式、结束原因、冻结配置、源会话标识、实际窗口、各源样本数和首末采样时间、路径及大小。

本次仅保存当前进程完成组合引用，不新增落盘 manifest、重启扫描或恢复数据库。组合失败不生成成功引用，也不回滚、删除另一源已完成文件；独立源列表按现有协议保留。后续 measurement 可以拿本轮 PPG 和 ACC 引用作输入，不从历史列表末尾猜测配对。

### 6. 产品提供固定、透明的工程采集配置

两页默认目标 30 秒。选择实际枚举到的后摄，查询预览＋分析组合，沿用现有能力驱动配置构建与校验；尺寸偏好 720×720、FPS 偏好 30，单块 `[1,1]`，明确请求补光。保留真实协商结果，不将偏好当交付值；必需后摄／补光不可用时反馈失败，不替换前摄或静默关灯。

血压仅加入 `accelerometer`，请求间隔 5,000 微秒，实际注册仍受设备能力与既有上限约束，不申请高采样率权限、不承诺实际 200 Hz。曝光、白平衡和对焦沿用现有明确支持模式的默认构建，不新增一套手动参数表单或未经确认的锁定门槛。配置和真实采样摘要进入次级详情，不能以请求参数保证模型有效。

这组参数是本地采集基线，不是医学标准；真实信号和后端算法适配由后续 measurement 联调验证，本提案不发起上传验证或补造合格样本。

### 7. “简易 UI”保持产品级设计，不保留假数据

遵守 `docs/development/frontend-development.md`，复用主题、`styled-components/native`、组件目录结构、`AppText`、`ActionButton`、`LoadingIndicator`、既有反馈宿主和操作资源。无需新设计系统、字体或色板。

| 区域 | 指尖 | 血压 |
| --- | --- | --- |
| 顶部 | 现有品牌与返回布局，真实来源对应返回名称 | 同一层级，标题表达血压采集，不显示估计读数 |
| 主视觉 | 保留圆形构图与装饰边框，准备后使用原生真实预览；中央轻量操作提示不显示覆盖百分比 | 复用 `op2` 贴胸操作资源；准备时提供真实后摄预览，开始后仍保留对应持机指引 |
| 主状态面板 | 全宽白色圆角面板，PPG 阶段与正式时间分组 | 同风格面板，组合阶段与时间为主，PPG／加速度各自状态为辅 |
| 主操作 | 主题渐变胶囊按钮；依真实阶段提供打开预览、开始采集、结束采集、重新采集／重试 | 同一操作语义，不引入第二套组件或控制台 |
| 完成信息 | 本轮两份 CSV 的清晰完成状态 | 本轮 PPG 双文件与加速度文件，整组失败不显示完成 |
| 次级详情 | 展开查看实际尺寸、FPS、配置、样本数及文件名称／大小／可核查路径 | 同时包含传感器请求／注册间隔、各源时间范围和文件情况 |

初次进入无设备副作用；用户点击打开预览后授权并挂载 `CameraPreview`，等待有效原生宿主布局再打开。预览时主按钮变为开始采集，用户确认放置后手动开始，不将经验遮挡提示当作自动触发条件。采集中提供明确提前结束，收尾按钮忙碌且不可重测；完成保留本轮信息，重新采集清空旧轮展示后重新打开预览。

保留现有指尖中央提示浮层的尺寸、圆角、最大宽度和不阻挡操作约束。只有真实原生经验提示才提供调整建议，未评估不宣称完整覆盖。取消覆盖百分比及模拟红层，但不删除可复用的圆形视觉。两页不提供没有真实来源的脉搏波、健康读数或质量分；不为保留旧分页而留空图或填模拟数值。

文件详情为次级展开区域，首屏不堆叠设备参数或绝对路径。状态同时用文字表达，不只靠颜色；主按钮保留加载、禁用与防重，至少 48 dp 触控。沿用现有反馈体系处理拒权、忙和失败，保留必要可恢复信息，不增加只为解释演示／测试身份的文案。

### 8. 根栈入口和页面生命周期保持一致

保留 `fingertip`／`chest` 方式与原设备偏好键，新增 `BloodPressureMeasurement` 根栈路由，指尖原位替换。`resolveMeasurementEntry()` 不再对 chest 返回空值，准备页确认也不再弹未接入说明。`target` 仍只传递说明上下文，不决定云端模型或承诺指标。

未跳过时确认后进入采集页、返回准备；当次选择跳过使用替换导航，已跳过直接进入，返回原功能分类。两页不显示产品底栏、不新增公开深链。页面 Hook 负责订阅、预览布局和展示映射；`app/measurement` 仅组装所需客户端及小型页面接入，不在按钮回调重新实现双源时序。

指尖与血压接入现有主动导航守卫，等待本页在途命令、本轮关闭及文件完成；失败留页允许再关闭。后台由原生中断，回来读取真实状态；卸载清理不是主要资源交接手段。面部和被动服务保持原生命周期。

### 9. 测试只证明本次采集能力

- 复用 PPG 双文件、传感器停止、队列和相机租约已有回归；只给新行为增加确定性覆盖：准备阶段不入窗、共同上下界、双源完整完成、部分启动失败、所有者隔离及旧轮截止不影响新轮。
- 页面级测试覆盖真实状态映射、本轮结果隔离和离页屏障；删除已废弃的覆盖动画／模拟时钟／模拟波形测试，不重新固定其实现细节。
- 在常规竖屏、默认字号的实际 Android 产品页面，分别走通指尖和血压的预览、30 秒自动截止、完成与重测；再定向检查提前停止、后台、必要权限／占用失败和返回收尾，不做穷尽组合或全设备矩阵。
- 按原文件协议检查本轮文件实际可读、表头、记录数、单块与精确 PPG／frame 配对；血压核对三份文件关联及真实两源时间，不以请求采样率或页面倒计时推算行数。仅模拟器可用时，注明只证明实际 CameraX／SensorManager 接入和文件，不证明人体信号。
- 实际界面检查同时检查两页的主题、主次层级、预览／操作图比例、状态、主按钮和详情可达，不能用编译成功或裸功能操作替代视觉检查；不新增横屏、大字号或专项无障碍范围。
- 本轮不向后端创建任务。后续 measurement 才进行文件到真实模型及完整健康业务闭环验证；当前采集通过不等于指尖指标或血压有效。

## Risks / Trade-offs

- [进行中页面规格尚未成为主规格] → 以其实际完成交付及增量为前置，本次只在自己的增量明确替换，不倒改旧提案；主规格同步按正常流程处理，不为写本提案提前归档。
- [共同软件窗口被误认为硬件同步] → 同时公开控制窗口与各源真实时间，并保留未知时钟语义，不改写原始时间或外推同步精度。
- [已有公开停止入口误停组合] → 在控制器内部检查所有者与具体会话，不仅在新页面／协调器上加锁。
- [停止或关闭失败时仍存在已完成文件] → 分开保存文件完成与资源错误，整体不假报成功、不自动删除，允许再次完成资源关闭。
- [简化测试页降低产品质感] → 以操作主视觉、统一状态面板、主题主按钮及次级详情组织信息，实际检查常规原生表面；不靠模拟数据填满布局。
- [固定工程配置不能保证有效生理信号] → 采集范围只验证真实样本和文件，实际协商及失败如实展示，不将质量／医学验证加入本次验收。

## Migration Plan

1. 等 `restore-native-measurement-pages` 完成实际实施及必要验证，以其最终组件与增量为迁移基线；不重跑或接管其未完成项。
2. 先落地原生会话窗口、所有者隔离、有限协调及公开低频合同，保留独立原始采集接口；用核心行为回归证明新合同。
3. 指尖原位切换为真实采集 UI，新增血压页并接通两个入口和离页屏障；删除 `fingertipDisplay`、专属模拟曲线消费者、过时文案及测试，不保留新旧模式开关。保留面部真实图表和波形历史基础设施。
4. 完成受影响检查及实际 Android 页面／文件验证后，更新采集、前端、架构和产品的当前能力说明，不保存验收流水。
5. 如需回退，撤销本次接口和页面接入改动，保留既有已完成采集文件；不回退前置页面变更、删除完成产物或改变被动设置，不建立长期兼容分支。
